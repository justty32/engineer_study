# 隨機程序與模擬（Stochastic Processes & Simulation）

> 名詞對照見 [中英名詞對照表 → 隨機程序與模擬](../中英名詞對照表.md#隨機程序與模擬)。

## 0. 本科定位

工業工程處理的系統極少是確定性的。一座晶圓廠裡，機台會隨機當機、維修時間不確定、客戶訂單來得毫無規律；一家醫院的急診室裡，病患到達間隔與處置時間都是隨機的；一條供應鏈裡，需求預測永遠有誤差。這些「隨機性」（stochasticity）不是分析上的雜訊——它正是系統行為的核心驅動力。如果忽略隨機性、假設一切都用平均值行事，分析結果往往帶來災難性的樂觀偏差（例如：以為利用率 95% 很合理，實際上的平均等待時間卻已經爆炸）。

本課程教授兩套相輔相成的工具來處理隨機系統：

- **隨機程序（stochastic processes）**：建立數學模型，描述「一個系統的狀態如何隨時間隨機演化」。當系統夠簡單（如單一服務窗口的排隊系統），可以推導出封閉公式——例如平均排隊人數、平均等待時間——直接得到解析解。
- **離散事件模擬（discrete-event simulation, DES）**：當系統太複雜、無法用封閉公式求解時，在電腦上建立系統的虛擬複製品，讓隨機事件依照機率分布發生，觀察系統在數千次「模擬天」中的行為。模擬是 IE 工具箱中最強大的「what-if」引擎：不需要打擾真實系統，就能測試不同布局、不同排班策略、不同庫存政策的長期效果。

兩者的關係類似物理學中的「解析力學」與「數值模擬」：排隊理論等解析模型給你洞察（為什麼等待時間暴增？因為利用率趨近 1），模擬則讓你把這些洞察延伸到複雜的真實系統中。

## 1. 隨機程序基礎

### 1.1 定義與分類

一個**隨機程序（stochastic process）**是一組以時間為索引的隨機變數：

$$\{X_t : t \in T\}$$

其中 $T$ 是索引集（index set），$X_t$ 是系統在時間 $t$ 的狀態。分類依兩個軸：

- **時間軸 $T$**：離散時間（discrete-time）——只觀察特定時刻 $t = 0, 1, 2, \dots$；或連續時間（continuous-time）——$t \in [0, \infty)$。
- **狀態空間（state space）**：離散狀態（如「機台上線中 vs. 機台當機中」只有兩種狀態）或連續狀態（如「水庫水位」可以是任何實數值）。

最常見的組合：離散時間＋離散狀態＝**馬可夫鏈**（Markov chain）；連續時間＋離散狀態＝**連續時間馬可夫鏈**（CTMC），其中排隊系統（等候人數 = 0, 1, 2, …）是最經典的例子。

### 1.2 馬可夫性質

隨機程序的「記憶」決定了分析難度。最極端的簡化假設是**馬可夫性質（Markov property）**：

$$P(X_{t+1} = j \mid X_t = i, X_{t-1}, \dots, X_0) = P(X_{t+1} = j \mid X_t = i)$$

意思是：「給定現在，未來與過去條件獨立。」系統的下一步只取決於當前狀態，與它是怎麼走到這個狀態的無關。這個假設看似很強，但許多實際系統**可以透過擴充狀態空間來滿足**——例如：如果今天的天氣不僅取決於昨天的天氣（一階馬可夫），你可以定義狀態為「連續兩天的天氣組合」，把二階依賴轉為一階馬可夫。這正是為什麼馬可夫鏈在工程中如此泛用。

### 1.3 轉移機率

在離散時間馬可夫鏈中，定義**一步轉移機率**：

$$P_{ij} = P(X_{t+1} = j \mid X_t = i)$$

所有 $P_{ij}$ 排成**轉移機率矩陣（transition probability matrix）** $P$，每一列都是一個機率分布（各列元素和 = 1）。**n 步轉移機率** $P_{ij}^{(n)} = P(X_{t+n} = j \mid X_t = i)$ 就是「從狀態 $i$ 出發，$n$ 步後抵達 $j$ 的機率」。

### 1.4 IE 中的典型例子

- **存貨水準 $\{I_t\}$**：$I_t$ 是第 $t$ 天結束時的庫存量。每天的顧客需求是隨機的；當庫存降到再訂購點以下就觸發補貨。$I_t$ 的轉移機率由需求分布與補貨策略共同決定。
- **排隊系統的顧客數 $\{N_t\}$**：$N_t$ 是時間 $t$ 時系統內的顧客數。顧客以隨機間隔到達，以隨機服務時間離開。這是最經典的出生–死亡過程（birth-death process）。
- **機台狀態**：機台可能處於「運轉中」、「當機維修中」、「待料中」。不同狀態間的轉移機率由失效間隔分布、維修時間分布、零件供應可靠性決定。

## 2. 馬可夫鏈（Markov Chains）

### 2.1 Chapman-Kolmogorov 方程

多步轉移機率滿足：

$$P_{ij}^{(n+m)} = \sum_k P_{ik}^{(n)} P_{kj}^{(m)}$$

這條等式意味著：從 $i$ 出發走 $n+m$ 步到 $j$，等於所有可能的中間停留點 $k$（在 $n$ 步後的位置）的路徑加總。矩陣形式就是 $P^{(n+m)} = P^{(n)}P^{(m)}$，也就是 $P^{(n)} = P^n$——$n$ 步轉移矩陣就是一步轉移矩陣的 $n$ 次方。這是非常強大的計算工具：給定今日狀態的機率向量 $\pi^{(0)}$，第 $n$ 步後的狀態分布是 $\pi^{(n)} = \pi^{(0)}P^n$。

### 2.2 狀態分類

馬可夫鏈的長期行為取決於鏈的「連通結構」，而不是初始狀態。關鍵分類：

- **可達（accessible）**：從 $i$ 出發可能到達 $j$（存在某 $n \ge 0$ 使得 $P_{ij}^{(n)} > 0$）。
- **溝通（communicate）**：$i$ 與 $j$ 互相可達——這是一個等價關係，把狀態空間分割成**溝通類（communicating class）**。同一類內的狀態共享相同的長期行為特性。
- **常返（recurrent）vs. 瞬態（transient）**：從常返狀態出發，最終必定會回來（機率為 1）；從瞬態出發，有可能一去不返。一個有限馬可夫鏈不可能讓所有狀態都是瞬態——必定至少有一個常返類。
- **正則常返（positive recurrent）vs. 零常返（null recurrent）**：常返狀態的平均回訪時間是否有限。有限狀態鏈的常返類必定是正則常返。
- **週期（period）**：回到狀態 $i$ 所需步數的最大公因數。週期為 1 時稱為**非週期（aperiodic）**。
- **吸收狀態（absorbing state）**：$P_{ii} = 1$——一旦進入就永遠被困在裡面。**吸收馬可夫鏈**至少有一個吸收狀態，且從任何非吸收狀態都可能抵達某吸收狀態。IE 應用中，這類鏈常用來計算「平均多久會到達終止條件」——例如：機台從正常運轉到最終報廢的平均運轉時數。

### 2.3 極限分布與穩態分布

對一個非週期、正則常返且不可約（irreducible——所有狀態互相溝通）的馬可夫鏈，存在唯一的**穩態分布（stationary distribution）** $\pi$，滿足：

$$\pi = \pi P, \quad \sum_i \pi_i = 1$$

$\pi_j$ 的物理意義是：**長期下來，系統處於狀態 $j$ 的時間比例**。可以透過解線性方程組求得（$n$ 個方程、$n$ 個未知數，再加一條正規化條件）。更重要的是：不管從哪個初始狀態出發，長期下來狀態分布都會收斂到 $\pi$（ergodicity）。

對於吸收馬可夫鏈，我們關心的是另一件事——**期望吸收時間**。將狀態重排，使吸收狀態排在最後，轉移矩陣可寫為：

$$P = \begin{bmatrix} Q & R \\ 0 & I \end{bmatrix}$$

其中 $Q$ 是非吸收狀態間的轉移，$R$ 是從非吸收轉入吸收的機率。則**基本矩陣（fundamental matrix）** $F = (I-Q)^{-1}$，其元素 $F_{ij}$ 表示：從非吸收狀態 $i$ 出發，在到達吸收之前，在狀態 $j$ 的平均停留次數。從 $i$ 出發的平均吸收步數就是 $F$ 第 $i$ 列的和。

### 2.4 IE 應用實例

- **機台可靠度模型**：兩狀態鏈（運轉 / 當機）。每小時從運轉轉入當機的機率為 $p$，從當機修復回到運轉的機率為 $q$。穩態分布：$\pi_{\text{運轉}} = q/(p+q)$、$\pi_{\text{當機}} = p/(p+q)$。也就是說，機台長期處於當機狀態的時間比例是 $p/(p+q)$。這個簡單模型是產能分析的基礎積木。
- **品牌切換模型**：消費者每個月選擇品牌 A 或品牌 B，切換機率由市場調查估計。轉移矩陣的穩態分布直接給出長期的市場占有率預測。
- **庫存系統**：庫存水準從 $s$（再訂購點以下）到 $S$（補貨後的最高水準），顧客需求是隨機的。轉移矩陣的穩態分布告訴你：長期下來，庫存 = 0 的時間比例（缺貨比例）。

## 3. 排隊理論（Queueing Theory）

排隊理論是 IE 的經典圖騰——因為排隊無所不在：工廠的在製品堆積在瓶頸機台前、急診病患在走廊上的等候、客服電話在等待接聽、資料封包在路由器緩衝區排隊。所有這些場景都可以抽象成：**顧客（customer）** 以某種隨機模式到達、排隊等候、由**伺服器（server）** 以某種隨機時間提供服務、然後離開。

### 3.1 Kendall 記號

描述一個排隊系統只需要五個參數，記為 A/B/c/K：

| 位置 | 意義 | 常用符號 |
|------|------|----------|
| A | 顧客到達間隔分布 | $M$（指數＝馬可夫／無記憶）、$D$（確定性）、$G$（一般） |
| B | 服務時間分布 | 同上 |
| c | 伺服器數量 | 整數 |
| K | 系統容量上限（含排隊與服務中） | 省略表示無限大 |

例如：M/M/1 表示指數到達間隔、指數服務時間、單一伺服器、無限容量——這是排隊理論的「氫原子」（最簡單、完全可解析）。M/M/c 是同樣假設下的多伺服器版本（客服中心、銀行櫃台）。M/G/1 是到達為指數但服務時間為一般分布的單伺服器系統——推導困難度遠高於 M/M/1，但更接近真實情境。

### 3.2 Little 定律

$$L = \lambda W$$

這是作業研究中最美、最意想不到的一條公式。$L$ 是系統內的平均顧客數（排隊中＋服務中），$\lambda$ 是平均到達率，$W$ 是一個顧客在系統內的平均停留時間。它的驚人之處在於：**不需要任何關於到達分布、服務分布、排隊紀律的假設**——只要系統處於穩態且沒有「顧客在系統中憑空消失或增生」，這條公式就必定成立。

同樣的關係對排隊部分也成立：$L_q = \lambda W_q$，其中 $L_q$ 是平均排隊人數、$W_q$ 是平均排隊等待時間。服務時間 $S$ 滿足 $W = W_q + S$。Little 定律是你驗證模擬結果的試金石——如果模擬跑出來的 $L$ 和 $\lambda W$ 不一致，你的程式很可能有 bug。

### 3.3 M/M/1 排隊系統

到達為速率 $\lambda$ 的卜瓦松過程（到達間隔 ∼ Exp($\lambda$)）、服務時間 ∼ Exp($\mu$)（速率 $\mu$）、一台伺服器。

定義**利用率（utilization）** $\rho = \lambda/\mu$。這是最重要的參數——**如果 $\rho \ge 1$，排隊長度會發散到無窮大**（到達比服務快，系統永遠清不完）。穩態存在的條件是 $\rho < 1$。

M/M/1 是一個出生–死亡過程（排隊人數增減一個的馬可夫鏈），其穩態機率為：

$$P_n = (1-\rho)\rho^n, \quad n = 0,1,2,\dots$$

其中 $P_n$ 是系統內有 $n$ 個顧客的長期機率（含正在被服務的那位）。由此導出關鍵績效指標：

$$\begin{aligned}
L &= \frac{\rho}{1-\rho} = \frac{\lambda}{\mu - \lambda} \\[4pt]
L_q &= \frac{\rho^2}{1-\rho} \\[4pt]
W &= \frac{1}{\mu - \lambda} \\[4pt]
W_q &= \frac{\rho}{\mu - \lambda}
\end{aligned}$$

### 3.4 利用率接近 1 的災難

看 $W_q = \rho/[\mu(1-\rho)]$：當 $\rho \to 1$ 時，分母的 $1-\rho \to 0$，$W_q \to \infty$。這是排隊理論最核心的工程教訓：**你永遠不該讓系統的利用率太接近 100%**。在 $\rho = 0.5$ 時排隊等待時間是 $1/\mu$（一個平均服務時間）；$\rho = 0.9$ 時暴增到 $9/\mu$；$\rho = 0.99$ 時是 $99/\mu$。

這就是為什麼高速公路在容量接近飽和時瞬間塞死、為什麼晶圓廠的機台利用率目標通常設在 85%–90% 而不是 100%、為什麼急診室在流感高峰期崩潰——根本原因不是「資源不夠」，而是**隨機變異加上高利用率必然導致等待時間的非線性爆炸**。增加資源只能緩解，無法根治；減少變異（標準化操作、平穩排程）是同樣重要的解方。

### 3.5 M/M/c 與 Erlang-C 公式

$c$ 台相同的伺服器，每台服務速率 $\mu$，共同排隊（不分工）。利用率為 $\rho = \lambda/(c\mu)$。穩態存在的條件同樣是 $\rho < 1$。

M/M/c 的關鍵公式——任何顧客到達時必須排隊等候的機率，即 **Erlang-C 公式**（也稱 Erlang 延遲公式）：

$$P(\text{等候}) = \frac{\frac{(c\rho)^c}{c!}\frac{1}{1-\rho}}{\sum_{k=0}^{c-1}\frac{(c\rho)^k}{k!} + \frac{(c\rho)^c}{c!}\frac{1}{1-\rho}}$$

這個機率是客服中心人力規劃的鐵律：給定 $\lambda$（來電率）、$\mu$（平均通話長度的倒數）與目標服務水準（例如「不超過 5% 的來電需要等候」），可以反推出需要多少接線員 $c$。Erlang-C 直接刻在客服系統的排班模組裡。

### 3.6 排隊心理學

排隊不只是數學問題——顧客對等待的「感受」往往比實際的等待時間更影響滿意度：

- **單線多窗口（蛇形排隊）遠優於多線多窗口**：前者對每個顧客公平（先到先服務），後者讓人焦慮「隔壁隊伍永遠比我快」。
- **已知等待時間比未知更容易忍受**：「預計等候 10 分鐘」比「不知道要等多久」讓人心安。
- **沒事的等待感覺比有事做的等待長**：所以在電梯旁放鏡子（可以照自己）、在客服熱線放音樂。
- **不公平的等待感覺特別長**：插隊——或感覺有人在插隊——會讓顧客憤怒。
- **獨自等待比群體等待更難熬**。

這些是 IE 與人因工程的交界處：知道數學上的最優解（如最小化平均等待時間的排班方式）之後，還必須兼顧顧客感受，否則即使排隊時間很短，顧客仍然不滿意。

## 4. 蒙地卡羅模擬（Monte Carlo Simulation）

名稱來自蒙地卡羅賭場——隨機性是這個方法的核心。基本想法極為簡單但深遠：如果你想計算某個隨機量 $\theta = E[g(X)]$（例如：某個複雜庫存策略下的平均每月缺貨成本），你不需要推導出 $g(X)$ 的分布。你只需要：

1. 依照 $X$ 的分布生成大量的隨機樣本 $x_1, x_2, \dots, x_n$。
2. 計算樣本平均 $\hat{\theta} = \frac{1}{n}\sum_{i=1}^n g(x_i)$。
3. 根據大數法則，$\hat{\theta} \to \theta$ 當 $n \to \infty$。

這就是蒙地卡羅的本質：把一個積分（期望值）的問題轉化為一個隨機抽樣的問題。在電腦上生成隨機變數是整個方法的基礎。

### 4.1 偽隨機數生成

真正的隨機數需要硬體熵源。但模擬需要的是**可重複**的隨機數（reproducible——這樣你才能除錯和比較不同策略），因此實務上使用**偽隨機數生成器（pseudo-random number generator, PRNG）**。

最經典的演算法是**線性同餘生成器（linear congruential generator, LCG）**：

$$Z_{n+1} = (a Z_n + c) \bmod m, \quad U_n = Z_n / m$$

其中 $a$（乘數）、$c$（增量）、$m$（模數）是精心挑選的整數。好的參數選擇（如 $a = 7^5 = 16807$、$m = 2^{31}-1$）能在一個完整週期內產生均勻分布在 $[0,1)$ 之間的數列，且統計檢定無法拒絕獨立性與均勻性的假設。

現代模擬軟體多使用 **Mersenne Twister** 演算法（週期長達 $2^{19937}-1$，幾乎所有統計檢定都無法與真隨機數區分），但理解 LCG 的原理就足以理解 PRNG 的核心思路：一個確定性的遞迴式，設計得「看起來夠亂就行」。

### 4.2 隨機變數生成

有了均勻隨機數 $U \sim \text{Uniform}(0,1)$，如何生成服從特定分布的隨機變數？

**逆變換法（inverse transform method）** 是最通用也最直覺的方法。原理：若要生成隨機變數 $X$ 服從 CDF 為 $F$ 的分布，則：

$$X = F^{-1}(U)$$

其中 $U \sim \text{Uniform}(0,1)$。證明基礎：$\mathbb{P}(F^{-1}(U) \le x) = \mathbb{P}(U \le F(x)) = F(x)$。以指數分布為例，$F(x)=1-e^{-\lambda x}$，則 $F^{-1}(u) = -\frac{1}{\lambda}\ln(1-u)$，而 $1-u$ 也是均勻的，故 $X = -\frac{1}{\lambda}\ln U$ 生成 Exp($\lambda$)。

逆變換法的限制是 $F^{-1}$ 必須有封閉形式。對於常態分布這種 CDF 無封閉形式的分布，常用的替代方案包括：

- **接受–拒收法（acceptance-rejection method）**：找一個容易生成的封套分布（envelope distribution），從中生成候選值，再以某個機率接受或拒收。原理類似用長方形框住一條曲線然後往框內隨機擲標。
- **Box-Muller 法**：專門生成標準常態分布：生成兩個獨立 $U(0,1)$ 的 $U_1, U_2$，則 $Z_1 = \sqrt{-2\ln U_1}\cos(2\pi U_2)$ 與 $Z_2 = \sqrt{-2\ln U_1}\sin(2\pi U_2)$ 皆 $\sim N(0,1)$ 且獨立。這個方法優雅、精確、只需兩個均勻隨機數和一對三角/對數函數。

### 4.3 變異數縮減技術

蒙地卡羅估計 $\hat{\theta}$ 的標準差是 $\sigma/\sqrt{n}$——要提高一位數字的精確度需要百倍的樣本數。這意味著，與其盲目加樣本，不如想辦法「讓同樣的樣本數給出更準的估計」。這就是**變異數縮減（variance reduction）**：

- **對立變數法（antithetic variates）**：對每個 $U$，同時用 $U$ 和 $1-U$ 生成兩個樣本。如果函數 $g$ 是單調的，這兩個樣本的誤差傾向互相抵消。極端情況下變異數可以減半——等於樣本數翻倍。
- **控制變數法（control variates）**：找一個與目標量高度相關、且期望值已知的輔助變量，利用它來校正估計。例如：在估計複雜衍生產品的價格時，以同一標的物的簡單歐式選擇權（封閉公式已知）作為控制變數。
- **共享隨機數（common random numbers）**：比較兩種策略 A 與 B 時，兩者使用完全相同的隨機數流。這樣做的效果是：兩種策略的輸出會高度正相關，差額 $D = Y_A - Y_B$ 的變異數大幅降低——因此能用少得多的模擬次數就偵測出 A 與 B 之間的顯著差異。使用不同的隨機數流做一次公平比較——這是很常見的入門級錯誤。
- **重要性抽樣（importance sampling）**：當你關心的是極端事件（例如：一個高度穩健的系統的失效機率——可能只有百萬分之一），用原本的分布取樣幾乎不可能碰到失效事件。解方是把抽樣分布「往失效區域傾斜」，再用概似比（likelihood ratio）加權來修正偏差。這在可靠度工程與金融風險評估中極為重要。

## 5. 離散事件模擬（Discrete-Event Simulation）

蒙地卡羅模擬處理的是「生成一堆獨立樣本然後取平均」。離散事件模擬（DES）處理的是更複雜的問題：**系統的狀態只在離散的「事件」發生的瞬間才改變**，在兩個事件之間狀態保持不變。這正好對應 IE 系統的特徵——「顧客到達」、「服務完成」、「機台當機」、「補貨到倉」都是瞬時事件。

### 5.1 核心機制：模擬時鐘與事件清單

DES 的核心是一個迴圈：

1. **事件排程（future event list, FEL）**：一個以事件發生時間排序的優先佇列，裡面裝著「未來會發生什麼事、何時發生」的紀錄。
2. **下個事件推進（next-event time advance）**：模擬時鐘不是一秒一秒地滴答前進——它直接跳到 FEL 中時間最早的那個事件。
3. **執行事件**：根據事件類型更新系統狀態（改變排隊長度、釋放或占用資源、累計統計量）。
4. **排程新事件**：當下事件可能觸發未來事件（例如：結束服務一個顧客後，若還有顧客在排隊，就排程下一個服務完成事件）。
5. 重複直到模擬終止條件滿足。

這種「只跳到有事發生的時刻」的機制是 DES 能夠處理長達數年時間跨度的大型系統的關鍵——如果一秒一秒地推時鐘，一個月的模擬需要 260 萬步；但事件推進只需要處理實際發生的事件（每天幾千到幾十萬個），效率高出好幾個數量級。

### 5.2 基本元素

DES 模型由以下元件組成：

- **實體（entity）**：在系統中流動的物件——顧客、工件、訂單、病患、AGV。一個實體從被「創造」開始，在系統中經歷一連串的處理步驟，最後被「消滅」（離開系統）。
- **屬性（attribute）**：每個實體攜帶的資訊——到達時間、優先級別、需要的處理時間、對應的產品類型。
- **資源（resource）**：提供服務的東西——機台、作業員、病床。資源有容量（一台機台一次只能加工一件），實體需要先「獲取」資源才能被服務，服務完畢再「釋放」資源。
- **佇列（queue）**：實體等候資源的地方。排隊紀律（FIFO 先進先出、優先級、最短處理時間優先）決定哪個實體先被服務。
- **統計累積器（statistical accumulator）**：在模擬過程中持續記錄平均排隊長度、資源利用率、週期時間分布等，供事後分析。

### 5.3 兩種建模世界觀

- **事件排程世界觀（event-scheduling worldview）**：程式設計師直接管理 FEL，手動撰寫每個事件類型的處理邏輯。這是 DES 最底層的視角——適合高效能的客製模擬引擎，但對建模者來說心智負擔較重。
- **程序互動世界觀（process-interaction worldview）**：建模者定義一個實體從產生到消滅的「完整生命週期」，語言或框架自動在實體需要等候資源時暫停其執行、在資源可用時自動恢復。這更接近人類對系統的直覺（「顧客走進來、排隊、被服務、離開」）。主流商業模擬軟體（Arena、Simio、AnyLogic）都採用此世界觀。

理解兩種世界觀的差異有助於選擇工具：如果要對奇特的資源排班邏輯做高效率模擬，事件排程更靈活；如果目的是快速對一個常見的製造／物流場景建模，程序互動的商業軟體生產力高得多。

### 5.4 輸出分析：模擬結果的可信度

跑完模擬只是第一步——你必須能回答「這個結果有多可靠？」。

#### 暖機期與穩態 vs. 終止型模擬

模擬通常從「空的」初始狀態開始（沒有顧客在系統中、所有資源閒置）——這是人為的低負載狀態，系統需要一段時間才能進入代表長期行為的區間。這段過渡期稱為**暖機期（warm-up period）**，其數據必須在分析時捨棄。

- **終止型模擬（terminating simulation）**：有一個自然的終止事件（例如：銀行營業到下午五點、演唱會散場），初始狀態本身就是系統運作的一部分。直接對多次獨立複製（replication）做分析即可。
- **穩態模擬（steady-state simulation）**：你想知道的是系統「長期」的行為（例如：晶圓廠連續運轉一年後的每月平均產出）。解法：設定一段暖機期、只分析暖機後的穩態數據；並確保模擬長度足以讓穩態估計收斂。實務上常使用 **Welch 圖形法**（畫出多次複製的平均值隨時間的走勢，目視判斷何時趨於平穩）來決定暖機長度。

#### 批次平均法與複製法

穩態模擬的輸出是一條高度自相關的時間序列（前一個小時的排隊長度高，下一個小時也高——不獨立）。常態的 t 檢定假設獨立樣本，這裡不成立。

- **批次平均法（batch means）**：把一次長模擬切成若干等長、互不重疊的「批次」，每個批次的平均視為一個（近似獨立的）觀測值。關鍵在於批次要夠大，使得批次之間的自相關可以忽略。
- **複製/刪除法（replication/deletion）**：跑多次完全獨立的模擬（不同的隨機數種子，各自經過各自的暖機期），每次得到一個平均績效，再用這些平均值來算信心區間。缺點是每次複製都必須重新經歷暖機期——暖機數據被浪費掉了。

兩種方法常協同使用：多次複製確保不同隨機數種子的穩健性；每次複製內部再使用批次平均法提高統計效率。

#### 隨機數流管理

比較兩個替代方案（如策略 A vs. 策略 B）時，使用共享隨機數（同一個隨機數流驅動兩種策略）可以大幅降低差額的變異數，用更少的模擬複製就能給出統計顯著的結論。在實務上，這意味著要小心管理隨機數種子：為每個不確定性來源（到達、服務、當機、需求）配置獨立的隨機數流，確保兩個情境在這些來源上受到「相同的隨機波動」——這樣績效差異才能歸因於策略本身，而不是運氣。

## 6. 模擬在 IE 的應用

### 6.1 製造系統

這是 IE 最經典的模擬場景。一座工廠裡，上百台機台透過複雜的途程（routing）相互串接，產品種類多、途程互異、各機台的加工時間分布與當機率各不相同。模擬可以回答：

- **瓶頸在哪裡**？把機台的利用率排序，最高利用率的機台就是瓶頸——它是限制整體產出的那台機台（呼應限制理論）。瓶頸的位置可能隨產品組合（product mix）改變而漂移，模擬可以預測這個漂移。
- **需要多少 WIP**？在製品（WIP）是雙面刃：太少則瓶頸機台可能因上游來不及供料而閒置（飢餓），太多則存貨成本高、週期時間長。模擬可以在這兩者之間找到最適緩衝水位。
- **精實方案的驗證**：引進看板系統、建立 U 型線、把批量從一千降到一百——這些變革在紙上看似合理，但導入後的實際效果（尤其是各站變異的交互作用）往往無法用解析公式預測。模擬可以在不擾動真實產線的前提下，驗證改善方案的真正效益。

### 6.2 物流與倉儲

模擬在物流系統中的角色類似「沙盤推演」：

- **自動化倉儲系統（AS/RS）**的運作策略——堆高機用哪種派車演算法（最近的工作優先？FIFO？）——可以透過模擬在同一個需求情境下比較。
- **AGV 路徑設計**：要幾台 AGV 才能維持目標產量？交叉路口會不會發生死結（deadlock）？模擬可以跑出尖峰時段的車輛利用率與平均等待時間。
- **港口的貨櫃吞吐**：船隻到達、靠岸、卸櫃、櫃場堆放、卡車提櫃——全系統的瓶頸在哪個環節，模擬一目了然。

### 6.3 醫療系統

醫療是 IE 技能日益重要的應用領域。醫院的運作充滿隨機性（病患到達不可預測、處置時間變異極大），且「等候的代價」不是金錢而是人命：

- **急診室的病患流**：多少人來、嚴重度分布如何、需要多少檢查、多少會住院——模擬不同醫師排班與分流的設計，減少病人的等候時間與未看診就離院率。
- **開刀房的排程**：不同科別共享有限的開刀房，緊急刀會擠掉常規刀。模擬可以找出最穩健的排程策略——預留多少緩衝時段給緊急刀，又不讓開刀房常常空轉。
- **護理師人數配置**：不同護病比對等候時間與照護品質的影響。模擬可以提供數據驅動的理由，支持管理層擴編——「根據模擬，每班多兩名護理師可以讓病人等候給藥的時間減少 40%」比「護理師很累」更具說服力。

### 6.4 服務系統與供應鏈

- **客服中心人力**：來電率隨時間變化（上午尖峰、午餐低谷）、服務時間有變異——用 Erlang-C 配合時變到達率的模擬來規劃各班次的人數。這也是排隊理論與離散事件模擬最經典的實務結合。
- **機場安檢設計**：幾條安檢通道、預檢查區的排隊動線安排、尖峰時段的通道調度——模擬可以讓安檢的吞吐量最大化，同時避免排隊人龍溢出到航廈大廳。
- **長鞭效應（bullwhip effect）的展示**：供應鏈中的「啤酒遊戲」是最有名的模擬教學——零售商的需求波動只有 ±10%，但經過批發商、經銷商、製造商的層層放大後，上游工廠端的訂單波動可以達到 ±50%。模擬讓這個反直覺的現象一目了然，也讓學生親自體會「資訊共享為何重要」。

## 碩士/博士延伸

**碩士層級：**

- **輸入建模（input modeling）**：如何在實際系統中收集數據，選擇合適的機率分布（透過機率圖、適合度檢定如 Kolmogorov-Smirnov 與卡方檢定），估計分布參數，並在建模中謹慎處理分布尾部（tail behavior——低估尾部就低估了極端等待時間的頻率）。
- **輸出分析進階研究**：序列化的批次平均（標準化時間序列法）、再生法（regenerative method——利用系統回到空狀態的再生點來構造獨立的再生週期）。
- **模擬最佳化（simulation optimization）**：不是單純地「跑模擬然後手動看哪個設計比較好」，而是將模擬嵌入一個最佳化迴圈中，讓演算法自動搜尋決策變數空間。困難點在於：模擬輸出有隨機誤差（無法用解析的梯度）、每次評估代價高（跑一次複雜模擬可能要好幾分鐘甚至幾小時）。代表方法：**OptQuest**（結合啟發式搜尋與統計檢定，內建在 Arena/Simio 中）、**隨機近似法**（stochastic approximation，如 Kiefer–Wolfowitz 演算法）、**排序與選取程序**（ranking and selection——從有限數量的替代方案中選出最好的）。

**博士層級（研究方向）：**

- **代理人基模擬（agent-based simulation, ABM）**：不像 DES 那樣把實體當作被動流動的物件，ABM 中每個「代理人」有自己的內部狀態與行為規則，代理人之間可以互動、學習、適應。應用場景：人群疏散動態（每個行人有各自的出發點、目的地、速度、對擁擠的反應策略）、金融市場的微結構模擬、疫情傳播的接觸網絡模型。
- **系統動力學（system dynamics）**：用存量（stock）與流量（flow）的觀點，配合回饋迴路，捕捉系統在總體層級上的非線性動態——例如工廠訂單的長鞭效應、都市成長與交通壅塞的共演化。與 DES 互補：DES 擅長細節的實體流，系統動力學擅長巨觀的資訊回饋結構。
- **數位孿生（digital twin）**：不只是「離線模擬設計方案」，而是維持一個與真實工廠**即時同步**的虛擬模型，即時接收感測器數據更新狀態，用來做線上預測（「未來兩小時瓶頸會移到第三站，建議現在調整排程」）。挑戰：數據同化（如何把即時數據餵進模擬而不破壞其內部一致性）、即時運算速度。
- **平行與分散式模擬（parallel/distributed simulation）**：對於超大規模系統（如全球供應鏈、整個都市的交通網路），單一處理器的模擬速度不夠。挑戰在於：DES 的事件必須依因果順序處理，如何在多處理器上切割模型並正確同步因果關係。
- **AI 驅動的模擬**：利用強化學習（reinforcement learning）的代理人與模擬環境互動，自動學習最佳排程策略或庫存策略——模擬作為 RL 的「訓練場」。這領域目前正在快速發展，也是模擬與機器學習最自然的交界。
