# 第五章：自己寫一個 Neovim 插件

這章要教你從零開始寫自己的 Neovim 功能——先從「在設定裡加一個命令」這種最小的事情起手，然後慢慢學怎麼把程式碼整理成一個獨立的模組，最後看懂 lazy.nvim 的 plugin spec 是怎麼一回事。

---

## 一、插件到底是什麼

你可能聽過「插件」這個詞，但其實它在 Neovim 世界裡有兩個意思：

**（a）第三方套件**：別人寫好、放在 GitHub 上、透過 lazy.nvim 幫你裝進來的東西，比如 `nvim-treesitter`、`telescope.nvim` 這些。

**（b）你自己寫的 Lua 模組**：這也算一種「插件」，只是是你自己寫的，不用放 GitHub，也不用 lazy.nvim 管理，直接放在 `~/.config/nvim/lua/` 底下就好。

這章教的是（b）——**你自己動手寫的那種**。

### Lua 模組怎麼被載進來的？

Neovim 啟動時，`~/.config/nvim/lua/` 這個資料夾會自動加進所謂的 **runtimepath**。只要東西放在這個資料夾底下，你就可以用 `require("模組名")` 把它叫進來。

舉個例子：你建了一個檔案 `~/.config/nvim/lua/myplugin/init.lua`，那麼在任何地方寫 `require("myplugin")` 就能載入它。

這套設定的結構是這樣的（從 `init.lua` 往下看）：

```
init.lua               ← 只有一行：require("config.lazy")
lua/
  config/
    lazy.lua           ← 設定 lazy.nvim，掃描 lua/plugins/ 底下所有 spec
    keymaps.lua        ← 載入自訂模組（require("config.cmera") 等）
    cmera.lua          ← 一個真正的自訂模組，有自己的邏輯
  plugins/
    rainbow.lua        ← 第三方套件的 spec
    parinfer.lua       ← 另一個第三方套件的 spec
```

`lazy.lua` 裡設定了 `spec = { { import = "plugins" } }`，意思是「去掃 `lua/plugins/` 底下所有檔，把它們都當 plugin spec 讀進來」。

## 二、最小的自訂功能：命令、快捷鍵、autocmd

先不管模組不模組，最直接的做法是直接把程式碼寫在 `lua/config/keymaps.lua` 裡（或任何會被載入的設定檔）。

### 加一個自訂命令 `:Hello`

```lua
vim.api.nvim_create_user_command("Hello", function()
  print("你好，世界！")
end, {})
```

貼進 `keymaps.lua` 存檔，重開 Neovim 或跑 `:source %`，然後在命令列輸入 `:Hello`，底部就會印出「你好，世界！」。

`nvim_create_user_command` 的三個參數：
1. 命令名字（字串，必須大寫開頭）
2. 執行時要做什麼（function）
3. 選項（table）——先給空的 `{}` 就好

### 加一個快捷鍵

```lua
vim.keymap.set("n", "<leader>hw", function()
  vim.notify("Hi！按到了。")
end, { desc = "打招呼" })
```

這個意思是：在 normal mode（`"n"`），按 `<leader>hw`，執行後面那個 function。`desc` 是說明文字，which-key 會顯示它。

`vim.keymap.set` 的參數順序：
1. mode（`"n"` normal、`"i"` insert、`"v"` visual，也可以給 table `{"n","v"}`）
2. 按鍵序列
3. 要做什麼（function 或字串命令）
4. 選項（`{ desc = "..." }` 是最重要的，讓自己以後看得懂）

### 加一個 autocmd

autocmd 的意思是「當某件事發生時，自動跑這段程式碼」。

```lua
-- 開啟 .txt 檔時，自動把 textwidth 設成 80
vim.api.nvim_create_autocmd("BufReadPost", {
  pattern = "*.txt",
  callback = function()
    vim.opt_local.textwidth = 80
  end,
})
```

`BufReadPost` 是事件名稱（「讀完檔案之後」）。`pattern` 是哪些檔名符合條件。`callback` 是要做什麼。

如果你要把多個 autocmd 分成一組方便管理，可以先建一個 augroup：

```lua
local group = vim.api.nvim_create_augroup("my_group", { clear = true })

vim.api.nvim_create_autocmd("BufReadPost", {
  group = group,
  pattern = "*.txt",
  callback = function()
    vim.opt_local.textwidth = 80
  end,
})
```

`{ clear = true }` 的意思是：每次重新載入設定時，先把這個 group 裡舊的 autocmd 清掉，避免重複疊加。

## 三、把程式碼整理成一個模組

當功能愈寫愈多，全部塞在 `keymaps.lua` 裡會很亂。這時候你會想開一個獨立的檔案——這就是「Lua 模組」。

### 建立一個模組

在 `lua/` 底下建一個資料夾和檔案：

```
lua/myplugin/init.lua
```

`init.lua` 的寫法：

```lua
local M = {}  -- M 就是這個模組的「公開介面」，是個 table

function M.setup(opts)
  opts = opts or {}

  -- 在這裡做初始化的事
  vim.api.nvim_create_user_command("Hello", function()
    print(opts.greeting or "你好！")
  end, {})

  vim.keymap.set("n", "<leader>hw", function()
    vim.notify(opts.greeting or "Hi！")
  end, { desc = "打招呼" })
end

return M  -- 把 M 回傳出去，require 時才拿得到
```

重點：
- `local M = {}` 是慣例，M 就是 module 的縮寫。
- 把你想讓外部呼叫的 function 掛在 `M` 上（`M.setup = ...` 或 `function M.setup()`）。
- 最後一定要 `return M`，不然 `require` 拿到的會是 `nil`。
- 用 `local` 宣告的 function（不掛在 M 上）就是「私有的」，外部 require 不到。

### 在設定裡呼叫它

在 `lua/config/keymaps.lua` 加一行：

```lua
require("myplugin").setup({ greeting = "早安！" })
```

這樣 Neovim 啟動時就會載入這個模組並執行 setup。

### 這套設定真實的做法

`lua/config/keymaps.lua` 的開頭就是這樣：

```lua
require("config.cmera")
require("config.codegen")
```

`config.cmera` 對應的是 `lua/config/cmera.lua`——這就是一個完整的自訂模組，裡面有自己的 `local M = {}`、私有 function、user command、autocmd，最後 `return M`。你在後面的章節會看到它的完整結構。

## 四、lazy.nvim 的 plugin spec

如果你想讓你的模組「像第三方套件那樣被 lazy.nvim 管理」，或者要載入別人 GitHub 上的套件，就在 `lua/plugins/` 底下開一個 `.lua` 檔，`return` 一個 table。

lazy.nvim 掃到這個檔時，就會照裡面的設定載入。

### 看真實範例：`rainbow.lua`

```lua
return {
  {
    "HiPhish/rainbow-delimiters.nvim",  -- GitHub 上的路徑：作者/repo 名
    ft = {                               -- 只在這些 filetype 才載入（lazy load）
      "lisp",
      "clojure",
      "scheme",
      -- ...
    },
    config = function()                  -- 載入後要做什麼設定
      local rainbow = require("rainbow-delimiters")
      vim.g.rainbow_delimiters = {
        strategy = { [""] = rainbow.strategy["global"] },
        query    = { [""] = "rainbow-delimiters", lisp = "rainbow-parens" },
      }
    end,
  },
}
```

逐行說明：

| 欄位 | 意思 |
|------|------|
| `"HiPhish/rainbow-delimiters.nvim"` | 要裝的 GitHub repo，lazy.nvim 會自動去 clone 它 |
| `ft = { ... }` | 只在這些 filetype 才載入，其他時候不佔資源（這就是 lazy load 的意思） |
| `config = function() ... end` | 插件裝好、載入後，執行這個 function 做初始設定 |

### 看另一個範例：`parinfer.lua`

```lua
return {
  {
    "eraserhd/parinfer-rust",
    ft = { "clojure", "scheme", "lisp", "racket", "hy", "fennel", "janet", ... },
    build = "cargo build --release",    -- 安裝完之後要執行的 build 命令
    init = function()                   -- Neovim 啟動時就跑（比 config 更早）
      vim.g.parinfer_mode = "smart"
      vim.g.parinfer_enabled = 1
    end,
  },
}
```

多了兩個欄位：

| 欄位 | 意思 |
|------|------|
| `build = "..."` | 安裝完或更新後要跑的 shell 命令（這個插件需要用 cargo 編譯 Rust） |
| `init = function() ... end` | Neovim 啟動時就跑，不管插件有沒有被 lazy load 到（比 `config` 更早） |

### 其他常見欄位

| 欄位 | 意思 |
|------|------|
| `opts = { ... }` | 直接傳給插件的 `setup()` 的選項，lazy.nvim 會自動幫你呼叫 `setup(opts)` |
| `keys = { ... }` | 定義快捷鍵，也可以用來觸發 lazy load（按到這個鍵時才載入插件） |
| `event = "VeryLazy"` | 在某個 Neovim 事件觸發時才載入（例如 `"BufReadPost"` 代表開完檔案後） |
| `dependencies = { ... }` | 這個插件依賴的其他插件，lazy.nvim 會先裝好它們 |
| `enabled = false` | 暫時關掉這個插件（不會載入，也不需要刪掉 spec） |

### 載入「本地還在開發中的」插件

如果你寫的功能放在本機的某個資料夾，還不是 GitHub 上的 repo，可以用 `dir` 欄位：

```lua
return {
  {
    dir = "/Users/你的名字/projects/my-awesome-plugin",  -- 本機路徑
    name = "my-awesome-plugin",                          -- 給它一個名字
    config = function()
      require("my-awesome-plugin").setup()
    end,
  },
}
```

這樣就可以邊開發邊在 Neovim 裡測，不需要先推到 GitHub。

## 五、常用 API 速查

寫自訂功能最常碰到的幾個 API：

| API | 用途 |
|-----|------|
| `vim.api.nvim_create_user_command(名字, fn, opts)` | 建立一個 `:命令` |
| `vim.keymap.set(mode, 按鍵, fn, opts)` | 設定快捷鍵 |
| `vim.api.nvim_create_autocmd(事件, opts)` | 建立自動命令（事件觸發時跑） |
| `vim.api.nvim_create_augroup(名字, opts)` | 建立 autocmd 群組（方便管理、避免重複） |
| `vim.notify(訊息, 等級)` | 跳通知（等級可以是 `vim.log.levels.INFO` / `WARN` / `ERROR`） |
| `vim.fn.expand("%:p")` | 拿到目前檔案的完整路徑（`%` 是當前檔、`:p` 是展開成絕對路徑） |
| `vim.fn.fnamemodify(路徑, 修飾符)` | 對路徑做各種變形（`:r` 去副檔名、`:h` 取目錄、`:t` 取檔名） |
| `vim.api.nvim_get_current_buf()` | 拿到目前的 buffer 編號 |
| `vim.api.nvim_buf_get_name(buf)` | 拿到某個 buffer 的檔名 |
| `vim.api.nvim_create_buf(listed, scratch)` | 建立一個新的 buffer |
| `vim.api.nvim_open_win(buf, enter, config)` | 開一個 floating window |
| `vim.opt_local.選項 = 值` | 設定 buffer 本地的選項（只影響目前檔案） |
| `vim.bo[buf].選項 = 值` | 對指定 buffer 設定 buffer-local 選項 |
| `vim.system(cmd, opts, callback)` | 非同步跑外部命令（Neovim 0.10+ 的寫法） |
