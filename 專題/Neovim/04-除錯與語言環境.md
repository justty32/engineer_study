# 04 除錯與語言環境

這章說明除錯器怎麼用（nvim-dap 吃 VSCode 的 launch.json）、GDScript/Godot 的環境設定，以及這份設定啟用了哪些語言 extras 和其他慣例。

---

## nvim-dap 直接吃專案的 launch.json

**你不需要為 nvim 另外維護一份除錯設定。** nvim-dap 會自動讀取你 `cd` 進去的目錄底下的 `.vscode/launch.json`。只要 `cd` 到專案目錄再開 nvim，按 `<leader>dc` 就會列出 launch.json 裡的除錯設定讓你選。

前提是 launch.json 裡的 `"type"` 要對得上 nvim 這邊有的 adapter。這份設定補了兩個對應：

| launch.json 的 `type` | 後端 | 說明 |
| --- | --- | --- |
| `cppdbg` | codelldb（LLDB） | 由 LazyVim 的 clangd extra 帶進來 |
| `lua-local` | local-lua-debugger-vscode | 在 dap.lua 手動註冊 |

### cppdbg 走 codelldb，不是 cpptools

在 Windows 上 VSCode 的 cppdbg 是接微軟的 cpptools（GDB/MI）。在 Linux 這邊，這份設定把 `cppdbg` 這個名字接到 **codelldb**（LLDB），不用 cpptools。

原因很實際：cpptools 是微軟的 VSCode 擴充，大約 90MB，mason 從 GitHub 抓它很慢且容易斷。而 codelldb 已經被 clangd extra 帶進來了、功能也夠用。

代價是：launch.json 裡 cpptools 專屬的欄位（`MIMode`、`miDebuggerPath`、`setupCommands` 裡的 `-enable-pretty-printing`、`set charset UTF-8`）會被 LLDB 忽略。實務上沒差，LLDB 本來就支援 STL 整齊列印和 UTF-8。

### 機器專屬路徑放平台區塊

launch.json 支援 `"windows"` / `"linux"` / `"osx"` 子物件。同一份 launch.json 在不同平台上，對應平台的子物件會被自動合併進去。

例如 Windows 上 GDB 的路徑要寫死，就這樣放：

```json
{
  "type": "cppdbg",
  "name": "Launch",
  "request": "launch",
  "program": "${workspaceFolder}/build/myapp",
  "windows": {
    "miDebuggerPath": "C:/mingw64/bin/gdb.exe"
  }
}
```

Linux 這邊不給 `miDebuggerPath`，cpptools（或這裡的 codelldb）就自己找 PATH 上的 gdb / lldb。**一份 launch.json 兩台機器共用**，就靠這個。

### 注意：nvim 不會跑 preLaunchTask

`preLaunchTask` 是 VSCode 整合 `tasks.json` 的機制，nvim 不認識這個。所以如果你的 launch.json 有設 `preLaunchTask`（通常是「先跑 cmake build」之類的），在 nvim 裡除錯前要**自己先手動建置**。

### lua-local：Lua 腳本除錯器

`lua-local` 是 [local-lua-debugger-vscode](https://github.com/tomblind/local-lua-debugger-vscode)，純 Lua 的除錯器，不需要原生模組。適合除錯獨立的 Lua 腳本。

前提是 `node` 要在 PATH 上（因為這個除錯器的 debug adapter 是 Node.js 寫的）。如果你是從桌面啟動器開 nvim，PATH 可能沒有 node（如果 node 是用 fnm 管理的話）。改從 shell 開 nvim 就沒問題。

### Lua 5.5 的已知坑（已自動修補）

local-lua-debugger-vscode 0.3.3 在 Lua 5.5 上有個 bug：它的 `lldebugger.lua` 對 for 迴圈的控制變數賦值，但 Lua 5.5 把 generic for 的控制變數改成唯讀，導致模組載入失敗。症狀是：DAP session 起得來、中斷點也顯示 verified，然後程式就直接跑完結束，什麼都沒停。

這份設定在 nvim 啟動時會自動做一個冪等修補（只有在發現壞的那行時才改），不需要手動處理。mason 更新套件後這個修補也會重新生效。

## DAP 常用鍵位

這些是 LazyVim 內建的 DAP 鍵位，不需要另外設定：

| 鍵 | 功能 |
| --- | --- |
| `<leader>db` | 設定 / 取消中斷點 |
| `<leader>dc` | 啟動除錯 / 繼續執行 |
| `<leader>di` | Step into |
| `<leader>do` | Step over |
| `<leader>dO` | Step out |
| `<leader>dq` | 停止除錯 |
| `<leader>du` | 開/關 DAP UI |

## GDScript（Godot）

GDScript 的 LSP 和 DAP 都走 **Godot editor 內建的伺服器**，所以：

**必須先開著 Godot editor，補全、診斷、除錯才會生效。** 只開 nvim 不會有任何 LSP 功能。

| 功能 | 連線位址 |
| --- | --- |
| LSP（補全、診斷） | `127.0.0.1:6005` |
| DAP（除錯） | `127.0.0.1:6006` |

### 工作流程

1. 開 Godot editor，把你的專案開著
2. 開 nvim，`cd` 到 Godot 專案目錄
3. 開 `.gd` 檔，LSP 功能（補全、錯誤提示）就有了
4. 在 `.gd` 檔設好中斷點（`<leader>db`），按 `<leader>dc` 啟動除錯
5. Godot editor 那邊會自動跑場景，遇到中斷點就停

### 語法高亮

treesitter 安裝了三個 parser：`gdscript`、`godot_resource`、`gdshader`。`.gdshader` 檔也有語法高亮。

## 已啟用的 LazyVim Extras

`lazyvim.json` 裡啟用了以下 extras（語言包和功能包）：

**語言：**
C/C++（clangd）、CMake、Python、Rust、TypeScript、Java、.NET/C#、JSON、Markdown、TOML、YAML、Git

**功能：**
DAP（除錯）、Testing（neotest）、VS Code（讀 launch.json 等整合）

這些 extras 會自動幫對應語言裝好 LSP、formatter、linter、treesitter parser。要加或移除 extras，跑 `:LazyExtras` 可以用 UI 選。

## 其他慣例

### 拼字檢查預設關閉

LazyVim 有個 autocmd（`lazyvim_wrap_spell`），會在開 Markdown、純文字、Typst、TeX、Git commit buffer 時自動開拼字檢查。這份設定把它移除了，所以這些 buffer 預設不會開拼字檢查。

需要的話可以：
- 暫時開：`:set spell`
- 用鍵位切換：`<leader>us`（LazyVim 內建）

### Markdown 不做 lint 和 format-on-save

這份設定用 `markdown.lua` 明確把 Markdown 的 formatter（prettier / markdownlint --fix）和 linter（markdownlint）都關掉了。

原因：這些工具會對中文筆記做不必要的事——行長警告、標題層級限制、重排段落。語法高亮、render-markdown 的美化顯示、marksman 的連結跳轉都保留著。

### 檔案樹寬度記憶

側邊的檔案樹（Snacks explorer）會記住你上次調整的寬度。關掉再開，寬度跟上次一樣。

### 補全鍵位

blink.cmp 的 preset 是 `super-tab`：`Tab` 選下一個補全項目，`Shift-Tab` 選上一個。
