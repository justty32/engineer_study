名詞與概念字典

輸入繁中、英文、縮寫或白話動作即可篩選。每張卡先說「它是什麼」，再標出位置、機制與不要混淆的邊界；因果概念仍回主線章節學。

協定（protocol）

白話：參與者共同遵守的訊息格式、順序與錯誤處理規則。

位置／機制：每一層都有自己的對等參與者與規則。

不要混淆：協定是規則；實作是執行規則的程式或設備。

封裝（encapsulation）

白話：下一層把上一層資料當負載，加入自己的控制欄位。

位置／機制：送端逐層加入，收端逐層解析或移除。

不要混淆：不是加密；標頭通常仍可被該層設備讀取。

訊框（frame）

白話：一段本地鏈路上傳送的資料單位。

位置／機制：鏈路層；帶本段鏈路需要的位址與錯誤檢查。

不要混淆：IP 封包跨網存在；外面的鏈路訊框會逐跳更換。

乙太網路（Ethernet）

白話：常見的有線區域鏈路技術，規定訊框與媒介存取。

位置／機制：鏈路與實體相關層；現代多由交換器全雙工轉送。

不要混淆：它不是整個 Internet，也不負責跨網路由。

介質存取控制位址（Media Access Control address, MAC address）

白話：指出目前本地鏈路上要交給哪個介面。

位置／機制：鏈路層訊框的來源與目的欄位。

不要混淆：不是跨網最終位址，也不是使用者或主機的永久身分。

位址解析協定（Address Resolution Protocol, ARP）

白話：已知本地下一跳的 IPv4 位址時，詢問其 MAC 位址。

位置／機制：本地鏈路廣播詢問、目標回覆並寫入快取。

不要混淆：遠端目的地只解析本地閘道，不直接取得遠端 MAC 位址。

交換器（switch）

白話：在同一鏈路網路內，依 MAC 位址把訊框送往適當埠。

位置／機制：從來源位址學習埠對應，再查目的位址。

不要混淆：路由器依 IP 前綴跨網轉送，責任不同。

網際網路協定（Internet Protocol, IP）

白話：給封包跨越多個網路所需的位址與逐跳轉送格式。

位置／機制：網路層；路由器讀目的位址並選下一跳。

不要混淆：盡力服務不保證抵達、有序或不重複。

網際網路協定第四版（Internet Protocol version 4, IPv4）

白話：使用 32 位元跨網位址的 IP 版本。

位置／機制：網路層；以點分十進位常見表示。

不要混淆：IPv4 位址可能被 NAT 改寫，不能當穩定身分。

網際網路協定第六版（Internet Protocol version 6, IPv6）

白話：使用 128 位元跨網位址的 IP 版本。

位置／機制：網路層；有不同標頭與鄰居探索機制。

不要混淆：不是把 IPv4 字串寫長；兩者線上格式不同。

無類別域間路由（Classless Inter-Domain Routing, CIDR）

白話：用斜線後的位元數表示網路前綴，例如 /24。

位置／機制：定址與路由彙整；路由器選最長匹配前綴。

不要混淆：前綴長度按位元計，不必落在小數點邊界。

路由器（router）

白話：連接不同網路，替每個 IP 封包選下一站。

位置／機制：查路由表的最長前綴匹配，遞減存活時間，再於新鏈路封裝。

不要混淆：它通常不替應用保證端對端可靠性。

預設閘道（default gateway）

白話：沒有更具體本地路由時，主機交付遠端封包的本地下一跳。

位置／機制：主機路由表中的預設路由。

不要混淆：它是第一個路由器，不一定是整條路徑唯一閘道。

網際網路控制訊息協定（Internet Control Message Protocol, ICMP）

白話：回報 IP 轉送的錯誤與診斷狀態。

位置／機制：網路層；可回報不可達或存活時間歸零。

不要混淆：沒有回覆不必然代表主機不可達，可能只是被過濾。

埠（port）

白話：讓作業系統把到達資料分給正確程式端點的數字標籤。

位置／機制：傳輸層來源與目的欄位。

不要混淆：不是實體插孔，也不是使用者身分。

使用者資料包協定（User Datagram Protocol, UDP）

白話：以少量控制欄位把獨立資料包交給目的埠。

位置／機制：傳輸層；保留資料包邊界，但不內建排序與重傳。

不要混淆：無連線不表示沒有任何狀態；應用或防火牆仍可能追蹤狀態。

傳輸控制協定（Transmission Control Protocol, TCP）

白話：把不可靠 IP 服務整理成可靠、有序的端對端位元組流。

位置／機制：傳輸層；靠握手、序號、確認、重傳、窗與擁塞控制。

不要混淆：不保留應用訊息邊界，也不保證應用業務成功。

網域名稱系統（Domain Name System, DNS）

白話：把階層名稱查成 IP 位址或其他記錄。

位置／機制：應用層；遞迴解析器沿委派鏈查詢並快取。

不要混淆：解析成功不是伺服器身分驗證。

存活時間（Time To Live, TTL）

白話：限制資料可被沿用或轉送多久的欄位名稱。

位置／機制：DNS 中常以秒限制快取；IP 中逐跳遞減以防迴圈。

不要混淆：同名但單位與作用不同，必須看所在協定。

超文字傳輸協定（Hypertext Transfer Protocol, HTTP）

白話：讓客戶端以方法操作資源，讓伺服器以狀態與內容回應。

位置／機制：應用層；請求與回應包含起始資訊、標頭與可選本文。

不要混淆：HTTP 狀態不等於 TCP 連線狀態。

統一資源定位符（Uniform Resource Locator, URL）

白話：描述如何找到某個資源的字串。

位置／機制：應用層；通常含方案、主機、可選埠、路徑與查詢。

不要混淆：URL 不是 IP 位址；名稱需先解析。

傳輸層安全性協定（Transport Layer Security, TLS）

白話：驗證對端並建立保護應用資料的加密通道。

位置／機制：位於應用與傳輸服務之間；握手後以工作金鑰保護紀錄。

不要混淆：加密通道不代表端點應用沒有漏洞。

公開金鑰基礎建設（Public Key Infrastructure, PKI）

白話：用憑證、簽發規則與信任庫把名稱連到公開金鑰。

位置／機制：身分驗證；沿簽章鏈連到本機信任的根。

不要混淆：有憑證不等於可信，仍要檢查名稱、期限與鏈。

QUIC（協定專名；早期名稱為 Quick UDP Internet Connections）

白話：在 UDP 上提供加密、多資料流與連線管理的現代傳輸協定。

位置／機制：HTTP/3 的承載；整合 TLS 1.3，讓不同資料流降低彼此阻塞。

不要混淆：跑在 UDP 上不表示它沒有可靠性或連線狀態。

封包擷取（packet capture）

白話：在某個網路介面記錄經過的線上資料單位與時間。

位置／機制：觀察點只能看到該介面可見的流量；加密後通常看不到應用明文。

不要混淆：沒擷取到不等於事件不存在，可能是觀察位置或卸載機制造成。
