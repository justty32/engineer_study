名詞與概念字典

輸入繁中、英文、縮寫或白話動作即可篩選。每張卡先說「它是什麼」，再標出位置、機制與不要混淆的邊界；因果概念仍回主線章節學。

協定（protocol）

白話：參與者共同遵守的訊息格式、順序與錯誤處理規則。

位置／功能／機制：每一層都有對等參與者；共同格式讓不同實作能交換可解讀的狀態與資料。

邊界：協定是規則；實作是執行規則的程式或設備。介面呼叫也不等於線上協定訊息。

可觀察證據：規格描述允許的訊息；封包、log 或狀態轉移只能證明某次實作行為。

封裝（encapsulation）

白話：下一層把上一層資料當負載，加入自己的控制欄位。

位置／功能／機制：送端逐層加入標頭或尾碼，讓各層取得轉送、分流或檢查所需資訊；收端反向解析。

邊界：不是加密；標頭通常仍可被該層設備讀取，一次應用寫入也不一定形成一個封包。

可觀察證據：封包分析器可在同一資料單位中展開各層欄位，但只代表擷取點可見的封裝。

訊框（frame）

白話：一段本地鏈路上傳送的資料單位。

位置／功能／機制：鏈路層以來源／目的鏈路位址、型別與錯誤檢查包住上層封包，完成單一鏈路交付。

邊界：IP 封包可跨多個網路；外面的鏈路訊框逐跳更換，訊框檢查成功也不保證端對端成功。

可觀察證據：介面擷取與交換器埠計數器可見訊框；不同鏈路觀察點會看見不同外層位址。

乙太網路（Ethernet）

白話：常見的有線區域鏈路技術，規定訊框與媒介存取。

位置／功能／機制：跨鏈路與實體相關層；現代交換式乙太網路多以全雙工鏈路傳送訊框。

邊界：它不是整個 Internet，也不負責跨網路由；Wi-Fi 也不是「無線乙太網路」的完全同義詞。

可觀察證據：介面協商速率、鏈路狀態、錯誤計數器與訊框擷取可驗證本段運作，不能證明遠端路徑。

介質存取控制位址（Media Access Control address, MAC address）

白話：指出目前本地鏈路上要交給哪個介面。

位置／功能／機制：出現在鏈路層訊框來源與目的欄位，交換器據此學習與轉送。

邊界：不是跨網最終位址，也不是使用者、主機或製造商不可改變的永久身分。

可觀察證據：ARP／鄰居快取、交換表與訊框欄位可見某時刻的位址對應與使用位置。

位址解析協定（Address Resolution Protocol, ARP）

白話：已知本地下一跳的 IPv4 位址時，詢問其 MAC 位址。

位置／功能／機制：在本地鏈路廣播詢問，持有該 IPv4 位址者回覆，送端把對應寫入快取後才能組出訊框。

邊界：遠端目的地只解析本地閘道，不直接取得遠端 MAC；IPv6 使用鄰居探索而不是 ARP。

可觀察證據：擷取可見詢問／回覆，快取可見目前對應；沒有回覆不能單獨辨認離線、隔離或設定錯誤。

交換器（switch）

白話：在同一鏈路網路內，依 MAC 位址把訊框送往適當埠。

位置／功能／機制：鏈路層設備從進入訊框的來源位址學習埠對應，再依目的位址轉送；未知目的通常泛送。

邊界：路由器依 IP 前綴跨網轉送；交換器學到的是可老化的轉送狀態，不是主機身分資料庫。

可觀察證據：MAC 位址表、埠流量與錯誤計數器可支持學習與轉送狀態，單一主機擷取通常看不到其他埠的全部流量。

網際網路協定（Internet Protocol, IP）

白話：給封包跨越多個網路所需的位址與逐跳轉送格式。

位置／功能／機制：網路層；主機與路由器讀目的位址、查路由並逐跳把封包推近目的網路。

邊界：盡力服務不保證抵達、有序或不重複，也不直接以網域名稱轉送。

可觀察證據：路由表顯示本機決策，封包擷取顯示 IP 欄位；兩者都不能保證後續每一跳。

網際網路協定第四版（Internet Protocol version 4, IPv4）

白話：使用 32 位元跨網位址的 IP 版本。

位置／功能／機制：網路層以來源、目的、協定、長度與存活時間等欄位承載逐跳轉送資訊；常以點分十進位表示位址。

邊界：IPv4 位址可能動態分配或被網路位址轉譯（Network Address Translation, NAT）改寫，不能當穩定身分。

可觀察證據：介面設定、路由表與 IPv4 標頭可證明某時刻的位址與線上使用方式。

網際網路協定第六版（Internet Protocol version 6, IPv6）

白話：使用 128 位元跨網位址的 IP 版本。

位置／功能／機制：網路層以固定基本標頭配合擴充標頭轉送，並用 ICMPv6 鄰居探索處理本地鄰居與路由器發現。

邊界：不是把 IPv4 字串寫長；位址、標頭與鄰居機制都不同，兩者可並存。

可觀察證據：IPv6 介面位址、鄰居表、路由表與封包標頭可驗證實際配置與資料流。

無類別域間路由（Classless Inter-Domain Routing, CIDR）

白話：用斜線後的位元數表示網路前綴，例如 /24。

位置／功能／機制：用於位址配置與路由彙整；前綴指定共同位元，路由器在所有匹配項中選最長者。

邊界：前綴長度按位元計，不必落在小數點邊界；它描述位址集合，不直接描述實體拓樸。

可觀察證據：介面與路由表的斜線表示可驗證配置；逐位元 AND 可手算某目的是否匹配。

路由器（router）

白話：連接不同網路，替每個 IP 封包選下一站。

位置／功能／機制：網路層依最長前綴匹配查轉送資訊、遞減跳數限制，再為輸出鏈路重新封裝。

邊界：它通常不替應用保證端對端可靠性；一台設備也可能同時有路由、防火牆與 NAT 等功能。

可觀察證據：路由／轉送表、介面計數器、ICMP 與路由器兩側擷取可支持逐跳決策。

預設閘道（default gateway）

白話：沒有更具體路由時，主機交付遠端封包的本地下一跳。

位置／功能／機制：主機路由表中的預設路由，IPv4 常寫成 0.0.0.0/0 並指向本地路由器。

邊界：它是第一個下一跳，不一定是整條路徑唯一閘道，也不會取代較具體路由。

可觀察證據：路由表可證明目前預設選擇，ARP／鄰居表可證明本地交付對應。

網際網路控制訊息協定（Internet Control Message Protocol, ICMP）

白話：回報 IP 轉送的錯誤與診斷狀態。

位置／功能／機制：網路層可回報不可達或存活時間歸零；ping 與 traceroute 類工具利用部分訊息做探測。

邊界：沒有回覆不必然代表主機不可達，可能是過濾、限速或回程問題；成功也不證明應用服務正常。

可觀察證據：ICMP 封包的類型、代碼、來源與往返時間可支持特定探測結果。

埠（port）

白話：讓作業系統把到達資料分給正確程式端點的數字標籤。

位置／功能／機制：TCP 與 UDP 標頭含來源與目的埠，作業系統連同位址、協定與連線狀態把資料分流給通訊端點。

邊界：不是實體插孔、使用者身分或跨所有傳輸協定共用的單一命名空間；埠號也不保證程式內容。

可觀察證據：監聽／連線列表可見本機綁定，封包可見線上埠號；兩者結合才容易定位端點。

使用者資料包協定（User Datagram Protocol, UDP）

白話：以少量控制欄位把獨立資料包交給目的埠。

位置／功能／機制：傳輸層保留每次資料包邊界，以埠分流並提供檢查和，但不內建握手、排序與重傳。

邊界：無連線不表示系統完全沒有狀態；應用、防火牆或上層協定仍可能維護會話與可靠性。

可觀察證據：封包可見每個 UDP 資料包與埠；擷取到送出不代表目的應用已接收或處理。

傳輸控制協定（Transmission Control Protocol, TCP）

白話：把不可靠 IP 服務整理成可靠、有序的端對端位元組流。

位置／功能／機制：傳輸層靠握手建立雙端狀態，以序號、確認、重傳、接收窗與擁塞控制交付位元組。

邊界：不保留應用訊息邊界，也不保證應用業務成功、延遲上限或連線永不斷。

可觀察證據：封包可見握手、序號與確認；作業系統狀態可見監聽與連線，應用 log 才能支持業務處理。

網域名稱系統（Domain Name System, DNS）

白話：把階層名稱與指定型別查成 IP 位址或其他記錄。

位置／功能／機制：應用層；stub 把問題交給遞迴解析器，解析器沿委派鏈取回權威資料並依 TTL 快取。

邊界：解析成功不是可達性或伺服器身分驗證；同一名稱也可能有多筆、隨位置或時間變化的答案。

可觀察證據：查詢輸出、快取與封包可見問題、型別、回覆碼及記錄，卻不能證明之後的連線結果。

存活時間（Time To Live, TTL）

白話：限制資料可被沿用或轉送範圍的欄位名稱。

位置／功能／機制：DNS TTL 以秒限制快取沿用；IPv4 TTL 雖沿用此名，實際由路由器逐跳至少減一以防迴圈。

邊界：同名但單位與作用不同；DNS 到期不是資料自動更新，IP TTL 也不是精準牆上時鐘。

可觀察證據：DNS 回覆可見剩餘秒數，IP 標頭與 traceroute 類探測可支持逐跳變化。

超文字傳輸協定（Hypertext Transfer Protocol, HTTP）

白話：讓客戶端以方法操作資源，讓伺服器以狀態與內容回應。

位置／功能／機制：應用層請求攜帶方法、目標、標頭與可選本文；回應攜帶狀態、標頭與可選本文。

邊界：HTTP 狀態不等於 TCP 狀態；2xx 也只表示該 HTTP 語意成功，不一定代表整個跨服務業務完成。

可觀察證據：瀏覽器工具、代理與服務 log 可見語意；TLS 加密後的一般封包擷取看不到明文。

統一資源定位符（Uniform Resource Locator, URL）

白話：描述用何種方案定位某個資源的字串。

位置／功能／機制：應用解析方案、主機、可選埠、路徑與查詢，再分別驅動 DNS、傳輸、安全與 HTTP 動作。

邊界：URL 不是 IP 位址或磁碟路徑；路徑如何映射到後端由服務決定。

可觀察證據：用戶端請求紀錄可見解析後元件；代理或伺服器可能只看到其中一部分。

傳輸層安全性協定（Transport Layer Security, TLS）

白話：驗證對端並建立保護應用資料的加密通道。

位置／功能／機制：位於應用與傳輸服務之間；握手協商、驗證憑證與導出工作金鑰，之後以受保護紀錄承載資料。

邊界：加密通道不代表端點應用沒有漏洞、使用者已授權或內容真實；一般模式主要驗證伺服器。

可觀察證據：握手與憑證檢視可見版本、名稱、鏈與警示；沒有工作金鑰的中間擷取通常看不到應用明文。

公開金鑰基礎建設（Public Key Infrastructure, PKI）

白話：用憑證、簽發規則與信任庫把名稱連到公開金鑰。

位置／功能／機制：身分驗證基礎設施；驗證者檢查憑證名稱、時間、用途與簽章鏈，直到本機信任錨。

邊界：有憑證不等於可信，仍要通過政策檢查；憑證也不含應保密的私密金鑰。

可觀察證據：憑證檢視器可見主體名稱、簽發者、有效期與鏈；信任結果還取決於該用戶端信任庫與時間。

QUIC（協定專名；早期名稱為 Quick UDP Internet Connections）

白話：在 UDP 上提供加密、多資料流與連線管理的現代傳輸協定。

位置／功能／機制：使用者空間傳輸協定，也是 HTTP/3 的承載；整合 TLS 1.3，以封包編號、確認與流控制維護可靠資料流。

邊界：跑在 UDP 上不表示沒有可靠性或狀態；降低資料流彼此阻塞也不等於消除所有網路壅塞或遺失延遲。

可觀察證據：封包可辨認 UDP 與部分 QUIC 握手特徵，但大量欄位受保護；端點追蹤更能解釋資料流狀態。

封包擷取（packet capture）

白話：在某個網路介面記錄經過的線上資料單位與時間。

位置／功能／機制：擷取驅動在特定介面複製可見流量，分析器再依協定格式解碼欄位、方向與時序。

邊界：沒擷取到不等於事件不存在；觀察位置、非對稱路由、交換器轉送、過濾與網卡卸載都會影響結果，加密後通常看不到應用明文。

可觀察證據：擷取本身就是該位置的線上證據；要證明端到端或業務結果，仍須其他位置擷取、OS 狀態與應用 log 交叉核對。

核心概念：從角色一路追到證據

封裝與解封裝

角色／資料流：送端應用交出資料，各層加控制欄位；收端依相反順序解析。

因果／結果：新增標頭使下一層能分流或轉送，代價是線上長度增加；路由器只處理轉送所需層級。

證據與邊界：封包分析器可展開欄位，但網卡卸載可能讓主機擷取與線上訊框不同；回第 00 章看數值模型。

本地下一跳解析

角色／狀態：路由先選下一跳 IPv4 位址，ARP 快取保存它與 MAC 位址的暫時對應。

因果／結果：快取缺少時廣播詢問，收到回覆才有足夠欄位送出乙太網路訊框；遠端目的解析的是閘道。

證據與邊界：ARP 封包、鄰居表與交換表分別涵蓋不同觀察點；回第 01 章操作。

最長前綴與逐跳路由

角色／狀態：每台路由器持有路由／轉送資訊，封包帶最終目的 IP 與有限跳數。

因果／結果：最具體的匹配前綴選出輸出與下一跳，跳數限制遞減後重新封裝；任何一跳無路由都會中斷。

證據與邊界：路由表只證明本機決策，traceroute 類工具也不保證顯示完整固定路徑；見第 02 章。

端對端可靠位元組流

角色／狀態：TCP 兩端以握手建立狀態，序號記位置、確認號指出下一個期待位元組。

因果／結果：缺口或計時器觸發重傳，接收端只依序交付；結果是可靠位元組流，不是應用訊息或業務交易。

證據與邊界：封包與 OS 連線狀態可支持傳輸進度，應用 log 才能支持內容處理；見第 03 章。

DNS 查詢與快取

角色／資料流：stub 問遞迴解析器，解析器利用快取或沿根、頂級網域與權威委派追查。

因果／結果：有效快取省略外部查詢；到期後重新查，結果是一種記錄，不是連線或身分保證。

證據與邊界：查詢輸出、快取與擷取可能看到不同階段；見第 04 章。

HTTP 請求與回應

角色／資料流：客戶端送方法、目標與資料，伺服器或中介元件處理後回狀態、標頭與內容。

因果／結果：路由與業務狀態決定回應，客戶端再依狀態採取動作；收到 404 也表示已到應用回應階段。

證據與邊界：開發工具與服務 log 可看語意，但入口 log 不保證後端交易完成；見第 05 章。

TLS 身分與通道

角色／狀態：客戶端保留原始名稱與信任庫，伺服器提出憑證與金鑰材料，雙方導出工作金鑰。

因果／結果：名稱、期限與信任鏈通過後才建立受保護紀錄；任一核心檢查失敗都應中止身分保證。

證據與邊界：握手可見憑證與警示，加密資料不證明端點應用安全；見第 06 章。

跨層故障定位

角色／狀態：用戶端、網路設備與服務各留下局部事件；診斷者沿名稱、路由、傳輸、TLS、HTTP 的相依順序比對。

因果／結果：找出第一個缺少預期輸出的階段，再取得能區分候選原因的下一份證據，避免把共同症狀當根因。

證據與邊界：任何單一工具都有觀察邊界；時間、位置與識別碼要能對齊。見第 07 章。

概念入口

若要學因果而非查字義，回到：封裝、本地下一跳、逐跳路由、端對端保證、名稱解析、請求與回應、身分與加密、證據診斷。
