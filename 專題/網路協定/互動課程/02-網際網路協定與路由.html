02・跨網轉送

網際網路協定與路由：每一跳怎麼選下一站？

網際網路協定（Internet Protocol, IP）提供跨網位址與盡力轉送：路由器讀目的 IP 位址，以最長前綴匹配查路由表，再把封包交給下一跳。它不保證抵達、順序或只送一次。

這章假設已懂：本地鏈路只需找到下一站。

自由實驗：本地交付還是送閘道？

位址不是主機名稱

網際網路協定第四版（Internet Protocol version 4, IPv4）位址長 32 位元；無類別域間路由（Classless Inter-Domain Routing, CIDR）以斜線後的數字表示前綴長度，例如 192.168.1.0/24。前綴辨認一群可用相同路由處理的位址，剩餘位元辨認該範圍內的介面。網際網路協定第六版（Internet Protocol version 6, IPv6）使用 128 位元位址；位址解析機制也不同。

逐跳因果

主機判斷目的是否在本地前綴否則選預設閘道路由器做最長前綴匹配存活時間遞減用下一段鏈路重新封裝

「最長」表示在所有能匹配目的位址的路由中，選擇指定位元最多、最具體的前綴。路由表是控制面的結果；實際逐包查詢與轉送是資料面的工作。

失敗如何留下證據

網際網路控制訊息協定（Internet Control Message Protocol, ICMP）讓主機或路由器回報不可達、存活時間歸零等網路層狀態。ping 常用其回應測試往返可達性；traceroute 類工具刻意改變存活時間來觀察各跳。沒有回覆不等於一定不可達，因為設備可能過濾控制訊息。

不要混淆

  • 路由決定下一跳，不保證後續每一跳或回程走同一路徑。
  • 前綴不是「把位址字串按小數點切開」；實際比較的是位元。
  • 網路位址轉譯（Network Address Translation, NAT）會改寫位址或埠，但它不是路由本身，也不是安全邊界的充分條件。
