02・跨網轉送

網際網路協定與路由：每一跳怎麼選下一站？

網際網路協定（Internet Protocol, IP）提供跨網位址與盡力轉送：路由器讀目的 IP 位址，以最長前綴匹配查路由表，再把封包交給下一跳。它不保證抵達、順序或只送一次。

這章假設已懂：本地鏈路只需找到下一站。

先把路由想成有優先序的條件表

軟體路由器可想成針對目的位址執行一組前綴規則：所有符合的規則中，位元條件最長者勝出。這個類比對應到真實的最長前綴匹配（longest prefix match）；但實作用專門資料結構或硬體完成，不一定逐列掃描路由表。

關鍵邊界：每台路由器只承諾選出自己的下一跳。去程、回程可不同，後續設備也可能有不同政策。

實驗怎麼玩

輸入目的 IPv4 位址並拖動本地前綴長度，觀察同一個位址何時從本地交付變成送往閘道；再調整跳數，注意存活時間欄位逐跳遞減。此工具示範判斷與計數，不模擬完整路由表、封包遺失或真實路徑。

自由實驗：本地交付還是送閘道？

位址不是主機名稱

網際網路協定第四版（Internet Protocol version 4, IPv4）位址長 32 位元；無類別域間路由（Classless Inter-Domain Routing, CIDR）以斜線後的數字表示前綴長度，例如 192.168.1.0/24。前綴辨認一群可用相同路由處理的位址，剩餘位元辨認該範圍內的介面。網際網路協定第六版（Internet Protocol version 6, IPv6）使用 128 位元位址；位址解析機制也不同。

前綴手算：為何不是看字串

IPv4 的 /24 表示前 24 個位元屬於前綴，遮罩為 255.255.255.0。把位址與遮罩逐位元 AND：192.168.1.37 AND 255.255.255.0 = 192.168.1.0，所以它屬於 192.168.1.0/24。若路由表同時有 0.0.0.0/0、192.168.0.0/16 與 192.168.1.0/24，目的 192.168.1.37 三者都匹配，但 /24 指定 24 位元，最具體，因此勝出。

IPv4 前綴含 232 − p 個位址，其中 p 是前綴長度，量綱是「位址數」。例如 p = 24 時有 28 = 256 個位址。這不等於一定有 254 台可用主機；可用範圍還受子網語意、保留位址與實際配置影響。

逐跳因果

主機判斷目的是否在本地前綴否則選預設閘道路由器做最長前綴匹配存活時間遞減用下一段鏈路重新封裝

「最長」表示在所有能匹配目的位址的路由中，選擇指定位元最多、最具體的前綴。路由表是控制面的結果；實際逐包查詢與轉送是資料面的工作。

失敗如何留下證據

網際網路控制訊息協定（Internet Control Message Protocol, ICMP）讓主機或路由器回報不可達、存活時間歸零等網路層狀態。ping 常用其回應測試往返可達性；traceroute 類工具刻意改變存活時間來觀察各跳。沒有回覆不等於一定不可達，因為設備可能過濾控制訊息。

查本機路由表可證明作業系統會選哪個介面與下一跳；traceroute 的某一列只能證明某次探測收到該位置的 ICMP 回覆，星號可能是過濾、回覆限速或遺失；ping 成功可支持往返 ICMP 可達與估計往返時間，卻不能證明 TCP 埠已開、HTTP 正常或資料路徑長期固定。

不要混淆

  • 路由決定下一跳，不保證後續每一跳或回程走同一路徑。
  • 前綴不是「把位址字串按小數點切開」；實際比較的是位元。
  • 網路位址轉譯（Network Address Translation, NAT）會改寫位址或埠，但它不是路由本身，也不是安全邊界的充分條件。
