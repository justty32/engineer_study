07・整合與診斷

跨層追蹤：從網址到回應，證據在哪一層斷掉？

診斷不是先猜協定，而是依相依順序問：名稱有答案嗎？下一跳與路由可達嗎？傳輸端點有回應嗎？加密身分檢查通過嗎？應用回了什麼？每一步只使用能支持它的證據。

這章假設已懂：主線 01 至 06 的角色與證據。

先凍結一次請求的邊界

把診斷當成分散式系統追蹤：先記下原始 URL、發生時間、用戶端、解析到的位址與一次重現結果，再沿相依鏈找第一個缺少預期輸出的階段。若一開始就換 DNS、關防火牆、清快取與重啟服務，狀態同時改變，最後即使恢復也很難知道原因。

判讀原則：症狀可跨層相似，證據卻有觀察邊界。「瀏覽器轉圈」不是根因；一筆帶時間、位置與方向的事件才有機會支持或排除假設。

實驗怎麼玩

選單已直接告訴你故障層，所以這不是猜謎。逐項切換，對照「使用者看到的症狀」與「下一份最有區別力的證據」；特別注意不同根因都可能表現成逾時。練習目的，是把檢查順序內化成最小成本的排除流程。

無壓力診斷：選一個已知故障點

這不是測驗。切換故障層，觀察外部症狀與下一份最有區別力的證據。

完整事件序列

  1. 使用者給應用一個統一資源定位符（Uniform Resource Locator, URL），其中包含方案、主機名稱、可選埠與路徑。
  2. 網域名稱系統（Domain Name System, DNS）將主機名稱解析成網際網路協定（Internet Protocol, IP）位址；快取可能省略外部查詢。
  3. 作業系統依目的 IP 查路由；若非本地，選預設閘道，再以位址解析協定（Address Resolution Protocol, ARP）找到下一跳的介質存取控制位址（Media Access Control address, MAC address）。
  4. 鏈路訊框攜帶 IP 封包；路由器逐跳選下一站並換上新鏈路訊框。
  5. 傳輸控制協定（Transmission Control Protocol, TCP）以三次握手建立可靠位元組流，或其他傳輸服務建立自己的狀態。
  6. 傳輸層安全性協定（Transport Layer Security, TLS）驗證伺服器名稱與憑證鏈，導出工作金鑰。
  7. 超文字傳輸協定（Hypertext Transfer Protocol, HTTP）請求進入加密紀錄；伺服器處理後以狀態、標頭與本文回覆。

一次失敗的因果範例

假設 DNS 已回 203.0.113.9，本機路由與 ARP 都有結果，TCP 的 SYN 卻重複送出而沒有 SYN-ACK。可支持的最窄結論是「在目前擷取點，建立 TCP 連線所需的回覆沒有及時出現」；候選原因仍包括去程封鎖、伺服器未監聽、回程路由、回覆被丟棄或擷取位置錯誤。此時查伺服器監聽狀態、伺服器端擷取與中間防火牆紀錄，比先查看 HTTP 500 紀錄更有區別力，因為 HTTP 尚未開始。

若 TCP 與 TLS 都成功，接著收到 HTTP 404，因果鏈已推進到應用層。這時重查 ARP 通常資訊量低；應看請求主機欄位、路徑、代理轉送規則與服務存取紀錄。診斷的核心不是「某工具最強」，而是工具的觀察層是否剛好包住故障邊界。

證據矩陣

觀察位置能支持不能單獨證明
DNS 查詢／快取問了什麼名稱、得到什麼記錄、何時過期目的服務一定可達或可信
封包擷取訊框／封包／傳輸欄位、順序、重傳與時序加密內文、程式業務成功
作業系統狀態路由、鄰居快取、監聽埠、連線狀態遠端內部如何處理請求
TLS 握手資訊版本、憑證、名稱檢查與警示端點程式沒有漏洞
應用／服務紀錄解密後請求、路由與業務步驟未記錄事件不存在

時間也要有單位與參考點

若總等待時間拆成名稱解析 tD、連線建立 tC、TLS 握手 tT、伺服器處理至第一個位元組 tS 與本文傳送 tB，簡化近似為 ttotal = tD + tC + tT + tS + tB，單位可統一用毫秒。假設五段為 20、40、60、180、30 ms，總計 330 ms，最大單段是伺服器等待 180 ms；這只是優先調查線索，不是根因證明。

真實實作可能平行解析與連線、重用既有連線、快取回應或使用 0-RTT，階段會重疊，不能永遠直接相加。比較兩台機器的 log 前還要校時；不同時鐘的時間戳若有偏差，事件順序可能被誤判。

資深程式設計者的落點

把每一層視為具有輸入、狀態與輸出的狀態機，但不要把抽象介面誤認為線上邊界。一次 send() 可能被拆成多個區段，一次 recv() 也可能只拿到部分位元組；TCP 不保留應用訊息邊界。若應用需要訊息，就必須在位元組流上定義長度、分隔或其他訊息框界定（framing，決定訊息起訖）規則。

不要混淆

  • 「第一個看到錯誤的元件」不一定是「造成錯誤的元件」；它可能只是最先有能力報告。
  • 逾時是期限內沒得到預期事件，不是協定層名稱；DNS、TCP、TLS、HTTP 與應用內部都可能逾時。
  • 相關性識別碼可串起代理與服務 log，但缺少或重複的識別碼會破壞追蹤，不能假設每筆紀錄天然屬於同一請求。
  • 單點封包擷取沒有看見封包，只能描述該觀察點；交換器鏡像設定、路由非對稱與網卡卸載都可能改變可見內容。

完成後的自我敘述

試著不看頁面，以「名稱 → 最終位址 → 下一跳硬體位址 → 程式埠 → 加密身分 → 應用資源」講完一遍。卡住時不是失敗：回到可搜尋字典或對應章節，找出那個角色的輸入、狀態變化與證據。
