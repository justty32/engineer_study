04・名稱解析

網域名稱系統：名稱如何變成位址？

網域名稱系統（Domain Name System, DNS）是階層式、分散式名稱資料庫。應用先問解析器「這個名稱的某種記錄是什麼」，得到網際網路協定（Internet Protocol, IP）位址後，網路層才有可路由的目的地。

這章假設已懂：路由使用 IP 位址，不直接使用人類網域名稱；傳輸層用埠找服務。

自由實驗：快取何時省下一整條查詢？

誰問誰

應用／作業系統的 stub 解析器遞迴解析器根名稱伺服器頂級網域名稱伺服器權威名稱伺服器

stub 是只會把問題交出去的輕量查詢端。遞迴解析器替用戶端追查答案並快取。根與頂級網域通常提供下一層委派；權威伺服器提供自己負責區域的記錄。這是一條可能路徑，快取可讓查詢在任一較早位置結束。

記錄不是只有位址

  • A 記錄把名稱對到網際網路協定第四版（Internet Protocol version 4, IPv4）位址；AAAA 記錄把名稱對到網際網路協定第六版（Internet Protocol version 6, IPv6）位址。A 與 AAAA 是標準記錄型別名稱，不是此處遺漏展開的縮寫。
  • 正式名稱記錄（Canonical Name record, CNAME record）把一個名稱別名指向另一個正式名稱。
  • 名稱伺服器記錄（Name Server record, NS record）描述某區域由哪些權威伺服器負責。

失敗與證據

不存在的名稱、逾時、伺服器失敗與有名稱但沒有該型別記錄，是不同結果。先看 DNS 回覆碼、問題名稱、記錄型別、回覆來源、存活時間（Time To Live, TTL）與是否命中快取。名稱解析成功只證明取得資料，不保證目的服務可達或可信。

不要混淆

DNS 把名稱映射成資料；傳輸層再連到某個 IP 位址與埠；傳輸層安全性協定則檢查目前伺服器憑證是否適用於原本要連的名稱。三者相接，但名稱解析不是身分驗證。
