10 · 數學正確還要能被程式證明

C++ 實作契約、測試與除錯證據

真正難抓的錯通常不是矩陣乘法，而是「這個矩陣把哪個框架變到哪個框架、角度是度還是弧度、向量是點還是方向」沒有進入型別與測試。

檢查 API 契約

struct JointState { std::array<Radian, 7> q; };
template<class From, class To> struct Transform;
Transform<ToolFrame, BaseFrame> forwardKinematics(const JointState&);

最小測試組

測試能抓什麼
零角與單一關節零位、軸方向、固定連桿平移與乘法順序
T·T⁻¹≈I、RᵀR≈I逆變換、旋轉漂移與矩陣區塊錯誤
雅可比有限差分關節軸／原點、叉積順序、框架錯配
FK→IK→FKIK 回傳解是否真正重建目標；不要要求 q 必須等於原 q
近奇異與極限案例數值爆炸、停止條件、阻尼與夾限行為

每次迭代留下什麼證據

記錄迭代編號、位置／姿態誤差、最小奇異值或條件指標、阻尼、||Δq||、最接近的關節極限及停止原因。只記「IK failed」無法區分不可達、數值錯誤、框架錯誤或種子不佳。
