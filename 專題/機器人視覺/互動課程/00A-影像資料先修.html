00A · 影像在記憶體裡是什麼

程式收到一張影像時，記憶體裡到底有什麼？

一句話答案：影像是有寬、高、通道數、元素型別與列步距的陣列；每個數值只代表某位置、某色彩通道的量化結果。先能正確讀這塊記憶體，才有資格談特徵、深度或人工智慧。

最小前置：光如何成為數字，以及 C++ 陣列與整數型別。這頁不要求線性代數或影像處理。

寬、高與列欄不是一回事

一張寬 640、高 480 的灰階影像可視為 480 列、每列 640 個像素。常用記法 I(v,u) 中，u 沿水平方向增加，v 沿垂直方向增加；C++ 容器卻常先索引列再索引欄，因此程式可能寫成 at(v,u)。不要因為數學寫 (x,y) 就直接假設記憶體索引順序。列步距（Row Stride）是相鄰兩列起點的位元組距離，可能為了對齊而大於「寬乘元素大小」；忽略它會讀到錯位資料。

灰階與顏色通道

灰階影像每個像素通常只有一個亮度相關數值。彩色影像常以紅、綠、藍三個色彩通道（Color Channel）表示，但通道順序不一定是 RGB；部分函式庫或相機輸出採 BGR。這些數值不是人眼感知亮度的完美線性刻度，也不是物體的固有顏色。白平衡、色彩矩陣、伽瑪與光源光譜都會改變數值。若演算法只需要幾何邊緣，轉灰階可能足夠；若要分辨紅色零件，就不能隨意丟掉通道。

取樣與量化是兩種不同的捨棄

空間取樣（Spatial Sampling）決定在哪些位置量測，也就是影像有多少列與欄；解析度從 640×480 降成 320×240，量測位置變少，窄線可能完全消失。量化（Quantization）決定每格能用多少離散數值。8 位元無號整數有 2^8=256 個階級，通常是 0 到 255；12 位元則有 4096 級。較多位元能描述更細的亮度差，但無法補回失焦、飽和或沒有取樣到的空間細節。

可手算的小例子

一張 640×480、每像素 3 通道、每通道 8 位元且無填充的影像，資料量是 640×480×3=921,600 位元組，約 0.88 MiB。每秒 30 張的原始資料率約 27,648,000 位元組／秒，也就是 26.4 MiB/s。若列步距是 1920 位元組，像素 (u=10,v=2) 的第一通道偏移量是 2×1920+10×3=3870。這個例子說明：解析度、通道、型別與步距都屬於介面契約，缺一項就可能把正確位元組解成錯誤畫面。

雜訊與模糊不是同一問題

雜訊（Noise）是量測值的隨機波動：同一個靜止暗區連拍十張，每格數字仍稍有不同。模糊（Blur）是鄰近位置的訊號被混合：一條由 20 跳到 220 的銳利邊緣，模糊後可能變成 20、60、110、170、220。平均濾波可降低獨立隨機雜訊，代價是也混合邊緣；它不能把已經因運動模糊丟失的細節可靠地還原。先觀察多幀變異與單幀邊緣寬度，才知道該處理哪一種問題。

現象數值證據不應急著下的結論
暗區顆粒跳動同一像素跨幀標準差高不是物體表面真的在閃
邊緣穩定但過渡寬多幀位置相同、梯度較小不一定是雜訊
大片值為 255直方圖在上限堆積不是「白色量得很準」
細格紋忽隱忽現縮放或視角微變就改樣式可能是取樣混疊，不是真紋理

給 C++ 工程師的資料契約

一個可靠的影像介面至少帶：寬、高、通道語意、元素型別、列步距、色彩排列、擷取時間戳與擁有權／生命週期。uint8_t* 只告訴你起點位址，沒有告訴你如何解釋資料。修改共享緩衝區、使用過期指標或把 16 位元深度當 8 位元灰階，都會產生看似可執行、幾何上卻荒謬的結果。

常見誤解與邊界

  • 「0 是沒有資料」：未必。灰階 0 可代表黑；深度影像才可能另定 0 為無效，必須讀格式契約。
  • 「解析度高就更準」：像素更多不保證光學解析力、標定與訊噪比更好。
  • 「轉成 JPEG 看起來一樣即可」：有損壓縮會改變像素與邊緣，不適合作為精密量測的透明替代。
  • 本頁只建立常見陣列模型；拜耳排列、HDR、浮點影像與壓縮碼流需要各自格式說明。

可觀察證據：印出影像 metadata、首兩列位元組偏移、各通道最小／最大值、飽和比例與固定區域跨幀變異。這能證明資料被怎樣編碼及是否穩定，不能單獨證明相機幾何已標定。
