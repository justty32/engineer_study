06 · C++ 感知介面與驗證證據

為什麼只回傳一個 Pose 很危險？

一句話答案：六個看似合理的數字，若沒有座標系、擷取時間、有效狀態、品質與來源，就無法知道它描述哪裡、哪一刻、是否可信。成熟介面傳遞的是「估測加證據契約」，而不是裸矩陣。

最小前置：感知—控制閉迴路；熟悉 C++ 型別、所有權與錯誤處理。這章利用你的軟體背景把前面物理與幾何落到介面。

輸入契約先於演算法

影像輸入至少要說清楚寬、高、像素型別、色彩／深度編碼、列步距、擷取時間、相機識別、標定版本與緩衝區生命週期。若一個 stage 把 BGR 當 RGB，程式仍能跑；若把接收時間當擷取時間，靜止測試仍可能通過；若非同步工作保留已釋放的 buffer，錯誤甚至只在負載高時出現。用強型別與不可變 metadata 讓錯誤更早暴露。

輸出要回答五個問題

一筆估測必須回答：估的是什麼；來源與目標座標系是哪兩個；對應哪個擷取時間；有效或拒用的理由；數值不確定性與品質證據為何。協方差（Covariance）可描述局部誤差尺度與方向關聯，但它不是「可信度百分比」，也不會自動涵蓋標定錯誤、模型選錯與對稱多解。

struct PoseEstimate {
  RigidTransform T_target_source; // 名稱明示方向
  FrameId target_frame, source_frame;
  CaptureTime captured_at;
  Matrix6d covariance;
  QualityMetrics quality;         // 內點數、殘差、覆蓋等
  CalibrationVersion calibration;
  EstimateStatus status;          // 有效、退化、過期、無對應……
};

可手算的小例子

相機在 12:00:00.000 擷取影像，管線 70 ms 後輸出物體位置；物體相對速度 0.5 m/s。若下游誤把輸出時間當擷取時間，對齊姿態時就可能有 0.5×0.070=0.035 m，即 35 mm 的系統性時空錯配。把演算法位置雜訊從 2 mm 改善到 1 mm，完全救不了這個 metadata 錯誤。

自由實驗：最小輸出契約

逐項拿掉時間、座標或不確定度，觀察下游失去的是哪一種判斷能力。全部選「有」也只代表介面足以開始驗證，不代表估測已正確。

管線的觀測點與可重播性

在擷取、前處理、特徵、匹配、幾何估測、座標轉換及輸出各 stage 記錄結構化證據。保存能重播的原始輸入、參數與版本，使相同資料能離線重現。線上指標看延遲分位數、拒用率、飽和像素、有效深度比例、內點空間覆蓋與殘差；不要只記平均 FPS 與「success=true」。日誌也要有容量與隱私策略，避免無限制保存影像。

驗證要分層

  • 資料層：用已知小陣列驗證通道、步距、型別與生命週期。
  • 幾何層：用合成點交叉驗算投影、反投影與變換方向。
  • 標定層：看保留資料的每區域殘差，不以訓練資料自證。
  • 估測層：按距離、角度、材質、遮擋與退化類型統計位置／方向誤差和失敗率。
  • 系統層：量曝光到命令與致動的延遲分布，注入過期、缺幀、錯標定及低品質資料，確認拒用路徑。

常見誤解與邊界

例外不是所有即時管線的唯一錯誤機制；關鍵是失敗必須顯式且不可被當成有效零值。單元測試通過不代表相機、機器人與時鐘整合正確；模擬資料也很難涵蓋反光、模糊與硬體時間抖動。反過來，只有實機端到端測試又難以定位根因。分層測試、可重播輸入與線上證據需要同時存在。本章給的是契約骨架，不是功能安全認證方案；真正接近人或設備的系統仍需獨立安全控制與風險分析。

完成證據：任取一筆錯誤抓取，你應能沿時間戳、影像 metadata、標定版本、匹配與殘差、變換鏈及控制拒用狀態重建因果。若只能看到最後 Pose，就還沒有可診斷的感知系統。
