01

RS-485 不是封包協定，而是把 0／1 搬上長線的電氣規則

MCU UARTTX/RX 邏輯位元RS-485 收發器A/B 差動電壓雙絞線遠端收發器UART／Modbus

UART 規定 start bit、data bits、parity、stop bit；RS-485 收發器只負責把邏輯轉成差動線路訊號。Modbus RTU 再定義位元組代表什麼。

一句話模型：UART 是位元格式，RS-485 是物理搬運，Modbus 是封包語言。
02

差動為什麼抗共同雜訊？

接收器主要看 Vdiff = VA − VB。外界干擾若同時讓 A、B 都增加相近電壓，兩者相減後大多被消掉；這叫抑制共模雜訊。

但收發器腳位相對本機 GND 的電壓仍有限制。兩地地電位差太大時，需要參考導體、保護或隔離。

雙絞線的作用：A、B 反覆交換空間位置，使外界電磁場較平均地耦合到兩條線。

03

兩線半雙工：DE 是共用麥克風開關

常見 2-wire RS-485 的所有節點共用同一對 A/B。任一時間通常只能有一個 driver 啟用。

DE=1UART shift register最後 stop bitTransmission CompleteDE=0等待回應

正確：最後一位真的離開腳位後再放手

軟體 buffer 空時，UART shift register 可能仍在送；要等硬體 TC flag。

為什麼太早／太晚都壞？

太早：最後一個 byte 或 stop bit 被截斷，遠端看到 framing／CRC error。

太晚：你的 driver 還霸住 A/B，遠端開始回答時發生 contention，回應開頭消失。

05

閒置偏壓：所有 driver 放手時，替總線決定預設狀態

終端電阻

處理訊號切換時的反射；配合電纜特性阻抗，放在主幹兩個物理端。

Failsafe bias

處理沒人發送時的 0 V 差動狀態；用電阻建立一個小而確定的 Vdiff。現代收發器也可能內建 failsafe，仍應看資料表。

偏壓、終端都會增加 driver 負載。阻值要把終端並聯效果、節點 unit load、所需 Vdiff 與功耗一起算，不能到處隨便加。

06

現場例子：桌上正常，接 50 公尺後偶發 CRC error

第一步：看供電與接線A/B 極性、參考地、線材、星狀支線、終端位置、屏蔽接法。
第二步：示波器看 A−B差動幅度、反射、過衝、交越多次、共模是否超出收發器範圍。
第三步：看 DE 與 UART最後 stop bit 是否完整、遠端回應是否與本端 driver 重疊。
第四步：才解 Modbus站號、鮑率、parity、silent interval、CRC、exception code。
長線守則：不要把 retry 當修復；先證明物理波形與 bytes 正確，再修改 parser。
