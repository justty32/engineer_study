SPI 原理與實例

每打一個 clock，主控與裝置同時交換一個 bit；真正規則由裝置資料表決定。

01

SPI 是兩個移位暫存器接成一個圈

SCLK主控產生節拍
MOSI主控送到裝置
MISO裝置送回主控
CS拉低選中這顆裝置

每個 clock 邊緣，兩邊都把一個 bit 推出去、把另一邊的一個 bit 收進來。因此 SPI 天生全雙工；即使你只想讀，也常要送 dummy byte 才能產生 clock。

02

CS 不只是「選哪顆」，還常定義一個命令的邊界

不同裝置共用 SCLK／MOSI／MISO，但各自有 CS。只有 CS 有效的裝置可以驅動 MISO。

CS 拉低裝置重置 bit counter、開始收命令
→
若干 clock命令、位址、dummy、資料依資料表移動
→
CS 拉高提交命令或結束 transaction

常見「全部讀到 0xFF」

MISO 若沒人驅動又有上拉，就會一直是 1：可能 CS 選錯、裝置沒上電、pin mux 錯，或命令後缺少 dummy clocks。先量 CS、SCLK、MOSI、MISO，不要先怪 parser。

03

CPOL／CPHA 只是約定「時脈平時在哪裡、哪個邊緣讀」

CPOL：SCLK 閒置時為低或高。CPHA：第一個或第二個有效邊緣取樣。四種組合形成 Mode 0～3，沒有哪個天生更好。

Mode 0：閒置低、第一緣取樣

資料在取樣邊緣前必須已穩定。若主控在裝置正準備改資料的邊緣讀取，就可能整排偏一個 bit。

工程做法：看資料表的 timing diagram，再設定 CPOL、CPHA、bit order、word width、最大 SCLK 與 CS setup／hold。
04

時脈很快，不代表有效資料一樣快

Flash 讀取可能包含 opcode、24-bit address、dummy cycles，之後才有 payload。小筆交易的固定開銷比例很高。

有效率 = payload bits / total clock bitsSPI 沒有通用 ACK／CRC；需要時由裝置協定自己定義。
線上時間29.6 µs
有效率86.5%

資料量越小，固定命令開銷越顯眼。

深讀

SPI 沒有自描述封包；每一筆交易都由資料表定義

序列周邊介面（Serial Peripheral Interface, SPI）通常由 controller 產生 SCLK、以 CS 選裝置，MOSI 與 MISO 分向傳輸。時脈極性（Clock Polarity, CPOL）決定閒置電位；時脈相位（Clock Phase, CPHA）決定在哪個邊緣取樣。Mode 相同只是必要條件，還要一致的 bit order、word length、CS setup／hold 與裝置命令格式。

時間預算例

讀 256 B，另有 4 B command／address，共 260 B = 2080 bit。SCLK = 20 MHz 時，純 clock 時間為 2080/20×106 = 104 µs。若每筆交易還有 5 µs CS 間隔，總計至少 109 µs；未含軟體設定與 DMA 完成延遲。

為何波形看起來有資料仍可能全錯

若 controller 在裝置改變資料的同一邊緣取樣，setup／hold margin 可能接近零，解碼器仍可能以自己的門檻顯示一串穩定但錯位的 byte。MISO 若多個裝置未在 CS deassert 後 high-Z，還會發生 bus contention。

證據邊界：邏輯分析儀核對 command、Mode 與 byte；示波器同時看 SCLK、資料與 CS 可量 setup／hold、振鈴與電壓。成功讀一次 device ID 不能證明最高頻率、溫度與所有板批都有裕度。
