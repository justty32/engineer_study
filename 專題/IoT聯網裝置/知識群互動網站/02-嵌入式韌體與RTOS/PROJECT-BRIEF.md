# IoT 嵌入式韌體、驅動與 RTOS 互動網站專案簡報

## 目標

把 MCU 執行模型、驅動資料流、ISR、RTOS 排程與同步、低功耗及復原機制組成一個可操作的韌體設計工作台。讀者完成後應能用時序、CPU、RAM 與故障證據說明架構選擇，而不是只背 API 名稱。

## 讀者與深度

- 讀者軟體能力強，但嵌入式硬體、時序與 RTOS 基礎不穩。
- 程式語法從簡；重點是暫存器／ISR／DMA／排程／低功耗等軟硬交界。
- 以大學層級概論為主；不展開特定 MCU 暫存器、完整 RTA、形式驗證或安全認證。

## 八個學習成果

1. 依任務數、deadline、阻塞流程與 RAM 選擇 superloop 或 RTOS。
2. 用最壞迴圈時間判斷非阻塞狀態機能否在期限內回應。
3. 建立 ISR 延遲與反應時間預算，知道 ISR 必須短且不可阻塞。
4. 量化 polling 與 DMA 的 CPU 成本，選擇合理驅動資料流。
5. 以 RMS／EDF 利用率與堆疊 RAM 做初步可排程性檢查。
6. 依事件、資料或共享資源選 queue、semaphore、notification 或 mutex。
7. 以喚醒成本與 duty cycle 判斷睡眠模式是否值得。
8. 用 watchdog、BOR、原子寫入、A/B 與 rollback 建立可復原流程。

## 邊界

- 不重複後續連線站的 AT、封包、重傳與網路協定。
- 不深入後續安全量產站的 secure boot、金鑰與簽章信任鏈。
- 所有計算都是教學預算；正式設計需量測 WCET、堆疊 watermark、電流剖面與故障注入。
- 純靜態、零外部資產、手機可操作；不抓取或生成圖片。
