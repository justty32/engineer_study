時序、CPU、RAM 與故障證據共同決定設計邊界。

先把韌體看成有期限、有容量的狀態系統

READ FIRST

一般應用程式多半在乎「最後算對」；嵌入式韌體還要保證在 deadline 前算完、RAM 不超量、硬體事件不漏掉，而且斷電或卡死後能回到安全狀態。以下八段會把滑桿與選單連回真實執行機制。

01 裸機、superloop 與 RTOS：選的是協調模型，不是效能等級

裸機（bare-metal）表示沒有作業系統核心；superloop 是在一個主迴圈中輪流推進各狀態機；即時作業系統（Real-Time Operating System, RTOS）則以 task、優先權與同步原語管理工作。若工作只有「讀鍵 → 更新 LED」，superloop 往往最容易驗證；若無線、感測、儲存各有不同 deadline 與阻塞來源，RTOS 能隔離責任，但也帶來 stack、競爭與排程分析成本。

工具的架構建議是初篩，不是證明。真正證據來自時序 trace、最壞執行時間（Worst-Case Execution Time, WCET）、RAM map 與錯誤注入；CPU 平均使用率低不能排除某次長阻塞。

02 狀態機：把「等待」變成可觀察狀態

有限狀態機（Finite-State Machine, FSM）把每個事件定義成 state + event → next state + action。這像明確的 reducer：同一輸入在同一狀態得到可預期結果。例：CONNECTING 收到 timeout，不是原地 busy-wait，而是遞增重試計數、轉入 BACKOFF 並設定下一次喚醒時間。log 至少記錄舊狀態、事件、新狀態與時間戳；這能重建控制流，但不能證明 GPIO 或無線電實際波形正確。

03 中斷延遲：deadline 看最壞鏈，不看平均 handler 時間

中斷（Interrupt）使核心保存現場並進入中斷服務常式（Interrupt Service Routine, ISR）。簡化反應時間 R = Tdisabled + Thigher + Tentry + Thandler。例：12 + 36 + 2 + 15 = 65 µs；若 deadline 為 100 µs，名義餘裕 35 µs。假設這些都是同一次事件可能遇到的上界，且沒有額外 bus stall、cache 或臨界區。

操作時逐項拉高，觀察哪個因素吃掉 headroom。邏輯分析儀以事件腳與 ISR 入口 debug pin 的時間差可量端到端延遲；只用函式 profiler 量 handler 本身，會漏掉進入前的等待。

04 Polling、interrupt、DMA：搬資料的 CPU 成本不同

輪詢（Polling）由 CPU 反覆查狀態；interrupt 在事件時通知；直接記憶體存取（Direct Memory Access, DMA）由硬體搬資料。以 256 B、每秒 500 次、每 byte 80 cycles、80 MHz 為例，輪詢搬運成本為 256 × 500 × 80 = 10,240,000 cycles/s，約 12.8% CPU。若 DMA 每次設定 800 cycles，成本 500 × 800 = 400,000 cycles/s，約 0.5% CPU。

DMA 省 CPU 不等於零成本：完成中斷、buffer ownership、對齊與 cache 一致性仍要設計。總線分析或 cycle counter 能證明吞吐與 CPU 時間；不能證明資料語意沒被上層覆寫。

05 RMS／EDF：可排程性與記憶體要分開過關

週期任務利用率 U = Σ(Ci/Ti)。預設三任務為 1/5 + 1/10 + 2/20 = 0.4，即 40%。速率單調排程（Rate-Monotonic Scheduling, RMS）在 n = 3 的經典充分界約 3 × (21/3 − 1) ≈ 77.98%；最早期限優先（Earliest Deadline First, EDF）在理想單核心、可搶占、deadline 等於 period 等假設下，以 U ≤ 100% 為基本條件。RMS 超過充分界不代表必定不可排程，需做反應時間分析（Response-Time Analysis, RTA）。

Stack 是另一個 gate：靜態配置總和沒超 RAM，也不表示單一 task 的最壞巢狀呼叫安全。watermark 能顯示測試期間峰值，不能保證未測路徑。

06 同步原語：事件、資料與所有權是三種不同問題

Task notification／binary semaphore 適合表示「有事發生」；queue 同時攜帶資料並緩衝速率差；mutex 保護共享資源並表達所有權。優先權繼承（priority inheritance）減輕高優先 task 被低優先持鎖者間接阻塞，卻不能消除鎖順序相反造成的 deadlock。ISR 只能呼叫明確標示可在 ISR 使用、且不會阻塞的 API。

操作不同 producer、consumer 與 primitive，觀察第一個不相容點。RTOS trace 可顯示喚醒與阻塞順序，但單次無 deadlock 不等於所有交錯都安全。

07 Tickless 與低功耗：睡眠要先償還進出成本

Tickless idle 讓核心在沒有工作時不被固定 tick 週期喚醒。簡化 break-even 時間 Tbe = Iwake × Twake/(Irun − Isleep)。以 wake 10 mA、5 ms，run 15 mA、sleep 0.02 mA 為例，Tbe ≈ 50/14.98 ≈ 3.34 ms；預期空檔遠大於此值才有淨節省。此式把喚醒輪廓簡化成矩形，未含晶振穩定、外設重設與穩壓器模式切換。

電流分析儀的時間積分能比較每週期電荷；datasheet 的 MCU sleep 電流不能代表整板，因為感測器、上拉與 LDO Iq 仍在耗電。

08 Watchdog 與持久化：重置只是復原起點

看門狗（watchdog）在健康證明逾時時 reset；brown-out reset（BOR）在電壓不可靠時阻止亂執行；原子寫入（atomic write）用雙區、journal 或版本加 CRC 避免半份設定被當成完整資料。A/B image 則保留已知可開機版本，首次啟動健康檢查失敗才回滾。

故障注入要真的在 Flash 寫入或更新各階段斷電，再檢查 reset cause、boot 選槽與資料版本。log 能證明軟體走過哪條復原路徑，但若 log 本身與資料同時半寫入，沒有外部電源與匯流排量測就不能完整還原。

常見誤解：RTOS ≠ 自動即時；interrupt ≠ 平行執行；DMA ≠ 零 CPU；volatile ≠ 原子性；watchdog reset ≠ 問題已修好。
