## 共通互動原則

- 所有操作使用原生 `select`、數值輸入、核取方塊與按鈕；不以拖放、圖像或橫向寬表格作為必要操作。
- 每個模組使用 `data-module`、`data-nav`、`data-complete`、`data-reset-module`；控制項變更時即時更新結果。
- 空值、非數字、`NaN`、無限大、除零、負值或不合法選項都要清除舊結果，並用文字指出原因。
- 狀態使用固定符號、文字、邊框與顏色同時呈現；動態回饋使用 `aria-live="polite"`。所有欄位有可見 `label`，按鈕使用 `type="button"`。

## 1. Bearer 選型

### 互動機制

用距離、payload 大小、供電方式、基礎設施歸屬與下行頻率五個條件進行連線 bearer 初篩。畫面顯示首選、備選、主要取捨與目前狀態；結果明確標示這只是初篩。

### 輸入／操作

- 使用 `select`：`bearer-range`（`room`、`campus`、`wide`，預設 `wide`）、`bearer-payload`（`small`，另有 `medium`、`high`）、`bearer-power`（`coin`，另有 `battery`、`mains`）、`bearer-infrastructure`（`private`、`operator`，預設 `operator`）、`bearer-downlink`（`rare`，另有 `frequent`）。
- 每次選項變更即時更新 `bearer-verdict`、`bearer-runner-up`、`bearer-tradeoff`、`bearer-status`、`bearer-feedback`。
- 提供 `data-reset-module="bearer-choice"` 的單模組重設按鈕，恢復契約預設值。

### 回饋

- 依契約固定決策順序顯示 NB-IoT、LTE-M、Wi-Fi、LoRaWAN、Thread 或 BLE 的初篩結果與 runner-up。
- 預設條件顯示 NB-IoT 為首選、LTE-M 為備選；回饋說明覆蓋、月租或自建部署、認證與實測仍需確認。
- `bearer-tradeoff` 用短句說明目前選擇犧牲或換取的距離、頻寬、功耗、基礎設施與下行能力，不把初篩當成最終採購決策。

### 錯誤路徑

- 選項缺值或不在契約允許集合時清除 verdict、runner-up、tradeoff 與舊回饋。
- 錯誤文字指出是哪個選擇無效，不以顏色作為唯一提示。

### 學習成果

能依裝置距離、資料量、能源、部署責任與下行需求做第一輪 bearer 選擇，並知道初篩仍須接續覆蓋、成本、認證與實測評估。

### 390px 注意事項

- 五個 `select` 單欄排列，完整顯示 label 與選項文字，不使用固定寬度比較表。
- 首選、備選與取捨拆成獨立結果列，長文字自然換行，不讓狀態文字壓住控制項。

## 2. Host 介面容量與 flow control

### 互動機制

以 UART baud、每 byte 位元數、payload 大小、訊息速率、burst 速率、burst 時間與接收緩衝區建立 host 介面預算。畫面同時呈現穩態使用率、突發超額與緩衝餘裕，讓使用者判斷流控或介面升級需求。

### 輸入／操作

- 使用數值欄位 `host-baud`、`host-bits-byte`、`host-payload-bytes`、`host-message-rate`、`host-burst-rate`、`host-burst-ms`、`host-buffer-bytes`。
- 預設值依契約為 115200、10、512、10、20000、100、2048；每個欄位在 `input`／`change` 時即時更新。
- 顯示 `host-capacity`、`host-steady-rate`、`host-utilization`、`host-burst-excess`、`host-buffer-headroom`、`host-status`、`host-feedback`，並提供 `data-reset-module="host-link"`。

### 回饋

- 預設結果顯示 capacity 11520 B/s、steady 5120 B/s、utilization 44.44%、burst excess 848 B、headroom 1200 B。
- steady rate 超過 capacity 或 buffer headroom 小於零時顯示阻擋，指出介面預算不足或突發資料無法容納。
- burst 超過介面容量但 buffer 仍足夠時顯示警告，建議評估 RTS/CTS、DMA、環形緩衝或更快介面；不要把緩衝暫存誤報為長期吞吐量。

### 錯誤路徑

- baud、bits per byte、buffer 必須大於零；payload、message rate、burst rate 與 burst time 可為零但不可為負。
- 空值或非法數字清除所有舊結果；對零值不可進行除零或沿用前一次使用率。

### 學習成果

能把 host 介面當成有容量限制的資料管道，區分穩態吞吐、突發超額與緩衝餘裕，並在需要時提出硬體流控、DMA 或介面升級。

### 390px 注意事項

- 七個輸入單欄排列，結果採上下堆疊的 metric，不使用需要左右捲動的寬表格。
- B/s、百分比與 byte 數值容器允許換行或以較短單位顯示，長 feedback 不得造成水平溢位。

## 3. AT／URC 解析狀態

### 互動機制

用目前狀態、收到的行類型、是否有待完成命令、是否註冊 URC handler，以及透傳 guard 五項選擇模擬 AT 引擎收到一行資料後的分流。畫面顯示分類、動作與下一狀態。

### 輸入／操作

- 使用 `select`：`at-state`（`idle`、`wait`，預設、`data`）、`at-line`（`ok`、`error`、`urc`，預設、`payload`、`prompt`）、`at-command-pending`（`yes`，預設、`no`）、`at-urc-handler`（`yes`，預設、`no`）、`at-transparent-guard`（`yes`，預設、`no`）。
- 每次選擇即時更新 `at-classification`、`at-action`、`at-next-state`、`at-status`、`at-feedback`；提供 `data-reset-module="at-engine"`。

### 回饋

- URC 與待完成命令分開分流；預設情境顯示分類為 URC、送至 handler、命令維持 wait。
- OK／ERROR 只有在 wait 且有 pending command 時完成命令；否則顯示警告並記錄為 unsolicited line。
- prompt 只有 wait 且有 pending command 時允許送 payload；payload 只有 data state 才進資料管道。
- data state 缺 transparent guard 時顯示阻擋，回饋提醒先建立透傳切換與退出保護。

### 錯誤路徑

- 缺少 URC handler 時，任何 URC 情境都必須阻擋，不可只顯示一般警告。
- 不合法選項或缺值時清除 classification、action、next state 與舊回饋；不能把 URC 當成目前命令的 OK／ERROR。

### 學習成果

能分辨同步命令回應、非同步 URC、prompt 與透明資料，理解 AT 引擎必須用狀態機與 handler 分流，而不是只等待下一行 OK。

### 390px 注意事項

- 五個 `select` 逐列顯示，狀態機結果使用「分類／動作／下一狀態」三個上下排列區塊。
- 長選項與阻擋原因可以換行；不能用裁切或省略號隱藏 `transparent guard` 等關鍵字。

## 4. 指數退避

### 互動機制

以基礎等待時間、目前重試次數、等待上限、jitter 百分比與最大重試次數，顯示當次 nominal delay、jitter 範圍、累積等待與是否應升級 supervisor。這個模組只呈現重連等待預算，不模擬網路成功率。

### 輸入／操作

- 使用數值欄位 `backoff-base`、`backoff-attempt`、`backoff-cap`、`backoff-jitter`、`backoff-max-retries`。
- 預設為 2 s、4、60 s、20%、6；`attempt` 與 `max-retries` 必須以非負整數輸入。
- 顯示 `backoff-nominal`、`backoff-min`、`backoff-max`、`backoff-cumulative`、`backoff-status`、`backoff-feedback`，並提供 `data-reset-module="backoff"`。

### 回饋

- 預設顯示 nominal 32.0 s、jitter 範圍 25.6–38.4 s、cumulative 62.0 s。
- 每次等待受 cap 限制，jitter 只改變等待範圍；回饋要同時顯示 nominal 與範圍，避免把隨機等待誤解為另一個重試次數。
- attempt 超過 max retries 時顯示阻擋，並提示交給 supervisor，不再無限重連。

### 錯誤路徑

- base 與 cap 必須大於零；attempt 與 max retries 為非負整數；jitter 必須介於 0 與 100 之間。
- 空值、非有限數值、負值或非整數重試次數清除舊結果與狀態；不可用零或前一次數值替代。

### 學習成果

能看出重連等待如何隨嘗試次數增加、如何受上限與 jitter 約束，並能辨認重試耗盡後應進入 supervisor 的升級路徑。

### 390px 注意事項

- 五個數值輸入與四個結果採單欄排列；將 min–max 範圍放在可自然換行的結果列。
- `backoff-feedback` 與升級提示放在結果下方，避免長秒數或百分比擠壓狀態符號。

## 5. 分層會話重建

### 互動機制

讓使用者選擇掉線、DNS／時間、TLS 或應用會話情境，再依固定的 registration → IP → time/DNS → socket → TLS → app session gate 檢查清單逐項完成。畫面回報第一個缺口與下一步，不能用後面的勾選抵銷前面的缺口。

### 輸入／操作

- 使用 `select` `session-case`，選項為 `network-drop`（預設）、`dns-time`、`tls-fail`、`app-session`。
- 六個核取方塊使用 `data-session-check`：`session-registration`、`session-ip`、`session-time-dns` 預設勾選；`session-socket`、`session-tls`、`session-app` 預設未勾選。
- 顯示 `session-first`、`session-second`、`session-count`、`session-next`、`session-status`、`session-feedback`，並提供 `data-reset-module="session"`。

### 回饋

- 依固定 gate 順序回報第一個未完成項目與下一步；全勾時才顯示會話重建 gate 通過。
- network-drop 先查註冊／URC，再查 IP／socket；dns-time 先確認時間源／DNS，再查 TLS。
- tls-fail 先看時間／憑證設定，再看 socket／TLS log；app-session 先查 transport，再查訂閱、QoS 與 sequence 恢復。

### 錯誤路徑

- 情境切換時重新套用該情境的診斷順序，不保留上一情境的 first、second 或 next 文字。
- 缺少任何前置 gate 時顯示具體第一個缺口；不能因 session、TLS 或 app 項目已勾選就宣稱通過。

### 學習成果

能用分層方式定位連線恢復缺口，知道註冊、IP、時間／DNS、socket、TLS 與應用會話必須按依賴順序逐層重建。

### 390px 注意事項

- 核取方塊清單單欄排列，label 可換行且點擊文字也能操作；不使用六欄 gate 表格。
- first、second、count、next 分開顯示，長診斷文字不可覆蓋下一個核取方塊。

## 6. Payload 與資料預算

### 互動機制

用 payload、編碼比例、額外 overhead、每日訊息數、交付倍率與計算天數估算 wire message、每日與期間資料量，再與未壓縮 baseline 比較節省比例。這是裝置端資料成本預算，不替代電信商計量規則。

### 輸入／操作

- 使用數值欄位 `data-payload`、`data-encoding-ratio`、`data-overhead`、`data-messages-day`、`data-delivery-factor`、`data-days`。
- 預設為 100 B、0.6、40 B、24、1.1、30；每次輸入即時更新。
- 顯示 `data-wire-message`、`data-daily`、`data-period`、`data-baseline`、`data-saving`、`data-status`、`data-feedback`，並提供 `data-reset-module="data-budget"`。

### 回饋

- 預設結果顯示 100.0 B/message、2640 B/day、79200 B/30d、baseline 110880 B、saving 28.57%。
- 結果並列 wire message、daily、period、baseline 與 saving，使使用者看見編碼縮減與 overhead 之間的取捨。
- 回饋提醒實際預算還可能包含 IP/TCP/TLS、連線握手與營運商計量；不得把此估算解讀為帳單保證。

### 錯誤路徑

- payload、overhead、messages 與 days 必須為非負，且 days 必須大於零；encoding ratio 必須大於零且不超過 2；delivery factor 至少為 1。
- 空值、非有限值或不合範圍時清除全部結果，不能保留前一次 saving 或把錯誤比例當成零。

### 學習成果

能把裝置 payload、編碼、協定外加量、重送或交付倍率與觀察期間放在同一個資料預算中，並知道模型邊界與實際計費的差異。

### 390px 注意事項

- 六個輸入與五個結果全部單欄排列；B/message、B/day 與百分比拆成獨立數值列。
- baseline 與 saving 的長數字允許換行；feedback 放在最下方，不使用固定寬度表格承載資料。

## 7. Keepalive、重連與 PSM

### 互動機制

以會話長度、keepalive 間隔、每次往返 bytes、每日報告數、每次重連 bytes 與可達性需求，對照持續會話 keepalive 和每次報告重連的網路 bytes。結果另外保留 PSM／eDRX 的能耗取捨，不把 bytes 直接當成能耗。

### 輸入／操作

- 使用數值欄位 `keepalive-seconds`、`keepalive-session-hours`、`keepalive-roundtrip-bytes`、`keepalive-reports`、`keepalive-reconnect-bytes`，以及 `select` `keepalive-reachability`（`frequent` 預設、`rare`）。
- 顯示 `keepalive-wakes`、`keepalive-bytes`、`reconnect-bytes`、`keepalive-byte-winner`、`keepalive-verdict`、`keepalive-status`、`keepalive-feedback`。
- 所有控制變更即時更新，並提供 `data-reset-module="keepalive"`。

### 回饋

- 預設顯示 wakes 288、keepalive bytes 28800 B、reconnect bytes 120000 B，byte winner 為 keepalive。
- `frequent` 時建議評估持續會話；`rare` 時一律建議評估 PSM、eDRX 或批次上傳，即使 reconnect bytes 較高。
- 回饋明確說明 bytes 比較只反映網路資料量，不能單獨推出電池能耗或可達性品質。

### 錯誤路徑

- keepalive seconds、session hours 與 reports 必須大於零；roundtrip bytes 與 reconnect bytes 可為零但不可為負。
- 空值、非有限值與不合範圍輸入清除所有比較結果，不用前一次 winner 或 verdict 掩蓋錯誤。

### 學習成果

能比較持續會話與重連的網路 bytes，理解可達性需求會改變策略，並知道 PSM／eDRX 的能源判斷不能只看 bytes。

### 390px 注意事項

- 數值欄位單欄排列；keepalive bytes、reconnect bytes 與 winner 使用上下堆疊結果列。
- `rare` 的 PSM／eDRX 提示要可換行且與狀態分開，不能讓長文字擠出 390px 視窗。

## 8. Supervisor 與故障升級

### 互動機制

讓使用者選擇無回應、掉註冊、socket drop 或 buffer overflow 情境，再操作七項 supervisor 檢查清單。畫面依情境固定必要項目回報第一個缺口、第二個觀察點、完成數與阻擋原因。

### 輸入／操作

- 使用 `select` `supervisor-case`，選項為 `no-response`（預設）、`deregister`、`socket-drop`、`buffer-overflow`。
- 七個核取方塊使用 `data-supervisor-check`：`supervisor-log`、`supervisor-timeout`、`supervisor-backoff` 預設勾選；`supervisor-soft-reset`、`supervisor-hard-reset`、`supervisor-flow-control`、`supervisor-watchdog` 預設未勾選。
- 顯示 `supervisor-first`、`supervisor-second`、`supervisor-count`、`supervisor-blocker`、`supervisor-status`、`supervisor-feedback`，並提供 `data-reset-module="supervisor"`。

### 回饋

- no-response 需 log、timeout、soft reset、hard reset、watchdog；先保存 AT log／最後命令，再依序升級。
- deregister 需 log、timeout、backoff；先看 URC、訊號與註冊原因，再使用 capped backoff。
- socket-drop 需 log、timeout、backoff；先區分 bearer、IP、socket，再重建上層會話。
- buffer-overflow 需 log、flow control；先看 RTS/CTS 與環形緩衝高水位，再降低 burst 或升級介面。

### 錯誤路徑

- 依目前情境重新判斷必要項目；情境切換不能沿用上一情境的 blocker 或 first／second 文字。
- 缺任一必要項目即阻擋，不以總完成數抵銷；部分勾選不得誤報 gate 通過。
- 缺值或不合法情境清除所有舊結果與狀態，並以文字指出需要重新選擇情境。

### 學習成果

能依故障證據安排保存 log、逾時、退避、軟重置、硬重置、流控與 watchdog 的升級順序，避免所有掉線都直接重開機或無限重試。

### 390px 注意事項

- 情境選擇與七項清單均採單欄，label 包含完整名稱並允許換行；不要用橫向 gate 表格。
- first、second、blocker 與 feedback 分開排列；阻擋原因要能在小螢幕完整閱讀且不遮住核取方塊。
