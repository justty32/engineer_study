# IoT 裝置安全、佈建、量產與生命週期：互動題型草案

← [專案簡報](PROJECT-BRIEF.md)｜[建置規格](BUILD-SPEC.md)

> 本檔只描述互動題型、操作、回饋與驗收方式。`BUILD-SPEC.md` 是唯一執行契約；不得新增控制 ID、改動選項集合、預設值、required set、gate 順序或公式。

## 共通互動原則

- 八個模組固定使用 `data-module`、`data-nav`、`data-complete`、`data-reset-module`；模組鍵依序為 `threat-model`、`device-identity`、`secure-boot`、`ota-budget`、`update-recovery`、`provisioning-line`、`production-gate`、`fleet-lifecycle`。
- 使用原生 `select`、數值輸入、核取方塊與按鈕；所有欄位有可見 `label`，按鈕使用 `type="button"`。控制值變更時即時更新結果。
- 空值、非數字、`NaN`、`Infinity`、除零、負值或不合法選項，均清除該模組所有舊結果與狀態，不以預設值或前一次結果代替。
- `status` 與回饋以固定符號、文字、邊框和顏色共同表達；結果與回饋區使用 `aria-live="polite"`，錯誤、警告與阻擋不能只靠顏色判斷。
- 每個模組提供 `data-reset-module` 單元重設，恢復規格預設值；進度只作輔助，不阻擋自由瀏覽。鍵盤 Tab 順序依操作順序，Space/Enter 可操作原生控制項與按鈕，focus 必須可見且結果更新不得搶焦點。

## 1. 威脅面初篩：`threat-model`

### 操作流程

1. 以四個 `select` 選擇 `threat-vector`（`remote` 預設、`physical`、`supply-chain`）、`threat-impact`（`control` 預設、`data`、`safety`）、`threat-scale`（`fleet` 預設、`single`）與 `threat-update`（`available` 預設、`none`）。
2. 每次選擇即時更新 `threat-priority`、`threat-first-control`、`threat-second-control`、`threat-status`、`threat-feedback`。
3. 依決策順序讀取第一、第二控制措施；用 `data-complete="threat-model"` 完成、`data-reset-module="threat-model"` 重設。

### 預設與回饋

- 預設為 remote、control、fleet、available；依 `remote+fleet` 顯示每裝置身分／雙向認證為第一批控制，撤銷／隔離／簽章 OTA 為第二批控制。
- `threat-update=none` 時，無論其他選擇為何，將可維護性標為最高缺口；`supply-chain` 時依序顯示簽章 artifact／信任根，再 station 授權與 audit；`physical` 時依序顯示不可匯出金鑰，再 secure boot／debug lock；其餘 remote 依序顯示 TLS 身分驗證，再最小權限與更新。
- `impact=safety` 將 `threat-priority` 標為高影響，`threat-feedback` 必須要求 safe state 與故障證據。所有結果均標示為初篩警告，不表示已完成 threat model。

### 警告、阻擋與錯誤

- 合法選項可完成初篩，但 `threat-status` 必須保留「初篩警告」語意；不能把初篩結果顯示成安全通過。
- 選項缺值或不在契約集合時，清除五個輸出並以文字指出無效選項；不沿用前一個情境的控制順序。

### 手機與 ARIA

- 700px 以下四個選擇單欄排列，390px 時首要控制、次要控制與限制說明各自成列並自然換行；不得用寬表格承載決策。
- 每個 `select` 有完整可見 label；五個輸出區以 `aria-live="polite"` 更新，`threat-status` 同時顯示符號與文字。

### 驗收案例

- 預設值：第一控制為每裝置身分／雙向認證，第二控制為撤銷／隔離／簽章 OTA，狀態為初篩警告。
- `threat-update=none`：第一優先缺口改為可維護性。
- 依序選 `supply-chain`、`physical` 與 `remote+single`，確認各固定決策順序和回饋限制更新。
- `impact=safety`：優先級為高影響，回饋包含 safe state 與故障證據要求。
- 移除或設定非法選項：五個輸出與舊回饋清除。

## 2. 每裝置身分 gate：`device-identity`

### 操作流程

1. 依固定順序操作六個 `data-identity-check` 核取方塊：`identity-unique`、`identity-key-nonexport`、`identity-cert-chain` 預設勾選；`identity-mutual-auth`、`identity-rotation`、`identity-revocation` 預設未勾選。
2. 即時讀取 `identity-first`、`identity-second`、`identity-count`、`identity-blocker`、`identity-status`、`identity-feedback`；用 `data-complete="device-identity"` 完成、`data-reset-module="device-identity"` 重設。

### 預設與回饋

- gate 順序固定為 unique identity→non-exportable private key→certificate trust chain→mutual authentication→rotation→revocation。
- 六項皆為必要項；預設第一缺口是 mutual authentication，第二缺口是 rotation；`identity-count` 只反映實際勾選數，不抵銷前置缺口。
- 六項全勾才顯示通過；回饋說明通過只代表身分生命週期有基本閉環，仍需 KMS/HSM、憑證政策、後端授權與實機驗證。

### 警告、阻擋與錯誤

- 缺任一必要項即阻擋，`identity-first` 回報固定順序中的第一缺口，`identity-second` 回報下一個缺口。
- 核取狀態不合法或資料缺失時清除所有輸出，不把總數當成通過依據。

### 手機與 ARIA

- 六個核取方塊單欄排列，label 可換行且文字可點擊；first、second、count、blocker、status、feedback 上下堆疊，390px 不水平溢位。
- 核取方塊使用原生鍵盤語意；結果區以 `aria-live="polite"` 更新，阻擋原因同時具備文字和固定符號。

### 驗收案例

- 預設值：前三項勾選、後三項未勾，第一缺口為 mutual authentication，狀態阻擋。
- 只勾選 rotation/revocation：count 增加但第一缺口仍為 mutual authentication。
- 依固定順序補齊六項才通過；取消 certificate chain 後第一缺口回到 certificate trust chain。
- 全勾時回饋仍列出 KMS/HSM、憑證政策、後端授權與實機驗證限制。

## 3. Secure boot 鏈：`secure-boot`

### 操作流程

1. 以 `boot-case` 選擇 `normal`（預設）、`tampered-image`、`downgrade` 或 `debug-attach`。
2. 依固定順序操作七個 `data-boot-check`：`boot-root-key`、`boot-bootloader-signature`、`boot-app-signature` 預設勾選；`boot-antirollback`、`boot-debug-lock`、`boot-fail-closed`、`boot-recovery` 預設未勾選。
3. 即時讀取 `boot-first`、`boot-second`、`boot-count`、`boot-blocker`、`boot-status`、`boot-feedback`；以 `data-complete="secure-boot"` 完成、`data-reset-module="secure-boot"` 重設。

### 預設與回饋

- gate 順序固定為 immutable root/key→bootloader signature→application signature→anti-rollback→debug lock→fail closed→signed recovery。
- `normal` 與 `tampered-image` 必要項為 root、bootloader、app、fail closed、recovery；`downgrade` 另需 anti-rollback；`debug-attach` 另需 debug lock。缺項即阻擋。
- 預設第一缺口為 fail closed，第二缺口為 signed recovery。回饋說明 CRC 只能檢查意外損壞，不能替代數位簽章真實性；debug lock 不可阻斷授權 recovery。

### 警告、阻擋與錯誤

- 後面的 checkbox 已勾而前面的必要 gate 未勾時，仍依固定順序回報第一缺口；`boot-count` 不抵銷缺項。
- 不合法 `boot-case` 或 checkbox 狀態清除所有舊輸出與狀態。

### 手機與 ARIA

- 情境選擇後接七個核取方塊，全部單欄；結果區拆成 first、second、count、blocker、status、feedback，長名稱允許換行。
- `boot-case` 與每個核取方塊有可見 label，原生 Space 可切換；結果和狀態以 `aria-live="polite"` 更新，不以顏色單獨表示阻擋。

### 驗收案例

- 預設 normal：勾選前三項，第一缺口為 fail closed，狀態阻擋。
- tampered-image：補齊 fail closed、recovery 後才通過；取消 root 時第一缺口為 immutable root/key。
- downgrade：即使其他項目全勾，未勾 anti-rollback 仍阻擋。
- debug-attach：未勾 debug lock 阻擋；補勾後仍要求該情境其他必要項。
- 驗證 CRC 說明與 debug lock/recovery 說明存在於回饋。

## 4. A/B OTA 容量與傳輸預算：`ota-budget`

### 操作流程

1. 以數值欄位輸入 `ota-flash-kib`、`ota-boot-kib`、`ota-image-kib`、`ota-slots`、`ota-scratch-kib`、`ota-config-kib`、`ota-rate-kib-s`、`ota-delivery-factor`；預設依序為 `2048`、`128`、`700`、`2`、`128`、`64`、`16`、`1.2`。
2. 每次輸入即時更新 `ota-required-kib`、`ota-headroom-kib`、`ota-transfer-kib`、`ota-transfer-seconds`、`ota-verdict`、`ota-status`、`ota-feedback`。
3. 以 `data-complete="ota-budget"` 完成，`data-reset-module="ota-budget"` 恢復預設值。

### 公式與預設回饋

- 嚴格使用：`required = boot + image×slots + scratch + config`；`headroom = flash−required`；`transfer = image×delivery factor`；`time = transfer/rate`。
- 預設結果為 `1720 KiB`、`328 KiB`、`840 KiB`、`52.5 s`，A/B 容量通過；回饋說明這是教學預算，不含檔案系統、對齊、delta update、TLS/協定 overhead、斷點續傳、flash wear 與真實網路功耗。

### 警告、阻擋與錯誤

- flash、boot、image、scratch、config 必須非負，且 flash、image、rate 必須大於零；`slots` 為大於等於 1 的整數；delivery factor 必須大於等於 1。
- `headroom<0` 為阻擋；`slots<2` 即使空間足仍警告沒有 A/B rollback。非法輸入、空值或除零清除全部七個輸出。

### 手機與 ARIA

- 八個輸入單欄排列；四個數值 metric、verdict、status、feedback 垂直堆疊，KiB、KiB/s 與秒數可換行，390px 不出現水平捲動。
- 每個欄位有單位 label；結果區與 `ota-status`、`ota-feedback` 使用 `aria-live="polite"`，容量阻擋與單 slot 警告皆以文字呈現。

### 驗收案例

- 預設值：四項結果為 `1720/328/840/52.5`，容量通過。
- 將 `ota-slots` 設為 `1`：容量仍可足夠但狀態警告沒有 A/B rollback。
- 將 flash 調小至 `headroom<0`：狀態阻擋，回饋指出容量不足。
- 將 rate 設為 `0`、清空 image 或輸入非法 delivery factor：所有舊結果清除。
- 改變 image 或 delivery factor：transfer 與 transfer-seconds 即時重算；公式以獨立值交叉驗算。

## 5. 更新故障復原 gate：`update-recovery`

### 操作流程

1. 以 `update-case` 選擇 `power-loss`（預設）、`signature-fail`、`first-boot-fail` 或 `fleet-regression`。
2. 依固定順序操作八個 `data-update-check`：`update-authenticity`、`update-integrity`、`update-inactive-slot` 預設勾選；`update-atomic-switch`、`update-health-confirm`、`update-rollback`、`update-staged-rollout`、`update-observability` 預設未勾選。
3. 即時讀取 `update-first`、`update-second`、`update-count`、`update-blocker`、`update-status`、`update-feedback`；使用 `data-complete="update-recovery"` 完成與 `data-reset-module="update-recovery"` 重設。

### 預設與回饋

- gate 順序固定為 signature authenticity→integrity/hash→inactive slot→atomic switch→boot health confirmation→rollback→staged rollout/pause→observability。
- `power-loss` 需前六項；`signature-fail` 需 authenticity、integrity、observability；`first-boot-fail` 需 inactive slot、atomic switch、health、rollback、observability；`fleet-regression` 需 health、rollback、staged rollout、observability。
- 預設 power-loss 第一缺口為 atomic switch，第二缺口為 boot health confirmation。回饋明示 gate 通過不表示韌體沒有漏洞，只表示失敗處理路徑完整。

### 警告、阻擋與錯誤

- 只完成後段項目時，仍以該情境的固定順序回報第一缺口；不以 count 抵銷必要集合。
- 情境或 checkbox 非法時清除所有舊結果；情境切換要重新套用必要集合。

### 手機與 ARIA

- 情境選擇與八個核取方塊單欄排列；first、second、count、blocker、status、feedback 分列，長回饋自然換行。
- 原生 checkbox 支援鍵盤操作；結果區 `aria-live="polite"`，狀態使用固定符號與文字共同表達。

### 驗收案例

- 預設 power-loss：前三項勾選，第一缺口為 atomic switch，狀態阻擋。
- signature-fail：取消或保留無關項目不影響必要集合；補齊 authenticity、integrity、observability 才通過。
- first-boot-fail：驗證 inactive slot、atomic switch、health、rollback、observability 缺任一即阻擋。
- fleet-regression：驗證 staged rollout/pause 與 observability 均必要；不得因 authenticity 已勾而通過。

## 6. 產線佈建 gate：`provisioning-line`

### 操作流程

1. 以 `provisioning-case` 選擇 `new-device`（預設）、`rework` 或 `certificate-rotation`。
2. 依固定順序操作八個 `data-provisioning-check`：`provisioning-station-auth`、`provisioning-unique-id`、`provisioning-key-nonexport` 預設勾選；`provisioning-cert-bind`、`provisioning-readback`、`provisioning-quarantine`、`provisioning-audit`、`provisioning-debug-lock` 預設未勾選。
3. 即時讀取 `provisioning-first`、`provisioning-second`、`provisioning-count`、`provisioning-blocker`、`provisioning-status`、`provisioning-feedback`；用 `data-complete="provisioning-line"` 完成、`data-reset-module="provisioning-line"` 重設。

### 預設與回饋

- gate 順序固定為 station authorization→unique serial/MAC→non-exportable key→certificate binding→readback/online challenge→failure quarantine→audit trace→debug lock。
- `new-device` 與 `rework` 八項皆必要；`certificate-rotation` 不要求 debug lock，但不得解鎖已鎖裝置，其餘七項必要。
- 預設第一缺口為 certificate binding，第二缺口為 readback/online challenge。回饋強調 provisioning 失敗品不得流入下一站，log 不可保存可重建 private key 的明文秘密。

### 警告、阻擋與錯誤

- 缺任一情境必要項即阻擋，依固定順序回報第一缺口；count 不可抵銷前置 gate。
- 情境或 checkbox 非法時清除舊輸出；certificate-rotation 即使不要求 debug lock，也要明確顯示「不解鎖已鎖裝置」限制。

### 手機與 ARIA

- 情境與八項清單皆單欄，完整 label 可換行；結果欄位依 first、second、count、blocker、status、feedback 垂直排列。
- 原生核取方塊與可見 focus 支援鍵盤操作；狀態和回饋使用 `aria-live="polite"`，隔離與明文秘密規則以文字顯示。

### 驗收案例

- 預設 new-device：前三項勾選，第一缺口為 certificate binding，狀態阻擋。
- new-device：八項全勾才通過；取消 quarantine 即阻擋且指出失敗品不得流入下一站。
- rework：八項仍全部必要，不可沿用 new-device 以外的結果。
- certificate-rotation：只要求前七項，debug lock 未勾仍可通過，但回饋必須說明不得解鎖已鎖裝置。
- 驗證 audit 回饋不允許保存可重建 private key 的明文秘密。

## 7. EVT 到 MP 證據 gate：`production-gate`

### 操作流程

1. 以 `production-stage` 選擇 `EVT`、`DVT`（預設）、`PVT` 或 `MP`。
2. 依固定順序操作八個 `data-production-check`：`production-test-points`、`production-fct` 預設勾選；`production-secure-update`、`production-rf-emc`、`production-fixture`、`production-provisioning`、`production-traceability`、`production-change-control` 預設未勾選。
3. 即時讀取 `production-first`、`production-second`、`production-count`、`production-blocker`、`production-status`、`production-feedback`；以 `data-complete="production-gate"` 完成、`data-reset-module="production-gate"` 重設。

### 預設與回饋

- gate 順序固定為 test points/SWD→ICT/FCT→secure boot/OTA evidence→RF/EMC prescan→production fixture→provisioning→traceability→change control。
- `EVT` 需前兩項；`DVT` 需前四項；`PVT` 需前七項；`MP` 八項皆需。預設 DVT 第一缺口為 secure boot/OTA evidence，第二缺口為 RF/EMC prescan。
- 回饋說明通過只是該階段的學習 gate，不等於良率達標、認證完成或可直接出貨。

### 警告、阻擋與錯誤

- 缺任一該階段必要項即阻擋；後段勾選不改變第一缺口。`production-count` 只顯示勾選數。
- 非法 stage 或 checkbox 狀態清除舊結果與回饋，不以較寬鬆階段的結果代替目前階段。

### 手機與 ARIA

- stage 選擇與八個核取方塊單欄排列；結果六項上下堆疊，`secure boot/OTA evidence` 等長 label 可自然換行。
- 每項有可見 label，原生 checkbox 支援 Space；結果和狀態以 `aria-live="polite"` 更新，不能只用顏色表達 gate。

### 驗收案例

- 預設 DVT：前兩項勾選，第一缺口為 secure boot/OTA evidence，狀態阻擋。
- EVT：只需前兩項；取消第二項即阻擋。
- DVT：補齊前四項才通過；補勾第五項不會改變 DVT 必要集合。
- PVT：前七項全勾才通過；MP：八項全勾才通過，取消 change control 即阻擋。
- 驗證通過回饋仍含良率、認證與出貨限制。

## 8. 機群事件與退役 gate：`fleet-lifecycle`

### 操作流程

1. 以 `lifecycle-case` 選擇 `compromised`（預設）、`certificate-expired`、`lost-device` 或 `retire`。
2. 依固定順序操作八個 `data-lifecycle-check`：`lifecycle-identify`、`lifecycle-quarantine` 預設勾選；`lifecycle-revoke`、`lifecycle-rotate`、`lifecycle-patch`、`lifecycle-verify`、`lifecycle-wipe`、`lifecycle-audit` 預設未勾選。
3. 即時讀取 `lifecycle-first`、`lifecycle-second`、`lifecycle-count`、`lifecycle-blocker`、`lifecycle-status`、`lifecycle-feedback`；用 `data-complete="fleet-lifecycle"` 完成、`data-reset-module="fleet-lifecycle"` 重設。

### 預設與回饋

- gate 順序固定為 identify scope→quarantine→revoke identity→rotate affected credentials→patch→verify recovery→wipe local data→retain audit evidence。
- `compromised` 需 identify/quarantine/revoke/rotate/patch/verify/audit；`certificate-expired` 需 identify/rotate/verify/audit；`lost-device` 需 identify/quarantine/revoke/audit；`retire` 需 identify/revoke/wipe/audit。
- 預設 compromised 第一缺口為 revoke identity，第二缺口為 rotate affected credentials。回饋說明退役要同時處理後端身分與裝置資料，恢復服務前要驗證，不能只看 OTA 任務成功。

### 警告、阻擋與錯誤

- 缺任一目前情境必要項即阻擋；未列為必要項的 checkbox 不得被誤算為缺口，但仍可顯示已勾數量。
- 情境切換重新套用必要集合並清除上一情境 first、second、blocker；非法選項或 checkbox 狀態清除全部舊結果。

### 手機與 ARIA

- 情境與八項清單單欄排列；first、second、count、blocker、status、feedback 分列，退役和 audit 長文字允許換行，390px 不水平溢位。
- 原生 checkbox 支援鍵盤與可見 focus；結果區 `aria-live="polite"`，隔離、撤銷、清除和驗證均以文字呈現，不只靠顏色。

### 驗收案例

- 預設 compromised：前兩項勾選，第一缺口為 revoke identity，狀態阻擋；補齊 identify/quarantine/revoke/rotate/patch/verify/audit 才通過。
- certificate-expired：驗證 rotate、verify、audit 必要，未勾 quarantine 不應被當成該情境缺口。
- lost-device：identify/quarantine/revoke/audit 缺任一即阻擋。
- retire：identify/revoke/wipe/audit 缺任一即阻擋，並確認回饋同時提到後端身分與裝置資料。
- 情境切換後不可殘留上一情境的 blocker；恢復服務的說明必須要求 verify recovery。

## 全站驗收交接

- 驗收需涵蓋八個模組預設值、每個單元重設、即時更新、錯誤輸入清除舊結果，以及 `data-complete`/`data-reset-module` 行為。
- 需特別驗證 OTA 空間不足與單 slot、四種 boot 情境、四種 update 情境、四種 lifecycle 情境、三種 provisioning 情境與四階段 production gate。
- 版面驗收涵蓋 700px 以下頂部橫向導覽與單欄、390px metrics/gate/長字串/選項不溢位；鍵盤、可見 focus、label 與 `aria-live="polite"` 均需可操作。
- 進度儲存鍵固定為 `engineerStudy.iotSecurityProduction.v1`；`progress-label`、`progress-fill`、`reset-progress` 只作全站輔助，不能取代各模組 gate 判準。
