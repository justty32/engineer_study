一句話：微控制器是會依時脈一步步執行指令，並能碰到真實腳位的小電腦

程式不是抽象地「在晶片裡跑」。電源讓電晶體可工作；clock 讓內部狀態按節奏前進；CPU 從 Flash 取得指令、從 SRAM 讀寫資料，再透過周邊控制腳位、計時、通訊與量測。

最後接回 C++變數、pointer、function 與 machine instruction。
01

晶片為什麼一定要有電源與 clock？

電源（power）

VDD 與 GND 建立電位差，讓晶片內數百萬個電晶體能當開關。沒有合法電源，0／1 沒有可靠的電壓意義，CPU 也不能執行。

時脈（clock）

週期性高低切換的訊號，像全晶片共同的「現在更新」節拍。它不提供程式邏輯，而是決定許多內部狀態何時向前一步。

自由實驗：頻率就是每秒幾次

一個週期
注意不等於每秒指令數

48 MHz 不代表每秒一定完成 4,800 萬條 C++ statement。不同指令需不同週期，還有 Flash wait state、bus 等待、中斷與 DMA 競爭。

02

bit、byte、binary、hex 到底是什麼？

bit（位元）是 0 或 1；在電路裡通常由某節點落在哪個電壓範圍表示。8 個 bit 組成 1 byte。hex（十六進位）只是更短的寫法：一個 hex 字元剛好代表 4 bit。

CPU 執行一條指令：取出、看懂、動手

Fetch：依程式計數器找下一條指令

PC（program counter）保存下一條指令的位址。CPU 把位址送上 bus，Flash 回傳那個位置的 machine code。

C++：counter += 1;
可能被編成：LOAD counter → ADD 1 → STORE counter

CPU 不認得變數名稱 counter；linker 已把它變成一個位址。

Pointer 為什麼能碰硬體？

在 MCU 的 memory map 中，某些位址分配給 SRAM，另一些分配給 GPIO、timer 等周邊。因此同樣是 dereference，目標可能是記憶體 cell，也可能是有副作用的硬體 register。

Bus 不是 I²C 那種外接線

這裡的 bus 多指晶片內部共享的位址、資料與控制傳輸網路。I²C/SPI 是 MCU 對外周邊介面；兩者層級不同。

05

Flash、RAM、register 三者不要混在一起

Flash

斷電仍保留。存 machine code、常數與初始資料；通常讀多、寫／擦少。

SRAM／RAM

通電執行時的工作桌。存變數、buffer、stack；斷電內容消失。

Register

有兩種常見意思：CPU register 是核心內的極快工作格；peripheral register 是硬體周邊的控制／狀態介面。

同一個中文「暫存器」可能指 CPU register 或 peripheral register。看到它時一定問：它在 CPU core 裡，還是在某個 GPIO／timer 周邊裡？

06

一條完整因果：程式讓 LED 亮

程式寫 1對 GPIO set register store
→
Bus 選中 GPIO位址解碼
→
輸出 latch 更新硬體記住 HIGH
→
電晶體導通腳位接向 VDD
→
電流形成回路GPIO → R → LED → GND

軟體只決定 register；真正讓 LED 發光的是電源、GPIO driver、限流電阻與閉合電流回路。這就是後面所有韌體知識的共同模型。
