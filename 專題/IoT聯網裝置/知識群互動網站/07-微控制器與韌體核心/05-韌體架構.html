03

Driver API 要描述生命週期

Result sensor_start_read(Buffer& out); // 只啟動，不等待
void   sensor_on_irq();                // 清硬體事件、推進 driver state
Event  sensor_poll_event();            // done / timeout / bus_error
void   sensor_cancel();                // 回到可再啟動的狀態

阻塞 API 何時可以？

啟動階段、短且有界的控制交易，或 RTOS task 明確允許等待時。仍需 timeout，不能永久等旗標。

Callback 的代價

呼叫上下文、重入規則與生命週期容易模糊。事件 queue 或明確 completion object 往往更好測。

04

Superloop、事件迴圈、RTOS 怎麼選

Superloop

最透明、成本低。每個 step 都必須短且不阻塞；適合功能少、時序單純。

Event-driven

用 state machine、timer event、queue 協調多個進行中操作；通常是中型 bare-metal 的甜蜜點。

RTOS

多個獨立 deadline、第三方 stack、阻塞式流程或權責團隊化時有價值；代價是同步、stack 與排程行為。

RTOS 不會自動修好 blocking driver、ISR 太長、共享 buffer 或沒有 timeout。它只是新增 task 與同步的執行模型。

05

C++ 在 MCU 上的實用邊界

RAII可管理短生命期的 lock／critical section；硬體 peripheral 的全域生命期仍要尊重 clock/reset 順序。
Templates可做零成本型別安全 register／pin abstraction；注意 code bloat 與 compile-time 複雜度。
Exceptions是否啟用看工具鏈與產品政策；禁用時 API 必須有一致 error model，不能假裝失敗不存在。
Dynamic allocation可在 startup 建構固定物件池，runtime 禁止無界配置；重點是上限與失敗可分析。
Atomic確認目標架構支援與是否 lock-free；memory order 仍要配合 ISR／DMA 的硬體語意。
Virtual dispatch成本通常可接受但不是免費；介面穩定性、可測性與記憶體預算一起衡量。
