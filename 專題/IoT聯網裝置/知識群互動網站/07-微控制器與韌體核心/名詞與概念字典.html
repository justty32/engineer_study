A

晶片與執行

微控制器（MCU, Microcontroller）

白話：把 CPU、Flash、RAM、GPIO、timer、ADC 與通訊周邊放進同一顆晶片的小電腦。

位置／功能／機制／邊界：位於電路板控制核心，以片內 bus 連接核心、記憶體與周邊；它執行 firmware 並透過 pin 影響外界，但仍需外部供電、時脈條件與必要收發器。Debugger 能證明片內執行，不能單獨證明板外訊號正確。

不要混淆：MPU 通常要外接 DRAM 並跑完整 OS；MCU 常跑 bare-metal 或 RTOS。

CPU／Core（處理器核心）

白話：負責取指令、解碼、運算與 load/store 的部分。

位置／功能／機制／邊界：位於 MCU 內，經 bus 讀取 Flash／RAM／MMIO；program counter 推進指令，例外會改變控制流。Core register 與 trace 可證明執行位置，但 CPU 不直接量類比電壓。

不要混淆：CPU 不是整顆 MCU；GPIO、ADC、DMA 是核心旁邊的周邊硬體。

Clock（時脈）

白話：週期性高低切換的同步節拍，告訴數位電路何時更新狀態。

位置／功能／機制／邊界：由內部 RC、外部晶振或 PLL 產生，經 clock tree 分配到 core 與 peripheral。它決定狀態更新節拍，實際指令時間還受 pipeline、memory wait state 與 bus stall 影響；clock output 或計時基準可量頻率。

不要混淆：clock frequency 不等於 C++ statement 每秒執行數，也不等於 timer 最終頻率。

Instruction／Machine code（指令／機器碼）

白話：CPU 能直接辨認的 bit pattern，例如載入、相加、儲存、跳轉。

位置／功能／機制／邊界：通常存於 Flash，由 CPU fetch、decode、execute；disassembly 與 program counter 可觀察實際路徑。指令只遵守 ISA，不知道 C++ 類別或產品需求。

不要混淆：一行 C++ 可能變成零條、一條或多條機器指令，取決於最佳化與目標架構。

ISA（Instruction Set Architecture，指令集架構）

白話：CPU 對軟體承諾的指令、register、例外與基本執行規則；ARM Cortex-M、RISC-V 都有自己的 ISA。

位置／功能／機制／邊界：它位於硬體與編譯器／作業系統之間的契約層，決定 binary 如何被核心解讀。ELF header 與 disassembly 可確認目標 ISA；同 ISA 晶片仍可能有完全不同的 memory map 與 peripheral。

不要混淆：ISA 是介面規格，不是特定一顆晶片的全部周邊。

Firmware（韌體）

白話：編譯後燒進裝置 Flash，直接管理硬體啟動、周邊、時序與產品功能的軟體。

位置／功能／機制／邊界：image 位於非揮發記憶體，reset 後由 CPU 執行，透過 MMIO 與中斷控制硬體。版本、雜湊與 trace 能證明執行內容；韌體無法補救超出額定值的電氣設計。

不要混淆：它仍是軟體；「韌」不是介於軟硬體之間的特殊物質。

B

記憶體與編譯

Address（位址）

白話：CPU 用來指定「要存取哪個位置」的數字。

位置／功能／機制／邊界：位址由 memory map 解碼到 Flash、SRAM 或 peripheral；CPU 發出 address 加讀寫控制後由目標回應。Map file／debugger 可核對映射；數字合法不表示該區允許目前寬度或權限的存取。

不要混淆：位址不是內容；同一數值資料可以被放在不同位址。

Bus（匯流排）

白話：搬運位址、資料與讀寫控制的共享連接系統。

位置／功能／機制／邊界：片內 bus fabric 連接 master 與 slave，仲裁同時請求並傳遞 transaction；bus matrix 與效能 counter 可觀察壅塞。它只搬資料，不保證上層資料一致性或即時期限。

不要混淆：片內 memory bus 與板外 I²C bus 都叫 bus，但電氣、時序與用途完全不同。

Flash

白話：斷電仍保存的非揮發記憶體，常放程式與常數。

位置／功能／機制／邊界：可在 MCU 片內或外接，以 page program、sector erase 改變儲存電荷。Readback、CRC 與 ECC status 可觀察內容；它有 erase granularity、寫入中斷風險與有限 endurance。

不要混淆：它不是無限次寫入的硬碟；需要先擦除，寫入慢且有磨耗。

SRAM／RAM

白話：程式執行時放變數、buffer、stack 的工作記憶體，斷電消失。

位置／功能／機制／邊界：片內 SRAM 由 CPU／DMA 經 bus 讀寫，保存執行中狀態；linker map、heap 統計與 watermark 可觀察用量。斷電不保存，且不同 bank 可能有 DMA、retention 或速度限制。

不要混淆：MCU 的 RAM 通常很小；成功編譯不代表最壞 stack 一定放得下。

Stack／Heap（堆疊／動態配置區）

白話：stack 自動保存呼叫 frame、區域變數與中斷現場；heap 供 allocator 動態分配。

位置／功能／機制／邊界：兩者由 linker／runtime 劃在 SRAM；呼叫與中斷改變 stack pointer，allocator 管理 heap block。Guard、watermark 與配置統計能找不足；測試峰值不能證明所有遞迴與錯誤路徑安全。

不要混淆：兩者都用 RAM，但生命週期、失敗模式與上限分析不同。

Linker（連結器）

白話：把 object files 與 library 的符號、區段和位址組成最終 firmware image。

位置／功能／機制／邊界：位於 build toolchain 後段，依 linker script 解析符號、配置 section 並產生 ELF／image。Map file 是位置與大小證據；連結成功不代表執行時 stack、硬體位址或初始化邏輯正確。

不要混淆：compiler 決定單個翻譯單元如何變成機器碼；linker 決定它們最後放哪裡。

Vector table（向量表）

白話：一張入口位址表，reset 與各種 exception／interrupt 用它找到 handler。

位置／功能／機制／邊界：通常位於 image 起點或可重定位區，硬體以 exception number 索引 handler address。ELF、memory dump 與 debugger 可核對；表正確仍不保證中斷來源已 enable 或 flag 已清。

不要混淆：它不是 C++ `std::vector`，也不是數學向量。

C

周邊與腳位

Peripheral（周邊）

白話：CPU 旁邊負責特定工作的硬體狀態機，例如 GPIO、UART、timer、ADC。

位置／功能／機制／邊界：位於 MCU 片內、掛在 peripheral bus，以 register 接受設定並獨立推進狀態。Status flag、interrupt 與 pin 波形可觀察結果；周邊不理解應用資料意義。

不要混淆：它不一定在晶片外；MCU 的 peripheral 多半就在晶片內。

Register（暫存器）

白話：少量、固定寬度的狀態格。CPU register 給核心運算；peripheral register 給軟體控制硬體。

位置／功能／機制／邊界：CPU register 位於核心資料路徑；peripheral register 位於周邊介面。讀寫可能啟動轉換、清 flag 或取出 FIFO；debug view 能看當下值，但讀取本身有時會改變狀態。

不要混淆：register 不是普通變數；周邊 register 讀寫可能有硬體副作用。

MMIO（Memory-Mapped I/O）

白話：把周邊 register 分配進 CPU 位址空間，讓 load/store 指令也能操作硬體。

位置／功能／機制／邊界：位於 memory map 的 peripheral 區，address decoder 把 CPU transaction 導向硬體。Bus trace／register view 可核對存取；`volatile` pointer 只保證發出存取，不保證順序、原子性或欄位語意正確。

不要混淆：位址看起來像 pointer，不代表目標是 RAM。

GPIO

白話：可設定成輸入、輸出、類比或交給其他周邊的通用腳位。

位置／功能／機制／邊界：GPIO block 連接片內 bus 與 pad 輸入／輸出級；direction、output latch、input sampler 與 pull 設定共同決定狀態。Register readback 加示波器可交叉驗證；每 pin 與總電流都有上限。

不要混淆：GPIO HIGH 是真實電壓與有限驅動電流，不是抽象 bool。

Pin mux／Alternate function（腳位多工／替代功能）

白話：晶片內部選擇器，決定同一支實體 pin 此刻接 GPIO、UART、SPI、timer 還是 ADC。

位置／功能／機制／邊界：位於 peripheral 與 pad 之間，mux field 選擇訊號來源，pad config 再決定電氣模式。Register 可證明選項，pin 波形證明外部效果；封裝未引出的功能不能靠設定產生。

不要混淆：開了 UART clock 不代表 TX 已接到外部 pin；還要設定 pin mux。

Timer／Counter（計時器／計數器）

白話：跟著時脈或外部脈衝自動加數的硬體，能在指定數值產生事件。

位置／功能／機制／邊界：片內 timer 由 clock／外部 pin 驅動 counter，compare／overflow 產生 interrupt、DMA request 或 PWM。Counter register 與輸出波形可量週期；prescaler、ARR 是否加一及中心對齊規則依晶片而異。

不要混淆：它不是 `sleep()`；CPU 可同時做別的事。

ADC

白話：把輸入電壓相對 Vref 的位置量化成整數 code。

位置／功能／機制／邊界：ADC 周邊在 analog pin 與數位 bus 之間，sample-and-hold 取樣後量化成 code。已知電壓、Vref 與 code histogram 可驗證；輸入範圍、來源阻抗、取樣時間、INL／DNL 與雜訊限制準確度。

不要混淆：更多 bit 不會自動消除雜訊、參考誤差與前端問題。

PWM

白話：固定週期、調整高電位時間比例的數位方波。

位置／功能／機制／邊界：通常由 timer compare 硬體直接驅動 pin，counter 與 threshold 決定 edge。示波器可量 frequency、duty 與 jitter；平均電壓還取決於輸出電位、負載與濾波，不能只由 duty 推出。

不要混淆：PWM pin 不是直接輸出連續類比電壓；負載或濾波器看到平均效果。

D

事件、並行與時間

Polling（輪詢）

白話：CPU 反覆讀硬體狀態，主動問「好了沒」。

位置／功能／機制／邊界：它是 firmware 控制流模式，以迴圈 load status 再判斷。Trace／cycle counter 可量等待成本；若沒有 timeout，硬體永不 ready 會卡住整條流程。

不要混淆：輪詢不一定錯；短、低速、啟動階段可能最簡單可靠。

Interrupt／ISR（中斷／中斷服務常式）

白話：硬體事件要求 CPU 暫停目前流程，跳到指定 handler 處理。

位置／功能／機制／邊界：Peripheral flag 經 interrupt controller 仲裁後讓 core 保存最小現場並查 vector table。Trace 與 debug pin 可量 latency；優先權、masking、巢狀與 handler 長度限制最壞反應。

不要混淆：它不是另一顆 CPU，也不是一般 thread；ISR 仍佔用同一核心。

DMA

白話：專門在周邊與記憶體間搬資料的硬體單元。

位置／功能／機制／邊界：DMA 是片內 bus master，依 descriptor／register 在 request 到來時讀寫地址並更新計數。Count、complete flag 與 buffer 可驗證搬運；可達記憶體、對齊、cache 與 bus bandwidth 都是邊界。

不要混淆：DMA 不理解資料意義，也不免除 buffer ownership、cache 與完成事件管理。

Latency／Jitter（延遲／抖動）

白話：latency 是事件到反應隔多久；jitter 是這段時間每次變動多少。

位置／功能／機制／邊界：它們是事件鏈的時間屬性，會累加 queue、blocking、interrupt masking 與執行時間變異。Timestamp／GPIO trace 可量分布；量測解析度與探針擾動會限制結論。

不要混淆：平均很快不代表最壞 latency 符合 deadline。

Real-time（即時）

白話：結果不只要正確，也要在明確時間限制內完成。

位置／功能／機制／邊界：它是整個系統需求，不是一個元件；deadline、WCET、排程與 blocking 共同決定是否成立。Worst-case analysis 與壓力 trace 提供證據；平均 CPU load 不能證明 hard real-time。

不要混淆：即時不是單純 CPU 很快；可預測的慢系統也可能是即時系統。

Atomic（原子操作）

白話：其他執行流看不到「做到一半」的不可分割操作。

位置／功能／機制／邊界：原子性可由單一硬體指令、exclusive access、短臨界區或資料結構協定提供，範圍必須明確。Race test／trace 可暴露錯誤，但有限測試無法證明所有 interleaving；memory ordering 也是另一層要求。

不要混淆：`volatile` 只影響 compiler 存取，不自動提供 atomicity。

E

啟動、除錯與可靠度

Reset

白話：把 CPU 與一組硬體狀態帶回規格定義的起始條件，再從 reset vector 開始。

位置／功能／機制／邊界：Reset controller 收集 pin、watchdog、software、POR／BOR 等來源，初始化規格指定狀態並重啟控制流。Reset-cause register 與外部 reset pin 可提供證據；retention domain 或外部器件不一定被重置。

不要混淆：reset 不一定切斷電源；power cycle 才是實際斷電重上。

Bootloader

白話：正式應用前先執行的小程式，負責選 image、驗證、更新與恢復。

位置／功能／機制／邊界：通常占用受保護 Flash 區，reset 後先於 application 執行，檢查 metadata／簽章後設定向量表與 stack 再跳轉。Boot log 與選槽紀錄可驗證決策；若信任根可被改寫，驗證鏈就沒有可靠起點。

不要混淆：startup code 建立 C runtime；bootloader 是可選的獨立 firmware 階段。

SWD／JTAG

白話：外部 debugger 與晶片核心溝通的硬體除錯介面，可燒錄、停機、單步與讀記憶體。

位置／功能／機制／邊界：由晶片 debug port 經專用 pin 連到 probe，可控制 core 與存取 debug resources。連線 log、halt PC 與 memory read 是片內證據；halt 會改變 watchdog、bus 與即時互動，量產還需評估鎖定政策。

不要混淆：debugger 看到 register 值，不代表外部腳的類比波形一定正常。

HardFault

白話：Cortex-M 無法正常繼續某些錯誤時進入的 fault handler。

位置／功能／機制／邊界：它是 Cortex-M exception 路徑，fault controller 保存 status，exception entry 將部分 core register 壓入 stack。保存 CFSR／HFSR、stacked PC／LR 與 fault address 可定位；若 stack 已毀或證據被 reboot 清除，handler 名稱不足以找根因。

不要混淆：它不是單一原因；非法位址、bus error、stack 問題等都可能匯入。

Watchdog（看門狗）

白話：若軟體未在期限內證明健康，就強制 reset 的獨立 timer。

位置／功能／機制／邊界：通常使用獨立低速 clock，在期限內未收到合法 refresh 就驅動 reset。Reset cause 與最後 heartbeat 能證明逾時；若卡死程式仍能無條件餵狗，watchdog 就無法代表系統健康。

不要混淆：它是恢復機制，不是 bug 修復；仍需保存 reset cause 與故障證據。

Brown-out reset

白話：電源掉到不可靠區域時先重置核心，避免在電壓不足時亂執行。

位置／功能／機制／邊界：類比電源監測器比較 rail 與門檻，低於規定範圍時保持 reset。示波器對齊 rail、reset 與 reset-cause 可驗證；BOR 門檻、遲滯與反應時間有限，不能吸收能量或保證進行中的非揮發寫入完整。

不要混淆：它不能替代足夠的電源容量、走線與去耦。

CONCEPT

八組最容易混淆的概念

CPU register ≠ peripheral register一個在核心運算資料；一個是硬體周邊的控制／狀態入口。
Clock ≠ timerclock 是節拍來源；timer 是利用節拍自動計數的周邊。
Reset ≠ power cyclereset 回起始狀態但可能仍供電；power cycle 真正切斷再恢復電源。
Interrupt ≠ parallel execution單核心 ISR 只是插入同一條控制流，不是同時多做一件事。
volatile ≠ atomic前者限制 compiler 最佳化；後者保證操作不可被觀察到半成品。
Fast ≠ real-time快是平均效能；即時要求最壞情況仍趕上 deadline。
PWM ≠ DACPWM 是高低方波；DAC 直接產生連續電壓階級。
RS-485 ≠ ModbusRS-485 規定實體電氣；Modbus 規定封包與資料意義。

CPU register／peripheral register 的資料流

指令在 core 內讀寫 CPU register；load/store 經 bus 與 MMIO 才到 peripheral register。Disassembly 與 register view 可分辨位置，外部 pin 波形再證明周邊效果。

Clock／timer 的因果

Clock tree 先提供輸入節拍，prescaler 與 counter 才產生 timer event。量 clock output 與 timer pin 可核對分頻；只讀設定值不能證明來源 clock 正確。

Reset／power cycle 的狀態差

Reset 只初始化指定 domain，外部器件、backup RAM 或 latch 可能保留；power cycle 讓供電降到失效後再上升。量 rail 與 reset cause 才能區分，不可只看開機 banner。

Interrupt／parallel execution 的控制流

單核心從 thread 切入 ISR 再返回，時間線仍只有一條；雙核心或 DMA 才可能真正同時推進。Trace 能看到 nesting，但不代表共享資料已正確同步。

volatile／atomic 的可見性

`volatile` 使每次存取對 compiler 可觀察；atomic 要讓其他執行流看不到中間狀態，可能需硬體指令或臨界區。檢查組譯與競爭測試可提供證據，但語言 memory model 仍要滿足。

Fast／real-time 的結果判準

Fast 比較平均或總吞吐；real-time 比較每筆完成時間是否在 deadline 內。Latency histogram 比平均值有用，hard real-time 還需上界分析。

PWM／DAC 的訊號機制

PWM 在 pin 上交替 HIGH／LOW，DAC 則輸出量化後的近連續電位。示波器可直接區分；萬用電表顯示相同平均值不能證明負載看到相同 ripple。

RS-485／Modbus 的分層

Modbus frame 先成為 UART byte，再由 RS-485 transceiver 轉成 A/B 差動波形。封包擷取證明 protocol，示波器證明 electrical layer；任一層正常都不能替另一層背書。
