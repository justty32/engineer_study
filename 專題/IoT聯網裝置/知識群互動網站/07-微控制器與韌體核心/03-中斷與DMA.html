CHAPTER 03

中斷與 DMA

它們不是「比較快的 callback」，而是硬體事件、控制流與資料所有權的重新安排。

一句話：polling、interrupt、DMA 是三種「誰等待、誰搬資料」

Polling：CPU 主動問硬體。Interrupt：硬體有事才打斷 CPU。DMA：另一個硬體搬運器直接在周邊與 SRAM 間搬資料，完成一批才通知 CPU。

03

DMA：CPU 不搬 byte，但仍負責契約

設定前

來源、目的位址、元素寬度、數量、增量方式、方向與觸發源。

搬運中

DMA 和 CPU 可能同時碰 SRAM／bus；buffer 在完成前通常歸 DMA，CPU 不可任意改。

完成後

半滿／完成／錯誤事件交還 buffer；有 cache 的 MCU 還要處理 cache coherency。

DMA 不等於零成本：短短幾個 byte，設定 DMA 的固定成本可能大於 polling；大批、固定速率、連續取樣才特別划算。
04

共享資料：volatile 不是同步原語

// ISR：只生產事件
rx_buffer[head] = UART->RDR;
head = next(head);          // 發布新資料

// main/task：只消費已發布資料
while (tail != head) consume(rx_buffer[tail]);

單生產者／單消費者

ring buffer 可設計成 ISR 只寫 head、task 只寫 tail；仍要考慮索引存取是否原子、memory ordering 與 overflow 策略。

臨界區

短暫關中斷或用 atomic，讓一組必須不可分割的操作完成。關太久直接增加所有被遮罩中斷的 latency。

05

優先權不是重要程度排行榜

它是在回答「兩個硬體事件同時等待時，誰先取得唯一 CPU」。高優先 ISR 必須更短，且只能呼叫允許在該 interrupt priority 使用的 RTOS API。

Latency事件發生到 ISR 第一條指令的時間。
Jitter同一事件每次實際反應時間的變動。
Preemption高優先 ISR 暫停低優先 ISR。
Pending事件已發生，但尚未獲准執行。
深讀

中斷處理控制流，DMA 處理資料搬運

中斷服務常式（Interrupt Service Routine, ISR）讓 CPU 在事件發生時切換控制流；直接記憶體存取（Direct Memory Access, DMA）讓硬體在周邊與 SRAM 間搬資料。兩者常合作：DMA 搬完一批才發一次 interrupt，CPU 只處理 buffer 邊界與語意。

CPU 成本例

UART 每秒收 100000 B。若每 byte interrupt 的入口與處理共 120 cycles，在 80 MHz CPU 上占用 100000 × 120 / 80×106 = 15% CPU。改為每 256 B 一次 DMA 完成中斷、每批 900 cycles，約需 391 批/s，CPU 約 391 × 900 / 80×106 ≈ 0.44%。假設 DMA 可連續服務、沒有 bus contention，且軟體解析成本另計。

Latency事件到開始處理的時間；受關中斷、高優先 ISR 與入口成本影響。
Throughput長時間搬運量；高 throughput 不保證單筆 latency 小。
OwnershipDMA 寫 buffer 時 CPU 不可把同一區當成完成資料覆寫。
Completionhalf／full／idle event 要明確對應可消費範圍。

證據：以 GPIO 在事件與 ISR 入口翻轉，可用邏輯分析儀量端到端 latency；cycle counter 量 CPU 時間；DMA descriptor 與 buffer dump 核對搬運。看到 DMA complete 只證明搬運條件達成，不代表 byte 沒有 framing error 或上層封包完整。

不要混淆：interrupt ≠ 平行 CPU；DMA ≠ 理解資料；volatile ≠ cache coherency；關中斷保護原子性會同時增加其他事件 latency。
