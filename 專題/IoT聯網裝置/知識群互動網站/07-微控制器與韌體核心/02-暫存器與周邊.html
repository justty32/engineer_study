Memory-mapped I/O：把硬體控制面偽裝成記憶體位址

CPU 發出「對位址 X 寫入數值 Y」；bus decoder 發現 X 屬於某周邊，便把寫入脈衝送到那個硬體 register。這不是普通 RAM：讀可能回報腳位狀態，寫 1 可能清除旗標，某些位元甚至只讀。

03

volatile 能保證什麼，不能保證什麼

它能做的

告訴 compiler：每次 source-level 存取都必須真的發生，值可能被硬體或未知執行流改變，不可只留在暫存器或消掉。

它做不到的

不提供 atomicity、memory ordering、跨核心同步或臨界區；也不能修復資料競態。ISR／DMA 共享資料仍要設計 ownership、原子操作或關中斷區段。

volatile uint32_t *status = (uint32_t*)STATUS_ADDR;
while ((*status & READY) == 0) { /* 每次真的讀硬體 */ }

// volatile 不代表這個 read-modify-write 不會被 ISR 插入
REG = (REG & ~MASK) | value;
04

六個常見 register 語意

R/W可讀可寫；但讀回可能是硬體目前狀態，不一定等於最後寫入。
RO唯讀狀態。寫入通常忽略，也可能是未定義行為。
W1CWrite 1 to Clear：想清哪個旗標就對該 bit 寫 1；寫 0 保持。
Set/Clear register分開的原子置位／清除入口，避免讀改寫競態。
Self-clearing寫 1 啟動動作，硬體完成後自己清零。
Read-to-clear讀取本身會消耗／清除事件；debugger 自動讀也可能改變現場。

周邊不動時，依相反方向查：enable bit → clock → pin mux → 實體腳電壓 → reset／電源，而不是重寫整個 driver。

深讀

MMIO 是位址介面；讀寫動作可能就是硬體命令

記憶體映射輸入輸出（Memory-Mapped I/O, MMIO）把周邊 register 放進 CPU 位址空間，因此 load/store 指令可設定硬體。但 register 不是普通 RAM：有些 bit 是唯讀狀態，有些寫 1 清除（write-one-to-clear, W1C），有些讀取會彈出 FIFO，還可能有保留位元必須維持規定值。

Read-modify-write 的陷阱

若要設定 bit 3，常見程式是先讀整個 register、OR 0x08、再寫回。假設同一 register 的 bit 0 是 W1C 且當下為 1，讀回後再原樣寫 1 會意外清除事件。安全作法由 reference manual 決定：可能有 SET／CLEAR 專用 register、只寫目標 mask，或需臨界區保護。`volatile` 讓 compiler 實際發出存取，卻不保證多步驟原子性，也不理解 W1C 語意。

Clock gate先供給周邊時脈；否則寫入可能無效或讀到 reset 值。
Pin mux把內部周邊訊號接到指定實體 pin；開 UART 不等於 pin 已切換。
Configuration設定方向、速度、模式與參數。
Status／flag讀取硬體進度，依規定方式清除。

可觀察證據：Debugger peripheral view 可核對 register 值，但停機可能凍結 timer 或錯過 race；邏輯分析儀／示波器能證明 pin 上的結果，卻不能指出是 clock gate、mux 還是 register 欄位寫錯。兩邊對照才形成完整因果鏈。
