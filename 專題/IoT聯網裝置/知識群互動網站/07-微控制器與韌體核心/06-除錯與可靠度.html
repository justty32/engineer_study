04

Watchdog、brown-out 與 reset cause

Watchdog

獨立計時器到期就 reset。餵狗必須代表整個系統健康，不是任一高頻 ISR 還活著就餵。

Brown-out reset

電源掉到 CPU 不再可靠的區域前主動 reset。它能避免亂跑，但不能替你補足電源與去耦。

Reset cause

上電第一時間保存 POR、BOR、watchdog、software reset 等旗標；清除前寫入持久 log。

自動重開只恢復服務，不等於修好。沒有 reset cause、最後事件與版本資訊，watchdog 會把可重現 bug 變成「偶爾自己好了」。

深讀

先保存故障現場，再談自動重啟

可靠度不是「不會壞」，而是能偵測錯誤、限制影響、留下證據並回到已知狀態。HardFault、watchdog、brown-out reset（BOR）、stack overflow 與更新中斷可能最後都表現成 reboot；若啟動時不保存 reset cause、fault register、stacked PC/LR 與軟體版本，重啟會把最有價值的證據洗掉。

Watchdog健康證明逾時就 reset；餵狗應代表整條關鍵路徑完成，不是由 timer ISR 無條件餵。
HardFault是多種 fault 的匯流點；要解碼 fault status 與 fault address，不能把 handler 名稱當根因。
BOR低電壓時阻止不可靠執行；不能修好電源路徑或保證 Flash 寫入原子性。
A/B update保留已知可開機映像，經健康確認才承認新版本；rollback 與 anti-rollback 的安全政策要協調。

故障注入才是復原機制的測試

操作 → 在設定寫入、image erase、metadata 切換或首次啟動時斷電 → 儲存狀態停在任意中間點 → 重上電後只能讀到舊版或完整新版 → 由 CRC／版本／commit marker 可見。一次正常寫入不能證明 atomicity；必須在不同時間點重複注入。

若 3.3 V rail 在 radio 發射時降到 BOR threshold 以下，示波器能證明電源事件與 reset pin／電流脈衝相關；reset cause 能證明 MCU 判為 brownout。兩者缺一時，不能只憑 log 最後一行推斷 root cause。Debugger 停機適合看記憶體，但可能讓 watchdog、peripheral 與即時互動改變，因此現場問題優先保留非侵入式 trace。

不要混淆：reset ≠ power cycle；watchdog recovery ≠ bug 已修；CRC ≠ 防惡意竄改；assert ≠ 完整錯誤處理；測試通過 ≠ 未測的時序交錯安全。
