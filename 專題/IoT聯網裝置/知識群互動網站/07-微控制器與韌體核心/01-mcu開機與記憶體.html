一句話模型：MCU 是一顆自帶記憶體與硬體服務的電腦

MCU（microcontroller）把 CPU core、非揮發 Flash、揮發 SRAM、clock/reset 與 GPIO、timer、ADC、通訊周邊放在同一顆晶片。CPU 仍只會取指、解碼、執行與 load/store；「量電壓」「送 UART」其實由旁邊的專用硬體狀態機做。

MCU vs MPU

MCU：內建 SRAM/Flash，通常 bare-metal 或 RTOS，啟動快、資源小、直接碰周邊。

MPU：多需外接 DRAM/儲存，通常有 MMU 並跑 Linux 等完整 OS。

「32-bit MCU」說的是什麼？

通常指核心暫存器與主要資料路徑寬度；不代表 ADC 是 32-bit，也不保證每次 memory access 都同寬。

02

Reset 到 main()：一步一步發生什麼

Reset：CPU 還沒跑 main

硬體把核心帶回已知狀態，從向量表第 0 項載入初始 SP、第 1 項載入 Reset_Handler。

C++ 特別注意：跨 translation unit 的全域初始化順序仍有風險；而且建構子若操作尚未開 clock 的周邊，比桌面程式更容易直接 fault。

03

記憶體區段不是術語表，而是兩種實體記憶體的搬運契約

Flash：vector table → .text → .rodata → .data 初始映像斷電後保留；讀快、寫／擦慢且有壽命。
SRAM：.data → .bss → heap … stack上電內容不保證；快但容量小，斷電消失。

04

stack、heap 與 linker script：嵌入式版的資源所有權

Stack

函式 frame、中斷自動保存、區域變數。最壞深度取決於 call chain、ISR 巢狀與 library；不是平均值。

Heap

不是不能用，而是必須知道 allocator、碎片、失敗路徑與即時上限。許多產品在啟動後不再配置。

Linker script

把區段放到指定 Flash/RAM 位址，定義 vector、bootloader、App、設定區與符號。它是硬體 memory map 與程式映像的契約。

FLASH (rx)  : ORIGIN = 0x08000000, LENGTH = 128K
RAM   (rwx) : ORIGIN = 0x20000000, LENGTH = 64K

.text  → FLASH
.data  → RAM，初始內容保存在 FLASH
.bss   → RAM，startup 清零
深讀

Reset 後不是直接進 main：先建立 C 執行環境

以常見 Cortex-M 為例，reset 後硬體先從向量表（vector table）取得初始 stack pointer 與 reset handler 位址。startup code 設定時脈與必要硬體、把 Flash 中的 .data 初值複製到 SRAM、把 .bss 清為 0，之後才呼叫 main。Bootloader 若存在，會在 application 前選映像、驗證並跳轉；它和 startup code 是不同角色。

.text／.rodata程式碼與唯讀常數通常留在 Flash，斷電保存。
.data有非零初值的可寫變數；初值在 Flash，執行副本在 SRAM。
.bss零初始化變數；通常只在 image 記大小，開機時清零。
stack／heap共用有限 SRAM，但生命週期與失敗方式不同。

容量算例

MCU 有 64 KiB SRAM；.data 6 KiB、.bss 18 KiB、各 task stack 合計 24 KiB、heap 預留 8 KiB，名義剩餘 64 − 6 − 18 − 24 − 8 = 8 KiB。這只是靜態預算，未含對齊、RTOS control block、DMA 專用區與最壞呼叫深度。Linker map 能證明區段配置；stack watermark 只能證明測試期間的峰值，不能涵蓋未走過的錯誤路徑。

因果證據：修改 linker script → section 位址改變 → image layout 改變 → map／ELF 可見；若位址超出實際 SRAM，可能在 startup copy 或首次存取時 fault。Debugger 停在 main 只能證明啟動已走到這裡，不能證明所有初始化值與 clock 都正確。
