# IoT 天線、RF、EMC 與法規邊界：互動題型草案

← [專案簡報](PROJECT-BRIEF.md)｜[建置規格](BUILD-SPEC.md)｜[A1 天線理論](../../../../電機/08-天線特化/A1-天線理論.md)｜[A2 微波工程](../../../../電機/08-天線特化/A2-微波工程.md)｜[A3 傳輸線與波導](../../../../電機/08-天線特化/A3-傳輸線與波導.md)

> 本檔只描述互動題型、學習回饋與驗收方式。`BUILD-SPEC.md` 是唯一執行契約；不得新增 DOM ID、改動選項集合、預設值、公式或判斷門檻。

## 共通互動原則

- 八個單元使用 `data-module`、`data-nav`、`data-complete`、`data-reset-module`，模組鍵固定為 `wave-region`、`link-budget`、`impedance-match`、`rf-layout`、`antenna-choice`、`detuning`、`edge-emi`、`compliance`。
- 數值欄位、`select`、核取方塊與按鈕均使用原生控制項；每個欄位有可見 `label`，按鈕使用 `type="button"`。
- 控制值變更後立即重算並更新結果。空值、非數字、`NaN`、`Infinity`、除零、負值或不合法選項必須清除該模組的舊結果與狀態，不能沿用上一次結果。
- 狀態以固定符號、文字、邊框與顏色共同表達；結果與回饋區使用 `aria-live="polite"`，不能只靠顏色判斷。
- 每個模組提供單元重設，恢復 `BUILD-SPEC.md` 的預設值；整體進度只作輔助，不限制跨單元瀏覽。

## 1. 波長、電氣長度與遠場：`wave-region`

### 操作流程

1. 以數值欄位輸入 `wave-frequency-mhz`、`wave-epsilon-eff`、`wave-trace-mm`、`wave-size-mm`、`wave-distance-mm`。初始值依序為 `2400`、`4`、`50`、`80`、`1000`。
2. 讀取 `wave-free-wavelength` 與 `wave-guided-wavelength`，比較自由空間與板上有效介質中的波長。
3. 讀取 `wave-phase`，把 `wave-trace-mm` 轉成傳輸線上的相位長度；再讀取 `wave-far-boundary` 與 `wave-region-verdict`，判斷 `wave-distance-mm` 是否在遠場邊界之外。
4. 透過 `data-complete="wave-region"` 完成單元；`data-reset-module="wave-region"` 恢復初始值。

### 計算與初始回饋

- 嚴格使用：\(\lambda_0=c/f\)、\(\lambda_g=\lambda_0/\sqrt{\varepsilon_{eff}}\)、`phase = 360ℓ/λg`、\(r_F=2D^2/\lambda_0\)。長度與頻率單位需依規格換算成一致單位後再代入。
- 初始結果約為 `124.91 mm`、`62.46 mm`、`288.2°`、`102.47 mm`；觀測點判為遠場。`wave-status` 應明確說明結果是幾何與近似模型的判讀。
- `wave-feedback` 說明有效介電常數會縮短導波波長，且遠場公式只用最大尺寸 `D` 做粗分區域，不代表量測場地已符合標準。

### 警告與阻擋

- `wave-frequency-mhz`、`wave-epsilon-eff` 必須大於零；其他數值必須非負。任一不合規時清除所有輸出 ID：`wave-free-wavelength`、`wave-guided-wavelength`、`wave-phase`、`wave-far-boundary`、`wave-region-verdict`、`wave-status`、`wave-feedback`。
- 輸入本身不設額外警告門檻；輸出若落在近場，回饋應以警告或阻擋文字指出不宜套用遠場觀察結論，但不得捏造超出規格的數值門檻。

### 手機呈現與可及性

- 700px 以下採單欄：輸入區、波長結果、相位結果、遠場結果、回饋依序排列；390px 時每個 metric 上下堆疊，單位可換行但不得水平溢位。
- 數值輸入以可聚焦原生欄位呈現，label 與欄位一一對應；結果區以 `aria-live="polite"` 更新，`wave-status` 文字不只用顏色表示。
- 鍵盤可用 Tab 依輸入順序操作，以 Enter 或空白鍵觸發完成/重設按鈕；focus 必須可見，結果更新不可自動搶焦點。

### 驗收案例

- 預設值：四個主要結果接近規格值，`wave-region-verdict` 為遠場。
- 參數實驗：把 `wave-trace-mm` 從 `50` 改為 `25`，`wave-phase` 即時減半；把 `wave-epsilon-eff` 改為 `1`，`wave-guided-wavelength` 應等於 `wave-free-wavelength`。
- 錯誤診斷：把 `wave-frequency-mhz` 清空或設為 `0`，所有舊輸出清除，並以文字指出頻率/介電常數必須大於零。
- 邊界理解：增大 `wave-distance-mm` 至遠場邊界以上，結果只改變區域判讀；回饋仍保留「粗分區域、不等於量測合規」的限制。

## 2. 自由空間鏈路預算：`link-budget`

### 操作流程

1. 依序輸入 `link-tx-dbm`、`link-tx-gain-dbi`、`link-rx-gain-dbi`、`link-loss-db`、`link-frequency-mhz`、`link-distance-km`、`link-sensitivity-dbm`、`link-required-margin-db`；初始值依規格為 `10`、`2`、`2`、`2`、`2400`、`0.1`、`-95`、`10`。
2. 讀取 `link-fspl`、`link-received`、`link-margin` 與 `link-headroom`，先看接收功率，再看相對 sensitivity 的餘裕與扣除需求餘裕後的 headroom。
3. 以 `link-status` 和 `link-feedback` 判斷是否可通過教學 gate；`data-complete="link-budget"` 與 `data-reset-module="link-budget"` 分別完成/重設。

### 計算與初始回饋

- 嚴格使用：\(FSPL=32.44+20\log_{10}(f_{MHz})+20\log_{10}(d_{km})\)；\(P_R=P_T+G_T+G_R-L-FSPL\)；`margin = PR − sensitivity`；`headroom = margin − required margin`。
- 初始結果約為 `80.04 dB`、`-68.04 dBm`、`26.96 dB`、`16.96 dB`，狀態為通過。
- `link-feedback` 必須說明 Friis/自由空間模型不含多徑、遮蔽、干擾、封包重送與實際天線效率；理論 headroom 不等於現場覆蓋保證。

### 警告與阻擋

- `link-frequency-mhz`、`link-distance-km` 必須大於零；`link-loss-db`、`link-required-margin-db` 必須非負；其他欄位必須為有限數。錯誤時清除四個計算輸出與狀態／回饋。
- `link-headroom < 0` 為阻擋，回饋指出鏈路預算不足，不能用理論覆蓋解釋為可交付。
- `0 ≤ link-headroom ≤ 3 dB` 為警告，指出餘裕偏低，應重新檢查損耗、天線增益、遮蔽與重送需求；大於 `3 dB` 才可顯示教學上的通過。

### 手機呈現與可及性

- 八個輸入單欄排列；四個結果以垂直 metric 呈現，單位跟在數值旁並允許換行，`link-feedback` 放在狀態下方。
- 所有輸入 label 明示 dBm、dBi、dB、MHz、km 等單位；`link-status` 與 `link-feedback` 使用 `aria-live="polite"`，警告/阻擋均有文字。
- 以 Tab 依欄位順序操作，數值欄位可直接輸入；完成、重設按鈕可由 Enter/空白鍵觸發，focus 不因即時重算消失。

### 驗收案例

- 預設值：四個輸出接近規格值且 `link-status` 為通過。
- 警告：將 `link-required-margin-db` 調高，使 `link-headroom` 落在 `0–3 dB`，狀態改為警告且回饋指出低餘裕。
- 阻擋：將 `link-distance-km` 調大到使 `link-headroom < 0`，狀態改為阻擋，不能沿用原本的通過文字。
- 錯誤診斷：清空 `link-frequency-mhz` 或輸入 `0`，所有舊 FSPL、接收功率、margin、headroom 清除。
- 跨層取捨：增加 `link-loss-db` 後 headroom 下降；回饋仍提醒現場多徑與遮蔽不能由 FSPL 單獨估計。

## 3. 阻抗失配：`impedance-match`

### 操作流程

1. 輸入 `match-z0`、`match-r`、`match-x`，初始值為 `50 Ω`、`75 Ω`、`0 Ω`。`match-x` 允許正負有限值，以表達電抗方向。
2. 讀取 `match-gamma`、`match-return-loss`、`match-vswr`、`match-reflected-power`、`match-loss`，從複數負載阻抗逐層觀察反射、駐波與功率損失。
3. 以 `match-status`、`match-feedback` 讀取 VSWR gate；`data-complete="impedance-match"` 完成，`data-reset-module="impedance-match"` 重設。

### 計算與初始回饋

- 對 \(Z_L=R+jX\)，嚴格使用：\(|\Gamma|=|Z_L-Z_0|/|Z_L+Z_0|\)；`RL = −20 log10 |Γ|`；`VSWR = (1+|Γ|)/(1−|Γ|)`；反射功率 `= |Γ|²`；失配損耗 `= −10 log10(1−|Γ|²)`。
- 初始結果為 `0.200`、`13.98 dB`、`1.50`、`4.00%`、`0.18 dB` 左右。
- 完美匹配的 return loss 顯示 `∞`；完全反射的 VSWR/loss 顯示 `∞`，但不得把 `Infinity` 寫進數值結果欄。`match-feedback` 必須說明良好 S11/低失配不等於高輻射效率。

### 警告與阻擋

- `match-z0 > 0`、`match-r ≥ 0`、`match-x` 必須為有限數；錯誤時清除五個計算結果及 `match-status`、`match-feedback`。
- `VSWR ≤ 2` 為通過；`2 < VSWR ≤ 3` 為警告；`VSWR > 3` 為阻擋。阻擋回饋要指出反射與匹配網路檢查，不以單一良好頻點推論整個頻帶。

### 手機呈現與可及性

- 三個輸入單欄排列；複數阻抗用兩個獨立欄位，不使用寬表格；五個 metric 上下堆疊，百分比、dB 與 `∞` 可自然換行。
- label 需標出 `Z0`、`R`、`X` 與 Ω；status/feedback 使用 `aria-live="polite"`，`∞` 同時提供文字語意，不讓符號成為唯一資訊。
- 原生數值欄位可由鍵盤輸入；Tab 順序為 Z0、R、X、結果、完成、重設；按鈕支援 Enter/空白鍵且保持可見 focus。

### 驗收案例

- 預設值：結果接近 `0.200 / 13.98 dB / 1.50 / 4.00% / 0.18 dB`，狀態為通過。
- 參數實驗：把 `match-r` 改成 `50` 且 `match-x=0`，反射功率與失配損耗為零，return loss 顯示 `∞`，VSWR 為 `1`。
- 完全反射：令 `match-r=0`、`match-x=0`，VSWR/loss 顯示 `∞`，不得出現字串 `Infinity` 於數值結果。
- 門檻：調整 R/X 使 VSWR 落入 `2–3` 與大於 `3`，分別驗證警告與阻擋。
- 錯誤診斷：`match-z0=0` 或任一欄為空，清除所有舊結果。

## 4. RF 饋線與 layout gate：`rf-layout`

### 操作流程

1. 以 `layout-case` 選擇 `pcb`（預設）、`chip` 或 `external`。
2. 依固定順序操作七個 `data-layout-check` 核取方塊：`layout-impedance`、`layout-ground`、`layout-short`、`layout-vias`、`layout-pi`、`layout-keepout`、`layout-guideline`。預設只有前四項勾選。
3. 讀取 `layout-first`、`layout-second`、`layout-count`、`layout-blocker`，再由 `layout-status` 與 `layout-feedback` 判斷 gate。
4. 以 `data-complete="rf-layout"` 完成，`data-reset-module="rf-layout"` 依契約恢復情境與勾選狀態。

### 初始回饋

- 固定 gate 順序必須是：controlled impedance → continuous ground → short/no stub → ground vias/connector launch → π match → antenna keep-out → vendor/module guideline。
- 初始 `pcb` 情境只完成前四項，`layout-first` 應指出 π match 是第一個缺口，`layout-second` 指出其後缺口，`layout-count` 反映實際勾選數，狀態為阻擋。
- 回饋指出實際線寬、間距與 via 由板廠疊層及模組 guideline 決定；不能把 checkbox 通過當成已完成阻抗計算或實體驗證。

### 警告與阻擋

- PCB 與 chip 天線情境七項皆必要；external 不要求 `layout-keepout`，仍要求其餘六項。缺任一必要項即阻擋，不以 `layout-count` 抵銷。
- 此 gate 沒有獨立的可通過但低信心警告門檻；缺項一律以 `layout-blocker` 與 `layout-status` 明確報阻擋。非法 `layout-case` 或 checkbox 狀態應清除舊結果。

### 手機呈現與可及性

- `layout-case` 單欄；七個 checkbox 每項獨立成列，label 可換行；結果依 `first`、`second`、`count`、`blocker`、`status`、`feedback` 上下排列。
- 核取方塊使用原生 keyboard semantics，label 點擊區需涵蓋文字；結果區 `aria-live="polite"`，阻擋文字不只用紅色表示。
- Tab 先到情境選擇，再依 gate 順序到核取方塊，最後到完成/重設；Space 切換 checkbox，Enter/Space 觸發按鈕，focus 可見。

### 驗收案例

- 預設 PCB：前四項勾選，第一缺口為 π match，狀態阻擋。
- PCB 全勾：七項勾選後才可通過；取消任何一項，第一缺口要回到固定順序中的該項。
- Chip 情境：七項仍全部必要，`layout-keepout` 不能被自動忽略。
- External 情境：`layout-keepout` 不列為必要缺口，但其他六項缺任一仍阻擋。
- 取捨診斷：勾選後面項目而取消前面項目，`layout-count` 可以增加/減少，但不能改變第一缺口的 gate 順序。

## 5. 天線型式初篩：`antenna-choice`

### 操作流程

1. 以五個 `select` 輸入條件：`antenna-enclosure`（`plastic` 預設，另有 `metal`）、`antenna-space`（`tiny` 預設，另有 `roomy`）、`antenna-cert`（`reuse` 預設，另有 `custom`）、`antenna-tuning`（`limited` 預設，另有 `vna`）、`antenna-cost`（`low` 預設，另有 `flexible`）。
2. 每次選擇即時更新 `antenna-verdict`、`antenna-runner-up`、`antenna-tradeoff`、`antenna-status`、`antenna-feedback`。
3. 由首選、備選與取捨回推機構、認證、調諧和成本限制；`data-complete="antenna-choice"` 完成，`data-reset-module="antenna-choice"` 重設。

### 初始回饋與固定決策

- 預設條件的首選 `antenna-verdict` 是「認證清單內的外接天線」，`antenna-runner-up` 是「晶片天線」；取捨應指出有限調諧能力與認證重用優先於小體積。
- 嚴格依序套用：metal enclosure → 認證清單內的外接天線；reuse+limited → 認證清單內的外接天線；tiny+VNA → 晶片天線；roomy+VNA+low → PCB 天線；limited → 外接天線；tiny → 晶片天線；其餘 → PCB 天線。
- `antenna-feedback` 必須說明所有結果只是初篩，仍須核對頻段、效率、機構、線纜損耗、天線清單與實測。

### 警告與阻擋

- 這是選型初篩，不以首選結果宣稱認證或性能通過；`antenna-status` 應保持「初篩」語意。
- 選項缺值或不在契約集合時清除五個結果，並以文字指出無效條件；不要以預設值代替錯誤選項。
- 規格沒有另設數值警告/阻擋門檻；真正送測前的頻段、效率、機構與實測缺口要在回饋中標示為待確認，而非假造 gate 結果。

### 手機呈現與可及性

- 五個 select 單欄排列，選項文字不可用省略號截斷；首選、備選、取捨、狀態、回饋各自為上下結果列。
- 每個 select 有可見 label，使用原生選單鍵盤操作；結果/狀態使用 `aria-live="polite"`，初篩限制以文字明示。
- Tab 依機構、空間、認證、調諧、成本順序；原生 select 支援方向鍵選項，完成與重設按鈕支援 Enter/Space。

### 驗收案例

- 預設值：首選外接天線、備選晶片天線，狀態明示初篩。
- 參數取捨：選 `metal` enclosure，首選必為認證清單內的外接天線；選 `tiny` + `vna`，首選必為晶片天線。
- 另一條件：選 `roomy` + `vna` + `low`，首選必為 PCB 天線；修改成本為 `flexible` 後不得沿用前一結果。
- 錯誤診斷：移除/設定非法 option 時清除 verdict、runner-up、tradeoff 與舊回饋。
- 邊界理解：任何首選結果都必須伴隨頻段、效率、機構、線纜、清單與實測的限制說明。

## 6. 介質負載與失諧：`detuning`

### 操作流程

1. 輸入 `detune-frequency-mhz`、`detune-epsilon-before`、`detune-epsilon-after`、`detune-bandwidth-mhz`；初始值為 `2400`、`2.5`、`3.2`、`100`。
2. 讀取 `detune-new-frequency`、`detune-shift-mhz`、`detune-shift-percent`，再以 `detune-band-edge` 比對原始可用頻帶 \(f_0\pm BW/2\)。
3. `detune-status` 顯示是否落在原頻帶內，`detune-feedback` 說明介質負載方向與模型限制；使用 `data-complete="detuning"` 完成，`data-reset-module="detuning"` 重設。

### 計算與初始回饋

- 嚴格使用簡化固定幾何模型：\(f_{new}=f_0\sqrt{\varepsilon_{before}/\varepsilon_{after}}\)；`shift = new − original`；原可用頻帶為 \(f_0\pm BW/2\)。
- 初始結果約為 `2121.32 MHz`、`-278.68 MHz`、`-11.61%`，並判定落在原頻帶外、狀態阻擋。
- 回饋要說明外殼、電池或人體改變附近介質可能使共振下降；此模型只顯示方向與敏感度，不能取代 VNA、暗室、OTA 或整機調諧。

### 警告與阻擋

- frequency、兩個 epsilon、bandwidth 都必須大於零；錯誤時清除四個輸出及 status/feedback。
- 新頻率落在原頻帶外為阻擋；落在原頻帶內可顯示通過，但仍保留模型近似限制。規格未另外定義警告區間，不自行新增門檻。

### 手機呈現與可及性

- 四個輸入單欄排列；new frequency、shift、百分比與 band edge 垂直堆疊，MHz 與百分比可換行；回饋不與結果同列。
- label 明確標示 before/after 與 MHz；`detune-status`、`detune-feedback` 使用 `aria-live="polite"`，阻擋文字同時包含原因與後續實測限制。
- Tab 順序依四個參數排列；數值欄位支援鍵盤編輯，完成/重設按鈕支援 Enter/Space，不讓即時更新搶走 focus。

### 驗收案例

- 預設值：結果接近 `2121.32 MHz / -278.68 MHz / -11.61%`，band edge 比對為頻帶外、阻擋。
- 參數實驗：令 `detune-epsilon-after` 等於 `detune-epsilon-before`，新頻率等於原頻率、shift 為零；增加 after epsilon 時 new frequency 下降。
- 頻帶邊界：調整 bandwidth 足以包住新頻率時，狀態不再以頻帶外阻擋，但回饋仍保留模型限制。
- 錯誤診斷：`detune-bandwidth-mhz=0` 或空值時清除舊結果，不得沿用先前的阻擋/通過文字。

## 7. Edge rate 與 EMI 邊界：`edge-emi`

### 操作流程

1. 輸入 `edge-rise-ns`、`edge-epsilon-eff`、`edge-trace-mm`；初始值為 `2`、`3.5`、`80`。
2. 讀取 `edge-knee-frequency`、`edge-guided-wavelength`、`edge-critical-length`、`edge-length-ratio`，以走線長度和臨界長度比較是否進入需以傳輸線/回流處理的範圍。
3. 讀取 `edge-verdict`、`edge-status`、`edge-feedback`；以 `data-complete="edge-emi"` 完成，`data-reset-module="edge-emi"` 重設。

### 計算與初始回饋

- 嚴格使用教學判準：\(f_{knee}=0.5/t_r\)；\(\lambda_g=c/(f_{knee}\sqrt{\varepsilon_{eff}})\)；`critical length = λg/10`；`ratio = trace/critical`。
- 初始結果約為 `250.0 MHz`、`641.0 mm`、`64.1 mm`、`1.25`；ratio 落在 `≥1` 的警告區，需以傳輸線/回流觀點處理。
- `edge-feedback` 必須指出關鍵是 edge rate，不是標稱 clock；分割地、迴路面積與外接線仍須另查。

### 警告與阻擋

- rise、epsilon 必須大於零，trace 必須非負；錯誤時清除全部輸出與 status/feedback。
- `edge-length-ratio ≥ 1` 為警告，回饋提醒檢查阻抗、回流與邊緣控制；`edge-length-ratio ≥ 2` 為阻擋，指出不可再以集中參數直覺處理。`ratio < 1` 可通過教學 gate，但不代表 EMI 已合規。

### 手機呈現與可及性

- 三個數值欄位單欄排列；四個 metric 使用垂直結果列，MHz、mm、ratio 可自然換行；verdict/status/feedback 分開以免長文擠壓。
- label 明示 rise time、有效介電常數與 trace length 的單位；`edge-status`、`edge-feedback` 使用 `aria-live="polite"`，警告/阻擋同時顯示符號和文字。
- Tab 依三個輸入、結果、完成、重設順序；所有按鈕可用 Enter/Space，結果更新不搶焦點；支援 `prefers-reduced-motion` 時不依動畫傳達狀態。

### 驗收案例

- 預設值：結果接近 `250.0 MHz / 641.0 mm / 64.1 mm / 1.25`，狀態為警告。
- 參數實驗：將 `edge-trace-mm` 改為 `0`，ratio 為 `0` 且不應警告；將 rise time 減半，knee frequency 應加倍。
- 阻擋：增加 `edge-trace-mm` 至 ratio `≥2`，狀態改為阻擋，回饋指出傳輸線與回流檢查。
- 錯誤診斷：`edge-rise-ns=0` 或 epsilon 空值時清除舊結果。
- 跨層判斷：回饋中搜尋/閱讀到的是 edge rate 而非標稱 clock，並保留分割地、迴路面積、外接線待查提示。

## 8. 預認證與整機法規 gate：`compliance`

### 操作流程

1. 以 `compliance-case` 選擇 `same-integration`（預設）、`antenna-change`、`enclosure-change` 或 `new-market`；以 `compliance-near-body` 選擇 `no`（預設）或 `yes`。
2. 依固定順序操作七個 `data-compliance-check` 核取方塊：`compliance-market`、`compliance-module-scope`、`compliance-antenna-list`、`compliance-rf-prescan`、`compliance-emc-prescan`、`compliance-sar`、`compliance-docs`。預設勾前三項。
3. 讀取 `compliance-first`、`compliance-second`、`compliance-count`、`compliance-blocker`，最後看 `compliance-status` 與 `compliance-feedback`。
4. 以 `data-complete="compliance"` 完成，`data-reset-module="compliance"` 重設情境、near-body 與 checkbox 狀態。

### 初始回饋與固定 gate

- 固定順序為 market → module scope → antenna list → RF prescan → EMC prescan → SAR → docs；第一缺口必須優先回報，後面勾選不得抵銷前面缺口。
- 預設 `same-integration`、`near-body=no` 且前三項勾選時，`compliance-first` 應為 EMC prescan，`compliance-second` 應為文件／標示，狀態阻擋；RF prescan 在此情境不是必要 gate。
- `same-integration` 必須有 market/module scope/antenna list/EMC prescan/docs；`antenna-change`、`enclosure-change`、`new-market` 另需 RF prescan；`near-body=yes` 一律另需 SAR/暴露評估。
- 全部該情境必要項目完成時只能顯示「送測前 gate 閉合」；`compliance-feedback` 必須說明這不是認證、法律意見或主管機關核准。

### 警告與阻擋

- 缺任一情境必要項即阻擋，`compliance-blocker` 必須指出具體缺口；不以 `compliance-count` 總數抵銷。
- 情境切換或 near-body 切換後，重新套用規格的必要項與順序，清除不再適用的 first/second/blocker 舊文字。
- 選項非法或 checkbox 狀態不可讀時清除所有輸出；不得把前三項勾選直接視為整機通過。

### 手機呈現與可及性

- 情境與 near-body 單欄；七個 gate checkbox 單欄顯示，label 可換行；first、second、count、blocker、status、feedback 依序上下排列。
- 原生 select/checkbox 提供鍵盤語意；label 點擊可操作，結果區 `aria-live="polite"`；「送測前 gate 閉合」與「不是認證」都必須以文字呈現。
- Tab 順序為 case、near-body、七個 gate、完成、重設；Space 切換核取方塊，Enter/Space 觸發按鈕，focus 可見；不使用水平 gate 表格。

### 驗收案例

- 預設情境：same-integration/no，前三項勾選，第一缺口 EMC prescan、第二缺口文件／標示，狀態阻擋。
- same-integration 完成：勾 market、module scope、antenna list、EMC prescan、docs，應顯示送測前 gate 閉合；RF prescan 非此情境必要項，不應被誤列為阻擋。
- antenna-change：除前三項與 EMC/docs 外，RF prescan 未勾時必須阻擋；勾上後才可進入下一缺口。
- enclosure-change 與 new-market：分別切換驗證都要求 RF prescan；切回 same-integration 時 first/second/blocker 重新計算。
- near-body：在任一情境選 `yes`，`compliance-sar` 未勾即阻擋；勾上後仍須完成該情境其他必要項。
- 錯誤診斷：切換情境時不可保留上一情境的通過文字；所有通過結果都要保留「非認證/法律意見/主管機關核准」限制。
