01・從檔案變成可管理的執行實例

行程是什麼：程式跑起來後的完整現場

磁碟上的程式只是靜態檔案；載入後，OS 還要記住它的記憶體、CPU 狀態與開啟資源。這個可排程、可隔離的執行實例就是行程（process）。

這章假設已懂：00 OS 的抽象、共享與隔離。

白話直覺與精確定義

食譜像程式（program），正在做菜的廚房現場像行程；同一份食譜可以同時有兩個不同現場。精確地說，行程包含程式碼、資料與虛擬位址空間，以及 PID、暫存器、狀態、開啟檔案等核心帳目。PID 是一次執行的識別碼，不是程式檔永久編號。

位址空間與狀態

典型示意由低位址到高位址是程式碼 code/text、靜態資料 data、向高位址成長的堆積 heap，以及由高位址向下成長的堆疊 stack。真實配置會受平台、載入器與隨機化影響，圖不是固定實體位置。行程則可能在新建、就緒（ready）、執行（running）、等待（blocked）與結束之間轉換；等待 I/O 不等於正在用 CPU。

數字實例：算出示意預留區用量

輸入 code=64 KB、data=32 KB、heap=128 KB、stack=16 KB。總用量依工具模型逐項相加：64+32=96，96+128=224，224+16=240 KB。相對工具設定的 1024 KB heap＋stack 示意預留區尚餘 1024−240=784 KB；這不是行程的真實位址空間上限。真實 64 位元虛擬位址空間遠大於 1 MB，程式通常先碰到 stack 上限、可用記憶體或配置政策。

為什麼／不要混淆

  • 一個程式可產生多個行程；一個行程也可含多條執行緒。
  • 就緒表示能跑但在等 CPU；等待通常表示事件尚未完成。
  • 虛擬位址空間大小不等於目前占用的實體記憶體。

可觀察證據

ps 可看 PID、狀態與命令；Linux 的 /proc/<pid>/status 描述狀態與記憶體摘要，/proc/<pid>/maps 顯示位址範圍及權限。行程結束後對應 PID 目錄會消失。

動手玩：組裝行程的記憶體佈局

調整四個區段大小，觀察總量、低到高排列與工具設定的 1024 KB heap＋stack 示意預留區；把 heap 拉大可看出它如何壓縮與 stack 之間的餘裕。

自我檢核（不計分，可重做）

先作答，再展開解析。

  1. 同一個程式檔同時啟動兩次，通常會得到什麼？（A）同一 PID（B）兩個獨立行程（C）只多一條 stack
    答案與解析

    答案：B。程式是靜態內容；每次執行會建立各自的 PID、位址空間與核心帳目。

  2. 行程正在等待磁碟資料時，最可能處於哪個狀態？（A）blocked（B）running（C）terminated
    答案與解析

    答案：A。事件尚未完成時行程會等待；這不表示它正在占用 CPU。

  3. 哪一項通常屬於行程執行現場，而不是程式檔永久內容？（A）PID（B）原始碼文字（C）安裝檔名
    答案與解析

    答案：A。PID 是一次執行的識別碼，行程結束後可被系統重新使用。

延伸：在 Linux 上是什麼

Linux 以 PID 與 /proc/<pid>/ 暴露行程快照。執行唯讀命令 ps -o pid,ppid,stat,comm -p $$，預期會看到 PID PPID STAT COMMAND 與目前 shell 的一列；STAT 常見 S（可中斷睡眠）或 R（正在執行），實際值會隨取樣瞬間改變。
