名詞與概念字典

搜尋繁中、英文、縮寫或功能。每張卡片說明名詞在哪一層、如何運作、不能推論什麼；證據欄則指向本機可觀察的行程、檔案或追蹤資訊。

作業系統（Operating System, OS）

白話／位置：介於應用程式與硬體間的資源管理者。

功能／機制：以抽象、多工、權限與隔離提供行程、記憶體、檔案及 I/O 服務。

邊界／證據：OS 不等於只有圖形介面；ps、free 與系統呼叫可看到其管理結果。

核心（kernel）

白話／位置：OS 中以最高權限執行的核心部分。

功能／機制：處理 syscall、中斷、排程、記憶體與驅動程式。

邊界／證據：核心不等於整套 OS；核心錯誤可能影響全機，訊息可見於系統核心日誌。

行程（process）

白話／位置：一份程式正在執行的獨立現場。

功能／機制：包含位址空間、CPU 狀態、PID 與開啟資源，由核心排程與隔離。

邊界／證據：不是磁碟上的程式檔；ps 與 /proc/<pid> 可觀察。

程式（program）

白話／位置：尚未或可被執行的指令與資料。

功能／機制：載入器把它映射進位址空間並建立行程。

邊界／證據：同一程式可同時有多個行程；檔案資訊由 stat 觀察。

執行緒（thread）

白話／位置：行程內的一條控制流與排程單位。

功能／機制：共享 heap、全域資料與檔案，各自保存暫存器與 stack。

邊界／證據：不是獨立位址空間；ps -L 可列出執行緒。

PID（Process Identifier）

白話／位置：核心給行程的數字識別碼。

功能／機制：讓工具與 syscall 指定目標行程。

邊界／證據：PID 會重複使用，不是永久身分；ps 可見。

行程狀態（process state）

角色／狀態流：描述行程位於新建、就緒、執行、等待或結束。

因果：被排程時 ready→running，等待事件時 running→blocked，事件完成再回 ready。

邊界／證據：blocked 不代表當機；ps 的 STAT 欄可觀察實作狀態。

情境切換（context switch）

角色／資料流：保存目前執行者的 CPU 狀態，再載入下一個。

因果：排程、阻塞或中斷可觸發切換，帶來固定管理成本。

邊界／證據：模式切換不一定換執行緒；vmstat 可看切換速率。

排程（scheduling）

角色：在可執行工作間分配 CPU。

機制：依佇列、優先權、時間片等規則選下一個工作。

邊界／證據：沒有單一演算法同時最佳化所有指標；top 可看 CPU 分配結果。

時間片（time slice, quantum）

白話／位置：RR 中一次允許工作連續使用 CPU 的上限。

機制：到期後未完成工作回到就緒佇列尾端。

邊界：過長趨近 FCFS，過短增加切換；不是工作完成期限。

先到先服務（First-Come, First-Served, FCFS）

角色：依到達順序讓工作做到完成或阻塞。

因果：長工作在前會使後方短工作久等。

邊界／證據：規則簡單但未必公平；可由完成時間軸重建等待時間。

時間片輪轉（Round Robin, RR）

角色：讓就緒工作依固定時間片輪流取得 CPU。

因果：未完成者回隊尾，縮短其他工作首次等待但增加切換。

邊界：不保證平均等待永遠低於 FCFS。

周轉時間（turnaround time）

定義：完成時間−到達時間，包含等待與實際服務。

功能：描述一份工作從提交到完成共花多久。

邊界：不是純 CPU 執行時間；須先說明到達時刻。

等待時間（waiting time）

定義：工作在就緒佇列中、未取得 CPU 的累積時間。

機制：簡化 CPU 工作可用周轉時間−執行時間求得。

邊界：通常不把真正執行時間算入；I/O 等待需依模型另分。

並行（concurrency）

角色：讓多項工作在同一段時間內都有進展。

機制：可由單核心交錯，或多核心同時執行。

邊界／證據：並行不保證同一瞬間同時跑；排程追蹤可看交錯。

平行（parallelism）

角色：多個核心在同一瞬間執行不同工作。

機制：工作須可拆分且有足夠硬體執行單元。

邊界／證據：執行緒多不保證平行；多核心 CPU 用量可提供證據。

Amdahl 定律（Amdahl's law）

角色：估算固定工作量加入核心後的理論加速。

機制：S=1÷((1−p)+p÷N)，串行比例限制上限。

邊界：未計同步與硬體成本；p 是工作負載假設，不是固定常數。

競態（race condition）

問題／因果：共享狀態的結果因未受控執行順序而改變。

機制：讀改寫交錯可使後寫覆蓋先寫，造成更新遺失。

邊界／證據：偶爾正確不代表安全；受控壓力測試或追蹤可重現。

臨界區（critical section）

白話／位置：操作共享狀態且必須維持一致性的程式區段。

機制：常以鎖或原子操作限制交錯。

邊界：不是越大越安全；範圍過大會犧牲並行。

鎖／互斥鎖（lock / mutex）

功能：同一時間只准一個持有者進入受保護區段。

機制：取得失敗者等待，持有者完成後釋放。

邊界：鎖不自動選對保護範圍，多鎖還可能死結。

號誌（semaphore）

白話／位置：可計數的共享資源許可證。

機制：取得時遞減、釋放時遞增；為零時等待。

邊界：二元號誌可像鎖，但所有權語意未必相同。

原子操作（atomic operation）

功能：保證操作不會被其他執行者觀察成半完成。

機制：由硬體指令與語言記憶體模型共同定義。

邊界：單一變數原子不自動保護跨多步驟的不變條件。

虛擬記憶體（virtual memory）

角色：把行程使用的虛擬地址映射到 RAM、檔案或暫未駐留的頁。

機制：頁表、權限與 page fault 支援配置、隔離及按需載入。

邊界／證據：不是無限 RAM；vmstat 可見交換壓力。

位址空間（address space）

白話／位置：一個行程可引用的虛擬位址集合與權限配置。

機制：頁表把各區段映射到不同實體來源。

邊界／證據：範圍大小不等於 RAM 用量；/proc/<pid>/maps 可見。

分頁（paging）

功能：把虛擬與實體記憶體切成固定大小單位來映射。

機制：位址拆成頁號與頁內偏移，頁表只轉換頁號。

邊界：不同於把整個行程當一段連續實體空間。

頁／框架（page / frame）

位置：page 是虛擬空間單位，frame 是同大小的實體 RAM 單位。

資料流：頁表把虛擬頁號對到實體框架號，偏移保持不變。

邊界：兩者不可因大小相同就當成同一層。

分頁錯失（page fault）

因果：CPU 存取的頁未駐留或權限不符，硬體轉交核心處理。

結果：合法頁可載入後重試；非法存取可能終止行程。

邊界／證據：不是每次都是程式錯誤；行程統計可見 fault 計數。

置換演算法：FIFO／LRU

角色：框架滿時選擇要移出的頁。

機制：FIFO 選最早載入；LRU 選最久未存取。

邊界：LRU 直覺利用局部性，但短序列不保證每次 fault 更少。

交換（swap）

位置／功能：磁碟上的後援空間，可暫存不駐留 RAM 的匿名頁。

機制：在記憶體壓力下換出，存取時再換入。

邊界／證據：速度遠非 RAM；vmstat 可見 swap in/out。

檔案（file）

白話／位置：有中繼資料、可由名稱引用的位元組序列。

機制：inode 記錄屬性與區塊位置，目錄提供名稱對照。

邊界／證據：檔名不是內容本身；stat 可觀察。

inode

白話／位置：檔案系統內描述檔案物件的中繼資料記錄。

機制：保存權限、大小、時間與資料區塊指標。

邊界／證據：通常不存檔名；ls -i 與 stat 可見編號。

目錄（directory）

白話／位置：把名稱對到 inode 的特殊檔案。

機制：路徑查找逐層解析目錄項目。

邊界：目錄不是單純把檔案內容「裝進去」的容器。

區塊（block）

位置／功能：檔案系統配置與存放資料的固定大小單位。

機制：檔案大小向上取整成所需區塊數。

邊界：不要與磁碟硬體 sector 或記憶體 page 無條件等同。

間接指標（indirect pointer）

功能：讓 inode 透過一個指標區塊描述更多資料區塊。

資料流：inode→指標表區塊→資料區塊。

邊界：多一層可擴充容量，也增加額外存取與中繼資料。

輪詢（polling）

角色：CPU 主動反覆檢查裝置是否就緒。

因果：檢查頻繁可降低發現延遲，但未就緒時浪費週期。

邊界：短且可預期等待時不一定比中斷差。

中斷（interrupt）

角色／資料流：裝置或硬體事件通知 CPU 暫停目前控制流並處理。

機制：核心執行處理常式，記錄或安排後續工作再返回。

邊界／證據：不是免費通知；/proc/interrupts 可看計數。

直接記憶體存取（Direct Memory Access, DMA）

角色：讓裝置控制器批次在裝置與 RAM 間搬資料。

機制：CPU 設定描述後，控制器搬運並在完成時通知。

邊界：不代表 CPU 完全不參與，也須處理一致性與權限。

緩衝（buffer / buffering）

角色：暫存資料以吸收生產與消費速度差，並合併小操作。

因果：批次變大可減少中斷或 syscall 次數。

邊界：占用記憶體且可能增加等待資料湊齊的延遲。

系統呼叫（system call, syscall）

角色：使用者程式請核心代辦受保護操作的入口。

機制：切入核心、驗證呼叫號與參數、執行後返回。

邊界／證據：不等於任意函式呼叫；strace 可列出呼叫與結果。

使用者模式／核心模式（user mode / kernel mode）

位置：CPU 的受限與特權執行層級。

資料流：程式以 syscall 受控進核心，以返回指令回使用者模式。

邊界：模式切換不等於必然換行程；模式是權限，不是兩顆 CPU。

死結（deadlock）與四個必要條件

角色／狀態：一組工作互等資源，沒有外力便都無法前進。

因果：互斥、持有並等待、不可搶佔、循環等待同時成立才可能死結。

邊界／證據：四條件齊全不是必然；執行緒 dump 的資源等待循環是直接證據。
