00・先看系統在仲裁什麼

為什麼需要作業系統：讓一份硬體安全服務很多程式

硬體只有有限的 CPU、記憶體與裝置，程式卻都想立刻使用。作業系統（Operating System, OS）把難用硬體包成介面、安排共享，並阻止一個程式越界傷害其他程式。

這章假設已懂：程式是指令與資料的集合；不需要硬體先備知識。

痛點：每個程式都直接控制硬體會怎樣

假設一顆 CPU 同時有三個程式要跑，兩個程式又想寫同一段記憶體。若沒有共同仲裁者，它們會爭用處理器、覆寫彼此資料，甚至每套程式都得懂每種磁碟與網卡。OS 的白話角色像大樓管理員；精確地說，它是具有特權的核心（kernel）與系統服務，管理資源並提供受控介面。

三件核心工作

  • 抽象：把磁碟區塊包成「檔案」，把執行資源包成「行程」。抽象不是假裝硬體無限，而是提供一致介面。
  • 多工共享：排程器讓程式輪流用 CPU，記憶體管理器分配與回收空間；「看似同時」不等於單核心真的同時執行。
  • 保護與隔離：使用者程式不能任意碰核心或別人的位址；故障通常只終止該行程，但硬體故障或核心錯誤仍可能影響全機。

數字實例：一顆 CPU 如何形成同時感

三個行程各取得 3 ms 時間片：t=0→3 跑 P1，3→6 跑 P2，6→9 跑 P3，9→12 再回 P1。12 ms 內每個都前進，但任何一瞬間單核心只執行一個。切換時 OS 還要保存與恢復狀態，因此時間片不是越短越好。

可觀察證據

ps 會列出行程與 PID；top 會持續顯示 CPU、記憶體用量與行程狀態。你看到許多行程同時存在，正是 OS 管理抽象與共享的外在證據，不代表它們每一刻都在 CPU 上執行。

動手玩：把日常需求翻成 OS 服務

選一個程式需求，輸出會指出背後的 OS 抽象與後續章節；逐項切換，觀察同一個「簡單動作」其實跨過哪些管理邊界。

自我檢核（不計分，可重做）

先選答案，再展開解析核對；收起解析即可重做。

  1. 把磁碟區塊包成程式可使用的名稱與位元組串流，主要是哪種抽象？（A）檔案（B）時間片（C）暫存器
    答案與解析

    答案：A。檔案系統把裝置區塊包成檔案；時間片用於 CPU 共享，暫存器則是處理器狀態。

  2. 單核心讓四個行程都持續前進，最精確的描述是？（A）四者每一刻都平行（B）OS 快速輪替執行（C）CPU 自動變成四核心
    答案與解析

    答案：B。單核心同一瞬間只跑一條控制流，排程與時間片造成並行的同時感。

  3. 使用者程式嘗試讀取另一行程未授權的記憶體時，OS 最應提供哪項能力？（A）隔離與保護（B）檔名解析（C）提高時脈
    答案與解析

    答案：A。位址空間與權限檢查用來阻止越界；另外兩項不能建立安全邊界。

延伸：在 Linux 上是什麼

Linux 的核心負責排程、記憶體、檔案與裝置介面。可安全、唯讀地執行 uname -sr 與 ps -eo pid,stat,comm | head；預期先看到類似 Linux 6.x.y，再看到欄名 PID STAT COMMAND 與數列行程。版本與 PID 會因機器而異，命令只讀取系統資訊。
