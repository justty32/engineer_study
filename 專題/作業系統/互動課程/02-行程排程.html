02・決定下一個輪到誰

行程排程：在等待、公平與切換成本間取捨

可執行的行程常比 CPU 核心多。排程器（scheduler）決定誰先執行、每次多久；不同規則會改變等待與回應感受。

這章假設已懂：01 行程與狀態。

兩種起點

先到先服務（First-Come, First-Served, FCFS）像單一排隊櫃檯，工作一旦開始便做完；時間片輪轉（Round Robin, RR）像每人限時服務，時間片（quantum）到就排回隊尾。核心保存目前狀態、載入下一個狀態叫情境切換（context switch），它是管理成本，不會推進使用者工作。

量測的是什麼

本章假設三行程都在 t=0 到達。完成時間 C 是結束時刻；周轉時間 T=完成−到達，因此此處 T=C；等待時間 W=T−執行時間。真實排程還會考慮到達時間、優先權與 I/O，本模型刻意隔離演算法差異。

數字實例：P1=6、P2=3、P3=8 ms

FCFS：C=(6,9,17)，W=(0,6,9)；平均等待=(0+6+9)÷3=5 ms，平均周轉=(6+9+17)÷3=10.67 ms。RR 取 q=3：依序跑 P1、P2 完成、P3、P1 完成、P3、P3 完成；完成時間=(12,6,17)，等待=(6,3,9)，平均等待=6 ms，平均周轉=11.67 ms，共 6 個執行片段。這組數字中 FCFS 平均較低，但 RR 讓短 P2 更早完成。

為什麼／不要混淆

  • 公平不等於每組工作都具有最低平均等待。
  • 時間片太長時 RR 趨近 FCFS；太短則切換更頻繁。
  • 周轉時間包含執行與等待，不是單純 CPU 執行時間。

可觀察證據

ps 可顯示狀態、累積 CPU 時間與排程相關欄位；top 會顯示行程取得 CPU 的比例。短時間內比例波動正常，因為排程是在時間軸上輪替。

動手玩：比較 FCFS 與 RR

改三個執行時間和時間片，輸出會逐一算等待、周轉與 RR 片段數；把 q 調大或調小，觀察公平性與潛在切換次數如何變化。
