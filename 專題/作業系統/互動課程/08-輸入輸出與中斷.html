08・讓快 CPU 不必一直等慢裝置

輸入輸出與中斷：通知、批次與搬運的取捨

CPU 每微秒能做很多事，磁碟、網路與鍵盤卻依自己的速度完成。OS 要安排何時檢查、何時通知，以及由誰搬資料。

這章假設已懂：02 CPU 是共享且有時間成本的資源。

三種角色

輪詢（polling）是 CPU 反覆讀裝置狀態，低延遲但空等會浪費週期；中斷（interrupt）讓裝置完成後通知 CPU，CPU 暫停目前控制流並執行處理常式；直接記憶體存取（Direct Memory Access, DMA）讓控制器在設定後直接於裝置與記憶體間搬一批資料，完成再中斷。DMA 仍需 CPU 設定與完成處理，不是完全免成本。

緩衝與批次

緩衝（buffering）暫存資料，吸收生產與消費速度差。較大 chunk 可減少中斷或操作次數，但可能要等更多資料湊齊，增加延遲；也會占用更多記憶體。吞吐量與單筆延遲不是同一指標。

數字實例：1024 KB、100 MB/s

純傳輸時間=1024÷(100×1024) 秒=0.01 秒=10000 μs。chunk=4 KB 時，中斷次數=⌈1024÷4⌉=256；每次 2 μs，總開銷=512 μs；相對傳輸時間=512÷10000×100%=5.12%。這只是把固定中斷成本與傳輸時間分開的模型，不含排隊、驅動或裝置延遲。

為什麼／不要混淆

  • 中斷減少忙等，但高頻中斷本身也會壓垮 CPU。
  • DMA 搬資料，CPU 仍處理控制、錯誤與完成通知。
  • 較大 chunk 改善批次效率，不保證互動延遲更低。

可觀察證據

/proc/interrupts 顯示各 CPU 收到的中斷計數與來源；vmstat 可看每秒中斷與情境切換摘要。計數快速增加只代表事件頻繁，是否異常要結合工作負載與吞吐量判斷。

動手玩：拆開傳輸與中斷成本

改資料量、速率、中斷成本與 chunk，觀察純傳輸時間、中斷次數及比例；將 chunk 加倍可看見批次化如何減少固定開銷。
