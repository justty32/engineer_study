# 圖解作業系統：立案

[建置契約](BUILD-SPEC.md)｜[派工](派工計畫.md)｜[工作流](../../../wf/workflows/interactive-study-site/README.md)

## 一句話定位

以舊作業系統 11 課為骨架，建造 20 課可離線閱讀與操作的繁中機制課。公開目錄 `dist/`，新 slug `operating-systems-little-lab`；舊站全部保留。原創 inline SVG 直接標示計算中的符號與狀態，不使用外部圖片。

## 讀者基線

讀者軟體能力強，但不假設已有作業系統、硬體中斷、頁表或持久性模型。程式語法只作必要銜接；先解釋誰持有哪個狀態、誰能改它，再介紹抽象名詞。讀者可以只看靜態正文完成例題，JavaScript 是自由探索的補充。

## prerequisite gap

最小缺口是「一段程式如何變成可暫停再繼續的執行狀態」。00 從硬體、核心、程式角色起步；01 建立 ready/running/blocked，再引入排程與同步。記憶體課先講 byte 編號與整除餘數，再分頁與 TLB；檔案課先分清 fd、開啟檔案描述、inode，再談落盤。

## 語言與名詞契約

正文與介面一律繁體中文、UTF-8，首次出現寫繁中（English, 縮寫）。沿舊課使用「行程」代表 process，必要時註「亦稱程序」；使用執行緒、記憶體、位元組、頁框、核心、就緒佇列、死結。容量用 KiB/MiB，1 KiB = 1024 B；KB/MB 不拿來代稱二進位。類比之後必須回到真實機制及邊界。算式的 = 與 ≈ 嚴格區分；位址是以 byte 為單位的索引，頁號與頁框號無單位。

## 目標能力

讀者能重建排程佇列並算回應／周轉／等待時間；以明確 toy trace 解釋同步與死結；拆解虛擬位址並追查轉換或失敗分支；用頁框狀態重算替換；追蹤 fd、offset、inode 及崩潰時的持久性；把一次 read 的使用者模式、核心、裝置與喚醒串起來。

## 概念依賴與頁面責任

00–02：OS角色→行程狀態→fork/exec/wait。03–05：指標與非搶占排程→輪轉→回饋佇列。06–09：執行緒→互斥→條件變數／號誌→死結。10–14：位址空間→分頁→TLB→缺頁→替換。15–17：開啟檔案→檔案系統→持久性。18–19：I/O→系統呼叫跨層整合。每頁明列前置並連回章節或字典；index 提供地圖，glossary 提供可搜尋回查。

逐課責任與例題見 [章節契約](evidence/chapter-contracts.json)，本地覆蓋與外部一手來源由 [來源說明](SOURCE-NOTES.md) 追溯。唯一原始材料為舊互動課程的 11 章及其程式、封存規格；封存檔僅供查核，不建立新導航連結。

## 教學與模型邊界

每課依「題目／已知與所求／選法理由→圖與符號→完整中間步驟→答案及條件→回代或不變量→遷移練習、提示、完整解」。排程是單 CPU、無 I/O、零切換成本的明示 toy；真實系統另說邊界。順序交錯模型不是有 data race 的 C/C++ 執行保證。位址轉換是 16-bit、單層頁表例子。日誌與更新流程說清檔案系統／裝置持久性假設，未把 write 或 close 成功當作落盤保證。

## 與其他課程的邊界／不做事項

不擴成完整 OSTEP 53 章，不教完整 Linux、RTOS、安全課或 kernel build；不操作宿主的 process/device/disk 實驗。舊站、Linux、RTOS、共享樣式、中央入口及發布工作流均不由本線修改。不新增依賴、外部執行期資源、圖片、字型或追蹤碼，不計分、不鎖進度。

## 交付物與完成定義

20 課加首頁與字典、原生 app.js／lab.css、每課原創圖及靜態完整例解與遷移練習。獨立來源、機制／演算、教學、技術檢查全部閉環；精確公開 manifest 綁同一 final digest。版本與部署由 publisher 在 root 放行後處理。

## 可延續性與已知風險

讀者與用語在本文件；章節地圖在 index；互動規則與例子在 BUILD-SPEC 及契約資料；來源／覆蓋／勘誤在 evidence；驗收在各獨立報告及驗收紀錄。最高風險是 toy 與真實系統邊界混淆、互動與正文不同條件、SVG標籤遮字；每項均由獨立 reviewer 檢查。所有 agent 使用實際繼承模型，不沿用舊流程的 Claude 型號稱呼。
