套件管理：安裝不只是把一個執行檔複製進來

Linux 發行版通常用套件管理器記錄檔案、版本、相依套件與來源簽章。apt 常見於 Debian／Ubuntu，dnf 常見於 Fedora／RHEL 系列；兩者概念相近，命令與政策不完全相同。

這章假設已懂：00 發行版包含使用者工具與套件管理器，並知道 04 sudo 受政策控制。

痛點：update 跑完了，程式怎麼還沒升級

把套件管理器想成有庫存目錄的倉管員；精確地說，它從設定的軟體庫取得中繼資料，解析相依與衝突，驗證套件，執行安裝或移除交易並更新本機資料庫。apt update 只刷新「有哪些版本可用」的清單，apt upgrade 才升級已安裝套件。

具體例子：安裝 nginx 前先看清交易

$ apt search nginx
$ sudo apt update
$ sudo apt install nginx
The following NEW packages will be installed:
  nginx nginx-common
Do you want to continue? [Y/n]

輸出會列出新增、升級、移除項目與下載量。Fedora 對應可用 dnf search nginx、sudo dnf install nginx；名稱與可用版本要以該發行版的套件庫為準。

為什麼／不要混淆

  • 搜尋通常不需 sudo：它只讀取套件中繼資料；改動系統安裝狀態才通常需要提權。
  • remove 未必刪設定：apt 的 remove 可能保留系統設定，purge 才連套件設定一併處理；使用者家目錄資料通常仍不在此範圍。
  • 套件名稱不是服務狀態：安裝成功不代表服務已啟動、可連線或設定正確，仍需看 systemd 狀態與日誌。
  • 不要混用來源：隨意執行網路上的 root 腳本會繞過發行版的來源、簽章與檔案追蹤。

可觀察證據

apt policy nginx 或 dnf info nginx 查看候選版本與來源；dpkg -L nginx 或 rpm -ql nginx 列出套件安裝的檔案；服務再用 systemctl status nginx 與 journalctl -u nginx 驗證。

動手玩：把目的翻成套件命令

示範什麼：apt 與 dnf 對應的五種操作。怎麼玩：切換搜尋、更新清單、安裝、升級與移除，並改套件名稱。看什麼：哪些操作使用套件名稱、哪些作用於整體中繼資料或已裝套件。
