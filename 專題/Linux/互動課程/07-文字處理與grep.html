文字處理與 grep：逐行保留符合樣式的證據

日誌有上萬行時，從頭閱讀很容易漏掉關鍵。grep 從檔案或 stdin 逐行比對樣式，把符合的整行寫到 stdout，因此能與管道、重導向組成可重複的篩選流程。

這章假設已懂：06 stdin、stdout、stderr 與管道。

痛點：搜尋 ERROR 卻撈到不該要的行

搜尋像用螢光筆標記文字；精確地說，grep 依樣式語言逐行判定是否匹配。單純 ERROR 可出現在行中任何位置，^ERROR 才要求從行首開始。大小寫預設不同，使用 -i 才會把 error 也視為符合。

具體例子：只留下行首 ERROR

$ grep '^ERROR' app.log
ERROR disk full
ERROR retry failed

若輸入同時有 INFO ERROR counter=0，它包含 ERROR 卻不在行首，因此不會命中。這能避免把「訊息內提到錯誤」誤當成「這一筆日誌的層級是錯誤」。

正規表達式先學最少一組

  • ^ 與 $：固定行首與行尾。
  • . 與 *：前者比對任一單一字元；後者重複前一個元素零次以上。
  • [0-9]：比對一個數字。grep 的基本與擴充語法不完全相同；要用常見擴充寫法時通常加 -E。

為什麼／不要混淆

正規表達式不是 shell glob：glob 的 *.log 由 shell 選檔名，正規表達式由 grep 在每一行內容中匹配。也不要把「沒有輸出」直接解讀成程式故障；grep 找不到匹配時通常以結束狀態 1 表示，語法或 I/O 錯誤才常是 2。

可觀察證據

grep -n '^ERROR' app.log 顯示命中行號；緊接著執行 echo $? 可看結束狀態；grep -c 計數、grep -C 2 顯示前後文。篩選結果只是檢視，不等於完整日誌。

動手玩：篩選一小段日誌

示範什麼：正規表達式逐行匹配與大小寫選項。怎麼玩：先用 ^ERROR，再改成 error 並勾選忽略大小寫。看什麼：命中行數與完整原文，尤其注意行首錨點造成的差異。
