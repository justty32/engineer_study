02・先看清目標，再做改動

檔案與目錄操作：指令作用在 shell 解析後的實際名稱

新手最危險的誤會，是把 *.txt 當成命令自己理解的條件。多數情況下，是 shell 先把萬用字元展開成一串現有檔名，命令才收到參數。

這章假設已懂：01 絕對路徑、相對路徑與 cwd。

痛點：同一個短指令可能碰到很多檔案

rm *.txt 看似只傳入一個樣式，實際可能等同 rm report.txt a.txt。萬用字元（glob）像先由櫃員列出符合條件的檔案；精確地說，shell 依目前目錄內容展開樣式，產生零個或多個字串參數，再啟動 rm。沒有符合項目時，各 shell 與設定的處理可能不同。

基本操作與可預覽做法

$ pwd
/home/alice
$ ls -ld -- *.txt
-rw-r--r-- 1 alice staff 120 Aug 26 09:00 a.txt
-rw-r--r-- 1 alice staff 842 Aug 26 09:01 report.txt
$ cp -- report.txt report.bak
$ mv -- report.bak archive/
$ rm -i -- a.txt

cp 複製、mv 搬移或改名、mkdir 建目錄、rm 移除。先用 pwd 與 ls 看清目標；-- 告訴常見工具後面都是路徑，可避免以連字號開頭的檔名被當成選項。不知選項時先用 command --help 看摘要，或用 man command 開手冊，在手冊中可用 /關鍵字 搜尋、按 q 離開；長輸出也可用 command | less 分頁閱讀。

為什麼／不要混淆

  • * 不會跨過斜線：*.txt 只比對這一層名稱，不會遞迴子目錄。
  • glob 不是正規表達式：glob 的 * 代表任意長度；正規表達式的 * 是重複前一個元素。
  • 移除不是資源回收筒：命令列 rm 通常直接解除名稱連結，沒有通用復原保證；遞迴與管理員權限尤其要慢。

可觀察證據

printf '<%s>\n' *.txt 可把 shell 展開後的每個參數逐行印出；find . -name '*.txt' 會由指定起點遞迴搜尋，不是 glob 自動遞迴；ls -li 顯示名稱、inode 與中繼資料，可用來觀察 ln 原檔 新名 建立的硬連結；操作前後執行 stat 路徑 可比較大小、權限與時間。

動手玩：預覽 glob 會選到哪些名稱

示範什麼：shell 展開萬用字元的結果。怎麼玩：把 *.txt 改成 a.?xt 或 [rn]*。看什麼：命中與未命中清單；這就是命令真正可能收到的檔名集合。

先預測，再揭曉

你預測會發生什麼？目前有 a.txt 與 b.txt，執行 printf '<%s>\n' '*.txt' 會印出兩個檔名嗎？

答案：不會；它會印出字面值 <*.txt>。

為什麼：單引號阻止 shell 展開 glob，因此 printf 只收到一個含星號的參數。

你預測會發生什麼？目錄中有名為 -draft 的檔案，執行 rm -- -draft 時，-draft 會被當成選項嗎？

答案：不會；支援這項慣例的 rm 會把它當成檔名。

為什麼：-- 表示選項到此結束，後續以連字號開頭的字串也按操作數處理。
