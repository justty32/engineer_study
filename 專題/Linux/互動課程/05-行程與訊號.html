05・先辨認狀態，再決定是否干預

行程與訊號：程式正在跑，不代表它一直占用 CPU

一份可執行檔是靜態內容；載入後的行程（process）才有 PID、記憶體、開啟檔案與執行狀態。多數行程常在等 I/O，看到 S 不代表故障，看到 Z 也不是還在運算。

這章假設已懂：04 使用者身分與基本存取判定。

痛點：程式沒回應，就直接 kill -9

行程狀態像候診燈號，只提示目前在做什麼；精確地說，它是核心排程與等待狀態的摘要。訊號（signal）則是送給行程的非同步通知。應先看狀態與應用日誌，再從可處理的 SIGTERM 開始；SIGKILL 是核心強制終止，程式沒有清理機會。

具體例子：從 ps 找到 PID 與狀態

$ ps -o pid,ppid,stat,cmd -p 4242
  PID  PPID STAT CMD
 4242  4100 S+   python worker.py
$ kill -TERM 4242
$ ps -p 4242
  PID TTY          TIME CMD

S+ 的 S 表示可中斷睡眠，+ 表示位於前景行程群組。送 SIGTERM 後輸出只剩表頭，表示 PID 4242 已不在該次行程清單；但真實程式可能攔截訊號做清理，因此不保證立刻消失。

行程狀態不要只看字面

  • R：正在 CPU 上執行或已可執行、正在等 CPU；不是永遠占滿核心。
  • S 與 D：S 等事件且可被訊號喚醒；D 通常在等待不可中斷的核心 I/O，長時間停留才值得查。
  • Z 與 T：Z 已結束但父行程尚未回收結束狀態；T 是被停止，可由 SIGCONT 恢復。

可觀察證據

ps -o pid,ppid,stat,cmd 查看 PID、父 PID 與 STAT；top 動態觀察 CPU 和狀態；kill -l 列出訊號名稱。若服務由 systemd 管理，還要看 systemctl status 服務 與 journalctl -u 服務，不要繞過管理器只殺子行程。

動手玩：解讀 ps 的狀態碼

示範什麼：R、S、D、Z、T 各代表哪種核心狀態。怎麼玩：逐項切換。看什麼：哪些狀態仍會回到執行、哪些需要父行程或外部事件處理。

動手玩：選擇行程訊號

示範什麼：常用訊號的意圖與能否攔截。怎麼玩：比較 SIGTERM、SIGKILL 與 SIGSTOP。看什麼：何者允許清理、何者強制生效，以及輸出給出的兩種 kill 寫法。
