08・看懂程式啟動前的字串處理

環境變數與 shell：命令執行前，文字已先被展開

你輸入的命令列不一定原封不動交給程式。shell 會處理變數、引號、萬用字元與重導向，再尋找並啟動命令；環境變數則是父行程可傳給子行程的一組名稱和值。

這章假設已懂：06 shell 會先建立資料流連接，並看過 02 glob 展開。

痛點：同一個腳本在另一台機器找不到命令

環境變數像行程啟動時隨身帶的設定便條；精確地說，它們是名稱到字串的映射，由行程環境傳給新程式。PATH 是以冒號分隔的目錄清單，shell 依序搜尋沒有斜線的命令名稱。找到哪一個，取決於 PATH 的順序與目前環境。

具體例子：展開與命令搜尋

$ echo "$HOME/projects 由 $USER 擁有"
/home/alice/projects 由 alice 擁有
$ command -v grep
/usr/bin/grep
$ printf '%s\n' "$PATH"
/usr/local/bin:/usr/bin:/bin

雙引號內仍展開變數，但保留展開結果為一個參數；單引號會保留字面字元。未加引號的變數結果還可能經過欄位分割與 glob，這是路徑含空白時常見的錯誤來源。

shell 變數與環境變數的邊界

name=alice 建立目前 shell 的變數；export name 才讓之後啟動的子行程收到它。子行程不能反向直接改父 shell 的環境，所以執行設定腳本與用 source 載入腳本效果不同。

為什麼／不要混淆

  • HOME 不等於 cwd：HOME 通常指家目錄，pwd 顯示的 cwd 可在任何位置。
  • PATH 不是檔案內容：它只列搜尋目錄；執行權限、檔案格式與直譯器仍須有效。
  • 變數沒有自動型別：環境值本質上是字串；程式如何解讀數字或布林值由程式決定。

可觀察證據

env 或 printenv 列出行程環境；printf '%s\n' "$HOME" "$USER" 看特定值；command -v 名稱 能反映 shell 對別名、內建與 PATH 命令的解析。

動手玩：觀察環境變數展開

示範什麼：shell 在程式啟動前替換 HOME 與 USER。怎麼玩：改兩個值，或把樣板寫成 $HOME/bin。看什麼：程式最後收到的完整字串；本工具只模擬這兩個變數，不模擬引號與欄位分割。
