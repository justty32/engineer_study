06・把螢幕文字看成三條資料通道

管道與重導向：改接資料流，不是複製畫面

每個命令預設有標準輸入 stdin、標準輸出 stdout 與標準錯誤 stderr。重導向把其中一條接到檔案；管道則把前一個行程的 stdout 接到下一個行程的 stdin。

這章假設已懂：05 命令啟動後會成為行程。

痛點：明明用了 >，錯誤還是出現在螢幕

把三條通道想成三條水管只是起點；精確地說，它們是行程啟動時通常編號為 0、1、2 的檔案描述子。> 預設只改接 fd 1，所以 fd 2 仍連到終端。shell 在啟動程式前建立或複製這些連接。

具體例子：成功輸出與錯誤分流

$ ls /home/alice /missing > files.txt 2> errors.txt
$ cat files.txt
/home/alice:
notes.txt  projects
$ cat errors.txt
ls: cannot access '/missing': No such file or directory

> 會先截斷並覆寫檔案；>> 從尾端附加。cmd > all.log 2>&1 先把 stdout 接到檔案，再複製那個連接給 stderr；順序反過來可能得到不同結果。

管道不是暫存檔捷徑

printf 'a\nb\n' | grep b 會讓兩個行程大致同時執行，核心在管道緩衝區傳遞位元組。管道只接 stdout；前一個命令的 stderr 仍會到終端，除非另外重導向。下游提早結束時，上游還可能收到 SIGPIPE。

為什麼／不要混淆

  • 畫面不是單一輸出：stdout 與 stderr 都可能顯示在同一終端，但仍是可分開改接的通道。
  • 2>&1 不是「檔名」：它表示讓 fd 2 指向 fd 1 當下的位置。
  • 管道傳的是位元組流：行與欄位的意義由兩端程式約定，不由管道自動理解。

可觀察證據

用 cmd >out 2>err 後分別執行 wc -c out err，可驗證資料去哪裡；ls -l /proc/目前PID/fd 能看到檔案描述子連到終端、管道或檔案。

動手玩：追蹤六種接線

示範什麼：覆寫、附加、錯誤、合併、管道與輸入重導向。怎麼玩：逐項切換。看什麼：哪個 fd 被改接、資料目的地，以及重導向順序是否重要。
