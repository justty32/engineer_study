指令集實例 1／3

x86-64：先追資料，再讀密集語法

x86-64 是 x86 指令集的 64 位元擴充。它保留長期相容性，因此指令長度、暫存器別名與定址方式較多；閱讀時不要從背指令開始，而要逐步記錄「來源值、目的位置、旗標與下一個指令位址」。

這章假設已懂：位元組、暫存器、記憶體位址、程式計數器，以及指令集架構（Instruction Set Architecture, ISA）與組合語言的差別。若還不穩，先回到通用指令模型。本頁使用 Intel 語法，也就是多數雙運算元指令寫成「目的、來源」。

最小可執行心智模型

讀取暫存器、立即值或記憶體運算元 執行搬移、算術或比較 寫回目的位置，必要時更新狀態旗標 順序前進，或由分支、呼叫、返回改寫控制流

x86-64 的一條指令可有不同長度，也可在算術指令中直接使用一個記憶體運算元。這是程式設計師看見的 ISA 規則；處理器內部可以把複雜指令拆成較小操作，不能從組合語言行數直接推斷微架構成本。

暫存器：同一儲存格有不同寬度名稱

一般用途暫存器

RAX、RBX、RCX 到 R15 可保存整數、位址或暫存結果。RSP 慣例上是堆疊指標；RIP 是指令指標。

寬度別名

RAX 是 64 位元，EAX 是低 32 位元，AX 與 AL 再取更低部分。寫入 EAX 會把 RAX 高 32 位元清零；寫入 AX 或 AL 不會。

狀態旗標

RFLAGS 保存零、符號、進位與溢位等狀態。cmp a, b 計算概念上的 a - b 並更新旗標，但不保存差值。

參數不是 ISA 固有規則

某個參數位於 RDI、RCX 或堆疊，是應用程式二進位介面（Application Binary Interface, ABI）與呼叫慣例的選擇，會隨作業系統與工具鏈改變。

六類動作

資料搬移

mov eax, 7 寫入立即值；mov eax, [rdi] 從記憶體載入；mov [rdi], eax 儲存。方括號表示取用該位址的內容，不是位址數字本身。

算術

add eax, ecx、sub、imul 會更新目的運算元；多數算術也更新旗標。lea rax, [rdi+8] 只計算位址算式，不讀取該記憶體。

比較與分支

cmp eax, 0 後，je 看零旗標，jl 依有號語意判斷小於，jb 依無號語意判斷小於。同一批位元可有兩種比較解讀。

呼叫與返回

call target 把返回位址壓入堆疊，再跳到目標；ret 從堆疊取回位址。被呼叫端還可能調整 RSP、保存暫存器與配置區域變數。

記憶體定址

[base + index*scale + displacement] 可組合基底、索引、比例 1／2／4／8 與常數位移，例如 [rdi+rcx*4+8]。有效位址算出後才進行載入或儲存。

控制流狀態

一般指令使 RIP 前進到下一條；跳躍、呼叫、返回與例外會改用其他位址。反組譯中的標籤只是工具替位址取的名字。

從 C++ 對照，但不要逐行硬配

int pick(const int* p, std::size_t i) {
    int x = p[i];
    return x > 0 ? x + 1 : 0;
}
; 示意 Intel 語法；暫存器分配與參數位置只是假設
mov  eax, [rdi + rsi*4] ; x = p[i]
test eax, eax           ; x 與 0 的關係寫入旗標
jle  .not_positive      ; 有號 x <= 0 時跳躍
add  eax, 1
ret
.not_positive:
xor  eax, eax           ; 常見的清零寫法
ret

編譯器可使用條件搬移、合併返回區塊、內聯函式或證明某分支不可能發生。組合語言應與語意和資料流對照，不保證與原始碼一行對一行。

手工追蹤 1：旗標如何決定分支

初始：EAX = 3。依序執行：

add  eax, 4
cmp  eax, 7
jne  .miss
imul eax, eax, 2

先在紙上記錄每步的 EAX、零旗標與是否跳躍，再展開結果。

展開追蹤結果
  1. add 後 EAX = 7。
  2. cmp eax, 7 的概念差值為 0，因此零旗標設為 1，EAX 仍是 7。
  3. jne 表示「不相等才跳」，條件不成立，所以落到下一條。
  4. imul 後 EAX = 14。

手工追蹤 2：位址計算與小端序載入

初始：RDI = 0x1000、RCX = 2；位址 0x1008 起的四個位元組依序為 78 56 34 12。執行：

mov eax, [rdi + rcx*4]
add eax, 1

先分開算「有效位址」與「該位址載入的值」。

展開追蹤結果
  1. 有效位址是 0x1000 + 2*4 = 0x1008。
  2. x86-64 採小端序，多位元組值的最低有效位元組放在最低位址，因此載入 EAX = 0x12345678。
  3. add 後得到 0x12345679；寫入 EAX 同時把 RAX 高 32 位元清零。

證據與邊界

可驗證的證據包括：目的檔或可執行檔中的機器位元組、反組譯結果、符號與重定位、除錯器中的暫存器與旗標、程序記憶體映射，以及單步後的記憶體內容。反組譯器選擇 Intel 或另一種常見語法會改變表面寫法，並不改變機器指令。

本頁不是完整 x86-64 規格，也未涵蓋浮點、向量、特權指令、並行記憶體模型或所有編碼。範例的參數暫存器只是示意；分析真實程式前必須確認平台 ABI、編譯器選項與語法模式。

常見誤解

  • mov 不一定真的「搬動」硬體中的資料。它定義架構狀態的結果；微架構可以重新命名暫存器或消除某些搬移。
  • lea 不等於載入。它計算方括號內的位址算式，名稱中的「有效位址」容易誤導。
  • cmp 不保存差值。後續條件跳躍讀取的是旗標，而且有號與無號條件不同。
  • RAX 不是永遠的返回值。這是常見 ABI 的慣例，不是每個執行環境與所有型別都相同。
  • 指令較複雜不等於每次都較慢。效能還受資料相依、快取、分支預測與具體微架構影響。
