指令集實例 2／3

AArch64：載入／儲存與明確的三運算元

AArch64 是 Arm 架構的 64 位元執行狀態，使用 A64 指令集。多數算術只操作暫存器，記憶體必須先用載入指令讀入、再用儲存指令寫回；這讓「位址形成」與「資料運算」在文字上較容易分開追蹤。

這章假設已懂：位址、暫存器、旗標、分支、呼叫與返回，以及通用指令模型。本頁使用常見的 Arm 組合語法，三運算元通常寫成「目的、來源一、來源二」。

最小可執行心智模型

ldr 把記憶體資料載入暫存器 算術與比較在暫存器之間進行 str 才把結果儲存回記憶體 分支、連結暫存器與返回改變控制流

「載入／儲存型」是程式設計模型，不代表實體處理器一次只做一件事。真實核心仍可有管線、多發射、亂序執行與快取；只要最終可觀察結果符合 ISA 即可。

暫存器與特殊角色

64 與 32 位元視圖

X0 到 X30 是 64 位元一般用途暫存器；W0 到 W30 是同一批暫存器的低 32 位元視圖。寫入 Wn 會把對應 Xn 的高 32 位元清零。

堆疊與返回

SP 是堆疊指標。X30 通常稱為連結暫存器，bl target 把返回位址放入其中；非葉函式若還要呼叫別人，通常先保存自己的返回位址。

零暫存器

依指令語境，編號 31 可表示零暫存器 XZR／WZR 或 SP。讀零暫存器永遠得到 0，寫入結果被丟棄；不能只看編碼編號忽略指令語境。

條件旗標

負、零、進位、溢位四個條件旗標常合稱 NZCV。會更新旗標的包括帶 S 後綴的算術／邏輯指令與比較類指令；普通 add 不更新旗標。

六類動作

資料搬移

mov w0, #7 是方便閱讀的別名，組譯器會選擇可表達它的真實編碼。ldr w0, [x1] 載入 32 位元；str w0, [x1] 儲存 32 位元。

算術

add x0, x1, x2 表示 x0 = x1 + x2，來源不被覆寫。sub、mul 類似；某些指令可把移位合併進來源運算元。

比較與分支

cmp w0, #0 是更新旗標而不保留差值的別名；b.eq、b.lt 等讀旗標。cbz w0, label 可直接測試暫存器是否為零並分支。

呼叫與返回

bl target 跳到目標並把下一條位址寫入 X30；ret 預設跳到 X30。這與 x86-64 的 call 直接把返回位址壓入堆疊不同。

記憶體定址

[x0, #16] 使用基底加立即位移；[x0, x1, lsl #2] 使用索引左移兩位，相當於乘 4。前置與後置索引還可在存取時更新基底暫存器。

程序參數

常見 64 位元 Arm 平台把前幾個整數參數放在 X0 起的一組暫存器，結果也常由 X0 返回；精確規則仍由平台 ABI 決定，不是所有值都如此。

從 C++ 對照：載入、計算、儲存分開看

void bump(int* p, std::size_t i) {
    p[i] += 3;
}
// 示意：X0=p，X1=i
ldr w2, [x0, x1, lsl #2] // 從 p + i*4 載入
add w2, w2, #3
str w2, [x0, x1, lsl #2] // 儲存回同一位址
ret

即使 C++ 只有一個複合指定運算，AArch64 的資料依賴仍是「記憶體 → 暫存器 → 算術 → 記憶體」。若別的執行緒可同時存取，這幾條普通指令並不自動提供 C++ 原子操作語意。

手工追蹤 1：普通加法不會自動改旗標

初始：W0 = 5、零旗標為 1。執行：

add  w0, w0, #1
b.eq .equal
subs w1, w0, #6
b.eq .six

追蹤 W0、W1、零旗標與兩個分支。

展開追蹤結果
  1. add 使 W0 = 6，但沒有 S 後綴，所以零旗標仍是原來的 1。
  2. 第一個 b.eq 會依舊旗標跳躍；若真的跳走，後兩條就不會執行。這是刻意展示「旗標來源」的重要性。
  3. 若忽略第一個跳躍、單獨分析後兩條，subs 得到 W1 = 0 並把零旗標設為 1，因此 b.eq .six 成立。

手工追蹤 2：連結暫存器為何要保存

假設 outer 由位址 0x4000 的呼叫者以 bl outer 呼叫，返回點為 0x4004。outer 又執行 bl inner，其返回點為 0x5008。

展開追蹤結果
  1. 進入 outer 時，X30 = 0x4004。
  2. 若 outer 未保存 X30，執行 bl inner 後，X30 被覆寫為 0x5008。
  3. inner 的 ret 可回到 0x5008；但 outer 接著直接 ret 仍會跳到 0x5008，無法回到原呼叫者。
  4. 因此非葉函式通常在堆疊或受規範保護的位置保存原本的 X30，返回前再還原。

證據與邊界

可觀察證據包括：固定寬度指令的機器位元、反組譯中的 X／W 寬度、除錯器中的程式計數器（Program Counter, PC）、SP、X30 與條件旗標、堆疊內保存的返回位址，以及載入／儲存前後的記憶體內容。函式序言並非固定模板；最佳化、葉函式與安全機制會改變它。

AArch64 不等於所有 Arm。32 位元 Arm、Thumb 與 AArch64 的暫存器、編碼和呼叫形式不同。本頁也未涵蓋浮點／向量、系統暫存器、特權層、記憶體一致性與指標驗證等擴充。

常見誤解

  • W0 與 X0 不是兩個獨立暫存器。它們是同一架構暫存器的不同寬度視圖。
  • 每個算術指令不一定更新旗標。要檢查是否有 S 形式，或是否為 cmp 等別名。
  • ret 不會自動從堆疊彈出返回位址。它通常跳到 X30；堆疊保存與還原是函式產生的額外指令。
  • ldr 的目的寬度會影響值。有號或無號擴展、32 或 64 位元載入不能只看位址。
  • 固定指令寬度不代表固定執行時間。快取、分支與資料相依仍會造成顯著差異。

建立 AArch64 use/def 表

ldr w3,[x0,x1,lsl #2] 讀 X0、X1 與四個 memory bytes，寫 X3 並清高 32 位，不更新 NZCV。adds x4,x4,x5 讀 X4、X5，寫 X4 與 NZCV。b.eq label 讀 Z flag，寫 PC。把隱含狀態列出，可避免把普通 add 誤當旗標來源。

範例一：陣列總和三輪

假設 X0=p、X1=n，X2 保存總和、X3 為索引。迴圈以 cmp x3,x1 與 b.hs 做無號邊界，ldr w4,[x0,x3,lsl #2] 載入，接著累加。令 p=0x2000、n=3，元素為 2、5、9。三輪 load 位址依序 0x2000、0x2004、0x2008，W2 依序 2、7、16；X3=3 時 b.hs 成立，mov w0,w2 返回 16 並清 X0 高位。

範例二：pair 指令與 frame bytes

假設 SP 原為 0x8000，stp x29,x30,[sp,#-16]! 先更新 SP=0x7FF0，再把兩個 64 位元值放在連續 16 bytes。小端序表示每個 X register 各自最低有效 byte 放低地址，不是將 X29、X30 bytes 交錯。ldp ...,[sp],#16 先讀回，再使 SP=0x8000。

範例三：頁相對地址形成

位置無關程式常以 adrp x0,symbol 取得 PC-relative 頁基底，再以 add x0,x0,:lo12:symbol 加頁內位移。若符號地址為 0x12345678，概念上先形成 0x12345000，再加 0x678。實際編碼、relocation 與 relaxation 要查工具輸出，不能把示意拆法當固定 machine sequence。

範例四：條件選擇

cmp w0,w1 後 csel w0,w0,w1,gt 在有號 w0>w1 時保留 w0，否則選 w1。兩個候選 register 值已存在，csel 選資料；b.gt 則選下一個 PC。編譯器取捨還要看 branch predictability 與 dependency。

範例五：函式指標與 blr

直接 bl label 用相對目標；間接呼叫把函式地址放入 register 再 blr x16，同時改 X30。除錯器中 X16 的值與 maps 可支持目標判定，但 PLT 跳板、PAC 等機制可能增加中間層。

證據工作流

  1. 從 object header 確認 AArch64，不帶入 32-bit Arm／Thumb 規則。
  2. 反組譯同時看 opcode、X/W、load/store suffix、地址更新符號與 alias。
  3. 用 ABI 辨認 X0～X7、X30、SP 的入口角色，再用資料流驗證。
  4. 單步看 PC 加 4 或改赴目標，函式前後核對 SP 與保存區。
  5. 效能另查具體 core events；ISA trace 不直接給 cache 或亂序細節。

固定 4-byte instruction 不代表每條一週期；看到 X29 不保證它是 frame pointer；ret 的實際目標與控制流保護仍要檢查。
