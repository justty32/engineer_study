13 · Lisp 讓程式碼和資料使用同一種列表結構，因此程式能讀、生成、搜尋與改寫另一段程式

13 — Lisp 程式即資料

閱讀時間：約 18 分鐘

為什麼你會在意

「對最短程式理想的可跑近似」需要一種能被列舉、變異、量長度與安全執行的程式表示。Lisp 式 AST 正好把這四件事放進同一份資料結構。重點不是改用某個 Lisp 品牌，而是替候選程式選一個容易操作、又能收緊能力邊界的表示法。

一、λ-演算：操作本身也是值

想解決什麼：Lisp 在 1958 年由 John McCarthy 提出。它最初要回答的問題是：能不能用一種統一形式，描述「運算」與「被運算的東西」？如果函式只能藏在語法裡，程式就很難把另一個操作當成輸入、輸出或組合材料。

核心想法：Lisp 蓋在 Church 於 1930 年代提出的 λ-演算之上。λ-演算把函式當成第一類公民。函式可以像數字一樣被傳遞、組合與操作。讀者常卡在「一段程式輸出的，到底該是一個操作，還是一個結果值？」答案是：操作本身就是一種值，不必二選一。你可以把「加法操作」丟給另一個函式，就像丟一個數字一樣自然。

和相近理論差在哪：圖靈機把計算描寫成讀寫頭在紙帶上移動；λ-演算把計算描寫成函式套用與代換。兩者的外表完全不同，但在可計算性上等價。Lisp 不是 λ-演算的原樣抄錄，而是把這種函式觀念放進可互動、可編程的語言。

常見誤解與限制：函式是一級值，不等於程式碼天然就是資料。許多現代語言也有高階函式，卻不一定提供 Lisp 那種直接、統一的語法樹表示。真正讓元程式設計順手的，是一級函式與 S-表達式一起出現。

二、同像性：程式、樹與列表是同一份結構

想解決什麼：一般語言的原始碼先是文字，再交給解析器變成 AST。若程式想生成或修改程式，往往得另外處理字串、語法與跳脫規則。Lisp 問的是：能不能讓程式從一開始就長成語言自己最會處理的資料？

核心想法：Lisp 用 S-表達式寫所有東西。看這段：

(/ (- c b) a)

它表示「c 減 b，再除以 a」。同一串東西可以看成一棵樹：根是 /，左子節點是 (- c b)，右子節點是 a；也可以看成巢狀列表：["/", ["-", "c", "b"], "a"]。程式＝樹＝列表，三者是同一份結構。這個性質叫同像性，也就是俗稱的「程式即資料（code as data）」。

和相近理論差在哪：反射（reflection）通常讓程式在執行期查詢型別、欄位或呼叫資訊；同像性更直接，因為語法本身就是可遍歷、可組裝的資料。序列化 AST 也能做到類似操作，但 Lisp 把這件事放進語言的日常語法，不必再發明一套樹的文字格式。

常見誤解與限制：程式即資料不表示任何資料都該直接執行。資料一旦進入求值器，就取得程式能力，也帶來注入、副作用與資源耗盡風險。實作時必須分清「只是檢視一棵樹」與「允許這棵樹執行」兩個權限層次。

三、巨集與自我修改：讓程式生成程式

想解決什麼：如果每個新控制結構都要修改編譯器，語言很難隨問題成長。Lisp 想讓程式設計者直接用現有語言產生新語法，把重複的程式結構壓成可重用的生成規則。

核心想法：既然程式就是列表，寫一段程式去生成或改寫另一段程式便是日常操作。巨集可在求值前接收一棵語法樹，再回傳另一棵語法樹。連 if/else、迴圈或小型 DSL 的控制結構，都能以 S-表達式組合。「決策本身也是一種決策」「生產工廠的工廠」這類自我指涉點子，因此有直接的表示方式。

2025 年的〈LLMs in a Persistent Lisp Metaprogramming Loop〉提出讓大型語言模型連上持久 Common Lisp REPL，跨回合保留函式、巨集與工具，再由模型檢視和改寫它們。這是概念性提案，作者自陳無實作與實測。它能當架構草圖，不能當成自我修改已被實驗證成有效的證據。

和相近理論差在哪：一般 function calling 只能從人先寫好的 API 清單選工具；持久 Lisp 環境想讓模型自己建立工具並累積狀態。差別不在括號，而在工具集合能否成為可讀、可改、可延續的程式資產。

常見誤解與限制：「自我修改」不是系統自動變聰明，也不是解除外部約束。修改規則本身仍須經過解析、測試、能力限制與回滾。完整 Common Lisp 的檔案、網路與行程能力太大，不適合直接交給未受信任的候選程式。

四、程式搜尋與演化：列表為什麼適合當基因

想解決什麼：程式合成不是只要一個能執行的表示，還要能局部修改候選、保留語法有效性、比較品質，並把常用片段變成新零件。純文字上的隨機改字很容易產生語法錯誤。

核心想法：S-表達式是一棵樹，因此可以把子樹當成變異與重組單位。拿 (/ (- c b) a) 示範：

  • 把 - 換成 +，得到 (/ (+ c b) a)。
  • 把 b 換成另一個節點，得到 (/ (- c d) a)。
  • 在外層包一層運算，得到 (* (/ (- c b) a) 2)。

這正是 Koza 的遺傳程式設計所做的事。它演化 Lisp 的 S-表達式樹，靠替換節點、改動或交換子樹來搜尋能解題的程式。只要每個節點帶型別，變異器還能限制「數字洞只能放回產生數字的子樹」，減少大量無效候選。

另一個操作是函式庫學習（library learning）。系統發現某個片段常出現、很好用，就把它命名為基礎零件：

(define (remove-offset c b) (- c b))
(/ (remove-offset c b) a)

DreamCoder 類系統就是一邊解題，一邊把好用片段沉澱成可重用詞彙。這不只縮短單一答案，也可能縮小之後的搜尋空間。

和相近理論差在哪：列舉搜尋依固定順序產生所有候選；遺傳程式設計以族群和隨機變異探索；函式庫學習則改變之後可用的原子零件。三者都能使用同一棵 AST，但搜尋策略與「學到什麼」不同。

常見誤解與限制：容易修改不等於容易找到。候選樹仍會組合爆炸；加入一個零件，也可能同時增加更多無用組合。真正的難題是搜尋順序、剪枝、型別、驗證器與資源預算，不是把括號排好就結束。

五、可計算性：圖靈完備的兩筆稅

想解決什麼：程式搜尋系統需要知道語言能力應開到哪裡。語言太弱，正解寫不出來；語言太強，候選可能不停機，也可能只在短範例上看似成功。

核心想法：Church–Turing 命題指出，圖靈機、λ-演算與一般遞迴函式在可計算能力上等價。白話講，一條無限紙帶加讀寫頭、Lisp／λ-演算與遞迴函式看似毫不相干，能算的東西卻一樣多。因此 Lisp 體系只要表達力足夠，理論上能算任何可算的東西。

第一筆稅是停機問題。語言一旦圖靈完備，就沒有通用方法能事先判定任意程式會不會跑完。候選可能陷入無限迴圈，搜尋器也不能只靠靜態檢查把所有這類情況找出來。

第二筆稅是可學習性。權重空間或語言裡「存在一個解」，不表示梯度或有限資料能找到它，更不表示從短輸入學到後能外推到長輸入。2026 年的 Transformer 與對角 SSM 結果，分別把「表達力不等於可長度泛化地學到」及「理論可表達但梯度找不到」做成了可檢查的反例。

把紙上完備性做成工具：作者自報的開源 PyTorch 套件可把圖靈機描述直接編譯成權重，不經訓練；它實作 WCM21 的 Transformer 建構（O(1) 精度、無需思維鏈），也實作 SS95 的有理數遞迴堆疊機（float64 下約可靠 pop 8 次）。這讓人能直接檢視、擾動原本只在證明裡的建構；但作者也明說，這種建構式可解釋性不會遷移到梯度下降訓練出的網路。

和相近理論差在哪：圖靈完備談的是存在性；停機性談執行是否結束；長度泛化談有限訓練能否外推；最佳化談訓練程序能否抵達那組權重。四個問題不能用一句「理論上做得到」混在一起。

常見誤解與限制：很多 DSL 故意放棄圖靈完備。例如規定 for 最多跑一萬次，或只允許保證終止的全函式。這是用表達力換取可分析、可驗證與有限搜尋。即使如此，終止保證也沒有自動解決長度泛化與搜尋成本。

六、工程上的 Lisp 式 DSL

想解決什麼：完整 Lisp 的巨集與自我修改能力很強，但早期系統需要的是可控候選，不是整個作業系統權限。最小實驗要把理論優點留下，同時壓住執行風險與搜尋空間。

核心想法：第一版完全可以在 Python、Rust 或 C++ 裡自建 Lisp 式 AST。節點只有封閉的純函式集合；每個節點有型別；求值器限制時間、記憶體、遞迴深度與輸出大小；序列化格式則讓程式長度可計算。這已足以支援列舉、變異、重組與描述長度比較。

和相近理論差在哪：sandbox 是執行隔離；DSL 是能力白名單；型別系統在生成時排除不合法組合；驗證器檢查輸出是否符合規格。它們處理不同失效面，應疊在一起，而不是互相取代。

常見誤解與限制：同像性只保證程式容易被當資料操作，沒有保證表示是最短的、搜尋是有效率的、結果是安全的或規則能跨題泛化。把 Lisp 當成「候選表示層」很有用；把它當成完整智能解法，則跳過了最難的部分。

七、最小求值器：把「資料」切換成「程式」的那一刻

想解決什麼：初學者看到 S-表達式，常以為括號本身帶有魔力。真正需要說清楚的是：同一棵列表何時只是一份資料，何時開始被當成呼叫執行。若這條界線含糊，搜尋器、驗證器與 sandbox 的責任也會混在一起。

核心想法：最小求值器可以只有三種規則。常數直接回傳；符號到環境表查值；列表則先讀第一個元素作運算子，再遞迴求值其餘元素作參數。概念上的虛擬碼如下：

eval(node, env):
  if node 是常數: return node
  if node 是符號: return env[node]
  op   = lookup(node[0])
  args = [eval(x, env) for x in node[1:]]
  return op(args)

對 (/ (- c b) a) 而言，求值器先查 /，再遞迴算 (- c b) 與 a。但若外層使用 quote，求值器可以直接回傳這棵列表，不執行 / 與 -。巨集則位於另一個時機：它接收尚未求值的語法樹，產生新樹，之後才交回一般求值流程。

和相近理論差在哪：解析器把文字變成 AST；求值器讓 AST 產生值；巨集展開器在求值前改 AST；編譯器則把 AST 轉成另一種可執行表示。小型 DSL 可以把四者合併在少量程式碼中，概念上仍應分開，因為錯誤與權限發生在不同階段。

常見誤解與限制：quote 不等於安全。被引用的列表之後仍可能再次送進求值器；巨集產生的樹也可能引入未核准運算。安全邊界應放在運算子白名單與求值器本身，並對每次執行設步數、深度與輸出上限，不能只靠候選程式自律。

這個最小求值器也說明為何 AST 適合搜尋。搜尋器只生成結構，不必先生成文字再解析；型別檢查可在節點接上樹之前執行；驗證器則用相同求值器跑所有示範。若兩棵 AST 在所有已見輸入都輸出相同，還可先視為觀察等價，暫時保留較短或成本較低者。這些做法沒有解掉組合爆炸，但能讓每個候選的產生、執行與淘汰都有明確位置。

把一次候選生命週期攤開，就能看見每層在擋什麼：

階段輸入先檢查什麼失敗時怎麼辦
生成帶型別的洞與可用運算子子樹型別能否接上不產生該候選
靜態檢查完整 AST運算子是否在白名單、常數是否越界直接淘汰
受限求值AST 與單一輸入步數、深度、記憶體、輸出大小中止並記為失敗
範例驗證候選在全部示範的輸出是否逐項符合規格淘汰或保留反例
保留資料驗證未參與搜尋的案例是否只記住示範降級，不進資產庫
固化已通過候選型別簽章、描述長度、版本與來源建立可撤回的新零件

這張表也點破「程式即資料」真正省下的成本：每一階段操作的是同一棵 AST，不必在文字、編譯結果與另一套演化基因之間來回轉換。省下的是表示層摩擦，不是驗證責任。

實作紀錄還應把候選的父節點、使用過的變異、淘汰理由與資源用量一起留下。當某個好解突然出現時，才能回放它從哪棵樹變來；當搜尋變慢時，也能判斷是型別剪枝不足、求值太貴，還是大量候選在同一組示範上觀察等價。這些資料比只保存最後冠軍更有用，因為下一輪要改善的是搜尋程序，不只是展示答案。

同一份紀錄也讓失敗候選變成反例庫。之後若新增運算子或 helper，可先重跑舊反例，確認搜尋空間擴大沒有讓既有驗證邊界失效。

反例若失效，應撤回新零件，而不是改掉舊測試配合它。

這是最小回滾原則。

回滾後也要保存失敗版本與理由，避免下一輪搜尋再次產生同一種越界候選。

這能把一次失敗轉成後續剪枝規則，而不是只留錯誤訊息。

  • 解存在，梯度卻可能找不到（arXiv 2603.01959）：原文事實（作者自報）：有限精度下，單層輸入相依複數值對角 SSM 無法表達非交換群狀態追蹤；k 層的充要條件是目標群有長度 k、因子皆交換的次正規列。實驗以 FP32、訓練長度不超過 60 並測到 1000；2 層 AUSSM 理論可表達 S₃、A₄，標準訓練卻失敗，只有初始化在 S₃ 解析解附近才學會並外推。對本篇的意義：能寫出或表示一個候選，和搜尋程序能抵達它，是兩個問題。摘要檔：2603.01959_Diagonal_SSM_StateTracking_Limits.摘要.md

自我檢核

  1. 問：高階函式與同像性是同一件事嗎？ 答：不是。高階函式讓操作成為值；同像性讓程式語法直接成為容易操作的資料結構。
  2. 問：為什麼 S-表達式適合程式演化？ 答：它天然是一棵樹，變異器能以節點或子樹為單位修改，型別還能限制替換是否合法。
  3. 問：圖靈完備保證搜尋器能找到解嗎？ 答：不保證。它只談表達力，沒有處理停機、搜尋成本、可學習性與長度泛化。
  4. 問：為什麼早期系統常選受限 DSL，而不直接開放 Common Lisp？ 答：受限 DSL 能封閉能力、保證部分終止性並縮小搜尋空間，較容易隔離與驗證。

延伸閱讀

  • 程式合成 C++ 專案總覽：program.hpp 的 AST 與直譯器，是程式即資料的最小可跑版本。
  • 列舉式合成：直接看 AST 候選如何被逐一生成與驗證。
  • 多型別 DSL：用型別導向列舉壓掉不合法的候選組合。
  • 長度泛化障礙摘要：補上「圖靈完備不等於學得會」的理論界線。
  • 持久 Lisp 元程式設計迴圈摘要：可讀其協定設計，但要連同「無實作與實測」的限制一起看。

一句話總結

Lisp 的精髓是「程式和資料長同一個樣子」。這讓程式變成可以被讀、生成、演化與改寫的一級物件，因此成為符號 AI 與程式演化的天然母語；真正落地時，還要用受限 DSL、型別、sandbox 與驗證器替這份表達力收邊。

之所以有人對它感興趣：當你想讓系統自動搜尋、組合、演化出小程式時，Lisp 或 Lisp 式 DSL 幾乎是訂做的。列表、操作即值與元程式設計都在同一份語意裡，能省下大量重造表示層的力氣。
