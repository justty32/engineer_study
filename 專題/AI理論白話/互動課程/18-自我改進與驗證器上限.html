18 · 當系統開始改寫自己，它能走多遠不取決於多會改，而取決於「驗收它的那把尺」有多可信、多獨立

18 — 自我改進 agent 與驗證器上限

閱讀時間：約 20 分鐘

為什麼你會在意

能自己改 prompt、工具、記憶甚至原始碼的 agent，看起來已經跨過「只能被人更新」的門檻。真正危險的時刻卻不是它第一次改成功，而是它也開始改測試、挑資料、解釋失敗，最後用自己定義的成功替自己蓋章。

外層驗證與回滾正是在切斷這條自我背書迴路：候選可以自由產生，部署權仍由獨立 gate 掌握。本篇只補驗收邏輯，不重述那份設計。

一、真問題不是「會不會改」，而是「誰來驗收」

想解決什麼：agent 若既提 patch、又寫測試、又解釋結果，「進步」可能只是把尺改得更容易通過。最難的 base case 是：第一次改寫前，憑什麼相信那份證明或測試？再找更高層 verifier，又會碰到誰驗 verifier 的無限後退。

核心想法：拆開提案權、驗收權與部署權。candidate-v8 可附自測，卻不能修改隱藏題、門檻或現役版；若可見測試多解對兩題、獨立 audit 卻少一題，gate 就保留 champion-v7。證據必須來自改動者控制範圍之外。

和相近理論差在哪：05 程式合成與演化計算只講理論版 Gödel Machine，停在 2003–2011 的「能證明有益才改」base case；本篇接手 2025–26 的工程譜系，討論形式證明被 benchmark、保留集與部署 gate 取代後，新版的驗收器上限。05 問怎麼產生與搜尋程式，本篇問產生後誰有資格說它比較好。

常見誤解與限制：外部只描述權限位置，不表示 verifier 天然正確。可信仍取決於資料代表性、樣本量、規格完整性與 audit 是否會被反推出來；獨立性不能補完錯誤規格。

二、從 Gödel Machine 到 DGM、紅皇后與 Mendel

想解決什麼：形式證明太難時，工程系統改用實跑；單一路徑又會被壞改動卡死。固定評估者可能飽和或被鑽漏洞，單一任務的一次失敗也未必指出該改哪裡。

核心想法：DGM 保存多個分支，讓次優版本成為日後的「墊腳石」；紅皇后把評估者也納入演化，但 epoch 內凍結，只在邊界以保留真值換版；Mendel 讓改寫參考跨任務與跨 lineage 對照。若 v4 在多種語言都敗，較像結構缺陷；只有單題失敗，可能只是偶然。

和相近理論差在哪：hill climbing 只沿當前最佳版；DGM 留多條譜系，Mendel 再拿譜系診斷。紅皇后不是讓評估者每步漂移，而是把非平穩評分切成暫時固定的 epoch。

常見誤解與限制：若分支共用錯誤 benchmark，多樣版本只會用不同方式過擬合同一把尺。跨 lineage 要求條件可比；評估者能演化也不等於真值能演化，換尺仍須外部保留集。

三、理論天花板：純自指為什麼會崩

想解決什麼：系統若只用自己的輸出訓練、再用自己的評分驗收，能否持續產生新知？多跑幾輪只是重排既有資訊，不等於取得新證據。

核心想法：第 t 代資料可寫成 αₜ·外部資料 + (1−αₜ)·自身資料。純自指 α=0 時，有限取樣先漏掉罕見模式；DPI 又限制封閉通道增加與真分布的互資訊。像每輪只從上一版字典抽 100 個詞重建，罕見詞一旦漏掉便永遠消失。出口是持續外部接地；符號錨再把漂移限制成可檢查的離散程式，由執行或推理器給形式結果。

和相近理論差在哪：模型崩潰講分布退化，Goodhart 講代理指標失真，符號錨則改變候選與驗證介面。程式可執行只接地「這個輸入做了什麼」，不證明需求寫對。

常見誤解與限制：這是無實機實驗、依賴 KL 類目標等假設的理論；αₜ 有正下界時反而可收斂。符號方法仍受近似誤差與規格完整性限制。

四、驗證器的實證上限：自寫測試與抽樣盲區

想解決什麼：實務 verifier 只看有限資料。自寫測試會和 policy 一起適應；獨立抽樣也可能沒碰到會翻轉決策的罕見規則。

核心想法：分開可見測試、不可見 audit 與部署分布。若單條軌跡碰到危險模式的機率是 r，抽 N 條仍全漏的機率是 (1−r)^N。例如角落有「進入後凍結」規則，隨機軌跡很少碰到，規劃器卻會利用假想捷徑。驗證因此要加入邊界、反例與規劃器查詢狀態，並記錄未覆蓋模式。

和相近理論差在哪：形式驗證在明確規格內可涵蓋所有情況；抽樣只證明抽到的輸入。獨立 gate 防改考卷，壓力測試檢查考卷是否碰到高風險區。

常見誤解與限制：隱藏不等於代表性，更多樣本也抓不到機率近零的模式。只回接受／拒絕可減少擬合，卻也減少修正資訊；回饋粒度仍須依風險實測。

五、部署治理：版本不是備份，而是決策證據

想解決什麼：一次勝出不代表應立即覆寫現役版。任務中途換 policy 會使失敗難歸因；只備份程式、不備份測試、schema 與記憶，也無法重現舊行為。

核心想法：生命週期拆成 search → register → audit → release → activate → monitor → rollback。Champion–challenger 在相同條件下成對比較；hidden audit 不洩漏樣本、門檻與逐題分數；候選只在下一個 task boundary 啟用，退化就回滾整個 bundle。

flowchart LR
  C["產生 Challenger"] --> V["註冊版本與 lineage"]
  V --> H["隱藏 audit：與 Champion 成對比較"]
  H -->|拒絕| K["保留 Champion"]
  H -->|接受| R["發布，但尚未啟用"]
  R --> B["下一個 task boundary 啟用"]
  B --> M["canary／部署監測"]
  M -->|退化| P["完整回滾 parent bundle"]

最小 bundle 要含程式、測試、資料與 schema 版本、適用範圍、親代、diff、seed、預算、audit 決策與回滾理由，才能重播退化。

和相近理論差在哪：11 AI 對齊、可解釋、可控講人怎麼踩煞車；本篇講系統自己的煞車為何失靈。一般 CI 問 build 是否過測試；這裡還要問測試是否也被改、證據是否洩漏。

常見誤解與限制：gate 太嚴會停滯，太鬆會累積退化。回滾也撤不回外部副作用；高風險動作仍需沙箱、最小權限與人工授權。

六、潑冷水：單次變好，可能只是順序、運氣或調參

想解決什麼：漂亮曲線可能來自 run 變異、由易到難的隱藏課程，或更多訓練時間，不能全算成「學會更好的學習方法」。

核心想法：報多個 seed 的平均、標準差、best–worst gap，再打亂任務順序。patch 另分 run 側（batch size、時長、checkpoint）與 learning 側（loss、監督、update rule、資料）。把 1 小時改成 4 小時後勝出，可能只是更會花算力。還要測舊任務 retention 與換環境後表現；技能污染則接到19 技能庫的生老病死。

和相近理論差在哪：超參數最佳化允許 run 側調整；若主張學習規則變好，就要證明 learning 側改變。多 seed、亂序、跨環境分別測隨機性、隱藏課程與分布依賴。

常見誤解與限制：learning 側也可能改壞，run 側也有工程價值；分類只為校準主張。多 run 雖貴，關鍵候選發布前仍不能只靠一次幸運結果。

七、對本設計的意義：把自我改進變成可撤銷交易

想解決什麼：規則、技能、世界模型與 harness 同時更新後，難以歸功或只撤回問題部分。沒有版本邊界，信用分配和治理會纏在一起。

核心想法：外層驗證與回滾把修改視為可撤銷交易：bundle 帶 parent、diff、證據與適用範圍進 gate，邊界才啟用，退化便回滾。待實測的最小對照是 self-test 與 hidden gate 的 retention，並記 false accept、false reject 和恢復成本；這不是已證明的 production 配方。

和相近理論差在哪：04 信用分配與經濟式智能管「規則之間怎麼分帳」；本篇管「改動之間怎麼分帳」，多了 lineage、版本、發布與回滾。技能生命週期見19 技能庫的生老病死，模型盲區見20 世界模型。

常見誤解與限制：治理只讓證據與失敗成本可檢查，不證明無限改進。尚無實證保證 audit 不被間接擬合，或版本化能處理所有跨元件作用；verifier 的輪替也要版本化。

自我檢核

  1. 問：外部 verifier 為什麼仍可能錯？ 答：外部只保證候選不能直接改它；若 audit 分布、樣本或規格不代表部署，它仍會放行退步。
  2. 問：α=0 的理論結果真正排除了什麼？ 答：在論文的 KL 類純自指模型內，封閉迴圈不能靠重複處理增加與真分布的資訊，還會因有限取樣失去模式；它不排除持續有外部接地的改進。
  3. 問：hidden audit 和多抽樣為何不是同一件事？ 答：前者防止候選直接擬合考卷，後者增加碰到錯誤區的機會；隱藏但失配的資料與公開但覆蓋廣的資料各有不同風險。
  4. 問：為什麼回滾要包含 tests、schema 與記憶？ 答：它們共同決定版本行為；只退 policy 可能讓舊程式在新介面或污染記憶下仍無法重現。
  5. 問：run 側變好能不能算有價值？ 答：可以，但應報成執行效率或調參改善；只有 learning 側證據才支撐「學習規則變好」的主張。

一句話總結

自我改進不是讓 agent 一直改自己，而是讓每個候選都必須面對一把它不能同時改寫、能說不知道、看得到部署風險且保留舊版本的尺；沒有外部接地、隱藏稽核、譜系與完整回滾，再漂亮的進步曲線也可能只是系統學會替自己放水。

外部只保證候選不能直接改它；若 audit 分布、樣本或規格不代表部署，它仍會放行退步。

`α=0` 的理論結果真正排除了什麼？

在論文的 KL 類純自指模型內，封閉迴圈不能靠重複處理增加與真分布的資訊，還會因有限取樣失去模式；它不排除持續有外部接地的改進。

hidden audit 和多抽樣為何不是同一件事？

前者防止候選直接擬合考卷，後者增加碰到錯誤區的機會；隱藏但失配的資料與公開但覆蓋廣的資料各有不同風險。

為什麼回滾要包含 tests、schema 與記憶？

它們共同決定版本行為；只退 policy 可能讓舊程式在新介面或污染記憶下仍無法重現。

run 側變好能不能算有價值？

可以，但應報成執行效率或調參改善；只有 learning 側證據才支撐「學習規則變好」的主張。
