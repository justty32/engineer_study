19 · 把經驗存成可重用技能能省下推理成本，但只會新增、不會驗證與退休的技能庫，最後可能比沒有技能庫更差

19 — 技能庫的生老病死

閱讀時間：約 20 分鐘

為什麼你會在意

本設計的typed DSL 與技能庫要把成功程序變成資產；難點是決定何時進庫、何時撤照。

名詞速查

術語白話一句例子
技能（skill artifact）可保存、讀取、修改與版本化的程序資產一份含介面、步驟與測試的 SKILL.md
optionRL 裡有啟動條件、內部策略與終止條件的多步策略站在門前才可啟動「開門」
固化（crystallization）把一次成功經驗整理成可重用資產將五次工具呼叫包成一個已測函式
准入閘門（admission gate）候選技能進正式庫前必須通過的檢查型別、測試與風險掃描全過才升格
技能漂移（skill drift）技能依賴的環境假設已失效API schema 改版後舊參數不再合法
技能陰影（skill shadowing）相似或多餘技能排擠正確技能影片技能因描述相似而搶走計數任務
技能合約（skill contract）技能承諾的輸入、輸出、前後條件與副作用輸入必須是清單，輸出保證已排序
退休（retirement）停止路由到有足夠負面證據的技能保留歷史版本，但狀態改為 deprecated
Shapley 值按不同合作組合中的平均邊際貢獻估值比較技能加入合法工具鏈前後的差值
最小描述長度（MDL）同時計算技能庫與使用它描述軌跡的成本helper 要省下的總碼長超過自身定義成本

一、LLM 時代的「技能」到底是什麼

想解決什麼：同一個 skill 名稱可能指程式碼、自然語言訣竅、模型 adapter 或一段記憶。若不先說清楚保存的是哪種東西，後面的「可重用」「可驗證」「可退休」會各說各話。

核心想法：技能生命週期綜述把用法分成六感：可執行程式碼、自然語言啟發式、SKILL.md 套件、參數化 adapter、記憶軌跡、能力標籤。本篇採較窄的定義：技能是檔案化、可讀、可版本化的 artifact，帶適用範圍、介面、使用方式、驗證證據與譜系。例如「下載 CSV 後依日期聚合」還要說明輸入 schema、輸出型別、副作用與測試版本。

flowchart LR
  E["證據"] --> P["候選"] --> G{"准入"}
  G -->|通過| A["正式庫"] --> U["使用"] --> M["監控"]
  G -->|退回| R["修寫／拒絕"]
  M --> A
  M -->|有害| D["退休"]

和相近理論差在哪：02 階層式 RL 與元學習的 option 是「啟動條件＋內部策略參數＋終止條件」，重點是用較粗時間尺度控制行為；本篇技能是模型外部的可編輯資產。option 常見問題是策略跨環境泛化失敗，本篇關心的則是檔案過時、語意陰影、版本衝突與庫腐化，失效面不同。

常見誤解與限制：可讀不等於可執行，可執行也不等於可攜。六類 artifact 不應共用一個「已驗證」旗標，因為它們能提供的驗證 handle 不同。

二、固化為什麼有用，又在哪裡撞牆

想解決什麼：長任務常重複同一串工具呼叫與狀態傳遞。每次都從零規劃，會反覆消耗 token、時間與除錯回合；但把所有片段都包成技能，又會膨脹成另一種負擔。

核心想法：固化把「再次思考整段流程」改成「選一個已驗證介面」。SkillCraft 的作者自報，在 126 個受控工具任務中，GPT-5.2 使用單層技能後成功率由 87% 到 90%，token 從 1.23M 降到 0.26M。像是把「搜尋→擷取→合併→檢查缺值」包成一次技能呼叫；收益主要來自程序壓縮，不是憑空增加知識。

和相近理論差在哪：一般快取保存「某個輸入的既有答案」；技能保存「可套到新輸入的程序」。巨集只展開固定動作，技能還可能帶前置條件、錯誤處理與驗證器。技能也不是組合愈深愈好：同一篇實驗中，GPT-5.2 的巢狀技能讓成功率由 90% 降到 79%，token 又從 0.26M 回升到 0.60M，顯示依賴鏈會放大潛伏 bug 與除錯成本。

常見誤解與限制：這些數字來自受控 MCP 環境，跨模型轉移也只測 8 個 hard 任務。工程上要同時量成功率、token、wall time、展開深度與修復次數，不能只報 token 下降。

三、表示形式之爭：散文還是帶型別偽代碼

想解決什麼：自由散文把用途、輸入、動作模板、例外與警告混在一起。模型每次讀取都要重新猜「要傳什麼」「會回什麼」「哪一步真的可執行」，相同合約成本被一再支付。

核心想法：帶型別偽代碼把技能拆成 signature + input/output type + pre/postcondition + side effects + action template。例如 summarize(rows: CsvRows) -> Report 比「整理這些資料並產生報告」多了可檢查邊界。SaP 的准入管線先做 Coverage、Binding、Replacement、Risk 四個確定性檢查，再做 Binding Extraction 與 Rewrite Cleanup 兩道 LLM 後驗證；在 ALFWorld 134 場、3 seeds 的 pooled 結果中，作者自報帶型別版本 82 勝、散文 47 勝，並少 22.8% input token。

和相近理論差在哪：JSON schema 只約束資料形狀；typed skill 還管前後條件、依賴與副作用。可執行程式較嚴格但綁定 runtime；偽代碼較可攜但仍需展開器。本機 progsynth_cpp/docs/m7_typed.md的列舉器只從相容型別的 bank 組子樹，非法組合根本不產生。

常見誤解與限制：型別只擋「形狀不合」，擋不了演算法本身錯誤。SaP 端到端只跑一個 skills_500 Markdown 庫，typed API 庫只做到前段解析；Replacement 也是靜態替換，尚非運行時展開證明。把散文改成看似正式的偽代碼，若沒有測試與風險檢查，只是增加權威感。

四、技能庫怎麼腐化

想解決什麼：append-only 的技能庫會同時遭遇三種退化：環境改了，舊技能靜默失效；名稱與描述太相近，路由器選錯；候選數增長後，平面相似度檢索失去辨識力。

核心想法：漂移是作業假設不再成立，例如端點下線或 schema 改版；陰影則是技能未必壞掉，描述卻排擠更適用者。受控研究中，202 個技能讓通過率相對 oracle 庫最多下降 0.21；陰影效果 0.14 的信賴區間排除零，上下文效果 0.07 的區間含零。另一曲線從 16 個技能的 97% 降到 128 個的 78%、256 個的 64%。

和相近理論差在哪：模型遺忘是參數更新後舊能力消失；技能漂移是外部 artifact 與環境契約脫鉤。一般 context overflow 關心提示太長；技能陰影指出即使 token 還放得下，相似候選也會改變選擇機率。去重只能處理近重複，抓不到「文字不同但依賴同一個已失效 API」的共同故障。

常見誤解與限制：庫大不是原罪，平面且無治理才是風險。SkillOps 的規模結果依賴半合成 ALFWorld 庫、結構化合約與 gold arguments。漂移監控也不能見到版本字串變動就報警；應只監控真正依賴的角色承載義務。

五、治理配方：准入、容量、修復與退休

想解決什麼：技能不能只分「存在／不存在」。候選需要證據才能升格，正式技能要持續健康檢查，負貢獻技能要停止路由，但稀有或剛出生的技能也不能因樣本少就被誤殺。

核心想法：最小配方有四層：准入檢查型別、測試、風險與來源；設活躍容量上限；持續監控合約並局部修復；證據足夠後按結果退休。Ratchet 至少試驗 Nmin=100 次、貢獻低於 −0.10 才退休，活躍上限 C=50，並用 meta-skill 約束作者風格。退休應改狀態而非抹除檔案，讓錯殺可復原。

階段最低證據可能動作
候選來源、介面、held-out 測試、風險掃描Add、Refine、Reject
活躍使用率、成功／失敗、版本與相依紀錄Rerank、Merge、Split、Rewrite
失效合約違反與可重現修復案例Repair、Deprecate、Rollback
過量容量、陰影、重複與負貢獻Prune、Distill、Archive

和相近理論差在哪：Ratchet 的結果驅動退休可視為04 信用分配與經濟式智能中 bucket brigade／XCS「賺不到且預測不準者破產」在 2026 技能庫的重現：不是按檔案年齡刪，而是讓使用結果形成可稽核帳本。Ratchet 還給出非發散邊界：在容量 C、退休門檻 τ 等假設下，期望效能跌破無技能地板的幅度受 τ+ε+Cδ 限制；這是指定模型的形式保證，不是任意部署都不退化的承諾。

常見誤解與限制：退休愈快不代表治理愈好。Ratchet 把證據地板降到 Nmin=20 時，增益變成 −0.019。冷門技能使用少不等於沒有價值；刪除前要有觀察期、依賴檢查與回滾點。

六、誰該留下：把成敗分回技能

想解決什麼：一次任務通常同時經過檢索、技能執行、工具與驗證。最後只有成功或失敗一個結果時，單看「被叫用幾次」會獎勵高頻路由節點，也可能把下游故障錯算給上游技能。

核心想法：Skill1 把同一結果拆成不同尺度：當集成敗給利用，跨集低頻趨勢給選擇，高頻的超額變異給蒸餾。技能長期穩定就提高選中機會；新軌跡明顯超越現有庫才值得固化。作者在 Qwen2.5-7B-Instruct 自報 ALFWorld 97.5%、WebShop 89.7%，但只測兩個文字環境。

和相近理論差在哪：頻率分解沿時間尺度分信用，適合線上更新；Shapley 式估值問的是「把技能加入不同合法合作組合時，平均多帶來多少邊際效益」。後者能揭露互補與替代，但依賴圖中的 coalition 必須向下封閉，還要把內容效益和 context 佔位成本拆開。這接回 04 篇的重點：Shapley 值依 coalition、採樣分布與成本定義而變，不是技能的唯一真實身價。

常見誤解與限制：常出現在成功軌跡裡，可能只是路由必經點；移除底層依賴造成整串壞掉，也不能把全部損失都算給它。頻率分解加依賴感知 Shapley 尚無實證，需在同一任務分布與 rollout 預算下實測。

七、接回壓縮理論與本設計的元件庫

想解決什麼：如果「短」被寫成單純少步數，agent 會學會草率捷徑；如果完全不計庫成本，又會替每個案例各造一個 helper。需要同時獎勵跨軌跡重用，並向技能字典本身收費。

核心想法：15 Solomonoff 與最短程式的 MDL 帳本正好提供判準：總成本 = 技能字典成本 + 用字典分段描述成功軌跡的成本。ReuseRL 把分段成本逐軌跡加進 GRPO；作者自報 ALFWorld OOD 93.28%，vanilla GRPO 為 79.85%。命題 1 更指出純回合長度懲罰只是只含單元素的退化固定碼，無法分辨兩條等長軌跡誰更可重用。換句話說，求短要求對地方：短的是跨任務的共同描述，不是某一局少按幾步。

和相近理論差在哪：05 程式合成與演化計算的 DreamCoder／Stitch回答「怎麼從解答壓出零件」；本篇回答「零件進庫後會發生什麼」。元件可記成 signature+types + pre/postconditions + test + dependencies + scope + lineage，對接typed DSL 與技能庫，再讓18 自我改進與驗證器上限限制升格、由20 世界模型提供漂移探針。

常見誤解與限制：MDL 只在固定語言、編碼與任務分布下可比。ReuseRL 的技能投影逐環境手寫，實驗限文字環境與 1.5–1.7B 模型。「typed DSL＋治理＋MDL」仍是待實測的工程假說。

  • 單層固化省很多，巢狀組合可能反噬（arXiv 2603.00718）：原文事實（作者自報）：126 個受控工具任務中，GPT-5.2 Skill Mode 成功率 87%→90%、token 1.23M→0.26M；巢狀模式則讓成功率 90%→79%、token 回到 0.60M。實驗限受控 MCP 環境，跨模型只測 8 個 hard 任務。對本篇的意義：組合深度也是治理指標。摘要檔：2603.00718_SkillCraft.摘要.md

自我檢核

  1. 問：本篇的技能和 02 篇 option 最重要的差別是什麼？ 答：option 是策略與時間抽象；本篇技能是模型外部、可讀、可版本化並接受准入與退休治理的 artifact。
  2. 問：為什麼留著不用的技能也可能有害？ 答：它可能在檢索時遮蔽正確技能、增加選擇歧義與 context 成本；「沒有被正確執行」不等於「沒有影響決策」。
  3. 問：為什麼不能看到幾次失敗就退休技能？ 答：證據少時估值變異很大，冷門技能也可能尚未遇到適用情境；Ratchet 的過早退休消融確實跌破無技能基準。
  4. 問：MDL 為什麼不等於少走幾步？ 答：MDL 同時計入技能字典與軌跡分段成本，獎勵跨案例可重用片段；純步數只是一種退化固定碼。
  5. 問：typed skill 通過型別檢查後是否就可信？ 答：否。型別只排除介面不合，演算法錯誤、環境漂移、副作用與錯誤組合仍需測試、合約監控與回歸驗證。
