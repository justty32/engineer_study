04 · 經濟式智能把規則視為會競標、賺賠與淘汰的參與者，用市場機制把成果分回真正有貢獻的步驟

04 — 信用分配與經濟式智能

閱讀時間：約 18 分鐘

為什麼你會在意

本設計讓多個規則與技能共同完成任務，最後卻只收到一筆總結果。若不知道誰立功，保留與淘汰都會變成猜測。 甲路線的 bucket brigade 設計直接採用這族思想。本篇用 LCS、XCS、Hayek 機器與分潤方法，說清楚市場比喻在哪裡成立、又會在哪裡壞掉。

讀完後應能要求一份可稽核帳本，而不是只接受「規則彼此競爭，所以好規則自然留下」這種口頭保證。 有交易紀錄，才有辦法重建一次錯誤淘汰是怎麼發生的。

一、LCS 與桶隊：把規則鏈變成生產鏈

想解決什麼：系統由很多「條件→動作」小規則組成，最後做對一件事、拿到一筆獎賞。臨門一腳有功，前面鋪路的規則也有功。若只獎勵最後一條，早期步驟永遠學不到；若平均分，又會讓沒貢獻的規則搭便車。

信用分配不是付款動作本身。市場、財富與競標只是拿來實現歸因的機制。一條規則很有錢，可能只因運氣好或站在金流必經處，並不代表它真的有用。程式比喻是：請求成功回應 200，路由、快取、驗證與 handler 各自貢獻多少？

核心想法：John Holland 在 1970 年代提出學習分類器系統（LCS）。系統維護大量 classifier，每條規則有條件、動作與強度。環境送入訊息，符合條件的規則競標執行權；執行後依結果調整強度，再用遺傳演算法讓高分規則交配、變異，並淘汰弱規則。規則群是一個會演化的市場，不是寫死的決策樹。

Bucket Brigade（Holland, 1985）讓得標規則把標金付給上一輪觸發它的規則，自己再等下一輪規則付款。只有鏈末真正解題者從環境取得外部報酬。獎賞像水桶接力，一輪一輪往上游傳。能長期從下游需求賺回成本者，才被視為有貢獻。

假設三條規則依序完成「找到鑰匙 → 開門 → 抵達終點」。第三條拿到環境獎賞 10，第二條為使用第三條產生的狀態而收到付款，第一條再從第二條的出價得到收入。若「找到鑰匙」沒有讓後續規則願意買，它的財富會逐步下降。信用不是事後由中央平均分，而是由下游需求沿交易鏈回傳。

遺傳演算法處理的是更慢的時間尺度。競標與付款在每次行動更新規則強度；選擇、交配和變異則過一段時間才改變規則族群。前者回答現有規則該信誰，後者回答要產生哪些新規則。把兩個尺度混在一起，容易讓剛變異出的規則還沒試夠就被淘汰。

和相近理論差在哪：TD 也沿時間把價值往前一步回傳，但它直接更新數值估計；bucket brigade 用競標與規則間付款傳遞信用。PSP 則不逐步結算，而是等整個 episode 完成後一次分潤。

常見誤解與限制：金流不等於因果貢獻。回流要很多輪才到上游，學得慢；中途還可能出現只收錢不做事的寄生規則。若競標、付款與外部獎賞的會計帳不守恆，通膨也會讓強度失去比較意義。

二、ZCS 與 XCS：從「賺得多」改成「預測得準」

想解決什麼：早期 LCS 用累積強度判斷規則好壞。一條規則若常在高獎賞狀態附近被觸發，就可能變得很有錢，即使它的條件與預測根本不準。資源最後被「強卻錯」的規則佔住。

核心想法：ZCS（Wilson, 1994）把 LCS 砍成零階版本，去掉複雜記帳，以簡化 bucket brigade 與 strength-based 適應度研究極簡市場。它證明小型機制也能學，卻把強度式評分的問題暴露得更清楚。XCS（Wilson, 1995）把規則好壞改成 prediction accuracy：預測誤差小才有高適應度。

這一改讓系統偏好「在仍然準確的前提下，涵蓋範圍盡量廣」的規則。最後形成較完整、較少重複、通用度適中的規則地圖。XCS 還用 niching 讓規則只在相近情境內競爭，避免一條全域規則霸佔所有資源。

和相近理論差在哪：ZCS 問「規則累積拿到多少回報」；XCS 問「規則對回報的預測有多準」。前者混合使用頻率、環境位置與真能力，後者把預測品質和最終報酬拆開。這正是從財富代理轉向可檢驗預測。

常見誤解與限制：accuracy-based 不代表參數消失。XCS 仍要設定探索、遺傳演算法頻率、刪除壓力、誤差門檻與生態位行為。規則過早淘汰也會扼殺還沒累積足夠證據的新能力；2026 的 LLM 技能庫實驗再次量到這條邊界。

這套「累積貢獻、低於門檻便破產」的機制已在 2026 年 LLM 技能庫重現，技能如何經歷入庫、修補與退役可接著看19 技能庫的生老病死。本篇處理的是「規則之間怎麼分帳」；若要處理「改動之間怎麼分帳」，還要記 lineage、版本與回滾點，見18 自我改進與驗證器上限。

XCS 想得到的不是一條全域最準規則，而是一組在各狀態—動作 niche 內準確且盡量一般化的規則。條件太窄會形成大量特例，記憶與搜尋成本上升；條件太寬則把不同回報混在一起，預測誤差變大。accuracy pressure 與 generalization pressure 必須同時存在。

例如 10#1 → 左轉 裡的 # 可匹配 0 或 1。較多 # 的規則覆蓋廣，但只有在覆蓋範圍內都能維持低誤差時才值得保留。這和單純獎勵短規則不同：短而錯的概括不會因形式漂亮就取得高適應度。

三、PSP 與 Hayek 機器：何時結算，產權怎麼定

想解決什麼：逐步信用回流太慢，整集分潤又太粗。多個 agent 共同改變世界時，還必須定義誰擁有當前狀態、誰向誰買入，以及外部報酬從何處注入，否則「市場」只是一個沒有帳本的比喻。

核心想法：分潤計畫 PSP（Grefenstette et al., 1988）記住整集軌跡，等回合結束後，把獎賞一次分給本集使用過的所有規則。上游更快拿到信用，代價是難以細分誰真正不可或缺。

代價回流慢、易有寄生者要存軌跡，歸因較粗

Hayek 機器（Baum & Durdanović, 1998–2000）把市場做得更完整。想動手的 agent 競標目前世界狀態；得標者向上一位狀態持有者付款，執行動作後再把新狀態賣給下一位。只有解題者從環境取得外部報酬。私有產權、自由競標與自負盈虧共同形成局部信用鏈。Baum 曾用它處理魔術方塊與 blocks world。

Hayek 機器的「世界狀態所有權」很關鍵。若每個 agent 都能免費讀取並轉賣同一份狀態，付款就無法指出誰提供了必要中介結果。把狀態當成有來源的商品後，每次轉換才留下可稽核的供應鏈。代價是所有權規則也可能阻礙有用資訊共享。

和相近理論差在哪：PSP 只改結算時間；Hayek 機器還明確定義狀態所有權與交易。Agoric computing 把 CPU、記憶體與儲存當商品，重點是資源配置，不一定包含學習。Holland 的 Echo 則讓 agent 交易、戰鬥與繁殖，用來研究食物鏈、共生等組織如何湧現。

常見誤解與限制：市場不會自動產生效率或合作。寄生 agent 可以買進後原價賣出，通膨可讓貨幣失去尺度，壟斷與局部均衡也都會發生。Baum 用保守原則等規則堵漏洞，正好說明市場仍需要機制設計與稽核。

Agoric computing（Miller & Drexler, 1988）把 CPU 時間、記憶體與儲存視為可交易商品。程式模組付費呼叫服務，也為占用資源付租金。它關心的是分散式資源配置，不要求模組會學習；若拿來類比技能市場，必須另加能力評估與更新機制。

Echo 更靠近人工經濟生態。一群 agent 持有資源，會交易、戰鬥與繁殖，研究食物鏈、共生與組織如何湧現。Echo 能展示複雜結構出現，不代表湧現結構符合外部任務。觀察到分工之後，仍要以介入或消融確認它真是因果承重組件。

四、適應度共享、縮放與 Shapley 值：不要只留一個冠軍

想解決什麼：演化族群若讓最高分個體快速佔滿全部位置，會過早收斂。合作系統若只看團隊總分，也不知道某技能的內容價值是否抵得過它占用 context 與維護資源的成本。

核心想法：fitness sharing（Goldberg & Richardson, 1987）讓同生態位個體分攤分數，同類擠得愈多，每個拿得愈少，迫使族群分散探索。fitness scaling 壓縮貧富差距，避免選擇壓力過強。Shapley 值則從合作賽局出發，考慮參與者以不同順序加入聯盟時帶來的平均邊際貢獻。

具體說，三條都能解題的規則若擠在同一 niche，sharing 會降低它們的個別適應度，讓另一種少見策略有生存空間。若要替技能庫分潤，Shapley 式方法會比較「加入這個技能前後，合法技能組合的成效差多少」，而不是只看它出現過幾次。

和相近理論差在哪：sharing 與 scaling 改變演化選擇壓力；Shapley 值試圖估合作中的邊際貢獻。bucket brigade 沿實際時間鏈付款，Shapley 需要評估多種 coalition，計算與採樣成本更高。

常見誤解與限制：縮放過頭會抹平真實差異，讓好規則和差規則幾乎同機率繁殖。Shapley 值也不是唯一客觀真相；在依賴圖中只允許哪些 coalition、採樣哪些加入順序、如何計入 context 成本，都會改變最後數字。

sharing 還依賴距離度量。兩條規則算不算同一 niche，可以按條件字串、行為軌跡或產生的狀態來定；度量一換，稀有性就跟著變。若把語法差很多、行為卻相同的規則當成兩種，族群表面多樣，實際能力仍單一。

Shapley 的計算成本則隨參與者數量快速上升，通常只能採樣加入順序。技能又有依賴時，並非任何 coalition 都能執行：高層技能缺了底層工具便沒有意義。只在合法 coalition 上估值是必要限制，也使結果變成「特定依賴模型下的分潤」。

五、各方法怎麼選：先分清楚你在分什麼

想解決什麼：LCS、bucket brigade、PSP、XCS、Hayek、Agoric 與 Echo 都使用市場詞彙，很容易被混成同一種演算法。實作前若沒說清楚信用、資源與多樣性哪個才是目標，就無法設計對照實驗。

核心想法：可以把這個家族拆成四層：LCS 是規則觸發、競爭、繁殖與淘汰的骨架；bucket brigade 和 PSP 決定時間信用怎麼回流；ZCS 到 XCS 修正規則品質的評分；Hayek、Agoric、Echo 與 fitness sharing 分別處理產權交易、資源計價、組織湧現與多樣性。

和相近理論差在哪：中央排程器直接指定資源與責任；市場式方法讓局部價格或邊際貢獻聚合資訊。前者較容易驗證全域約束，後者較能分散決策，但不保證價格就是正確信用。

常見誤解與限制：至少要拿隨機搜尋、無信用回流、無淘汰或固定分潤當基線。只看總報酬會掩蓋誰在寄生、哪些規則被誤殺，以及多個同質 agent 是否一起犯同一個錯。

  • 多 agent 投票不等於可靠度相乘（arXiv 2608.12895）：原文事實（作者自報）：18,000 個 two-agent-handoff 任務的預註冊實驗中，兩個 mistral-small-24b agent 在至少一個失敗的任務裡有 90.0% 同時失敗（log OR=6.66，φ=0.916）；換成不同模型後，六個對比都顯著降低關聯。結果只涵蓋中型開源模型，模型身分與能力差異也未完全分離。對本篇的意義：同質參與者的失敗高度相關，不能把多票當成彼此獨立的可靠度乘法；市場裡的模型多樣性是風險控制，不是裝飾。摘要檔：2608.12895_AgentContractsII.摘要.md
  • 技能修補也要按規則型別分帳：ClawTrace（arXiv 2604.23853）：原文事實（作者自報）：OpenClaw＋gpt-5.4 的 CostCraft 完整版品質保留率為 83.3%、有 5 個衰退；拿掉 prune 修補後衰退增至 14 個。SkillsBench 跨 benchmark 遷移的 5 個品質變化事件完全按規則型別分流：preserve 導致 3 個衰退，prune 帶來 2 個改善。實驗只涵蓋單一 runtime／backbone，失敗類型由單一標註者編碼。對本篇的意義：聚合總分會藏住規則型別的不對稱風險；會計帳不只要記哪個技能改了，還要記這次改動是 preserve、prune 還是 repair。摘要檔：2604.23853_ClawTrace.摘要.md

一份最低限度的市場帳本應記錄：每次誰出價、誰得標、付款流向、外部報酬來源、規則被叫用次數、成功與失敗次數、淘汰原因，以及貨幣總量如何變化。沒有這些事件，就無法區分「有錢因為有用」和「有錢因為壟斷通道」。

消融也要對準機制。拿掉競標只測競爭是否有用；保留競標但打亂付款接收者，才測信用鏈是否真的對準上游；延後或提前破產門檻，則測證據量與淘汰速度。總分相同時，規則多樣性、錯殺率與恢復速度仍可能差很多。

若系統有三層，信用帳也要保留三種 id：這次外部任務、這條執行軌跡、被叫用的規則版本。技能更新後仍沿用同一名稱，卻沒有版本 id，歷史成功可能被錯算到新實作；規則被複製或合併後若失去 lineage，淘汰判斷也會把祖先與後代混在一起。

最後要區分「報酬少」和「證據少」。冷門但關鍵的規則可能一個月只被叫用一次，不能因財富低就當成無用；高頻規則則可能靠大量微小交易累積財富。用最少試驗數、信賴區間或保留期限制破產，目的都是先確保有足夠證據再作不可逆淘汰。
