09 · 認知架構談的不是單一演算法，而是一個會思考與行動的智能體，該怎麼安排記憶、注意力、模組分工與卡關後的重想

09 — 認知架構

閱讀時間：約 19 分鐘

為什麼你會在意

大模型能回答問題，不等於它已經是一個能持續行動的智能體。認知架構、接地與控制的設計參考需要的是感知、規劃、記憶、控制與重試的整體迴圈。這些老架構提供的不是現成模型，而是一張很實用的工程檢查表。

這篇講的是一群「整體設計藍圖」。當你想做一個會思考、會行動的智能體，光有一個聰明的模型還不夠，你得回答一堆工程問題：記憶要分幾種？同一時刻誰能佔用「注意力」？很多模組要怎麼合作？想不出答案時要怎麼辦？

不同年代的研究者給了不同答案，下面這幾套是最有代表性的。它們彼此競爭，但放在一起看，剛好把「組織一個心智」的各個面向都覆蓋到了。

最早大家以為「智能＝一個夠聰明的中央程式」。但這條路一直撞牆：中央程式太龐大、太脆、改一個地方就到處壞。於是有人開始問——會不會智能根本不是一個聰明核心，而是很多不那麼聰明的零件協作出來的？ 這幾套架構，多半是在回答「該怎麼把零件組裝成一個會思考的整體」。

一、去中心化的心智：心智社會與包容架構

想解決什麼：中央程式會越長越脆。Minsky 與 Brooks 都改問：能否讓許多局部能力合作，不靠一個全知總管？

核心想法：以下兩套架構從不同方向回答。

心智社會（Society of Mind；Minsky, 1986）

Marvin Minsky 的主張很反直覺：心智是由一大堆「本身沒有智能」的小 agent 拼出來的，沒有總指揮。 智能是這些笨零件互相呼叫、競爭、接力之後「湧現」出來的。

生活化例子：你「拿起一個杯子」這個動作，其實是「伸手」「張開手指」「抓握」「保持平衡」這些小程序彼此抑制、接棒完成的。沒有哪一個小程序懂「拿杯子」的全局意義——但合起來就做到了。寫程式的人可以想成：沒有一個 main() 在統籌，只有一堆互相觸發的小函式，行為從它們的互動中跑出來。

限制：Minsky 給的是哲學藍圖，不是能直接訓練的工程方案，落地很難。

包容架構 / 行為式 AI（Subsumption；Brooks, 1986）

Rodney Brooks 反對「先在腦中建一份完整世界地圖、再規劃」這套老做法，因為地圖又笨重又容易過時。他主張把智能拆成一疊「感知→動作」的反射層：避障層、漫遊層、探索層……每層獨立並行跑，高層只在必要時「壓制」低層的輸出。

他有句名言：「世界本身就是最好的模型。」 意思是與其在腦中維護一份隨時可能失準的地圖，不如直接去現場感測。

例子：掃地機器人不需要先畫出整個房間，它只要「撞到→轉向」「沒撞到→前進」這幾條反射層疊起來，就能在真實房間裡活動。限制是純反射很難做長程、抽象的規劃。

和相近理論差在哪：心智社會強調許多小 agent 的互動與湧現；包容架構強調感知到動作的並行反射層，以及高層對低層的壓制。前者是心智組織藍圖，後者更接近可部署的機器人控制架構。

常見誤解與限制：沒有中央總管，不代表沒有控制問題。心智社會難直接訓練；包容架構雖能快速反應，卻不擅長長程與抽象規劃。局部模組一多，衝突仲裁仍得有人負責。

二、有限舞台與雙記憶：GWT、ACT-R

想解決什麼：許多模組可以並行，但同一時刻哪些資訊能進入決策？事實記憶與操作規則又該如何分工？

核心想法：GWT 用競爭與廣播處理注意力，ACT-R 用兩種記憶處理知識取用。

全局工作空間理論（GWT；Baars, 1988 / Dehaene 後續神經實證）

這套要解釋的是意識：為什麼大腦裡那麼多平行的無意識歷程，最後只有少數內容能「被我們意識到、能講出來、能被全腦共用」？

核心機制：眾多專門模組同時並行，搶一個容量極小的「全局工作空間」（一個小舞台）。勝者把自己的內容「廣播」給全腦其他模組，於是它能同時被記憶、語言、決策取用——這就對應到「意識」。注意力，就是決定誰能擠上這個小舞台的篩選閘門。

程式化的比喻：一堆背景執行緒搶一個容量為 1 的全域廣播頻道，搶到的那個訊息會被廣播給所有其他執行緒共享。瓶頸（舞台很小）是刻意的，因為「全部同時意識到」反而無法形成連貫行為。

ACT-R（John Anderson；1990 年代起）

ACT-R 的招牌是雙記憶系統，而且要能對上人類心理實驗的反應時間數據：

  • 宣告性記憶（declarative）：存「事實」，像一塊塊知識（chunk）。例：「巴黎是法國首都」。
  • 程序性記憶（procedural）：存「怎麼做」，也就是 if-then 規則。例：「看到紅燈就踩煞車」。

認知就是這兩種記憶不斷比對狀態、觸發、改寫的循環。每塊知識還帶一個「激活度」，決定它被取用得多快、會不會被遺忘——常用的調得快、久沒用的就沉下去。

程式化的比喻：宣告性記憶像資料庫裡的事實表，程序性記憶像一堆 if-then 規則；激活度像 LRU 快取的熱度分數。

和相近理論差在哪：GWT 管的是「誰能被全系統同時取用」；ACT-R 管的是「事實與技能如何儲存、競爭與取回」。前者像容量為 1 的廣播頻道，後者像帶熱度的資料庫加規則引擎。

常見誤解與限制：工作空間瓶頸不是算力不足的瑕疵，而是形成連貫行為的設計；但容量與競爭規則很難設定。ACT-R 能對心理實驗反應時間提出預測，卻不是從大規模原始資料自動長出能力的通用訓練方案。

三、卡關後重想：SOAR 與專家系統

想解決什麼：規則系統最怕走到沒有規則可用的狀態。SOAR 把卡關變成新的問題；專家系統則把領域知識明確寫成可演繹規則。

核心想法：SOAR 是 Newell「統一認知理論」的旗艦實作，幾十年持續開發。幾個關鍵機制：

  • 問題空間搜尋：所有目標導向的行為，都看成「在一個問題空間裡，從目前狀態找路走到目標狀態」。
  • 產生式規則（production rules）：知識的唯一單位就是 if-then 規則。系統不斷比對「現在的狀態符合哪條規則」，然後觸發它。
  • 卡關→自動開子目標（impasse → subgoal）：當現有規則不足以決定下一步，SOAR 會自動生出一個子目標去專門解決這個卡關，而且可以遞迴往下開。這就是「想不出來時，自動退一步去想一個更小的問題」。
  • Chunking（組塊化）：解掉一個子目標之後，SOAR 把「這次的解法過程」總結成一條新規則存起來。下次遇到同樣情況，直接套規則，不用再從頭搜尋。這是它的核心學習機制。

後期版本還加上了強化學習、情節記憶、語意記憶。

專家系統 / 語義網路 / 知識圖譜

1970–80 年代 AI 的主流。專家系統把領域知識寫成「事實＋if-then 規則」，再由推理引擎做演繹（經典例子是醫療診斷系統 MYCIN）。語義網路用節點代表概念、用邊代表關係（is-a「是一種」、part-of「是一部分」），把知識組織成一張網——這就是今天「知識圖譜」的前身。

限制都一樣：知識要人工一條條灌進去，又脆、又難處理例外與不確定性。這也是為什麼後來資料驅動的機器學習取而代之。

和相近理論差在哪：專家系統遇到缺規則通常只會失敗或要求人工補；SOAR 把 impasse 本身變成可遞迴處理的子目標，並把解法編回規則庫。

常見誤解與限制：chunking 不是理解的保證。若子目標的條件抓錯，新規則只會更快重現舊錯誤。人工規則也會面臨例外爆炸、維護成本與不確定性處理困難。

四、共享工作面：黑板系統與 2026 變形

想解決什麼：多個專家若彼此直接呼叫，依賴關係很快纏成一團。黑板系統讓模組只讀寫共享狀態，降低耦合。

核心想法：

黑板系統（Blackboard；Hearsay-II，1970 年代 CMU 語音辨識）

為了讓「好幾個各有專長、但誰也不夠強」的模組合力解一個難題而生。做法是：這些「知識源」不直接互相呼叫，而是讀寫同一塊共享的「黑板」。 誰看到自己能補上一塊，就上去黑板寫一筆，逐步把零碎的局部猜測拼成完整解答。

例子：解一道難題時，叫來幾位各有專長的專家，圍著同一塊白板。誰想到一段就上去寫，別人看到後接著補。優點是模組鬆耦合、好增刪；限制是「誰該何時動手」這個控制流本身很難設計。

2026 的 SCL 把 Retrieval、Cognition、Control、Action、Memory 五模組放進受 Regulation 管理的迴圈；CORAL 則讓多個 agent 透過檔案系統式的 attempts、notes、skills 共享持久記憶。兩者都保留「不直接互叫，透過共享工作面合作」的黑板精神。

和相近理論差在哪：傳統黑板由中央排程器決定知識源何時動手；CORAL 不預設通訊拓撲，協調更去中心化。SCL 則刻意讓神經模組生能力、符號控制層做治理。

常見誤解與限制：共享黑板不會自己解決控制流。誰可以寫、衝突如何合併、何時終止、錯誤資料怎麼回滾，都要另訂規則。共享記憶若被污染，也會把錯誤廣播給所有模組。

常見誤解與限制

  • 「認知架構＝在模仿大腦」：不完全是。它們更像「組織一個會思考系統的工程藍圖」，靈感取自人類認知，但目的不是證明系統「像人」，而是提供清楚的模組邊界。
  • 它們多半是符號式的、要人工灌規則：在深度學習當道的今天，純符號架構難以從資料中自己長出能力——這是它們共同的痛點。
  • 這些不能直接合併成單一演算法：比較合理的用法是「分別當參考」，例如借 GWT 的注意力瓶頸、借 SOAR 的卡關重思、借 ACT-R 的雙記憶。

把架構翻成可執行的迴圈

一個最小 agent 可以把上述思想排成固定循環：感知模組把環境寫入工作記憶；規劃器從目標與事實產生候選計畫；控制器挑一個動作；執行器回報結果；記憶模組保存成功、失敗與原因。若前置條件已不成立，計畫立即作廢並重規劃。這個循環同時借了黑板的共享狀態、SOAR 的卡關處理與 ACT-R 的記憶分工。

observe → update memory → propose plan → validate → act
   ↑                                            │
   └──────────── failure / changed world ───────┘

實作時最容易漏掉的是資料所有權。工作記憶應有明確 schema，標記每筆事實的來源、時間與信心。規劃器可以提出候選，不能直接竄改感測事實；執行器可以回報成敗，不能自行把失敗寫成成功。模組邊界若只存在於架構圖，實際上仍共用一個可任意修改的物件，就沒有治理效果。

第二個陷阱是把「記住」當成「學會」。黑板保存一次成功軌跡，只代表下次能檢索；SOAR 的 chunking 還要抽出成立條件，ACT-R 還要處理取用競爭。若規則過度具體，只能重播；若過度一般化，會把偶然成功套到不相干情境。因此每個新技能都要帶前置條件、效果、失敗案例與版本。

第三個陷阱是沒有終止規則。多個模組一直在黑板補充內容，看似忙碌，任務卻沒有進展。控制器應量測狀態是否真正改變、同一工具是否重複呼叫、資源預算是否耗盡。SCL 的去重、容錯上限與終止判定，就是把傳統黑板最難的調度問題寫成確定性控制。

以「替使用者訂一段行程」為例，Retrieval 只負責取得車次與旅館資料；Cognition 產生候選；Control 檢查日期、預算與重複預訂；Action 才能呼叫外部服務；Memory 保存已確認選擇。若日期改變，舊計畫不該由每個模組自行猜測是否仍有效，而要由共同狀態標成 stale，再觸發重規劃。這就是認知架構把日常例外變成一般控制規則的價值。

同一例子也顯示 GWT 與黑板的差別。黑板可以同時保存很多候選與事實；工作空間只廣播當下最需要全系統處理的一件事，例如「轉車時間不足」。若把整塊黑板全部廣播，每個模組都要重讀大量無關資訊；若工作空間沒有保留來源連結，勝出訊息又會失去證據。因此小舞台應傳遞摘要與指標，完整內容留在可追溯記憶。

記憶還要分時間尺度。工作記憶保存本輪狀態，情節記憶保存某次任務的事件序列，語意記憶保存較穩定的事實，程序記憶保存可執行技能。把四者塞進同一向量庫，檢索雖方便，更新規則卻會混亂：一次失敗可能誤改長期事實，一條過期事實也可能被當成技能。ACT-R 與 SOAR 的老分法，在現代 agent 上仍是資料治理的好起點。

最後要用故障注入驗收架構，而不是只跑成功 demo。讓感測資料延遲、規劃器回空集合、工具重複回應、記憶出現衝突，再看系統是否能停下、開子目標或回滾。認知架構的好壞，不只看正常路徑能不能完成，也看模組失靈時錯誤是否被限制在清楚邊界內。

這也解釋了為什麼架構文件要列出狀態機，而不能只畫模組方塊。方塊告訴你有哪些零件；狀態機才說明誰有權讓任務從「候選」走到「已執行」，失敗又回到哪一步。沒有這些轉移條件，模組化只是檔名不同，行為仍無法稽核。可稽核，才有資格安全地自動重試，也才能逐步找出究竟是哪個模組失靈。

一句話總結

認知架構回答的是「一個會思考的東西內部要怎麼擺放」——記憶分幾種、注意力給誰、模組怎麼協作、卡關了怎麼自動退一步重想。

為什麼有人會對它感興趣：因為現在的大模型很強，但「整體怎麼組織成一個會持續行動的智能體」這件事，這些老架構早就把問題拆得很清楚，是很好的設計清單。
