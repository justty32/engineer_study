00A · 不預設你懂機器學習數學

機率、函數、參數、損失、梯度與最佳化

白話問題：訓練時常見的數學字眼到底在做什麼？一句話答案：函數負責把輸入變輸出，參數決定函數目前的形狀，損失把「差多遠」變成一個數，梯度指出哪個參數方向會讓損失增加最快，最佳化器再往相反方向走一小步。

最小前置：懂四則運算、座標與 C++ 函式即可。公式是精確說法，不需要先背。

函數與參數：可調整的程式

函數（function）是輸入到輸出的規則。最小例子是 y = wx + b：x 是輸入，y 是輸出，w 與 b 是參數（parameter）。假設關節誤差 x=0.2 rad，目前 w=3、b=0，輸出便是 0.6。訓練不是改掉公式的呼叫介面，而是尋找較好的 w 與 b。神經網路只是把大量這類簡單運算接在一起，參數數量很多，基本角色沒有改變。

量綱必須先對上。若 x 是 rad、y 是 rad/s，則 w 的量綱是 1/s，b 的單位是 rad/s；「w = 3」應完整讀成 3 1/s，才能得到 y = 3 1/s × 0.2 rad = 0.6 rad/s。rad 在量綱分析常視為無因次，但工程介面仍應標示它是角度，避免和圈數或度混用。若輸入先做正規化，部署端也必須使用訓練時同一組尺度。

函數不等於因果：模型觀察到 x 與 y 可被某函數擬合，只表示在資料範圍內有預測關係。若 x 其實是場景暗號，改變 x 不一定會物理地造成 y 改變；要主張因果，還需要實驗設計或領域機制。

損失：把「不好」寫成可計算的數

損失函數（loss function）比較預測與期望。例如期望速度 1.0，模型輸出 0.6，平方誤差是 (0.6-1.0)²=0.16；若輸出改成 0.9，損失變成 0.01。損失越小只代表更符合這個定義。若你只懲罰位置誤差、不懲罰高速，模型可能快速撞向目標；數學正確，目標卻寫錯。整個資料集通常取平均損失，避免單筆資料主宰判斷。

以三筆速度誤差 −0.4、0.1、0.2 m/s 為例，均方誤差 MSE = ((−0.4)2 + 0.12 + 0.22) ÷ 3 = (0.16 + 0.01 + 0.04) ÷ 3 = 0.07 (m/s)2。開根號得到均方根誤差 RMSE = √0.07 ≈ 0.265 m/s，才回到速度單位。MSE 會讓大誤差權重較高；這是設計選擇，不是唯一正確的損失。

梯度與最佳化：往哪裡調、一次調多少

梯度（gradient）可以看成每個參數旁的一張敏感度表：參數增加一點，損失大約變多少。若某參數梯度是 +4，增加它會讓損失上升，所以梯度下降（gradient descent）往負方向更新：新參數 = 舊參數 − 學習率 × 梯度。舊參數 3、學習率 0.01、梯度 4，更新後是 2.96。學習率太大可能跨過好位置並震盪，太小則進展很慢。最佳化器（optimizer）是實際決定更新步幅的演算法；它找到的是對資料與損失較好的參數，不保證找到唯一或全域最好答案。

把符號寫完整就是 θnew = θold − η∂L/∂θ，其中 θ 是參數，η 是學習率，∂L/∂θ 是損失對參數的偏導數。若 θ 單位為 1/s、L 單位為 (m/s)2，梯度量綱是 L 除以 θ；實作中的 η 因參數化與損失縮放而承擔相應尺度，不能把不同損失定義下的學習率直接照搬。自動微分能精確套用鏈式法則，卻不會替你檢查目標是否合理。

一維導數從哪裡來

若 L(θ) = (θ − 3)2，則梯度是 2(θ − 3)。在 θ = 5 時，梯度為 4；取 η = 0.1，更新為 5 − 0.1×4 = 4.6。再算一次損失：原本 L = 4，更新後 L = (4.6 − 3)2 = 2.56，確實下降。這只證明此步對這個光滑一維函數有效；多維非凸問題可能有平台、鞍點、雜訊與梯度爆炸。

機率：不是神祕信心值

機率（probability）是對不確定結果的數值描述，範圍 0 到 1。若策略對三個動作給出 0.7、0.2、0.1，表示依其模型設定抽樣時，第一動作較常被選；它不等於「有 70% 機率安全」。期望值（expected value）是依機率加權的平均：成功得 10 分且機率 0.8，失敗得 −20 分且機率 0.2，期望是 0.8×10+0.2×(-20)=4。平均為正仍容許嚴重失敗，機器人安全不能只看平均。

隨機變數（random variable）是把每種隨機結果對應到數值的規則。上例令 R 代表回報，則期望 E[R] = Σipiri = 4 分；機率 pi 無單位，ri 是分，因此期望仍是分。若做 10 次得到平均 4 分，不足以證明真實期望恰為 4；還要報樣本數、變異與抽樣條件。

條件機率：策略真正使用的形式

π(a∣s) 表示「已知狀態 s 時，選動作 a 的機率」。例如在杯子偏右的狀態，向右、向左、停止的機率為 0.8、0.1、0.1，三者總和為 1。換到杯子偏左的狀態，整組機率應改變。π(a∣s) 描述策略的抽樣規則，不等於環境做完動作後成功的機率。

批次、訓練與驗證

一次用少量資料估梯度，這一組叫小批次（mini-batch）；看完整批次後更新不是必要條件。訓練集用來改參數，驗證集用來挑設定，測試集只在最後估未知資料表現。若測試資料參與正規化、挑模型或反覆決策，它已不再是獨立證據。

假設有 1,000 筆訓練資料，小批次大小 100：走完 10 個小批次稱為一個訓練週期（epoch），通常發生 10 次參數更新；訓練 20 個 epoch 約使用 200 個小批次更新，但每筆資料會被重看約 20 次。epoch 多不等於新增證據，只是更反覆配合既有資料。

從操作到證據：怎麼知道數學管線真的照預期走

  1. 操作：固定一個小批次與亂數種子，執行一次前向計算、反向計算與更新。
  2. 狀態變化：先產生預測與損失，再產生各參數梯度，最佳化器狀態與參數隨後改變。
  3. 結果：以足夠小的步幅，對同一批資料重算的損失通常應下降；若不降，要查梯度符號、尺度、非有限值與模型模式。
  4. 證據：訓練 log 與參數雜湊可證明執行過哪次更新；有限差分可抽查梯度，但只驗局部數值實作，不能證明泛化或安全。
可觀察證據：記錄每次更新的學習率、損失、梯度大小、參數是否出現 NaN（非數值）、訓練與驗證差距。這些能診斷數值與過度配合資料，不能直接證明真機安全。
不要混淆：參數不是手動設定的超參數；損失不是任務成功率；梯度不是每個動作的物理方向；模型輸出的機率也不是經校準的真實世界頻率，除非另做校準檢驗。

先拆掉數學恐懼：符號只是欄位名稱

沒有這層翻譯，讀訓練論文時很容易把 θ、L、∂ 當成三個神祕操作，最後只能背公式。其實 θ 可當成「所有可調欄位的集合」，L 是一個回傳不好程度的函式，∂L/∂θ 是「某欄位微調時，L 對它有多敏感」。寫成 C++ 心智模型，就是 loss = evaluate(model.parameters, batch)，再由自動微分產生每個參數的敏感度。符號比程式短，但沒有增加超自然能力。

比方說 θ 只有兩個欄位 w 與 b，模型 y = wx+b。令 x = 2、目標 y* = 5、w = 1、b = 1，先算 y = 1×2+1 = 3，再算誤差 e = y−y* = −2，平方損失 L = e2 = 4。若把 w 改成 1.1，y = 3.2、L = (3.2−5)2 = 3.24；小幅增加 w 讓損失下降。這就是梯度要濃縮的局部資訊。

用有限差分親手驗一次梯度

即使還不會導數，也能用「往右試一小步、往左試一小步」估斜率。對 L(θ) = (θ−3)2，取 θ = 5、h = 0.01：L(5.01) = 2.012 = 4.0401；L(4.99) = 1.992 = 3.9601。中央差分為 [L(5.01)−L(4.99)]÷(2h) = (4.0401−3.9601)÷0.02 = 4，正好接近解析梯度 2(5−3)=4。

再換 θ = 2：L(2.01)=0.9801，L(1.99)=1.0201，估計梯度 (0.9801−1.0201)÷0.02 = −2。負號表示 θ 增加會讓損失下降，所以更新式減去負梯度，θ 反而往右增加。若想把「斜率是輸入微小變化造成的輸出變化」從圖形與數字重新建立，可讀機器人數學基礎第 11 章：變化率、導數與梯度。

有限差分能證明什麼：在 h 不太大也不太小時，它可抽查程式算出的梯度方向與尺度；它不能證明損失定義合理，也不能保證沿這個方向走很遠仍下降。浮點誤差、非平滑函式與隨機層也會干擾檢查。

多個參數只是多個方向，不是另一種魔法

假設 L(w,b) = (2w+b−5)2，目前 w=1、b=1，前面算得誤差 −2。此時 w 增加 0.1 會讓輸出增加 0.2，而 b 增加 0.1 只讓輸出增加 0.1，所以 L 對 w 的敏感度是對 b 的兩倍。梯度為 (∂L/∂w, ∂L/∂b) = (−8,−4)。取學習率 η=0.05：wnew=1−0.05×(−8)=1.4，bnew=1−0.05×(−4)=1.2。新輸出 2×1.4+1.2=4，損失從 4 降到 1。

但若 η=0.5，會得到 w=5、b=3，新輸出 13，損失變成 64，反而更糟。方向在原點附近是下降方向，不代表任意大步都好。真實最佳化器還會做動量、逐參數尺度調整或權重衰減；這些機制改善數值行為，仍不能修正錯誤標籤與錯誤任務目標。

機率與平均值要連同風險一起讀

假設策略 A 有 99% 機率得到 1 分、1% 機率得到 −100 分，期望為 0.99×1+0.01×(−100)=−0.01 分；策略 B 永遠得到 0 分，期望反而較高。若災難成本改成 −10，A 的期望變成 0.89 分，但那 1% 事故仍可能不可接受。期望值把整個分布壓成一個平均，沒有保留尾端風險。

用 100 次試驗觀察到 0 次事故，也不能推論事故機率為 0；只能說這批有限樣本沒看到。若要補「機率、條件機率、期望與樣本」的直覺，見機器人數學基礎第 12 章：機率一點點。評估時應同時報成功率、失敗類型、樣本數、場景分層與不確定區間。

想更深入：把常見名詞一對一拆開
  • 參數（parameter）：訓練會更新的 w、b 或網路權重；超參數（hyperparameter）是學習率、批次大小等訓練設定。
  • 損失（loss）：單筆或小批次用來更新的量；指標（metric）是供人判讀的成功率、RMSE 等，兩者可以不同。
  • 梯度（gradient）：參數空間的局部敏感度；它不是機器人在 x、y、z 空間應移動的方向。
  • 機率輸出：是模型按其訓練形成的數字；只有經過可靠性檢驗，才能把 0.8 解讀成長期約八成發生。
  • 訓練誤差：看過的資料上有多合；泛化誤差：新資料上有多合。前者接近零也可能只是記住資料。
