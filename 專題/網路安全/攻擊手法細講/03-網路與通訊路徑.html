03 / 網路與通訊路徑

通訊路徑可被觀察、延遲、重放或改寫

網路本身負責傳遞，不保證名稱、端點、內容或時間的新鮮度。安全協定必須明確補上這些性質。

先修：位址、連接埠、封包、路由與傳輸狀態及傳輸層安全性協定。

先建立直覺

送得到、送對人、內容沒變，是三個不同保證

網路像一組會轉寄訊息的佇列與路由器：它主要解決可達性，不自動知道名稱對應是否真實、路徑上的節點是否可信，也不保證舊封包不會再出現。傳輸層安全性協定（Transport Layer Security, TLS）等安全協定，才把端點身分、完整性與機密性加到傳輸之上。

加密也不是隱形斗篷。被動觀察者通常仍可看到來源與目的位址、時間、方向及密文長度；主動路徑攻擊者也可能丟棄或延遲封包。應用必須另外處理交易唯一性、重試與冪等性。

切換情境時，先把能力分成只能送封包、可看到回程、位於同一區域網路、控制名稱解析，或能成為實際中繼。能力不同，能觀察與改寫的範圍也不同；「中間人」不是任何網路異常的通稱。

重放的數字直覺

假設接收端只接受序號 n 且維護最高序號 nmax。已處理 n = 4201 後，再收到 n = 4201，因 n ≤ nmax 而拒絕。若重啟後遺失 nmax，同一訊息可能再次被接受。此簡化模型假設訊息依序抵達；真實網路需容許有限亂序窗並持久化去重狀態。

證據的互補

封包擷取能顯示握手順序與重傳，但擷取點只看得到其所在路徑。DNS、鄰居表與路由表能顯示當時的控制狀態；憑證日誌能顯示驗證結果。單一抓包不能證明整條端到端路徑沒有其他觀察者。

  • 偵察不等於入侵：探測增加攻擊者知識，未必改變目標狀態。
  • 重傳不等於重放：TCP 重傳維持同一傳輸；應用重放是舊動作被再次接受。
  • 代理不等於惡意中間人：授權反向代理可終止 TLS；是否越界取決於架構信任與憑證驗證。
  • 名稱正確不等於端點可信：DNS 回覆仍須由應用層身分驗證收尾。

看到加密流量仍能觀察端點、時間、大小與方向；看到明文流量也不代表其中一定含秘密。證據結論必須對應資產與協定語意。
