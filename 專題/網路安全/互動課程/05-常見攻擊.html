05 / ATTACKS

攻擊是因果鏈，不是魔法名稱

一句話答案：攻擊者利用可達入口與弱點，借用或改變真實機制，使系統進入非預期狀態；每一步都可能留下不同層次的證據。

這章假設已懂：資產、攻擊者能力、信任邊界與控制。本頁只做防禦導向的機制概觀，不提供針對真實目標的操作步驟。

把攻擊名稱還原成系統行為

看到「注入」「中間人」或「供應鏈攻擊」時，不要先背工具名稱。先問正常系統原本會做什麼：解析輸入、接受憑證、載入相依元件或分配資源。攻擊者不是創造魔法，而是讓既有機制在錯誤的輸入、身分或信任假設下工作。

一條可診斷的敘述至少包含：必要前置 → 被濫用機制 → 安全狀態改變 → 對資產的結果 → 可阻斷或發現的控制 → 證據。少任何一段，都容易把症狀誤當根因。

怎麼玩這個實驗

每選一類攻擊，先遮住標題，只讀「必要前置」與「真實機制」，嘗試自己預測狀態改變；再用畫面核對。這能訓練你從機制推結果，而不是看到名稱就套固定產品。

接著比較不同類別的證據層次：憑證冒用需要身分與工作階段，注入需要應用、程序或資料庫，資源耗盡則需要請求率、佇列與主機資源。單一工具不可能同時具有所有語意。

此工具以一條主因果鏈教學。真實事件常把多類串接，例如先竊取憑證，再橫向移動，最後匯出資料；防禦與調查必須保留跨階段關聯。

常見手法按被濫用的機制分類

身分與社交工程

釣魚、密碼重用、工作階段竊取都試圖取得或繞過身分保證。關鍵不是郵件長相，而是攻擊者最後取得哪種憑證或工作階段。

輸入與記憶體

注入讓資料被解譯成指令；記憶體破壞則讓程序控制流或資料結構偏離設計。參數化介面、記憶體安全、隔離與低權限共同縮小後果。

網路位置與協定

竊聽、重放、冒牌名稱解析與中間人攻擊濫用網路可觀察或可改寫性。加密還要搭配端點身分、時效性與重放防護。

權限與橫向移動

攻擊者取得第一個立足點後，尋找額外憑證、過大權限與可達服務，擴大控制範圍。網路分段若沒有服務身分與授權，只是增加路徑障礙。

可用性

分散式阻斷服務（Distributed Denial of Service, DDoS）由多來源消耗頻寬、連線、中央處理器、記憶體或昂貴下游。防禦需要找到真正稀缺資源。

供應鏈

攻擊者改變原始碼、相依元件、建置環境、簽章或更新路徑，借用既有信任大規模散布。來源與成品的可追溯性是核心證據。

進階分支的讀法

「常見攻擊手法細講」會把每一類再拆成：系統前置 → 攻擊者能力 → 被濫用機制 → 狀態改變 → 控制 → 封包／日誌證據 → 反例。它不會把工具輸出當成理解，也不會提供武器化命令。

以資源耗盡建立量化直覺

假設一個請求平均占用服務時間 s 秒，穩態到達率為 λ 次/s，單一工作者的粗略利用率可寫成：

ρ = λ × s

ρ 無單位；在這個簡化、平均化且只有一名工作者的模型中，ρ 接近 1 時等待容易快速上升。例：每次平均占用 s = 0.02 s，正常 λ = 30 次/s，ρ = 0.6；若升到 λ = 55 次/s，ρ = 1.1，需求已超過單一工作者平均處理能力。

這不是實際容量保證：真實系統有多工作者、突發流量、快取、鎖競爭、下游與不同成本的請求。流量紀錄能量到到達率，主機遙測能看到中央處理器（Central Processing Unit, CPU）、記憶體與佇列；兩者都不能單獨證明流量具有惡意意圖，也可能是正常熱門事件或程式回歸。

一條跨層攻擊鏈範例

  1. 操作：攻擊者使用遭竊工作階段呼叫原本合法的匯出介面。
  2. 狀態變化：身分層接受工作階段，應用授權若範圍過大便建立大量資料讀取，資料庫與網路隨之輸出。
  3. 結果：沒有漏洞錯誤訊息，仍可能造成機密性破壞；每個單次請求都看似正常。
  4. 證據：登入地點或裝置變化、工作階段識別碼、授權物件範圍、查詢筆數與輸出位元組數合起來才支持推論。

異常登入告警不能證明資料已外洩；大量回應位元組也不能證明攻擊者實際保存或閱讀內容。調查結論要把「直接觀察」與「合理推論」分開。

常見誤解／不要混淆

  • 弱點 ≠ 已遭利用：掃描或版本資訊支持「可能存在」，實際狀態改變需要執行與資產證據。
  • 惡意程式 ≠ 初始入口：它可能是釣魚、相依竄改或既有立足點之後的載荷。
  • 注入 ≠ 只有資料庫：任何把資料送進命令、模板、查詢或其他解譯器的邊界都可能混淆控制與資料。
  • DDoS ≠ 所有服務中斷：設定錯誤、容量不足、依賴失效與部署回歸也會有相似症狀。
  • 阻擋指標 ≠ 移除根因：封鎖某個位址或檔案雜湊只涵蓋已知表現，攻擊者可換路徑。
