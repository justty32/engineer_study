10・頻譜與功率共同面對的天花板

頻譜效率與 Shannon 極限：容量不是建議值，而是不可跨越的上限

1 MHz、20 dB 的理想通道容量是 6.658211 Mbit/s。64-QAM 可送 6.000000 Mbit/s，看似很接近，卻仍有 8.486430 × 10−3 的位元錯誤率。

這章假設已懂：09 數位調變與星座圖的頻譜效率與08 匹配濾波器與位元錯誤率的 Eb/N0。

痛點：位元率低於容量，為什麼實際傳輸還是會錯

看到 Rb 小於 C，常有人直接下結論：「既然沒超過容量，就一定可靠。」這把 Shannon–Hartley 容量與某個具體星座的表現混成一件事。容量只說存在一套足夠長、足夠理想的方法，可以讓錯誤機率任意小；它沒有保證未編碼的 64-QAM 自動獲得那種能力。

另一個痛點是把頻寬與功率分成兩張互不相干的表。工程上它們其實由 η 接在一起：同一個 SNR，若每赫茲硬塞更多位元，每位元分到的能量就更少；反過來，把 η 壓得很低可以靠更寬頻寬省功率，但頻寬不是免費資源。這一章要找的不是單一最佳點，而是任何方案都必須待在其下方的天花板。

這也解釋了為什麼只報峰值速度沒有意義。少了頻寬、接收 SNR 與容許錯誤率，速度數字既無法比較功率代價，也無法判斷是否可達；完整問題一定要把三者放在同一個工作點上。

白話直覺：容量像房間的消防上限，不代表每種排隊方式都順暢

可以暫時把容量想成房間的法定人數上限：低於上限只是「有可能安排得下」，不保證眼前的動線設計不塞車。比喻到此為止，精確說法是：在給定頻寬 B 與 SNR 的 AWGN 模型中，C ＝ B log2(1 + SNR) 是可達位元率上界；具體調變仍有自己的點距與錯誤率。

沿因果鏈走一次。來源是平均訊號功率 S，接收頻寬 B 內累積雜訊功率 N；選定星座後，每符元攜帶 k 個位元，於是 η ＝ Rb/B 在 α ＝ 0 時近似為 k。這個決定換到較高位元率，卻使 Eb/N0 ＝ SNR/η 下降。當 Rb 超過 C，不論接收機多昂貴都不能把錯誤率壓到任意小；當它低於 C，也只是取得可能性，仍要看實際方案離天花板多遠。儀器可以量 SNR 與錯誤率，卻不能直接量出一個「容量粒子」。

頻譜效率（spectral efficiency）η 的單位是 bit/s/Hz；功率效率（power efficiency）以達到目標錯誤率所需的 Eb/N0 衡量。軟體那一端，Wi-Fi 的速率自適應會依量到的 SNR 選 MCS；每次升降檔，都是在這條取捨曲線上移動。

來源：14-通訊系統-下 §12。

推導：從功率帳反解每赫茲的最低能量

第一步，連接 SNR 與 Eb/N0。每位元能量乘每秒位元數得到訊號功率：S ＝ Eb × Rb；單邊雜訊功率譜密度乘接收頻寬得到雜訊功率：N ＝ N0 × B。兩式相除，SNR ＝ S/N ＝ (Eb/N0) × (Rb/B) ＝ (Eb/N0) × η。S、N 用 W，Eb 用 J，Rb 用 bit/s，B 用 Hz；兩個比值皆無單位。

第二步，把容量改寫成能量下界。在邊界 Rb ＝ C，將 SNR ＝ η Eb/N0 代入 C ＝ B log2(1 + SNR)，兩邊除以 B，得到 η ＝ log2(1 + η Eb/N0)。移項後 2η ＝ 1 + η Eb/N0，所以 Eb/N0 ≥ (2η − 1)/η。η 越高，最低能量比越快上升。

第三步，取得寬頻極限。當 η → 0，用 2η ＝ eη ln 2 ≈ 1 + η ln 2，便得 (2η − 1)/η → ln 2 ＝ 0.693147，換成 dB 是 −1.591745 dB。這個 Shannon 極限只在頻寬趨於無限、頻譜效率趨於零時成立；它不是 η ＝ 6 的門檻。

第四步，看高 SNR 的代價。SNR 遠大於 1 時，C/B ＝ log2(1 + SNR) ≈ log2 SNR。要讓 C/B 增加 1 bit/s/Hz，SNR 約要乘 2，也就是增加約 3 dB。因此高階星座並非免費把速度往上堆，而是持續付更高功率。

模型邊界。本課用的是一階教學模型：AWGN、頻寬受限、α ＝ 0、平均功率固定。Shannon 結果是理論存在性上限，不包含延遲、封包開銷、同步誤差與硬體非線性。如何靠編碼逼近上限留給數位通訊課。

數字回答了痛點：6.000000 Mbit/s 的確低於 6.658211 Mbit/s，但未編碼 64-QAM 仍不是達成容量定理的理想方法。容量／位元率 1.109702 只代表尚未撞天花板，不代表位元錯誤率已合格。

量級與邊界對照。QPSK（η ＝ 2）同條件 → Rb 2 Mbit/s、Eb/N0 16.989700 dB、Pb 7.619853 × 10−24，浪費了 4.658211 Mbit/s 的容量換到極低錯誤率；η ＝ 2 的最低 Eb/N0 1.760913 dB。16-QAM → Eb/N0 13.979400 dB、Pb 2.904081 × 10−6，不加編碼剛好可用；最低為 5.740313 dB。

SNR ＝ 10 dB 選 16-QAM → C ＝ 3.459432 Mbit/s < 4 Mbit/s，超過容量，任何編碼都救不回；SNR ＝ 0 dB、BPSK → C ＝ 1.000000 Mbit/s ＝ Rb，剛好碰到容量；SNR ＝ −10 dB → C ＝ 0.137504 Mbit/s，BPSK 超過容量。SNR ＝ 40 dB → C/B ＝ 13.287857，64-QAM 只用了 45 %；B ＝ 20 MHz、20 dB → C ＝ 133.164230 Mbit/s，是 Wi-Fi 一條 20 MHz 頻道的量級；SNR ＝ 17 dB 選 64-QAM → C ＝ 5.675780 < 6，超過容量。

自由實驗：把方案放到 Shannon 天花板下

場景是一條頻寬與平均接收功率都受限的 AWGN 鏈路。調整頻寬、SNR 與星座，回饋會比較方案位元率和容量，並算出當前 η 的最低 E_b/N_0，判斷是撞上天花板，還是只因方案本身離天花板太遠。

不要混淆

  • 容量是存在性上限，不是某個具體方案的錯誤率；未編碼 64-QAM 在容量內仍可錯 0.85 %。
  • 頻譜效率與功率效率是一條曲線上的取捨，不能在固定資源下同時無限制改善。
  • −1.591745 dB 只屬於 η → 0 的極限；η ＝ 6 時的最低門檻是 10.211893 dB。
  • SNR 與 Eb/N0 相差 η；同一 SNR 下，η 越大，每位元分到的能量比越小。
  • 增加 B 會讓容量隨之增加，但若接收功率固定，實際 SNR 也會因累積更多雜訊而改變；自由實驗是把 B 與 SNR 當獨立教學參數。

可觀察證據：量 SNR、錯誤率與最高可用檔位

用什麼量。用向量訊號分析儀量實際鏈路的 SNR，再用位元錯誤率測試儀逐一測各個 MCS，記下仍達目標錯誤率的最高 η，最後與 log2(1 + SNR) 比較。

能證明什麼。量測能證明一個實作在指定條件下用了容量的多少比例，也能找出由硬體、同步與具體方案共同造成的實作缺口；若 Rb 接近 C 而錯誤率仍高，就能看出「容量內」不等於「未編碼可用」。

不能證明什麼。有限次量測不能證明容量定理本身，也不能由某次成功傳輸宣稱已越過容量。儀器只能顯示實作沒有超過上限，以及工作點離上限多遠。
