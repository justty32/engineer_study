06・不做算術，只做選擇與翻譯

多工器、解碼器與編碼器：一顆多工器就是一張可以接線的查表

這四個元件都不算加減乘除，只回答「要哪一條」與「這個碼是哪一條」。多工器還有一個常被忽略的身分：它的布林式本身就是一個標準 SOP，只是乘積項的係數變成可外接的資料線，所以不必化簡也能實作任何函數。

這章假設已懂：03 布林代數與邏輯閘的 AND、OR、NOT 與閘的接法，以及04 標準型 SOP 與 POS的真值表與最小項。

痛點：化簡了半天，為什麼有人不化簡也把電路做出來了

學完卡諾圖後最常見的疑問是：既然每個函數都得先列真值表、再圈相鄰格、再數閘數，那為什麼有人只拿一顆晶片，把真值表那一欄的八個值用跳線接成高低電位，電路就會動了？他一次化簡都沒做，而這還是正規解法。

問題出在我們把「實作一個布林函數」等同於「用閘拼出最簡 SOP」。其實還有第二條路：把整張真值表原封不動存起來，用選擇線去查。這一章的四個元件都不做算術，只做選擇與翻譯，而多工器剛好就是那張表——看懂這件事，也就看懂了第 13 章的可程式邏輯為什麼用查找表當基本單元。

白話直覺：選好之後只有一條路被接通，其餘七條被硬壓成 0

可以先把多工器（multiplexer, MUX）想成收音機的選台旋鈕：轉到哪台就聽哪台。比喻到此為止——真實的多工器裡沒有任何會轉動的東西，它是八個 AND 閘加一顆 OR 閘，選擇線解碼後只讓一個 AND 閘有機會輸出 1，其餘七個被硬壓成 0，所以 OR 閘只看得到被選中的那一路。

順著因果鏈走一次。輸入從哪來：八條資料線 D0 到 D7 可能來自感測器、暫存器，也可能只是接固定的高低電位；三條選擇線 S2S1S0 通常來自計數器或控制邏輯。這一層做了什麼決定：把八條線壓成一條，代價是另外七筆資料這一拍被丟掉。花掉多少：8 對 1 多工器約是八個四輸入 AND、一顆八輸入 OR 與三個反相器，訊號要穿過解碼與選擇兩層，約 2 到 3 個閘延遲，以單閘 1.0 ns 估就是 2 到 3 ns；沒被選中的七條線照樣在充放電，功耗不會因此消失。邊界在哪：致能（enable, EN）腳拉低時輸出被強制為 0，這個 0 不代表資料真的是 0。儀器量到什麼：示波器夾在輸出腳只看得到一條波形，看不出它來自哪條輸入。

另外三個元件是同一個想法的不同接法。解多工器（demultiplexer, DEMUX）把一條資料送到 2n 條輸出的其中一條，是多工器的反向；解碼器（decoder）把 n 位元的碼翻成 2n 條「只有一條為 1」的輸出線，它其實就是資料端固定接 1 的解多工器；編碼器（encoder）再反過來，把 2n 條線壓回 n 位元的碼。寫成程式的話：多工器是陣列取索引，解碼器是把整數展開成只有一格為真的陣列，編碼器是回報那一格的索引。

來源：10-邏輯設計 §4.2。

推導：把四個元件的布林式一條一條寫出來

（a）8 對 1 多工器的完整式子。三條選擇線共八種組合，每種對應一個最小項。把「選中第 i 條」寫成該最小項乘上 Di 再全部相加，得到 Y = Σi=0..7 (Di · 第 i 個最小項)，展開就是 Y = D0 · ¬S2 · ¬S1 · ¬S0 + D1 · ¬S2 · ¬S1 · S0 + D2 · ¬S2 · S1 · ¬S0 + … + D7 · S2 · S1 · S0。這個式子的形狀就是第 04 章的標準 SOP，八個乘積項一個不少，差別只在每項的係數從固定的 0 或 1 變成可外接的 Di。所以任何三變數函數都能這樣實作：選擇線接 A、B、C，真值表輸出那一欄的八個值接到 D0 到 D7，不必化簡也不必再加閘。多工器天生就是一張查表。

（b）解碼器的每一條輸出就是一個最小項。3 對 8 解碼器的第 5 條輸出是 Y5 = S2 · ¬S1 · S0，第 3 條是 Y3 = ¬S2 · S1 · S0，其餘依此類推。八條輸出剛好把八個最小項全部產生出來，把函數用到的那幾條接進一顆 OR 閘就是標準 SOP。這是實作 SOP 的另一種作法，而且一顆解碼器可同時餵好幾個輸出函數。

（c）編碼器為什麼一定要做成優先編碼器。樸素作法是把每條輸入接到它自己那個碼為 1 的位元上，再用 OR 閘合併，這在「同時只有一條線為 1」時正確。但兩條同時為 1 就出事：D3 的碼是 011、D5 是 101，OR 陣列逐位元相或得到 111，也就是 7——一個根本沒被按下的索引。優先編碼器（priority encoder）用一條規則堵住這個洞：同時為 1 時只回報索引最大的那一條。代價是每個輸出位元要多帶「比它更大的輸入都不為 1」的條件，閘數變多。

（d）為什麼還要多拉一支 GS 腳。三位元的輸出只有八種值，沒有一種能表示「一條都沒有」。輸入全 0 會輸出 000，只有 D0 為 1 也輸出 000，碼一模一樣。GS（group select）就是分辨這兩種情況的那條線：有任何輸入為 1 時 GS = 1，全 0 時 GS = 0。少了它，中斷控制器分不出「0 號裝置發出中斷」與「沒有裝置中斷」。

數值實例：同一組輸入分別餵進四個元件

設定選擇線 S2S1S0 = 101（十進位 5），致能 EN = 1，八條資料線 D0 到 D7 = 1, 0, 1, 1, 0, 1, 0, 0，分別送進四個元件。

元件輸出
8 對 1 多工器Y = D5 = 1
1 對 8 解多工器（資料輸入取 D0 = 1）Y5 = 1，其餘 7 條全 0
3 對 8 解碼器Y5 = 1，其餘 7 條全 0（與上一列一模一樣，因為解碼器就是資料端固定接 1 的解多工器）

邊界對照：把 EN 設成 0 → 多工器 Y = 0、解多工器與解碼器八條輸出全 0、優先編碼器輸出 000 且 GS = 0——這時的 000 不是選中 0，是根本沒有致能。把八條輸入全設成 0 → 優先編碼器輸出 000 但 GS = 0，這正是 GS 存在的理由；只有 D0 為 1 時同樣輸出 000，但 GS = 1。

用 8 對 1 多工器實作第 04 章的多數決：多數決是 F = Σm(3, 5, 6, 7)，把 D0 到 D7 設成 0, 0, 0, 1, 0, 1, 1, 1，選擇線接 A、B、C，輸出就是多數決，不用化簡也不用任何額外的閘。取捨要擺在一起看：第 04 章的最簡 SOP 是 A · B + B · C + A · C，4 個閘、6 個字面；查表法 0 個閘，但要一顆多工器加八條接線，訊號仍得穿過 2 到 3 個閘延遲，以單閘 1.0 ns 計約 2 到 3 ns。省的是設計時間，不是面積與延遲。

不要混淆

  • 多工器選的是哪一條線，不是把幾條線加起來；其餘七條不進入結果。
  • 解多工器與解碼器的差別只在資料端接什麼：接真的資料線是解多工器，固定接 1 是解碼器，內部邏輯一樣。
  • 優先編碼器輸出的 000 沒有 GS 就沒有意義，它可能是「D0 被按下」也可能是「一條都沒被按下」。
  • 「用多工器實作函數」不需要化簡，但代價是用八條資料線的硬體去實作可能只要三、四個閘的函數：省的是設計時間，不是面積也不是延遲。
  • 致能腳拉低的全 0 輸出不是「算出來是 0」，是「這顆元件不參與」。

可觀察證據：拿什麼量、量到什麼

拿一顆 74151（8 對 1 多工器），選擇線接三個指撥開關，八條資料線依多數決真值表接到高位準或低位準，輸出接 LED 加限流電阻。掃過八種選擇線組合，把 LED 亮滅與真值表逐列比對，再接到用四個閘搭的最簡 SOP 電路比對輸出。

能證明：這顆多工器的選擇邏輯正確，以及查表法與化簡法在八種輸入下輸出完全一致。不能證明：兩種作法延遲相同——多工器內部也是好幾層閘，肉眼看 LED 分辨不出 2 ns 的差別，要比延遲得用示波器抓輸入與輸出邊緣。也證明不了「化簡法一定比較好」：這實驗只量到功能，量不到面積與延遲。

連到哪門課

可程式邏輯裡的查找表（look-up table, LUT）就是「內容可以寫進去的多工器」：組態位元取代外接的資料線，選擇線就是函數的輸入，這是本課第 13 章的主題。處理器的資料路徑裡則到處都是多工器——選運算元、選寫回哪個暫存器、選下一個位址從哪來，見計算機組織的處理器資料路徑與指令週期。下一章把選擇換成算術，而 ALU 的最後一級剛好又是一顆多工器。
