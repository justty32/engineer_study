02・同一組位元，兩種解讀，兩種「有沒有出錯」

二補數與有號數運算：為什麼減法可以用同一台加法器做完

硬體不想為了負數多蓋一套減法電路，於是挑一種編碼讓「減 B」等於「加上 B 的補數」。這一章推出二補數的兩個等價定義，說明 A − B = A + ¬B + 1 為什麼成立，並把 C、V、N、Z 四個旗標一次講完：同一組位元，無號說沒事、有號說出錯，兩邊都沒有騙你。

這章假設已懂：01 數值系統與編碼的二進位寫法與位元寬度的意思。

痛點：最高位是符號位，那不就好了嗎，為什麼要繞一圈

直覺上最省事的作法是把最高位當成正負號，剩下的位元寫大小，這叫符號加大小法。可是這樣做，硬體馬上要面對一堆特例：兩個數相加要先比大小、再決定是加還是減、再決定結果的符號；而且 0000 0000 與 1000 0000 會變成正零與負零兩個位元組合，判斷「結果是不是零」得比對兩次。加法器因此又大又慢。

另一個常被跳過的痛點是：明明是同一次加法，為什麼有時候說「進位了」、有時候說「溢位了」，兩個詞聽起來都像出錯，卻常常一個是 1 一個是 0。很多人乾脆把兩個都當成錯誤旗標，結果無號比較時誤判、有號比較時又漏判。這一章要把兩件事分開：C 問的是無號有沒有超過範圍，V 問的是有號有沒有超過範圍。

白話直覺：在 n 位元的世界裡，所有運算本來就是模 2n

走一次因果鏈。輸入從哪來：兩個 n 位元的位元組，本身沒有正負，正負是讀的人加上去的解讀。這一層做了什麼決定：硬體只做一件事——把兩個位元字串逐位相加、逐位進位，最後把超出 n 位元的部分丟掉。花掉多少代價：一台 n 位元加法器就這麼多閘，減法不必再蓋一套，只要加一排反相器與一條進位輸入。邊界或例外在哪：丟掉的那一位對無號解讀是超過 2n − 1，對有號解讀卻可能完全正常，反過來也一樣。儀器量到什麼：用除錯器看旗標暫存器可以直接讀到 C 與 V，但它不會告訴你這段程式本來想用哪一種解讀。

可以暫時把 n 位元運算想成鐘面上的指針，走過一圈就回到原點。比喻到此為止，精確的說法是：n 位元加法是模 2n 的算術，任何超過 2n 的部分都從最高位掉出去，而二補數就是刻意選一種編碼，讓「模 2n 的加法」同時對無號與有號兩種解讀都給出正確答案。

n 位元二補數的表示範圍是 −2n−1 到 2n−1 − 1。8 位元就是 −128 到 127，它不對稱：負的多一個。原因是零只佔一個位元組合，不像符號加大小法浪費兩個，多出來的那一格分給了負數。

四個旗標的分工也一次講清楚：C（carry）是無號意義下的進位或借位，也就是掉出最高位的那個位元；V（overflow）是有號意義下的溢位，代表結果跑出 −2n−1 到 2n−1 − 1；N（negative）只是複製結果的最高位；Z（zero）代表所有位元都是 0。

來源：10-邏輯設計 §1。

推導：四個為什麼

（a）為什麼 2n − X 等於「逐位反相再加 1」。2n − 1 是全 1 的位元字串。用全 1 去減 X，每一位都是 1 − xi，而 xi 只能是 0 或 1，所以逐位都不需要借位，結果就是把每一位翻過來，也就是 ¬X。再補回少掉的那個 1 就得到 2n − X。所以取補數在電路上只要一排反相器加一個進位輸入，成本極低，這是二補數勝出的關鍵。

（b）為什麼減法可以變加法。在 n 位元的世界裡所有運算都是模 2n。因為 2n ≡ 0 (mod 2n)，所以 A − B ≡ A + (2n − B) (mod 2n)。把（a）代進去就得到 A − B = A + ¬B + 1，右邊全部是加法。多出來的那個 2n 正好從最高位掉出去，而掉出去的那一位就是 C。這也解釋了一件反直覺的事：做減法時 C = 1 代表「不需要借位」，也就是無號意義下 A ≥ B。

（c）為什麼 V = Cn ⊕ Cn−1。Cn 是從最高位往外掉出去的進位，Cn−1 是從次高位進到最高位的進位。有號解讀時最高位是符號位。若進到符號位的量與從符號位掉出去的量一致，符號位的變化就是合法的模運算結果；一旦兩者不同，代表下面的數值部分污染了符號位，結果的符號是假的。所以兩個進位不同就是有號溢位，這正是互斥或。口訣「正加正得負、負加負得正就是溢位」是這條式子的結果，不是另一條規則。

（d）為什麼 C 對有號沒有意義、V 對無號沒有意義。C 判定的是「結果有沒有超出 0 到 2n − 1」，V 判定的是「結果有沒有超出 −2n−1 到 2n−1 − 1」。兩個判準的合法區間不同，所以答案當然可以不同。硬體很省事：它同時算出兩個旗標，把「該看哪一個」丟給寫程式的人決定。這就是為什麼無號比較與有號比較用的是不同的條件分支指令。

數值實例：8 位元，A = 100、B = 45

減法那一列的細節：45 的 8 位元二補數是 28 − 45 = 256 − 45 = 211，寫成位元是 1101 0011。於是 100 + 211 = 311，311 − 256 = 55，多出來的 256 就是從最高位掉出去的進位，所以 C = 1。前面推導過，減法時 C = 1 代表不需要借位，也就是 A ≥ B，這裡 100 ≥ 45 成立。

加法那一列更值得盯著看：100 與 45 都是正數，相加卻得到最高位是 1 的 1001 0001，有號讀成 −111。兩個正數加出負數，這就是有號溢位，V = 1。可是以無號解讀，145 沒超過 255，沒有位元掉出最高位，C = 0。同一組位元，無號說沒事、有號說出錯，兩邊都沒錯，只是問題不同。

邊界對照一：A = 127、B = 1 做加法，0111 1111 + 0000 0001 = 1000 0000，無號讀 128、有號讀 −128，C = 0 而 V = 1，正加正得到負。邊界對照二：A = −128、B = −128 做加法，1000 0000 + 1000 0000 = 0000 0000，無號 0、有號 0，此時 C = 1、V = 1、Z = 1——負加負得到零，這是最違反直覺的一種溢位。邊界對照三：A = B = 0 時只有 Z = 1，其餘全 0。

量級對照：這些旗標不是免費的。判定 V 需要把最高位與次高位的進位取互斥或，多一顆閘、多一級延遲；而整條進位鏈本身才是真正的瓶頸——單一邏輯閘的傳播延遲約 1.0 ns，本課第 07 章會算出 4 位元漣波進位加法器要 9.0 ns，位元寬度愈大這條鏈愈長。

自由實驗：同一組位元的兩種讀法與四個旗標

場景是一台 8 位元加法器：兩個運算元進來，做加法或減法，硬體同時算出結果位元與四個旗標。拉 A 與 B、切運算，看結果位元怎麼變，也看無號讀法與有號讀法什麼時候會說出不同的結論。切換解讀方式只改變哪一行被標成主要結果，位元本身完全不動。

這個模式用到 A、B 兩個滑桿；解讀方式只改變下面哪一行被標成主要結果，不改變位元。A = 0110 0100（無號 100、有號 100），B = 0010 1101（無號 45、有號 45）。運算式 100 + 45，結果位元 1001 0001：無號讀 145，有號讀 −111。旗標 C = 0、V = 1、N = 1、Z = 0。有號溢位：兩個同號數相加卻得到異號結果，超出 −128 到 127，真值應該是 145。位元就是那一組位元，C 問的是無號有沒有超過 255，V 問的是有號有沒有跑出 −128 到 127，兩個問題可以有不同答案。

不要混淆

  • 二補數不是「加一個符號位」。1000 0000 在符號加大小法是負零，在二補數是 −128，兩者是不同的編碼，不能混著讀。
  • C 不是錯誤旗標。做無號算術時它就是正常的第 9 個位元，多精度加法還要靠它往上串；做有號算術時它不該被拿來判斷對錯。
  • N 只是複製結果的最高位，不保證「結果真的是負的」。溢位時 N 會騙你：127 加 1 得到 N = 1，但真值 128 是正的。
  • ¬A + 1 的那個「加 1」不是四捨五入，也不是修正項。它來自 2n − A = (全 1 − A) + 1 這條恆等式，是推導出來的結果。
  • 位元寬度不夠時的截斷與符號延伸是兩件事：把 8 位元擴成 16 位元要複製符號位，不是補零，否則 −111 會變成 145。

可觀察證據：拿什麼量、量到什麼

在任何一顆處理器上寫一小段組合語言，把 100 與 45 放進 8 位元暫存器相加，用除錯器單步停在加法之後看旗標暫存器：C 與 V 會分別是 0 與 1，跟本章算出來的一致。更貼近日常的作法是在 C 語言裡宣告同一個位元組，分別用 signed char 與 unsigned char 印出來，會看到 −111 與 145 同時成立。也可以在 EDA 模擬器裡跑 8 位元加法器的 testbench，逐位檢查進位鏈。

能證明的是：這顆處理器的旗標定義與本課一致、某個位元組在兩種解讀下分別是多少、溢位發生在哪一次運算。不能證明的是：這段程式「應該」用有號還是無號——那是設計者的意圖，硬體只提供兩種讀法，不會告訴你選錯了；也不能證明程式別處沒有把同一個位元組當成另一種編碼再讀一次。除錯器看到的旗標是那一瞬間的值，下一條指令就可能覆寫它。

連到哪門課
