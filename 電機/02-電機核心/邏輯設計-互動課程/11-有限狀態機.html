11・狀態的意義就是已經對上了規格的哪一段前綴

有限狀態機：把「要記得剛剛發生過什麼」變成一張可以直接接線的表

正反器讓電路有了記憶，但記憶要記什麼？這章給一套可操作的流程：規格 → 狀態表 → 狀態編碼 → 下一狀態邏輯加狀態暫存器加輸出邏輯，並用同一個規格把 Moore 與 Mealy 的差別算給你看。

這章假設已懂：09 閂鎖與正反器的 D 正反器、10 時脈與時序限制的時脈邊緣，以及04 標準型 SOP 與 POS的組合邏輯寫法。

痛點：狀態要怎麼想出來，不是背幾個圈圈

「我知道正反器會記住位元，可是一個題目說『偵測到 1101 就輸出 1』，我怎麼知道要幾個狀態？書上直接畫好圈圈給我看，我照抄得出來，換一題就完全不會了。」

問題出在狀態被當成畫圖的產物。其實狀態是可以推導的：每個狀態代表「到目前為止，已經對上了規格字串的哪一段前綴」。想清楚這句話，狀態表就自己寫出來了，圈圈只是事後的畫法。第二個常見的卡點是 Moore 與 Mealy——很多人記得「一個看狀態、一個看狀態加輸入」，卻算不出同一個規格下兩者差幾個狀態、輸出差幾拍。

白話直覺：狀態就是「我還記得多少」的壓縮

有限狀態機（finite state machine, FSM）＝有限個狀態＋轉移規則＋輸出規則。可以暫時把狀態想成閱讀時的書籤；比喻到此為止，精確的說法是：狀態是對「過去所有輸入」的一個有損壓縮，只留下未來還用得到的資訊。偵測 1101 時，過去讀了幾百位元不重要，重要的只有「結尾已經對上 1101 的前幾個字元」。

照因果鏈走一遍。輸入從哪來：每個時脈邊緣進來一個位元。這一層做了什麼決定：由目前狀態與這個位元決定下一個狀態，必要時同時決定輸出。花掉多少：標準結構是三塊——狀態暫存器（正反器）、下一狀態邏輯（組合）、輸出邏輯（組合）。狀態數 N 決定正反器數，二進位編碼要 ⌈log2N⌉ 顆，one-hot 要 N 顆；每多一顆正反器就多一份面積與功耗，而下一狀態邏輯的深度直接算進第 10 章的 tlogic。邊界或例外在哪：位元數湊不滿的編碼會留下未使用狀態，上電時正反器的值不確定，可能一開機就掉在裡面。儀器量到什麼：把設計燒進 FPGA，用內建邏輯分析儀同時抓輸入、狀態暫存器與輸出，逐拍對照。

三種常見編碼各有取捨：二進位最省正反器；格雷碼（Gray code）讓相鄰狀態只差 1 個位元，減少同時翻轉的數量；one-hot 每個狀態一顆正反器，下一狀態邏輯最淺，在 FPGA 上通常反而最快。

來源：10-邏輯設計 §6.1、§6.2。

推導：從「偵測 1101（允許重疊）」推出兩張狀態表

（a）狀態的意義。把狀態定義成「目前已經對上了規格字串的哪一段前綴」。規格是 1101，前綴有空字串、1、11、110、1101 五個，Mealy 只需要前四個。

目前狀態意義輸入 0 → 下一狀態 / 輸出輸入 1 → 下一狀態 / 輸出
T0還沒對上任何東西T0 / 0T1 / 0
T1已對上 1T0 / 0T2 / 0

（b）T2 收到 1 為什麼留在 T2。此時看到的結尾是 111，它最長的「既是自己的後綴、又是規格前綴」的部分是 11，所以還在 T2，不能退回 T0。（c）T3 收到 1 之後為什麼回 T1 而不是 T0。偵測成功的那一刻剛吃進去的 1 本身就可以當下一次的開頭，這就是「允許重疊」的意思。

（d）Moore 的狀態表。輸出必須是目前狀態的函數，所以「已經對上 1101」這件事得自己佔一個狀態。

（e）Moore 為什麼多一個狀態、又為什麼慢一拍。Mealy 可以把「偵測到了」掛在轉移上，Moore 只能掛在狀態上，所以多一個 S4。而輸出既然是狀態的函數，就得等時脈邊緣把狀態推進去才看得到，因此比 Mealy 晚一拍。（f）正反器數。二進位與格雷碼都要 ⌈log2N⌉ 顆，one-hot 就是 N 顆；未使用狀態數 = 2 的正反器數次方減掉狀態數。

不要混淆

  • 「狀態」不是「輸出」。S4 的輸出是 1，但輸出是 1 不代表一定在 S4——Mealy 就沒有這樣的狀態。
  • Mealy 狀態少不代表電路小。它的輸出邏輯要同時吃狀態與輸入，比較複雜，而且輸出會跟著輸入的突波抖動。
  • one-hot 用最多正反器不代表最慢。它的下一狀態邏輯最淺，在 FPGA 上常常反而最快，多數合成工具預設就選它。
  • 「未使用狀態」不是「不會發生」。上電時正反器的值不確定，安全的狀態機必須讓任何未使用狀態都能回到已知狀態。

可觀察證據：拿什麼量、量到什麼

用什麼量。把狀態機合成到 FPGA，用內建的邏輯分析儀（在晶片內部插一段取樣邏輯與緩衝區）同時抓輸入、狀態暫存器的每一位元與輸出，設好觸發條件後連續抓幾百拍；同時翻合成報告，看工具實際選了哪種編碼、用了幾顆正反器。

量到什麼（能證明）。能證明實際的狀態轉移序列與上面那張表一致、輸出比輸入晚幾拍、實際用掉幾顆正反器，也能證明重疊偵測確實發生在相距 3 拍的位置。

不能證明什麼。抓到的只是跑過的那幾百拍，不能證明狀態機在所有可能輸入下都正確——那要形式驗證或完整的測試向量。也證明不了「不會掉進未使用狀態」：那要靠設計時就把自恢復寫進去，量測只能說這次沒掉進去。此外內建邏輯分析儀本身會佔用資源並改變繞線，量到的時序不完全等於原來的設計。
