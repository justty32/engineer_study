05・相鄰就是只差一個變數，圈起來就能把它消掉

卡諾圖與不關心項：把化簡從背口訣變成可操作的程序

上一章的標準型一定寫得出來，但一定不是最省。這章給出把它壓短的機械程序，並說明「這個輸入組合不可能發生」為什麼是免費的化簡燃料。

這章假設已懂：04 標準型 SOP 與 POS的最小項與積之和寫法。

痛點：化簡到底有沒有終點

拿到標準型之後，用第 03 章的恆等式東湊西湊，通常真的能變短一點。問題是：什麼時候該停？兩個人化出兩個不一樣的式子，誰對？這種靠眼力與運氣的做法沒辦法交給工具，也沒辦法在報告上寫「這已經是最短的了」。

第二個痛點來自規格本身。BCD 編碼只用到 0 到 9，10 到 15 這六種位元組合根本不會出現在輸入端。如果硬要為這六種不可能的輸入指定輸出，等於白白多付閘；但如果放著不管，又不知道該怎麼在式子裡表達「隨便」。這章要的就是一套把「隨便」變成好處的做法，以及一個能宣告「化到底了」的判準。

來源：10-邏輯設計 §3.1、§3.3。

白話直覺：把表重排成「鄰居只差一個位元」的格子

可以暫時把卡諾圖（Karnaugh map）想成把真值表折成一塊布，讓原本相隔很遠的列變成鄰居；比喻到此為止，收回精確定義——卡諾圖就是一張二維表格，列標與行標都照格雷碼順序 00, 01, 11, 10 排，於是任何上下或左右相鄰的兩格，其輸入組合恰好只差一個位元。

依因果順序走一次。輸入從哪來：一張真值表的 2n 個輸出值，其中有些是 1、有些是 0、有些是不關心項（don't-care term）。這一層做了什麼決定：把相鄰而且都是 1 的格子圈成一組，圈裡那個「取遍 0 與 1」的變數就被消掉，一個圈換成一個乘積項。花掉多少代價：圈越大、乘積項的字面越少，對應的及閘輸入數就越少；本章的例子從 10 個閘壓到 3 個閘，若單閘傳播延遲取 1.0 ns，路徑也從三層約 3.0 ns 縮到兩層約 2.0 ns。邊界在哪：卡諾圖靠「用眼睛看相鄰」運作，5 變數已經要疊兩張圖，6 變數以上人眼就失效了，必須換成 Quine–McCluskey 這種表格化算法；而且不關心項的好處建立在「那些輸入真的不會發生」這個規格假設上，假設錯了電路就會做出你沒設計過的行為。儀器量到什麼：測試向量掃過全部 2n 種輸入，可以逐格比對化簡前後兩個電路，但只在合法輸入上該相同。

寫成程式的話：真值表是查表陣列，卡諾圖化簡就是把這張陣列壓成一串較短的條件式，而不關心項是「這幾格你愛填什麼都行」的自由度。

推導：相鄰為什麼能消變數，以及演算法怎麼走

（a）相鄰能消變數的代數理由。A · B · ¬C + A · B · C = A · B · (¬C + C)（分配律，把 A · B 提出來）= A · B · 1（用互補律 ¬C + C = 1）= A · B（單位律）。兩格合成一格，C 消失了，因為在這兩格裡 C 取遍了 0 與 1，輸出卻沒變。

（b）圈為什麼必須是 2 的次方而且要對齊。上面的合併能成立，前提是被合併的那些格子構成「某 k 個變數取遍全部 2k 種組合、其餘變數固定不變」的完整集合。少一格就不完整，多一格就會把固定的變數也弄亂，兩者都無法整段提出公因式。所以圈 2k 格消掉 k 個變數，而 3 格、6 格這種大小不合法。

（c）卡諾圖為什麼是環狀的。AB 的格雷碼順序是 00, 01, 11, 10，首尾兩項 10 與 00 也只差一個位元，所以最上一列與最下一列其實相鄰，最左一行與最右一行也相鄰。圈可以從邊緣繞回另一邊。

（d）Quine–McCluskey 的三步驟（互動元件就是照這個實作）。第一步，把 on-set 與不關心項的最小項依 1 的個數分組，反覆把「只差一個位元」的兩項合併成帶 - 的樣式，直到不能再合併，剩下沒被合併掉的就是質蘊涵項（prime implicant）。第二步，做覆蓋表，只有一個質蘊涵項覆蓋的最小項（不含不關心項）→ 那個質蘊涵項是必要質蘊涵項（essential prime implicant），全部選入。第三步，若還有最小項沒被覆蓋，反覆挑「覆蓋最多未覆蓋最小項」的質蘊涵項，平手時取字面數較少者，再平手取位元樣式字典序較小者（- 小於 0 小於 1）。

來源：10-邏輯設計 §3.2。

數值實例：BCD 大於等於 5 偵測器

輸入 A B C D 是一個 BCD 數字，A 是最高位；F = 1 表示這個數字大於等於 5。規格寫成 F = Σm(5, 6, 7, 8, 9) + d(10, 11, 12, 13, 14, 15)——10 到 15 不是合法的 BCD 編碼，所以列為不關心項。卡諾圖的列是 AB、行是 CD，兩軸都用格雷碼順序：

AB \ CD00011110
00m0 = 0m1 = 0m3 = 0m2 = 0
01m4 = 0m5 = 1m7 = 1m6 = 1
11m12 = xm13 = xm15 = xm14 = x
10m8 = 1m9 = 1m11 = xm10 = x

最簡 SOP 必須逐列驗證，x 代表不關心、怎麼算都可以：m0 0000 → A=0、B · D=0、B · C=0 → 0 ✓；m1 0001 → 0 ✓；m2 0010 → 0 ✓；m3 0011 → B=0 → 0 ✓；m4 0100 → A=0、B · D = 1 · 0 = 0、B · C = 1 · 0 = 0 → 0 ✓；m5 0101 → B · D = 1 · 1 = 1 ✓；m6 0110 → B · C = 1 · 1 = 1 ✓；m7 0111 → 1 ✓；m8 1000 → A = 1 ✓；m9 1001 → A = 1 ✓；m10 到 m15 → A = 1 或 B = 1，輸出 1，但它們是不關心項，輸出什麼都不算錯。

四組邊界對照要記住。第一，16 格全部設成 1 → 唯一的質蘊涵項是 ----，F = 1，0 個閘。第二，16 格全部設成 0 → 沒有任何最小項，F = 0，0 個閘。第三，16 格全部設成 x → on-set 為空，本課約定輸出 F = 0，並提示全部都是不關心項時 F 可以是任何函數，本課取最省的 0。第四，四變數奇偶檢查 F = A ⊕ B ⊕ C ⊕ D，也就是 Σm(1, 2, 4, 7, 8, 11, 13, 14) 這 8 格（1 的個數為奇數者）→ 8 個質蘊涵項，每個都是 4 字面的單格，全部必要，完全化簡不掉。這是卡諾圖的最壞情形：相鄰格永遠一個 1 一個 0，沒有任何兩格可以合併。

自由實驗：逐格切 0／1／x，看質蘊涵項與最簡式重算

不要混淆

  • 卡諾圖的行列順序不是 00, 01, 10, 11。邊界就在第二格與第三格之間：照二進位順序排的話，01 與 10 差了兩個位元，「相鄰只差一個位元」這個前提立刻破掉，整個方法失效。
  • 圈可以重疊，但不能有洞、不能是非 2 的次方。重疊沒關係是因為 A + A = A，同一格被兩個圈蓋到不會算兩次；但 3 格、6 格的圈提不出公因式，寫不成單一乘積項。
  • 不關心項可以圈進去，但不用特地去覆蓋它。判斷質蘊涵項是否必要時，只看 on-set 裡的最小項；一個只蓋住不關心項的圈，留著只是白花閘。
  • 「最簡」指的是字面數或閘數最少，不是「唯一」。同一個函數可能有好幾個一樣簡的答案；只有當全部質蘊涵項都必要時，答案才唯一。
  • 質蘊涵項不等於必要質蘊涵項。質蘊涵項只是「不能再變大的圈」，必要與否要看有沒有哪個最小項只被它一個蓋到。

可觀察證據：拿什麼量、量到什麼

把化簡前的標準型電路與化簡後的三閘電路都合成，在模擬器裡用測試向量掃過全部 16 種輸入並逐筆比對；也可以把兩者燒進同一片可程式邏輯元件，用邏輯分析儀同時抓兩路輸出。

能證明：在 0 到 9 這 10 種合法輸入下兩個電路完全等價，而在 10 到 15 這 6 種輸入下可能不同（化簡後的電路會把它們輸出成 1）；以及化簡後的閘數確實由 10 降到 3，這是數得出來也量得到功耗差異的。不能證明：那 6 種非法輸入「永遠不會發生」。那是規格的假設，不是量測結果；如果上游元件故障或雜訊翻轉了某個位元，化簡後的電路就會做出你從來沒設計過的行為。這是不關心項最大的風險，安全相關的設計常常刻意放棄這份免費的化簡燃料，把不關心項全部釘成 0。

連到哪門課

真實的 EDA 工具不會畫卡諾圖，它把 Quine–McCluskey 這類算法規模化成可以處理上百萬個閘的邏輯合成流程，見本課13 可程式邏輯與 HDL。化簡出來的組合邏輯在處理器裡最典型的用途，是控制單元把指令欄位解出一堆控制訊號，見計算機組織的組合邏輯與算術。下一章換一條完全不同的路：不化簡，直接拿一顆多工器把真值表當查表用。
