## 1. 一句話定位

把 `電機/02-電機核心/13-控制系統.md`（195 行、概論重點式、沒有任何數值例）做成一門講**「怎麼用回授把一個動態系統的行為塑造成想要的樣子」**的零基礎互動課：從「回授到底買到什麼、付出什麼」開始，一路蓋到建模、方塊圖、穩態誤差、二階閉迴路、Routh、根軌跡、波德圖與裕度、PID、領先／落後補償、狀態空間的可控可觀與極點配置。古典控制為主，狀態空間只到入門；全程繁體中文、純文字公式、完全離線。

課名（顯示於 index 的 `h1`）：**控制系統（零基礎互動課）**

部署 slug：`control-systems`（`.github/workflows/pages.yml` 課程表的目標目錄；掛站接線屬收尾 agent，本隊不做）。

本課同時套用 **foundations-first**（零基礎入口、繁中／英文術語、名詞與概念分開、拆頁）與 **principles-first**（先講為什麼、狀態與能量去向、量測證據、易混概念拆開）。

**本課最大的特殊性：數學語言已經在既有課「信號與系統」教完了。** 拉氏轉換、轉移函數、極點與零點、二階系統的 ζ／ω<sub>n</sub> 與四個時域指標的推導，全部在 `../信號與系統-互動課程/` 的 07、08 章，本課**一律以一行「前置：見〈…〉」連回去，不重講推導**。本課只做既有課沒有的東西：**把回授接上去之後，極點被搬到哪裡、指標怎麼跟著動、怎麼判穩、怎麼設計控制器。**

**配額詞的規則（踩過的雷，不得偏離）**：上表 6 個「恰好 1 處」的詞（反饋、傳遞函數、階躍、超調、伯德圖、工廠），**只允許出現在 `名詞與概念字典.html` 對應卡片的「不要混淆」欄位**，作為「你在別的書會看到這個寫法」的對照，且**必須以明碼 UTF-8 字元寫出**，**嚴禁使用 `&#NNNNN;` 之類的 HTML 數字實體或任何轉義規避掃描**。verifier 的掃描一律先做 `html.unescape` 再計數。

其餘用語裁決：

1. **減號與負號一律 U+2212 `−`**；半形 `-` 只出現在檔名、CSS class、`<input>` 屬性值與使用者輸入。
2. **乘號一律 `×`（U+00D7）**，前後各一個半形空格。**全課 0 個 `*` 當乘號。**
3. **微符號一律 U+00B5 `µ`**；歐姆一律 U+03A9 `Ω`（0 個 U+2126）；**希臘字母 ζ、ω、τ、α、β、ε、φ 直接用 Unicode 字元**。
4. **虛數單位一律寫 `j`**（電機慣例，與信號與系統課一致）。
5. **人名譯法固定**：拉氏（Laplace，全名「拉普拉斯」只在 00 章首次出現時展開一次）、奈奎斯特（Nyquist）、梅森（Mason）、Routh–Hurwitz 與 Ziegler–Nichols **保留拉丁字母不譯**（對照表寫法）。
6. **控制符號固定寫法**：參考命令 `r`、誤差 `e`、控制量 `u`、輸出 `y`、干擾 `d`；控制器 `C(s)`、受控體 `G(s)`、感測器 `H(s)`、迴路增益 `L(s) = C(s)G(s)H(s)`、閉迴路轉移函數 `T(s)`、靈敏度 `S(s) = 1 / (1 + L(s))`。阻尼比 `ζ`、自然頻率 `ω<sub>n</sub>`、阻尼振盪頻率 `ω<sub>d</sub>`、增益交越頻率 `ω<sub>gc</sub>`、相位交越頻率 `ω<sub>pc</sub>`、增益裕度 `GM`、相位裕度 `PM`。
7. 術語首次出現寫 `繁中（English, 縮寫）`，例：`相位裕度（phase margin, PM）`、`比例—積分—微分控制（proportional–integral–derivative control, PID）`。
8. **角度一律用度（°）**、角頻率一律 rad/s、時間一律 s（毫秒時寫 ms）、增益一律 dB 或無單位並標明。

## 5. 目標能力（學完能算什麼、能判斷什麼）

**能算**

1. 給定受控體靜態增益、增益漂移與干擾，算開迴路與閉迴路的輸出誤差與靈敏度 `S = 1 / (1 + L)`。
2. 由直流馬達的 J、b、R、K<sub>t</sub> 寫出一階轉移函數 `G(s) = K / (τs + 1)`，算 K、τ、極點與步階響應。
3. 由 C、G、H 算閉迴路轉移函數 `T = CG / (1 + CGH)`、閉迴路極點、閉迴路時間常數與直流增益。
4. 由迴路增益的型式與誤差常數 K<sub>p</sub>／K<sub>v</sub>／K<sub>a</sub> 算步階／斜坡／拋物線命令的穩態誤差。
5. 由單位回授 `K / (s(s + a))` 算閉迴路 ζ、ω<sub>n</sub>、極點、M<sub>p</sub>、t<sub>p</sub>、t<sub>s</sub> 與斜坡穩態誤差，並判斷第三個極點能否忽略。
6. 對三階與四階特徵多項式逐列算 Routh 表，數首行符號變化，處理首元為零與全零列。
7. 由 `K / (s(s + a)(s + b))` 算根軌跡的漸近線重心與角度、分離點、虛軸穿越的 K 與 ω，以及任一 K 下的三個閉迴路極點。
8. 對 `K / (s(τ<sub>1</sub>s + 1)(τ<sub>2</sub>s + 1))` 在任一頻率算精確與漸近的振幅（dB）與相位，並讀出轉角頻率與斜率。
9. 算增益交越頻率、相位交越頻率、增益裕度、相位裕度與臨界增益，並用奈奎斯特判定穩定度。
10. 對三階受控體加 PID，用 Routh 判穩、用固定步長模擬算超越量、上升、整定與穩態誤差，並算 Ziegler–Nichols 的 K<sub>u</sub>、T<sub>u</sub> 與建議參數。
11. 設計領先補償器的 z、p、最大相位提升與新相位裕度；設計落後補償器的 β 與新的 K<sub>v</sub>。
12. 對 2 × 2 狀態空間算特徵值、可控矩陣與可觀矩陣的行列式與秩、Ackermann 公式的極點配置增益。

**能判斷**

1. 什麼時候回授反而讓輸出更不準（模型準、無干擾、增益低）。
2. 一個系統是否「可以用一階近似」（第二個極點離得夠遠）。
3. 提高迴路增益帶來的三件事同時發生：穩態誤差變小、極點往虛軸靠、超越量變大。
4. 型式 0／1／2 對三種命令各自的穩態誤差是零、常數還是無限大。
5. Routh 表首行出現負數代表什麼、出現零與全零列代表什麼。
6. 根軌跡跨過虛軸的 K 與 Routh 算出的臨界增益是同一件事。
7. 波德圖在轉角頻率的漸近線誤差是多少（−3.01 dB），以及斜率每過一個極點降 20 dB/十倍頻。
8. PM 太小的系統步階響應長什麼樣（ζ ≈ PM / 100 的粗估與失效範圍）。
9. 積分項為什麼能消除穩態誤差、也為什麼會讓系統更容易振盪。
10. 領先補償改善的是相位裕度與頻寬，落後補償改善的是低頻增益與穩態誤差，兩者不可互換。
11. 一個系統不可控時極點配置為何無解，不可觀時觀測器為何無解。

## 9. 教學邊界

1. **語言**：正文、按鈕、回饋、導覽一律繁體中文。術語首次出現用 `繁中（English, 縮寫）`。
2. **公式**：一律純文字 HTML（`<sup>`／`<sub>`／Unicode）。**嚴禁** `\(` `\)` `\[` `\]` `$` `$$`、MathJax、KaTeX。符號規約見第 2 節與 BUILD-SPEC 第 3 節。
3. **`<option>` 內只能放純文字**：不得含 `<sub>`／`<sup>`／任何標籤，下標一律改用底線寫法（`K_p`、`omega_n`、`t_s`）。Unicode 字元（ζ、ω、²）例外允許。
4. **離線**：不得有圖片、外部字型、CDN、遠端 API、分析碼、第三方腳本。唯一允許的外部連結是每頁頂端 `main-site-link` 指向 `https://justty32.github.io/engineer_study/`。
5. **不畫圖**：步階響應以「指定時刻的 y(t) ＋ 四個指標」、根軌跡以「三個根的座標表」、波德圖以「指定頻率的讀值表」、奈奎斯特以「環繞次數判定句」替代。
6. **每個公式後面要寫出每個符號的意思、單位與假設**（例：「τ 是時間常數，單位 s；本課的馬達模型忽略電樞電感，所以只有一個極點，真實馬達還有一個很快的電氣極點」）。
7. **比喻必須收回**：只能出現一次且立刻收回到精確定義。
8. **每章必須先講「這一招買到什麼、代價是什麼」**：依 principles-first 的因果骨架 `命令從哪來 → 誤差怎麼被放大 → 能量或控制量往哪裡去 → 極點被搬到哪 → 指標變成多少 → 儀器量到什麼`，每章的「白話直覺」段落至少走完一次這條鏈。
9. **可觀察證據必須誠實**：示波器量得到超越量與整定時間，量不到極點位置（要反推）；掃頻量得到 |L(jω)| 但要先斷開迴路；模擬能證明模型下穩定，證明不了真實系統穩定（模型誤差、飽和、延遲）。**不能證明什麼要跟能證明什麼寫一樣清楚。**
10. **無強制測驗**：章節頁沒有題目；自我檢核頁的題目不計分、不阻擋、可無限重做，回饋一定附「為什麼」與來源章節連結。
11. **統一內容門檻**：**每章正文（不含 `section.workspace` 內容）1800–2600 個中文字**，計法＝**漢字＋全形標點**。低於 1800 視為未完成，高於 2600 要拆段但不得刪推導。短少 2 % 以內不構成回派。
12. **安全警語**：09 章必須有一段 `p.warning`（把高增益或未驗證的 PID 參數直接下到真實馬達、加熱器或機械手臂會撞到極限、燒毀或傷人；先在模擬與限幅下驗證，實機一律加輸出限幅與急停）。
13. **可延續性**：清除對話後，新 agent 只靠 `PROJECT-BRIEF.md` ＋ `BUILD-SPEC.md` ＋ `驗收紀錄.md` 就能接手；不得有只存在於聊天紀錄的決定。
