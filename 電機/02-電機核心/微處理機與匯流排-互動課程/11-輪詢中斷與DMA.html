11・沒有哪一種永遠比較好，答案會隨事件率翻轉

輪詢、中斷與 DMA：同一把尺量出 CPU 各被吃掉多少

CPU 要跟外面的世界說話，只有三種基本姿勢：自己去問、等對方叫、或者請別人代勞。這章把三種姿勢放在同一個成本模型上，用同樣的事件率與資料量算出各自吃掉多少百分比的 CPU，並說明為什麼名次會隨著事件率整個翻過來。

這章假設已懂：00 微處理機世界觀與效能公式的拍數觀念。前置：見〈09 程序ABI呼叫與系統邊界〉計算機組織：程序 ABI 呼叫與系統邊界——使用者程式怎麼跨越系統邊界屬於那一頁，這章只做三種 I/O 方式的成本比較。

痛點：教科書說中斷比輪詢好，可是我的量測不是這樣

「我做高速資料擷取，一開始用中斷，每來一筆就進一次中斷服務常式，事件率拉高之後 CPU 直接被吃光；改成輪詢反而順了。可是換到低速的按鍵裝置，同樣改成輪詢又變得超級浪費。到底哪一種才對？」

兩種量測都沒錯，錯的是「哪一種比較好」這個問題本身。三條成本式吃的是不同的自變數：輪詢只跟你多久問一次有關，中斷只跟對方多久叫你一次有關，直接記憶體存取兩者都不太看。自變數不同，曲線一定會交叉；交叉點在哪得把數字代進去才知道。

白話直覺：三種姿勢各自在買什麼

輪詢（polling）＝ CPU 主動且週期性地去讀裝置的狀態暫存器。中斷（interrupt）＝ 裝置有事才拉一條線通知 CPU，CPU 存好現場、跳進中斷服務常式、處理完再返回。直接記憶體存取（direct memory access, DMA）＝ 板上另一個控制器代替 CPU 搬資料，CPU 只負責下設定，搬完收一次完成中斷。三種方式讀寫裝置暫存器時多半都走記憶體對映 I/O（memory-mapped I/O）：裝置的暫存器被映射進位址空間，用一般的載入儲存指令就能存取。

比喻只用一次：這三種姿勢像是自己每分鐘去信箱看一次、裝一個門鈴、還是請宅配直接放進屋裡——比喻到此為止，下面一律用拍數算。

照因果鏈走一次。工作量從哪來：一秒內有多少個事件、每個事件要搬多少位元組。這一招做了什麼決定：輪詢決定「固定用某個頻率去問」，中斷決定「付一筆固定的進出代價換低延遲」，DMA 決定「多花一顆控制器，把搬運整個外包」。省下多少、多花多少：以預設設定算，輪詢每秒 2248000 拍、中斷 2848000 拍、DMA 1200000 拍，2.0 GHz 下的佔用率是 0.112400 %、0.142400 %、0.060000 %。邊界在哪：輪詢頻率若低於事件率就會漏資料，省下的 CPU 是假的。儀器量到什麼：中斷計數與 CPU 使用率。

來源：11-計算機組織與微處理機 §6.1。

推導：三條成本式與它們各自的自變數

（a）三條式子。

輪詢 = 輪詢頻率 × 每次查詢拍數 + 事件率 × 位元組數 × 每位元組拍數

中斷 = 事件率 × (中斷服務拍數 + 位元組數 × 每位元組拍數)

DMA = 事件率 × DMA 設定拍數

符號說明：輪詢頻率與事件率的單位都是次/秒；每次查詢拍數是讀一次狀態暫存器並判斷的成本，單位拍；中斷服務拍數含進出中斷的固定代價（存暫存器、換堆疊、跳轉、返回），單位拍；每位元組拍數是 CPU 用指令一個一個搬時的成本，單位拍/位元組；DMA 設定拍數含寫描述子與完成中斷。三條式子算出來都是「每秒拍數」，除以時脈就是佔用率。這是一階教學模型，真實系統還有中斷合併、快取污染與排隊效應。

（b）為什麼輪詢在高事件率反而划算。輪詢沒有「每次事件的固定進出成本」這一項。事件率逼近輪詢頻率時，幾乎每次查詢都有收穫，那 20 拍的查詢成本被真正的工作攤掉；中斷卻是每來一次事件就得再付一次 800 拍。反過來說，事件率極低時輪詢的查詢幾乎全部白做。

（c）為什麼輪詢頻率必須大於等於事件率。兩次查詢之間若來了不只一個事件，裝置的緩衝區就可能溢位，資料直接丟掉。所以輪詢頻率不是可以任意調低的省電旋鈕，它有一條由事件率決定的下限。

（d）為什麼 DMA 的成本與資料量無關。資料是 DMA 控制器搬的，CPU 只付設定與完成中斷這兩筆固定開銷，所以式子裡根本沒有位元組數這一項。代價有三個：多一顆控制器的成本與功耗、它會跟 CPU 搶記憶體頻寬、以及它搬的那段記憶體與快取之間的一致性要另外處理（見本課第 09 章）。

安全提醒：DMA 控制器會繞過 CPU 直接寫記憶體，來源位址、目的位址或長度只要設錯一個欄位，它就會安靜地覆蓋別人的資料結構，而且不會觸發任何保護例外，現象往往是幾秒鐘之後在完全無關的地方當掉。在裸機或驅動程式層填 DMA 描述子時，標準實務是：逐欄檢查來源、目的與長度，用平台提供的 DMA 映射介面取得正確的裝置端位址，確認緩衝區在整段傳輸期間都不會被搬移或釋放，並在傳輸前後依平台規定做快取的清除與失效；系統若有 IOMMU 就把它打開，讓越界的存取被擋下來而不是直接生效。

數值實例：同一個裝置，三種方式的帳單

設定：事件率 1000 次/秒、每次 512 位元組、時脈 2.0 GHz、每次查詢 20 拍、輪詢頻率 10000 次/秒、中斷服務 800 拍、DMA 設定＋完成中斷 1200 拍、程式化搬移每位元組 4 拍。

方式每秒拍數CPU 佔用率
輪詢10000 × 20 ＋ 1000 × 512 × 4 ＝ 22480000.112400 %
中斷1000 × (800 ＋ 512 × 4) ＝ 28480000.142400 %
DMA1000 × 1200 ＝ 12000000.060000 %

資料吞吐量 ＝ 1000 × 512 ＝ 512000 位元組/秒。輪詢的最壞事件延遲 ＝ 1 / 10000 ＝ 100.000000 µs；中斷延遲（200 拍 @ 2 GHz）＝ 0.100000 µs——輪詢在這個設定下比中斷省 CPU，延遲卻差了三個數量級。這正是「沒有哪一種永遠比較好」的具體形狀。

邊界對照。事件率拉到 100000 次/秒、每次 4096 位元組、輪詢頻率同步拉到 100000 → 輪詢 82.020000 %、中斷 85.920000 %、DMA 6.000000 %：資料量一大，只有 DMA 撐得住，因為前兩者的位元組搬運都掛在 CPU 身上。事件率降到 10 次/秒（輪詢頻率仍 10000）→ 輪詢 0.011024 %、中斷 0.001424 %、DMA 0.000600 %：輪詢變成最貴的，因為 99.9 % 的查詢都白做。名次真的翻過來了。

自由實驗：把事件率拉一遍，看三條曲線交叉

場景是一個外接裝置，每秒觸發固定次數的事件，每次事件要把若干位元組搬進記憶體。同一個工作量分別用輪詢、中斷與 DMA 處理，成本全部換算成每秒拍數與 CPU 佔用率。要看的是三者的名次會在哪裡交換，以及輪詢頻率一旦低於事件率會發生什麼事。

目前是「三種都比較」，九個控制全部都會用到。事件率 1000 次/秒、每次 512 位元組、2.0 GHz。輪詢每秒 2248000 拍 ＝ 0.112400 %；中斷每秒 2848000 拍 ＝ 0.142400 %；DMA 每秒 1200000 拍 ＝ 0.060000 %。吞吐量 512000 位元組/秒。輪詢最壞事件延遲 100.000000 µs，中斷延遲 0.100000 µs。目前佔用率最低的是 DMA，因為它的成本裡沒有位元組數這一項。為什麼：輪詢的成本看的是查詢頻率，中斷看的是事件率，DMA 兩者都不看——所以答案會隨事件率翻轉。邊界提醒：事件率調到 1 時輪詢幾乎全部白做，中斷明顯划算；把每次位元組數拉到 4096 且事件率拉到 100000，程式化搬移會吃掉大半個 CPU，這就是 DMA 存在的理由；若把輪詢頻率調到低於事件率，兩次查詢之間會來不只一個事件，會漏資料；佔用率一旦超過 100 % 表示 CPU 已經被吃光，實際上會開始漏事件或延遲暴增。

不要混淆

  • 中斷不是「比較快」。它降低的是延遲不是 CPU 佔用——同一個工作量下每秒拍數常常比輪詢還高。
  • 輪詢不是「原始的做法」。高事件率下它反而可能比中斷省，因為它沒有每次事件的固定進出成本；高速網路卡的驅動程式就會在忙碌時主動切回輪詢。
  • DMA 不是「零成本」。它有設定成本與完成中斷，會跟 CPU 搶記憶體頻寬，而且搬進來的資料與快取的一致性還要另外處理。
  • 記憶體對映 I/O 的那些「變數」不是普通記憶體。讀它可能清掉一個狀態旗標，也就是讀取本身有副作用，所以編譯器不能把重複讀取最佳化掉，也不能任意重排。

可觀察證據：拿什麼量、量到什麼

用什麼量。Linux 的 /proc/interrupts 直接列出每個中斷來源累計觸發了幾次，vmstat 的 in 欄位給出每秒中斷數。要做對照就把驅動程式從中斷模式切成輪詢模式（網路卡的 NAPI 就是這個機制），在同樣的流量下再量一次 CPU 使用率。

能證明什麼。能證明這個裝置實際觸發了多少次中斷，也能證明切換方式之後整機的 CPU 使用率有沒有降、降了多少。這兩個數字合起來足以驗證本章的取捨方向。

不能證明什麼。證明不了某一次中斷實際花了多少拍——那要用追蹤工具，而追蹤本身就會干擾被測系統。也證明不了「DMA 一定比較好」：小量高頻的事件下設定成本可能比直接搬還貴，而且 CPU 使用率不會告訴你有多少是記憶體頻寬被搶走造成的。
