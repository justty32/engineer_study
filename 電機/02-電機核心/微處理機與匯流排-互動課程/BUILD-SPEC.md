3. **公式一律純文字 HTML，嚴禁 LaTeX**：不得出現 `\(` `\)` `\[` `\]` `$` `$$`，不得引入 MathJax／KaTeX／任何算式引擎。轉寫規約見第 3 節。
4. **`<option>` 內只能放純文字**（HTML 內容模型限制）。`<option>` 與自我檢核選項的顯示文字**不得含 `<sub>`／`<sup>`／任何標籤**，一律用底線／脫字號寫法：`T_c`、`t_hit`、`t_penalty`、`2^k`、`10^6`。**Unicode 上標字元例外允許**（`I²C` 的 `²` 是字元不是標籤，照寫）。違反此條瀏覽器會靜默丟棄標籤，掃描抓不到但顯示會壞。

## 3. 公式與符號轉寫規約

來源筆記用 LaTeX，網頁**一律純文字 HTML**。

### 3.1 允許的字元

- 上下標：`<sup>` 與 `<sub>`。不要用 Unicode 下標數字（₀₁₂）。**上標 `²` `³` 與 `I²C` 的 `²` 例外允許**（純字元）。
- 數學與集合符號（限這份清單）：`× ÷ ± ≈ ≤ ≥ ≠ → ⇒ ⌈ ⌉ ⌊ ⌋ Σ ∞ ∈ √`
- 希臘字母：`α µ Ω λ`
- **乘號一律 `×`（U+00D7），前後各一個半形空格**：`IC × CPI × T<sub>c</sub>`。**全課 0 個 ASCII `*` 當乘號。**
- **除號用半形 `/`**，前後各一個半形空格：`1 / T<sub>c</sub>`；分數列式時可用 `÷`。
- **負號與減號一律 U+2212 `−`**；半形 `-` 只出現在檔名、CSS class 與 `<input>` 屬性值。
- **微符號一律 U+00B5 `µ`**（µs、µW）。歐姆用 `Ω`（U+03A9）。
- 次方可直接用 `²` `³`；其餘用 `<sup>`：`2<sup>−149</sup>`、`10<sup>6</sup>`。
- 單位一律半形英文緊接數字後空一格：`2.0 GHz`、`0.500000 ns`、`228.800000 ns`、`50 µs`、`7876.923077 MB/s`、`64 KiB`、`5 W`。

### 3.2 排版規則

1. **二進位字面值每 4 位元一個半形空格**：`0100 0001 0100 0110`。需要標明底數時寫 `1100.011<sub>2</sub>`。
2. **十六進位一律 `0x` 前綴＋大寫英數**：`0x41460000`、`0x424`、`0x4028C00000000000`。
3. **位元組序列用兩位十六進位、以半形空格分隔**：`00 00 46 41`。
4. **拍數一律寫「拍」**（例「50 拍」），不寫「週期數」；時脈週期符號 `T<sub>c</sub>`，頻率 `f`。
5. **效能符號固定寫法**：`IC`（指令數）、`CPI`（每指令拍數）、`IPC`（每拍指令數）、`T<sub>c</sub>`（時脈週期）、`t<sub>hit</sub>`、`t<sub>penalty</sub>`、`AMAT`、`S`（加速比）、`p`（可平行化比例）、`s`（該段加速倍率）。
6. **管線階段一律寫 `IF`／`ID`／`EX`／`MEM`／`WB`**，首次出現要展開（取指／解碼／執行／記憶體存取／寫回）。
7. **MESI 狀態一律寫單一大寫字母 `M`／`E`／`S`／`I`**，首次出現展開（Modified 已修改／Exclusive 獨占／Shared 共享／Invalid 無效）；轉移寫 `E → M`（箭頭 U+2192，前後各一空格）。
8. **快取位址切分一律寫「標籤（tag）／索引（index）／區塊內偏移（offset）」**，順序固定由高位到低位。
9. **逐拍表與存取序列一律用原生 `<table>`**，表頭用 `<th>`。
10. **百分比一律 `<數字> %`**（數字與 `%` 之間一個半形空格），六位小數：`87.500000 %`。
11. **容量單位**：`KiB`／`MiB` 是 2 的次方，`MB/s`／`GB/s` 是 10 的次方；**同一段裡兩者同時出現時必須各標一次**。公式所在段落用 `<p>`；需要凸顯時可用 `<code>`（`styles.css` 已設 `overflow-wrap:anywhere`）。

### 00 `00-微處理機世界觀與效能公式.html`

**目標**：把「快」這件事講成一條可以算的式子——執行時間 ＝ 指令數 × 每指令拍數 × 時脈週期。三個因子分別由誰決定（編譯器與 ISA 決定 IC、微架構決定 CPI、製程與電路決定 T<sub>c</sub>），以及為什麼只動其中一個永遠拿不到你以為的加速。最後給出本課地圖：第 03–07 章都在壓 CPI，第 08–10 章都在避免記憶體把拍數吃光，第 11–13 章在處理 CPU 以外的世界。

**要點**：抽象階層（abstraction layer）由上而下八層（應用程式、作業系統與編譯器、指令集架構、微架構、暫存器轉移層、邏輯閘、電晶體、半導體物理）；**指令集架構（instruction set architecture, ISA）是軟硬體之間的契約**，介於第 3 與第 4 層；微架構（microarchitecture）是同一份契約的不同實作；執行時間 ＝ IC × CPI × T<sub>c</sub>；每秒百萬指令（MIPS）為什麼不能拿來比不同 ISA 的機器；一拍 0.5 ns 的量級感。**前置：處理器怎麼把一條指令執行完，見既有課〈04 處理器資料路徑與指令週期〉，本章不重講機制。** 來源：11-計算機組織與微處理機 §1、§7.1。

**推導必寫**：（a）三個因子為什麼是相乘而不是相加：`(指令數 / 程式) × (拍數 / 指令) × (秒數 / 拍)`，中間兩個單位對消之後只剩 `秒數 / 程式`——這條式子是量綱推出來的，不是背的。（b）為什麼「時脈加 20 %」的收益比「CPI 減 20 %」小：時間與時脈成反比，加 20 % 等於乘 `1 / 1.2 ≈ 0.833333`；而 CPI 減 20 % 等於乘 `0.8`，加速 `1 / 0.8 = 1.25`。**同樣是 20 %，除以 1.2 和乘以 0.8 不是同一件事。** （c）為什麼 MIPS 會騙人：`MIPS = f / (CPI × 10<sup>6</sup>)` 完全沒有「這些指令做了多少事」這一項，換一個 ISA 就不可比；同一支程式在 CISC 上指令少而 CPI 高，在 RISC 上指令多而 CPI 低，MIPS 高的那台不一定跑得快。

**數值實例**：IC ＝ 1 億條（100 × 10<sup>6</sup>）、CPI ＝ 1.5、時脈 2.0 GHz。

| 量 | 算式 | 結果 |
| --- | --- | --- |
| 時脈週期 | 1 / 2.0 GHz | **0.500000 ns** |
| 執行時間 | 100 × 10<sup>6</sup> × 1.5 × 0.5 ns | **75.000000 ms** |
| MIPS | 2 × 10<sup>9</sup> / 1.5 / 10<sup>6</sup> | **1333.333333** |
| 指令數減 20 % | 80 × 10<sup>6</sup> × 1.5 × 0.5 ns | **60.000000 ms，加速 1.250000 倍** |
| CPI 減 20 % | 100 × 10<sup>6</sup> × 1.2 × 0.5 ns | **60.000000 ms，加速 1.250000 倍** |
| 時脈加 20 % | 100 × 10<sup>6</sup> × 1.5 × 0.416667 ns | **62.500000 ms，加速 1.200000 倍** |

邊界對照：三項**同時**各改 20 % → **40.000000 ms，加速 1.875000 倍**（不是 1.25 ＋ 1.25 ＋ 1.2，是三個係數相乘）。CPI 拉到 6.0（記憶體密集程式的常見量級）→ 執行時間 **300.000000 ms**，此時把時脈加 20 % 只省 50.000000 ms，而把 CPI 壓回 1.5 省 225.000000 ms——**這就是第 03–10 章存在的理由**。

### 01 `01-ISA契約與定址模式.html`

**目標**：說清楚 ISA 是一份**契約**——它承諾的是「這些指令會做什麼」，不承諾「用什麼方式做」。然後用同一件事（把 `陣列[i]` 讀進暫存器）比較 RISC 與 CISC 各要幾條指令、幾個位元組、幾個 micro-op，讓讀者看見「指令數少不等於工作量少」。

**要點**：ISA 契約包含哪些東西（指令集、暫存器、位址空間、例外模型、記憶體模型）；RISC（reduced instruction set computer）＝ 少而簡單、固定長度、load／store 架構；CISC（complex instruction set computer）＝ 指令多、長度不固定、運算元可以直接是記憶體；**現代 x86 兩件事同時成立：外面是 CISC 編碼、裡面把每條指令解碼成一到多個微運算（micro-operation, micro-op），跑在類 RISC 的核心上**；四類指令（資料搬移、算術與邏輯、控制流、特權與系統）；定址模式（addressing mode）家族：立即、暫存器、基址加位移、索引加縮放、記憶體間接、PC 相對；碼密度（code density）與指令快取壓力。**前置：RISC-V 與 x86-64 的指令逐條怎麼寫，見既有課〈07 RISC-V組合語言〉與〈05 x86-64組合語言〉，本章不教語法。** 來源：11-計算機組織與微處理機 §3.1、§3.2、§3.3。

**推導必寫**：（a）為什麼固定長度指令讓管線變簡單：取指階段不必先解碼就知道下一條在哪裡，`PC + 4` 即可；變長編碼必須先看第一個位元組才知道要再讀幾個，所以 x86 前端要多一級長度解碼並且很難平行取多條。（b）為什麼 CISC 的碼密度高卻不一定快：同一件事 CISC 用 4 個位元組、RISC 用 12 個位元組，指令快取壓力較小；但 CISC 那一條在核心裡仍然被拆成同樣多的 micro-op，**真正決定拍數的是 micro-op 數不是指令數**。（c）索引定址 `EA = 基底 + 索引 × 縮放 + 位移` 為什麼值得做成一條指令：陣列走訪是最常見的樣式，把「乘以元素大小再相加」做進位址產生單元（AGU）就不必占用 ALU。（d）記憶體間接為什麼現代 RISC 不做：它需要**兩次**資料記憶體存取，中間還有相依，塞不進單一管線階段。

**數值實例**：基底暫存器 ＝ 1024、位移 ＝ 16、索引暫存器 ＝ 5、縮放倍率 ＝ 4，PC ＝ 16384（`0x4000`）。

| 正確性判準 | ① `is-mode` 是 `imm` 或 `reg` → 必須寫「這個模式沒有有效位址，運算元不在記憶體裡」；② `is-mode = indirect` → 必須寫「兩次資料記憶體存取，而且第二次要等第一次的結果，這是現代 RISC 拿掉它的原因」；③ `is-style` 非 `both` 時開頭要寫「這個模式只顯示 X 那一側」；④ 每次都要附因果句：「碼密度比講的是體積，micro-op 數講的才是拍數，兩個指標會給你相反的結論。」 |
| 邊界情形 | `is-scale` 不是 1 且 `is-mode` 不是 `indexed` → 「縮放倍率只有索引定址用得到，這個模式忽略它」；`abs(is-disp) > 127` → 「位移超出 1 個位元組，CISC 這條指令要多花 3 個位元組」；`is-base + is-index × is-scale + is-disp < 0` → 「有效位址算成負值，真實機器會依位元寬度回繞，本課直接顯示負值並提醒這是設定不合理」，**不得輸出 NaN** |

**不要混淆（至少四條）**：ISA 與微架構是兩件事——同一份 x86-64 契約，Intel 與 AMD 的微架構完全不同；RISC 不是「指令比較少」而是「每條指令做的事比較單純且長度固定」，RISC-V 的擴充加起來指令一點都不少；碼密度高不等於執行快，它只降低指令快取與記憶體頻寬壓力；「x86 是 CISC」與「x86 內部是 RISC」不是互相反駁，是兩個不同層次的敘述。

**可觀察證據**：用 `perf stat` 讀 `instructions` 與（在支援的機器上）`uops_issued`，兩者的比值就是平均每條指令幾個 micro-op；反組譯器可以直接告訴你每條指令佔幾個位元組。**能證明**：這段程式碼實際的指令數、位元組數與 micro-op 數。**不能證明**：某條指令內部被拆成哪幾個 micro-op（那是廠商未完全公開的實作細節）；也證明不了「換成 RISC 會比較快」——那要換一台機器實測。

### 02 `02-IEEE754與端序.html`

**目標**：把浮點數從「會有誤差」講成「誤差有多大、來自哪一個欄位」。把一個十進位數切成符號、指數、尾數三段，算出實際存進去的是哪一個數、離你要的差多少、這個量級下最小可分辨的間隔（ULP）是多少；再用同一組位元組講端序。

**要點**：IEEE 754 的 binary32（單精度）＝ 1 符號 ＋ 8 指數 ＋ 23 尾數，偏移量 127；binary64（雙精度）＝ 1 ＋ 11 ＋ 52，偏移量 1023；**隱含前導 1**（正規數的尾數其實是 24 或 53 位元）；非正規數（subnormal）＝ 指數欄位全 0，沒有隱含 1，用來填補 0 附近的空隙；指數欄位全 1 時：尾數為 0 是無限大（infinity），非 0 是 NaN（not a number）；ULP（unit in the last place）＝ 這個量級下相鄰兩個可表示數的間隔；端序（endianness）＝ 同一個多位元組值在記憶體裡由低位址往高位址怎麼排。**前置：整數的二補數表示與旗標，見姊妹課〈02 二補數與有號數運算〉，本章只做浮點。** 來源：11-計算機組織與微處理機 §2。

**推導必寫**：（a）為什麼要用偏移量而不是二補數存指數：加了偏移之後，指數欄位的**無號**大小順序就等於數值大小順序，比較兩個正浮點數可以直接當整數比，硬體省下一個特例。（b）隱含 1 買到什麼：正規數一律寫成 `1.xxx × 2<sup>e</sup>`，那個 1 不必存，等於白賺一個位元的精度；代價是**沒辦法表示 0**，所以要把指數全 0 這個編碼挪去當 0 與非正規數。（c）ULP 怎麼算：尾數有 23 個小數位元，所以在指數 `e` 這一段裡相鄰兩數差 `2<sup>e−23</sup>`；`e` 每加 1，間隔就加倍——**浮點數的精度是相對的，不是絕對的**。（d）為什麼 0.1 存不下：0.1 在二進位是無限循環小數 `0.0001100110011…`，截到 24 個有效位元就一定有殘差。

**數值實例**：輸入值 12.375，格式 binary32。

| 欄位 | 內容 | 說明 |
| --- | --- | --- |
| 十進位轉二進位 | `1100.011<sub>2</sub>` ＝ `1.100011 × 2³` | 正規化 |
| 符號位元 | **0** | 正數 |
| 指數欄位 | `1000 0010`（十進位 **130**） | 130 − 127 ＝ **3** |
| 尾數欄位（23 位元） | `100 0110 0000 0000 0000 0000` | 隱含前導 1 不存 |
| 完整位元組合 | `0100 0001 0100 0110 0000 0000 0000 0000` | |
| 十六進位 | **`0x41460000`** | |
| 實際儲存值 | **12.375（剛好可精確表示）** | 誤差 0 |
| ULP（此量級） | 2<sup>3−23</sup> ＝ 2<sup>−20</sup> ＝ **9.536743 × 10<sup>−7</sup>** | |
| 小端序位元組 | **`00 00 46 41`** | 低位元組放低位址 |
| 大端序位元組 | **`41 46 00 00`** | 高位元組放低位址 |
| 同值的 binary64 | **`0x4028C00000000000`**（小端序 `00 00 00 00 00 C0 28 40`） | 指數欄位 1026，去偏移仍是 3 |

邊界對照：輸入 **0.1** → binary32 是 **`0x3DCCCCCD`**，實際儲存值 **0.100000001490116119384765625**，絕對誤差 **1.490116 × 10<sup>−9</sup>**；換成 binary64 是 `0x3FB999999999999A`，**還是存不下，只是誤差小很多**。特例：`+0` ＝ `0x00000000`；最小非正規數 ＝ `0x00000001` ＝ **1.401298 × 10<sup>−45</sup>**；最小正規數 ＝ **1.175494 × 10<sup>−38</sup>**；最大有限值 ＝ **3.402823 × 10<sup>38</sup>**；`+∞` ＝ `0x7F800000`；quiet NaN ＝ `0x7FC00000`。有效十進位位數：binary32 ＝ 24 × log<sub>10</sub>2 ＝ **7.224720 位**，binary64 ＝ 53 × log<sub>10</sub>2 ＝ **15.954590 位**。

**不要混淆（至少四條）**：浮點誤差不是「電腦算錯」，是**這個格式一開始就存不下那個數**；雙精度不是「兩倍精度」，是 53 個有效位元對 24 個，差距是 2<sup>29</sup> 倍；非正規數不是壞掉的數，是刻意保留下來讓 0 附近不要出現斷崖（代價是很多硬體處理它會慢很多）；端序是**記憶體裡的位元組順序**，不是位元順序，暫存器裡的值沒有端序問題。

### 03 `03-五階段管線與吞吐量.html`

**目標**：把管線講成一個**吞吐量**的設計，不是延遲的設計。用同一堆工作量比較單週期與 k 級管線的總時間，讓讀者親眼看到：加速比永遠追不上級數、每級暫存器的固定負擔會在級數變多時吃掉一切、而且只跑一條指令時管線反而更慢。

**要點**：單週期（single-cycle）為什麼慢——時脈週期被**最慢的那條指令**綁死，其他階段的硬體大部分時間閒著；五階段管線的 IF（取指）／ID（解碼並讀暫存器）／EX（執行）／MEM（記憶體存取）／WB（寫回）；每級之間要插一組管線暫存器，帶來固定負擔 t<sub>latch</sub>；填充（fill）與排空（drain）；吞吐量（throughput）與延遲（latency）是兩件事。**前置：一條指令怎麼走完取指、解碼、執行、寫回，見既有課〈04 處理器資料路徑與指令週期〉，本章只做吞吐量的量化。** 來源：11-計算機組織與微處理機 §4.1、§4.2。

**推導必寫**：（a）`T<sub>total</sub> = (N + k − 1) × T<sub>p</sub>` 的來源：第一條指令要走完 k 級才產出，之後每一拍多產出一條，所以是 `k − 1` 拍的填充加上 `N` 拍的穩態。（b）為什麼理想加速上限是 `T<sub>1</sub> / T<sub>p</sub>` 而不是 `k`：`T<sub>p</sub> = t<sub>comb</sub> / k + t<sub>latch</sub>`，那個 t<sub>latch</sub> 不會被切分，所以 `T<sub>1</sub> / T<sub>p</sub> = (t<sub>comb</sub> + t<sub>latch</sub>) / (t<sub>comb</sub> / k + t<sub>latch</sub>) < k`。（c）為什麼級數不能無限加：當 `t<sub>comb</sub> / k` 遠小於 `t<sub>latch</sub>` 時，`T<sub>p</sub> ≈ t<sub>latch</sub>`，再切下去只是多付暫存器的錢與功耗；而且級數越深，第 05 章的分支誤判懲罰越大。（d）為什麼單條指令的延遲變差：`k × T<sub>p</sub> = t<sub>comb</sub> + k × t<sub>latch</sub> > T<sub>1</sub>`。

**數值實例**：100 條指令，5 級，組合延遲總和 t<sub>comb</sub> ＝ 10.0 ns，每級暫存器負擔 t<sub>latch</sub> ＝ 0.2 ns。

| 量 | 算式 | 結果 |
| --- | --- | --- |
| 單週期時脈週期 T<sub>1</sub> | 10.0 ＋ 0.2 | **10.200000 ns** |
| 管線時脈週期 T<sub>p</sub> | 10.0 / 5 ＋ 0.2 | **2.200000 ns** |
| 單週期總時間 | 100 × 10.2 | **1020.000000 ns** |
| 管線總時間 | (100 ＋ 4) × 2.2 | **228.800000 ns** |
| 實際加速比 | 1020 / 228.8 | **4.458042 倍** |
| 理想加速上限 | 10.2 / 2.2 | **4.636364 倍** |
| 填充損失 | 4 × 2.2 | **8.800000 ns（佔 3.846154 %）** |
| 吞吐量 | 100 / 228.8 | **0.437063 指令/ns** |
| 暫存器負擔佔 T<sub>p</sub> | 0.2 / 2.2 | **9.090909 %** |

邊界對照：級數拉到 **12** → T<sub>p</sub> ＝ **1.033333 ns**、總時間 **114.700000 ns**、加速 **8.892764 倍**（理想上限 9.870968），但暫存器負擔已佔 T<sub>p</sub> 的 **19.354839 %**——**再切下去邊際效益急速遞減**。級數 **1**（等於沒有管線）→ 加速 **1.000000 倍**。指令數 **1** → 單週期 10.200000 ns、管線 11.000000 ns，加速 **0.927273 倍**，**管線反而慢**。指令數 200 → 加速 **4.545455 倍**，越接近理想上限。

**可觀察證據**：用 `perf stat` 讀 `cycles` 與 `instructions`，在一段沒有冒險的直線程式碼上 CPI 會趨近 1，這就是管線在穩態運作的證據；把迴圈長度縮到只剩幾條指令，CPI 會明顯上升，那是填充成本裸露。**能證明**：這台機器在這段程式上實際的每拍完成率。**不能證明**：管線有幾級（廠商公布的級數與實際不一定一致）；也證明不了「CPI 接近 1 就沒有停頓」——可能是停頓與超純量剛好抵消。

### 04 `04-管線冒險旁路與插泡.html`

**目標**：說清楚「每拍完成一條」是理想值，而現實有三種東西會打斷它：資源不夠（結構冒險）、資料還沒好（資料冒險）、下一條在哪還不知道（控制冒險）。本章把資料冒險量化到**逐拍**：同一段程式，有旁路要插幾拍泡、沒旁路要插幾拍泡、CPI 差多少。

**要點**：結構冒險（structural hazard）＝ 同一拍有兩級要用同一個資源（經典例：只有一個記憶體埠時 IF 與 MEM 撞車）；資料冒險（data hazard）＝ 先寫後讀（read-after-write, RAW）相依；**旁路（forwarding／bypassing）**＝ 不等寫回，直接把 EX 或 MEM 階段的結果接到後面那條的 EX 輸入；**停頓與插泡（stall／bubble）**＝ 把後面的指令凍住並塞一個什麼都不做的空拍；**載入使用冒險（load-use hazard）**＝ 即使有旁路，`lw` 的資料要到 MEM 結束才拿得到，比下一條的 EX 需要的時間晚一拍，**必須插一拍泡**；控制冒險留給第 05 章。**前置：資料路徑與各階段做什麼，見既有課〈04 處理器資料路徑與指令週期〉。** 來源：11-計算機組織與微處理機 §4.3。

**推導必寫**：（a）沒有旁路時為什麼要插 `3 − d` 拍：生產者在第 `i + 4` 拍才在 WB 寫回暫存器，消費者在第 `j + 1` 拍的 ID 讀暫存器，要成立必須 `j ≥ i + 3`，也就是相依距離至少 3；距離 `d` 時缺 `3 − d` 拍。（b）有旁路時為什麼只剩 load-use 那一拍：ALU 結果在 EX 結束就有了，可以直接接到下一拍的 EX 輸入，距離 1 就夠；但 load 的資料要等 MEM 結束，只能接到**再下一拍**的 EX。（c）為什麼插泡而不是重排：硬體只能凍結，重排是編譯器或亂序引擎的工作（第 06 章）；編譯器把無關指令排進那一拍就把泡填掉了。（d）結構冒險為什麼現代機器少見：指令快取與資料快取分開（哈佛式的分離快取）之後，IF 與 MEM 不再搶同一個埠。

**本課鎖定的指令序列（章節作者與 app.js 都用這一組，不得改）**：

```text
1  lw   x2, 0(x1)      從記憶體讀一個字進 x2
2  add  x3, x2, x4     用 x2
3  sub  x5, x3, x6     用 x3
4  and  x7, x5, x8     用 x5
5  or   x9, x7, x2     用 x7
```

**數值實例**：5 條指令、相依距離 1、啟用旁路、單一記憶體埠未勾選。

| 指令 | IF | ID | 泡 | EX | MEM | WB |
| --- | --- | --- | --- | --- | --- | --- |
| 1 `lw` | 1 | 2 | — | 3 | 4 | 5 |
| 2 `add` | 2 | 3 | **4** | 5 | 6 | 7 |
| 3 `sub` | 3 | 4–5 | — | 6 | 7 | 8 |
| 4 `and` | 4–5 | 6 | — | 7 | 8 | 9 |
| 5 `or` | 6 | 7 | — | 8 | 9 | 10 |

旁路路徑：指令 1 的 MEM → 指令 2 的 EX；指令 2 的 EX → 指令 3 的 EX；指令 3 的 EX → 指令 4 的 EX；指令 4 的 EX → 指令 5 的 EX。

| 設定 | 泡數 | 總拍數 | CPI | 穩態 CPI |
| --- | --- | --- | --- | --- |
| 距離 1、有旁路（預設） | **1** | **10** | **2.000000** | **1.200000** |
| 距離 1、無旁路 | **8** | **17** | **3.400000** | **2.600000** |
| 距離 2、有旁路 | **0** | **9** | **1.800000** | **1.000000** |
| 距離 2、無旁路 | **3** | **12** | **2.400000** | **1.600000** |
| 距離 3、有或無旁路 | **0** | **9** | **1.800000** | **1.000000** |
| 距離 1、有旁路 ＋ 單一記憶體埠 | **2** | **11** | **2.200000** | **1.400000** |

邊界對照：指令數拉到 **12**、距離 1：無旁路 22 拍泡共 **38 拍**（CPI 3.166667），有旁路 1 拍泡共 **17 拍**（CPI 1.416667）——**指令越多，旁路的價值越大，因為填充成本被攤薄**。指令數 **2**、距離 3 → 沒有任何相依對，總拍數 **6**、CPI **3.000000**：**這時 CPI 高不是因為冒險，是因為只有 2 條指令而填充要 4 拍**。

### 05 `05-分支預測與管線清空.html`

**目標**：說清楚控制冒險為什麼比資料冒險難——資料至少知道要等誰，分支是**連下一條在哪都不知道**。硬體的答案是猜，猜錯就把管線裡的東西全部丟掉重來。本章把「猜得多準」與「猜錯要賠多少」拆成兩個獨立的數，再合成對 CPI 的貢獻。

**要點**：控制冒險（control hazard）；靜態預測（static prediction）＝ 永遠猜跳或永遠猜不跳，編譯器也可以給提示；**1 位元預測器**＝ 記住上一次的結果；**2 位元飽和計數器（2-bit saturating counter）**＝ 四個狀態（強不跳 00、弱不跳 01、弱跳 10、強跳 11），跳就加一、不跳就減一、不越界，**預測結果只看最高位元**；遲滯（hysteresis）的意義＝ 一次例外不會立刻翻掉預測；**管線清空（pipeline flush）**＝ 猜錯時把已經進管線的錯誤路徑指令全部作廢；誤判懲罰（misprediction penalty）與管線深度成正比。**前置：指令怎麼被取出與 PC 怎麼更新，見既有課〈04 處理器資料路徑與指令週期〉。** 來源：11-計算機組織與微處理機 §4.3。

**推導必寫**：（a）誤判懲罰為什麼等於「分支結果確定的那一級的編號減一」：從取指到確定要不要跳之間已經進了幾條指令，就要丟掉幾條；五階段在 EX 確定，所以是 3 拍；20 級的深管線就是 15 到 20 拍。（b）2 位元為什麼比 1 位元好：迴圈的最後一次「不跳」在 1 位元預測器會造成**兩次**誤判（這一次猜錯、下一次因為記住了不跳又猜錯），2 位元只會錯一次，因為狀態只從 11 掉到 10，仍然預測跳。（c）為什麼 `T N` 交替樣式會讓兩者都全錯：1 位元永遠猜上一次，而上一次永遠跟這一次相反；2 位元從弱狀態出發時也會在 01 與 10 之間震盪，**這是預測器的已知盲區**，實務上靠更長的歷史（gshare、TAGE）解決，本課不展開。（d）CPI 的合成：`CPI = CPI<sub>base</sub> + 分支比例 × 誤判率 × 懲罰拍數`，三個係數任何一個變大都線性放大。

**本課鎖定的分支結果樣式（`T` ＝ 跳、`N` ＝ 不跳）**：

- `loop`（預設）：`T T T T T T T N`，重複 4 次 ＝ **32 個分支**（典型的 8 次迴圈）
- `alt`：`T N`，重複 4 次 ＝ 8 個分支
- `ttnn`：`T T N N`，重複 4 次 ＝ 16 個分支
- `taken`：`T`，重複 4 次 ＝ 4 個分支
- `nottaken`：`N`，重複 4 次 ＝ 4 個分支

**數值實例**：樣式 `loop`、重複 4 次（32 個分支）、預測器為 2 位元飽和計數器、初始狀態 `01`（弱不跳）、誤判懲罰 3 拍、分支指令佔比 20 %。

| 預測器 | 初始 | 誤判次數 | 誤判率 | 準確率 | 對 CPI 的貢獻 | 總 CPI |
| --- | --- | --- | --- | --- | --- | --- |
| 2 位元飽和計數器（預設） | `01` | **5 / 32** | **15.625000 %** | **84.375000 %** | 0.093750 | **1.093750** |
| 2 位元飽和計數器 | `11` | **4 / 32** | **12.500000 %** | **87.500000 %** | 0.075000 | **1.075000** |
| 1 位元 | 不跳 | **8 / 32** | **25.000000 %** | **75.000000 %** | 0.150000 | **1.150000** |
| 靜態：永遠猜跳 | — | **4 / 32** | **12.500000 %** | **87.500000 %** | 0.075000 | **1.075000** |
| 靜態：永遠猜不跳 | — | **28 / 32** | **87.500000 %** | **12.500000 %** | 0.525000 | **1.525000** |

逐輪說明（2 位元、初始 01）：第 1 輪誤判 2 次（第 1 個分支因為初始是弱不跳而猜錯，第 8 個因為狀態已飽和在 11 而猜錯），第 2 到第 4 輪各誤判 1 次（只有每輪最後那個 `N`）。**這 1 次額外的暖機成本就是「永遠猜跳」在這個樣式上贏過 2 位元預測器的原因。**

邊界對照：樣式改 `alt` → **1 位元與初始 01 的 2 位元都是 100.000000 % 誤判**；把 2 位元的初始改成 `11` → 降到 **50.000000 %**（跳的那一半全對）。樣式改 `ttnn` → 2 位元初始 01 是 **75.000000 %** 誤判，**比 1 位元的 50.000000 % 還差**：遲滯在這個樣式上反而幫倒忙。懲罰改 **20 拍**（深管線）→ `loop` ＋ 2 位元的總 CPI 從 1.093750 升到 **1.625000**；分支佔比改 40 % → **1.187500**。

**不要混淆（至少四條）**：分支預測不是「猜對就沒有成本」——預測本身要查表、要在取指階段就完成，那是硬體面積與功耗的成本；誤判率低不代表影響小，深管線把懲罰放大到 20 拍時 5 % 的誤判就很痛；2 位元不是「比 1 位元多記一次歷史」，它記的是**信心**不是歷史；管線清空丟掉的是**已經算出但還沒寫回**的結果，架構狀態沒有被污染，所以這在功能上永遠是安全的（安全問題出在微架構的痕跡，見第 06 章）。

**可觀察證據**：`perf stat` 的 `branches` 與 `branch-misses` 直接給出這支程式的分支數與誤判數，兩者相除就是實測誤判率。**能證明**：這支程式的分支行為好不好猜、改寫（例如把資料排序後再過濾）之後誤判率有沒有降。**不能證明**：處理器用的是哪一種預測器（廠商不公開）；也證明不了「誤判都發生在這個 if」——計數器不分位置，要用取樣剖析而且有偏差。

**連到哪門課**：管線清空丟掉的是哪幾級的內容，見本課第 03 章的逐拍表；為什麼深管線的懲罰更大，見本課第 03 章的級數對照；分支之外的推測（記憶體相依推測）見本課第 06 章。

### 06 `06-超純量亂序與推測執行.html`

**目標**：把「每拍完成一條」再往上推——同時發射多條、不按順序執行、甚至先做了再說。本章用一條 Little's law 的不等式把四個限制放在同一個天平上：發射寬度、指令視窗、平均停留拍數、程式本身能取出的平行度，讓讀者看見**加寬機器常常沒用，因為瓶頸在程式**。

**要點**：超純量（superscalar）＝ 一拍發射多條；亂序執行（out-of-order execution）＝ 依資料就緒與否重排，架構順序靠重排序緩衝器（reorder buffer, ROB）在退休時還原；**暫存器重新命名（register renaming）**＝ 把架構暫存器映射到更多的實體暫存器，消除 WAR（先讀後寫）與 WAW（先寫後寫）這兩種**假相依**；推測執行（speculative execution）＝ 在分支結果確定前就往下做，錯了就丟；Little's law 在這裡的形式 `視窗內指令數 ＝ 完成率 × 平均停留拍數`，所以 `IPC ≤ 視窗大小 / 平均停留拍數`；ILP（instruction-level parallelism）的實務天花板。**前置：一條指令的完整執行流程見既有課〈04 處理器資料路徑與指令週期〉。** 來源：11-計算機組織與微處理機 §4.4。

**推導必寫**：（a）為什麼 WAR 與 WAW 是假的：它們不是「資料要傳過去」，只是**兩條指令剛好用了同一個名字**；換一個實體暫存器名字，兩條就可以同時跑。RAW 換不掉，因為值真的要從一邊流到另一邊。（b）重新命名需要多少實體暫存器：在飛的指令每條可能寫一個結果，所以可用的重新命名空間 ＝ 實體暫存器數 − 架構暫存器數；這個數字小於指令視窗時，**視窗填不滿，等於白買**。（c）Little's law 為什麼是上限而不是實際值：它只說「機器裡最多裝這麼多」，實際還要看程式取不取得出這麼多獨立工作。（d）推測執行的安全直覺：被丟掉的指令雖然沒有改變架構狀態，卻**已經把某些資料搬進快取**，這個痕跡可以被後續的計時觀察到——這就是 Spectre 與 Meltdown 這一類問題的來源。**本課到此為止，不教任何攻擊手法。**

**本課鎖定的一階模型（app.js 照抄）**：

- 沒有重新命名時，假相依把可取平行度壓到 `min(ILP, 1.5)`。
- 沒有推測執行時，分支把視窗切斷，可取平行度壓到 `min(ILP, 1.8)`。
- 有效視窗 ＝ `min(指令視窗, 實體暫存器數 − 架構暫存器數)`。
- 視窗上限 ＝ 有效視窗 / 平均停留拍數。
- `IPC = min(發射寬度, 可取平行度, 視窗上限)`；`CPI = 1 / IPC`。

**數值實例**：發射寬度 4、指令視窗 64、平均停留 16 拍、可取 ILP 2.5、重新命名啟用、推測執行啟用、實體暫存器 128、架構暫存器 16。

| 量 | 算式 | 結果 |
| --- | --- | --- |
| 可取平行度 | 兩項都啟用，維持原值 | **2.500000** |
| 重新命名空間 | 128 − 16 | **112 個** |
| 有效視窗 | min(64, 112) | **64** |
| 視窗上限 | 64 / 16 | **4.000000** |

### 07 `07-SIMD與平行加速上限.html`

**目標**：把「平行」拆成三個層級（指令級、資料級、執行緒級），再用 Amdahl 定律說明一件事：**只要有一段不能平行，加速就有天花板，而且天花板來得比你以為的快**。資料級平行用 SIMD 當具體案例，算出向量寬度換到的實際加速與尾數迴圈的效率損失。

**要點**：ILP（instruction-level parallelism）＝ 超純量與亂序（第 06 章）；DLP（data-level parallelism）＝ 同一個運算套用到很多筆資料，SIMD（single instruction multiple data）與 GPU 都屬這一類；TLP（thread-level parallelism）＝ 多核心與同時多執行緒（simultaneous multithreading, SMT）；SIMD 的向量寬度（vector width）＝ 一個向量暫存器裝幾個元素；**尾數迴圈（tail loop）**＝ 資料量不是寬度的整數倍時剩下的那一批，通道只用了一部分；Amdahl 定律 `S = 1 / ((1 − p) + p / s)` 與它的上限 `1 / (1 − p)`；平行化的固定開銷（同步、資料搬移）。來源：11-計算機組織與微處理機 §4.4、§7.2、§7.3。

**推導必寫**：（a）Amdahl 定律怎麼來的：把總時間正規化成 1，不能平行的那段是 `1 − p`、能平行的那段從 `p` 縮成 `p / s`，相加取倒數。（b）為什麼上限是 `1 / (1 − p)`：`s → ∞` 時 `p / s → 0`，剩下的就是那段永遠不動的 `1 − p`。**p ＝ 80 % 時上限只有 5 倍——這比大多數人的直覺低很多。** （c）SIMD 的實際加速為什麼是 `N / ⌈N / W⌉` 而不是 `W`：迴圈次數必須向上取整，最後一次可能只用到部分通道；`N` 是 `W` 的整數倍時兩者才相等。（d）為什麼固定開銷要放進分母：同步、把資料搬進向量暫存器、跨核心的快取一致性流量（第 09 章）都是**不管平行幾倍都要付**的成本，它跟 `1 − p` 一樣會壓住天花板。

**數值實例**：可平行化比例 p ＝ 80 %、平行層級選資料級（DLP）、向量寬度 8、資料元素 1000 筆、固定開銷 0 %。

| 量 | 算式 | 結果 |
| --- | --- | --- |
| 向量迴圈次數 | ⌈1000 / 8⌉ | **125 次** |
| SIMD 有效加速 | 1000 / 125 | **8.000000 倍** |
| 通道使用效率 | 8.000000 / 8 | **100.000000 %** |
| 尾數元素 | 1000 − 124 × 8 | **8 筆（最後一次剛好滿）** |
| Amdahl 總加速 | 1 / (0.2 ＋ 0.8 / 8) | **3.333333 倍** |
| 加速上限（s → ∞） | 1 / (1 − 0.8) | **5.000000 倍** |

邊界對照：向量寬度改 **16** → 迴圈次數 **63 次**、有效加速 **15.873016 倍**（不是 16）、通道效率 **99.206349 %**、尾數 **8 筆只用了一半通道**；代入 Amdahl 之後總加速 **3.993610 倍**——**向量寬度加倍，總加速只從 3.333333 升到 3.993610，因為那 20 % 動不了**。資料量改 **5 筆**、寬度 16 → 迴圈 1 次、有效加速 **5.000000 倍**、效率只有 **31.250000 %**：**資料太少時 SIMD 幾乎白做**。固定開銷改 **5 %** → 總加速從 3.333333 掉到 **2.857143 倍**。p 改 **95 %**、s ＝ 16 → **9.142857 倍**（上限 20.000000）；p 改 **50 %**、s ＝ 64 → **1.969231 倍**（上限只有 2）。

**不要混淆（至少四條）**：SIMD 不是多執行緒——它是**一條指令**同時算多筆，仍然在同一個核心的同一條管線裡；向量寬度加倍不等於加速加倍，尾數與那段不能平行的程式都會扣分；Amdahl 定律講的是**固定問題規模**，問題規模隨機器變大時要看 Gustafson 的觀點（本課只提一句）；「這台機器有 8 核」不代表你的程式能快 8 倍，`p` 才是決定性的那個數。

**可觀察證據**：把同一個迴圈分別用純量與向量指令編譯（編譯器的向量化報告會告訴你哪一個迴圈被向量化、哪一個因為相依而沒有），再用 `perf stat` 比較 `instructions` 與 `cycles`：指令數大幅下降而拍數只小幅下降，就是 Amdahl 在扣分。**能證明**：這個迴圈有沒有被向量化、向量化之後省下多少指令。**不能證明**：`p` 到底是多少（要靠剖析工具估計，而且會隨輸入資料變）；也證明不了「加不了速是因為 Amdahl」——也可能是記憶體頻寬飽和。

### 08 `08-快取設計四維度.html`

**目標**：這是全課的互動核心。用**同一組存取序列**跑過四個設計維度（對映方式、替換策略、寫策略、區塊大小），讓讀者親眼看到：同一段程式，換一個快取設計，命中率可以從 0 % 跳到 87.5 %；而且「更相聯」「更大」不一定更好。

**要點**：時間區域性（temporal locality）與空間區域性（spatial locality）；快取行／區塊（cache line／block）；位址切成標籤（tag）／索引（index）／區塊內偏移（offset）；三種對映——直接對映（direct-mapped）、n 路組相聯（n-way set-associative）、全相聯（fully-associative），統一寫成 `組數 = 容量 / (區塊大小 × 路數)`；替換策略 LRU／FIFO／MRU（**Random 因為本站禁用亂數只講不做**）；寫策略：寫回（write-back）＋寫配置（write-allocate）對寫穿（write-through）＋不配置（no-write-allocate）；失誤三分類（3C）：強制（compulsory）、容量（capacity）、衝突（conflict）；`AMAT = t<sub>hit</sub> + 失誤率 × t<sub>penalty</sub>`。**前置：快取與記憶體階層的機制，見既有課〈08 記憶體階層與虛擬記憶體〉；本章只做設計取捨的量化。** 來源：11-計算機組織與微處理機 §5.1、§5.2。

**推導必寫**：（a）索引為什麼取位址的中間幾位而不是高位：低位是區塊內偏移，若索引用高位，相鄰的區塊會全部擠進同一組，空間區域性反而變成災難。（b）失誤三分類怎麼算：強制 ＝ 這個區塊第一次被碰到（等於不同區塊的個數）；容量 ＝ 同容量**全相聯**的失誤數減強制數；衝突 ＝ 實際失誤數減同容量全相聯的失誤數。（c）為什麼衝突失誤可能算出負值：全相聯配 LRU 在**循環走訪超過容量**時是最壞情形（每次都剛好把下一個要用的踢掉），而直接對映因為映射固定反而保住了一部分——**這是三分類法本身的已知破口，不是計算錯誤**。（d）寫策略的流量取捨：寫回把多次寫合併成一次整行回寫，寫穿每次都送 4 個位元組但省下逐出時的整行搬移；哪一個省要看寫的密集程度。

**不要混淆（至少四條）**：命中率不是快取的性質，是**快取與存取樣式一起**的性質；「更相聯一定更好」是錯的（`loop` 那組反例）；區塊變大不是免費的——它同時降低區塊數並增加每次失誤的搬運量；寫穿不等於「比較慢」，它在寫少讀多時流量反而比寫回低；失誤三分類是**分析工具**不是物理量，它會在極端情形算出負值。

**可觀察證據**：`perf stat` 的 `cache-references` 與 `cache-misses`、以及 `L1-dcache-load-misses` 這類細項，可以量出一段程式的實際失誤率；把矩陣乘法的迴圈順序從 `i j k` 換成 `i k j`，失誤數會明顯下降。**能證明**：這段程式在這台機器上的失誤次數、以及改寫之後有沒有降。**不能證明**：失誤屬於三分類的哪一類（計數器不分類，要靠模擬器）；也證明不了「這是快取容量不夠」——可能是對映衝突，換一下陣列的起始位址（padding）就會知道。

### 09 `09-多核一致性MESI.html`

**目標**：說清楚多核心的隱藏成本——同一條快取行只要被兩個核心搶著寫，兩邊都會不停地把它拉來拉去，而**這件事在原始碼上完全看不出來**。本章用 MESI 的狀態轉移把這個成本算成拍數，並拆開「真正共享資料」與「偽共享」這兩種完全不同的問題。

**要點**：快取一致性（cache coherence）要保證的是「所有核心對同一個位址看到一致的值」；MESI 四個狀態——M（Modified 已修改，只有我有而且已改，主記憶體是舊的）、E（Exclusive 獨占，只有我有而且沒改）、S（Shared 共享，可能不只我有，沒改）、I（Invalid 無效）；三種匯流排交易——BusRd（讀）、BusRdX（讀並取得獨占）、BusUpgr（我已經有 S，只要把別人失效掉）；**E 狀態存在的意義**是讓「只有我有而且沒改」的情形可以**不發任何交易**就升級成 M；**偽共享（false sharing）**＝ 兩個核心各寫各的變數，但兩個變數落在同一條快取行裡，硬體以整行為單位，於是兩邊互相失效。**前置：快取本身的機制見既有課〈08 記憶體階層與虛擬記憶體〉，本章只做一致性的代價。** 來源：11-計算機組織與微處理機 §5.4。

**推導必寫**：（a）為什麼要有 E 而不是只有 M／S／I：如果第一次讀進來就標成 S，之後要寫時一定要發一次 BusUpgr——但實際上根本沒有別人持有它，那次廣播是純浪費。E 讓「讀了之後接著寫」這個最常見的樣式省下一次交易。（b）為什麼 M 狀態的核心必須負責供應資料：主記憶體那一份是舊的，別人讀時只能由持有 M 的那個核心提供（並順便回寫）。（c）偽共享的成本從哪裡來：一致性協定的單位是**快取行**不是變數，兩個變數只要落在同一條 64 位元組行內，硬體無法分辨。（d）為什麼加一點填充（padding）就能解決：把兩個變數的距離拉到大於等於一條快取行，它們就落在不同行，各自維持 M 狀態，完全不必交談。

**本課鎖定的成本模型**：主記憶體供應 200 拍、遠端快取供應 40 拍、失效廣播（BusUpgr）10 拍、本地命中 1 拍。

| 正確性判準 | ① `me-offset < me-line` 且 `me-seq = pingpong` → 「這是偽共享：兩個核心寫的是不同變數，但硬體以整行為單位」；② `me-offset ≥ me-line` → 「兩個變數落在不同行，各自維持 M，穩態回到 4 拍」；③ `me-seq = share` → 「唯讀共享幾乎免費，S 狀態允許所有核心同時持有」；④ `me-step = 0` → 只顯示初始狀態（兩邊都是 I）與一句「還沒有任何存取」；⑤ 每次都要附因果句：「一致性的單位是快取行不是變數，所以問題出在資料佈局而不是演算法。」 |
| 邊界情形 | `me-offset = 0` → 「距離 0 表示兩個核心寫的根本是同一個變數，這是真共享不是偽共享，要靠演算法解決而不是填充」；`me-remote > me-mem` → 「遠端快取比主記憶體還慢是不合理的設定，真實系統不會這樣，但公式照算」；`me-iter = 1` → 「只跑一輪時冷啟動的 200 拍佔絕大部分，比值會被稀釋」 |

**不要混淆（至少四條）**：一致性（coherence）與記憶體一致性模型（memory consistency）是兩件事——前者管「同一個位址」，後者管「不同位址之間的順序」，本課只做前者；偽共享不是程式邏輯錯誤，程式的結果完全正確，只是慢；MESI 的 S 狀態不保證「真的有別人持有」，它只表示「可能有」；加鎖與偽共享無關——就算完全沒有鎖，兩條執行緒各寫各的變數一樣會互相拖慢。

**可觀察證據**：多核心機器的效能計數器可以量到「來自遠端快取的存取次數」這一類事件；更直接的做法是把兩個執行緒各自的計數器變數之間加上 64 位元組的填充，重跑一次看時間有沒有變。**能證明**：加了填充之後這段程式變快了多少。**不能證明**：慢的原因一定是偽共享（也可能是記憶體頻寬）——所以填充前後的對照實驗是必要的；也證明不了協定的實作細節（現代處理器多半是 MESIF 或 MOESI 的變形，本課用最經典的 MESI）。

### 10 `10-TLB與頁缺失的代價.html`

**目標**：把虛擬記憶體從「機制」轉成「帳單」。每一次存取除了拿資料，還要先把虛擬位址翻譯成實體位址；這件事平常只花 1 拍，但 TLB 沒命中要 100 拍、頁缺失要十萬拍。本章把三個量級放在同一張帳單上，讓讀者看到**哪一項在什麼比率下開始主導**。

**要點**：轉譯後備緩衝區（translation lookaside buffer, TLB）是**分頁表翻譯結果的快取**；TLB 失誤要走頁表（page table walk）；頁缺失（page fault）＝ 那一頁根本不在實體記憶體裡，要由作業系統從儲存裝置載入；顛簸（thrashing）＝ 工作集大於實體記憶體時頁缺失率暴增；把時間換算成拍數才能跟其他成本比較（`拍數 = 秒數 × 時脈`）。**前置：分頁、頁表與 TLB 的機制，見既有課〈08 記憶體階層與虛擬記憶體〉；本章只算代價。** 來源：11-計算機組織與微處理機 §5.3。

**推導必寫**：（a）為什麼要把時間換成拍數：頁缺失的 50 µs 聽起來很短，但在 2 GHz 下是 **100000 拍**，等於一萬條指令的機會成本；**不換算就永遠沒有量級感**。（b）平均轉譯成本的合成：`轉譯 = t<sub>tlb</sub> + (1 − TLB 命中率) × 走訪拍數 + 頁缺失率 × 頁缺失拍數`，三項是機率加權而不是相加。（c）為什麼百萬分之一的頁缺失率仍然要在意：一次一萬倍的懲罰，乘上百萬分之一還有 0.1 拍，佔總成本 1.639344 %；率只要再高一百倍就完全主導。（d）為什麼 TLB 這麼小卻這麼有效：一個 4 KiB 頁涵蓋 4096 個位元組，一筆 TLB 條目就服務整整一頁的所有存取，**它的區域性槓桿比資料快取大得多**。

**數值實例**：TLB 命中率 99 %、TLB 查詢 1 拍、頁表走訪 100 拍、頁缺失率每百萬次存取 1 次、頁缺失服務用 NVMe SSD（50 µs）、時脈 2.0 GHz、L1 資料快取命中率 95 %、L1 失誤懲罰 60 拍。

| 量 | 算式 | 結果 |
| --- | --- | --- |
| 頁缺失換算成拍 | 50 µs × 2 × 10<sup>9</sup> | **100000 拍** |
| TLB 查詢 | 固定 | **1.000000 拍** |
| TLB 失誤攤提 | 0.01 × 100 | **1.000000 拍** |
| 頁缺失攤提 | 10<sup>−6</sup> × 100000 | **0.100000 拍** |
| 平均轉譯成本 | 1 ＋ 1 ＋ 0.1 | **2.100000 拍** |
| 資料存取成本 | 1 ＋ 0.05 × 60 | **4.000000 拍** |
| 每次存取合計 | 2.1 ＋ 4.0 | **6.100000 拍（＝ 3.050000 ns）** |
| 頁缺失佔比 | 0.1 / 6.1 | **1.639344 %** |

邊界對照：假想**完全沒有 TLB**（每次存取都走頁表）→ 100 ＋ 0.1 ＋ 4 ＝ **104.100000 拍**，是有 TLB 的 **17.065574 倍**——**TLB 是整個虛擬記憶體能被接受的唯一原因**。TLB 命中率降到 **90 %** → 合計 **15.100000 拍**（轉譯從 2.1 跳到 11.1）。TLB 命中率 **100 %** → **5.100000 拍**。頁缺失率拉到每百萬 **100 次**且改用**機械硬碟**（10 ms ＝ 20000000 拍）→ 頁缺失攤提 **2000.000000 拍**，合計 **2006.000000 拍**，是預設的 **328.852459 倍**：**這時候微架構怎麼調都沒用，唯一的答案是不要缺頁**。

### 11 `11-輪詢中斷與DMA.html`

**目標**：把「CPU 跟裝置說話」的三種方式放在同一把尺上量：同樣的事件率與資料量，輪詢、中斷、DMA 各吃掉 CPU 多少百分比。並說明為什麼答案會隨事件率翻轉——**沒有哪一種永遠比較好**。

**要點**：輪詢（polling）＝ CPU 主動且週期性地查裝置狀態，成本只跟**輪詢頻率**有關、跟事件率無關；中斷（interrupt）＝ 裝置有事才通知，成本跟**事件率**成正比，但每次要付進出中斷的固定代價（存暫存器、換堆疊、跳轉、返回）；直接記憶體存取（direct memory access, DMA）＝ 另一個控制器代替 CPU 搬資料，CPU 只下設定並在完成時收一次中斷；記憶體對映 I/O（memory-mapped I/O）＝ 裝置暫存器被映射到位址空間，用一般的載入儲存指令存取；中斷延遲（interrupt latency）與最壞情況延遲。**前置：使用者程式怎麼跨越系統邊界，見既有課〈09 程序ABI呼叫與系統邊界〉。** 來源：11-計算機組織與微處理機 §6.1。

**推導必寫**：（a）三條成本式：`輪詢 = 輪詢頻率 × 每次查詢拍數 + 事件率 × 位元組數 × 每位元組拍數`；`中斷 = 事件率 × (中斷服務拍數 + 位元組數 × 每位元組拍數)`；`DMA = 事件率 × DMA 設定拍數`。（b）為什麼輪詢在**高事件率**時反而划算：它沒有每次事件的固定進出成本，事件率逼近輪詢頻率時幾乎每次查詢都有收穫；反之事件率極低時輪詢的查詢全部白做。（c）為什麼輪詢頻率必須大於等於事件率：否則兩次查詢之間會來不只一個事件，裝置緩衝區溢位就會漏資料。（d）DMA 的成本為什麼跟資料量無關：資料是由 DMA 控制器搬的，CPU 只付設定與完成中斷；**代價是 DMA 控制器會直接寫記憶體，位址設錯就踩壞別人的資料**（見警語），而且它搬的那段記憶體與快取的一致性要另外處理。

**數值實例**：事件率 1000 次/秒、每次 512 位元組、時脈 2.0 GHz、每次查詢 20 拍、輪詢頻率 10000 次/秒、中斷服務 800 拍、DMA 設定 1200 拍、每位元組 4 拍。

| 方式 | 每秒拍數 | CPU 佔用率 |
| --- | --- | --- |
| 輪詢 | 10000 × 20 ＋ 1000 × 512 × 4 ＝ 2248000 | **0.112400 %** |
| 中斷 | 1000 × (800 ＋ 512 × 4) ＝ 2848000 | **0.142400 %** |
| DMA | 1000 × 1200 ＝ 1200000 | **0.060000 %** |

資料吞吐量 ＝ 1000 × 512 ＝ **512000 位元組/秒**。輪詢的最壞事件延遲 ＝ 1 / 10000 ＝ **100.000000 µs**；中斷延遲（200 拍 @ 2 GHz）＝ **0.100000 µs**——**輪詢省 CPU 但延遲差了三個數量級**。

邊界對照：事件率拉到 **100000 次/秒**、每次 **4096 位元組**、輪詢頻率同步拉到 100000 → 輪詢 **82.020000 %**、中斷 **85.920000 %**、DMA **6.000000 %**：**資料量一大，只有 DMA 撐得住**。事件率降到 **10 次/秒**（輪詢頻率仍 10000）→ 輪詢 **0.011024 %**、中斷 **0.001424 %**、DMA **0.000600 %**：**輪詢變成最貴的，因為 99.9 % 的查詢都白做**。若輪詢頻率**小於**事件率 → 必須顯示「輪詢頻率低於事件率，兩次查詢之間會來不只一個事件，會漏資料」。

| 邊界情形 | `io-rate = 1` → 「事件率極低時輪詢幾乎全部白做，中斷明顯划算」；`io-bytes = 4096` 且 `io-rate = 100000` → 「程式化搬移已經吃掉大半個 CPU，這是 DMA 存在的理由」；`io-clock` 最小 0.5，**分母恆為正** |

`p.warning`（**必寫，內容照此要旨**）：DMA 控制器會**繞過 CPU 直接寫記憶體**，來源位址、目的位址或長度設錯時，它會安靜地覆蓋別人的資料結構，而且不會觸發任何保護例外；在裸機或驅動程式層寫 DMA 描述子時，務必逐欄檢查位址與長度，並確認那段緩衝區在傳輸期間不會被搬移或釋放。

**不要混淆（至少四條）**：中斷不是「比較快」——它降低的是**延遲**不是 CPU 佔用；輪詢在高事件率下反而可能比中斷省，因為它沒有每次事件的固定進出成本；DMA 不是「零成本」，它有設定成本、完成中斷，還會跟 CPU 搶記憶體頻寬；記憶體對映 I/O 的那些「變數」不是普通記憶體，讀它可能有副作用，所以編譯器不能把它最佳化掉。

**可觀察證據**：Linux 的 `/proc/interrupts` 直接給出每個中斷來源的觸發次數；`vmstat` 的 `in` 欄位給出每秒中斷數；把驅動程式從中斷模式切成輪詢模式（例如網路卡的 NAPI）再量一次 CPU 使用率，就能實測這一章的取捨。**能證明**：這個裝置實際觸發了多少次中斷、切換方式之後 CPU 使用率有沒有降。**不能證明**：某一次中斷花了多少拍（要用追蹤工具且會干擾被測系統）；也證明不了「DMA 一定比較好」——小量高頻的事件下 DMA 的設定成本可能超過直接搬。

### 12 `12-匯流排家族PCIe到CAN.html`

**目標**：把六種常見介面放進同一張比較表，用**同一筆資料量**（64 KiB）算出各自要傳多久，並把「原始位元率」與「有效位元組率」的差距（線路編碼負擔）講清楚。最後給一個可操作的選型判準：速率、距離、裝置數、線數四項一起看。

**要點**：匯流排（bus）＝ 多個裝置共用一組線並靠仲裁（arbitration）決定誰能講；點對點連結（point-to-point link）＝ 只有兩端，要接多個裝置得靠交換器（switch）或集線器（hub）；序列與並列的取捨（並列在高速下受偏斜與串音所限，現代高速介面幾乎全是序列差動）；**線路編碼負擔**：8b/10b（效率 80 %）、128b/130b（效率 98.461538 %）、I²C 每 8 個位元要一個確認位元（效率 8/9）、UART 8N1 每個位元組要 10 個位元（效率 80 %）、CAN 一個標準訊框 111 個位元只送 64 位元資料（效率 57.657658 %）；主從式（SPI）、多主式（I²C、CAN）與仲裁；`有效位元組率 = 原始位元率 × 編碼效率 / 8`。**注意單位**：這裡的 MB/s 是 10<sup>6</sup> 位元組/秒，而 64 KiB 是 65536 位元組。來源：11-計算機組織與微處理機 §6.2。

**推導必寫**：（a）為什麼要有線路編碼：接收端沒有獨立的時脈線，必須從資料流本身還原時脈，所以編碼要保證足夠的邊緣密度並維持直流平衡；代價就是那 20 % 或 1.5 % 的額外位元。（b）為什麼 128b/130b 比 8b/10b 划算：同樣的目的只花 2 個額外位元而不是 2 個位元組，但它需要更好的接收器（擾碼加對齊），**這是製程進步換來的**。（c）CAN 為什麼效率這麼低：它是為了**可靠與仲裁**設計的——識別碼、CRC、確認槽、訊框間隔全都不是資料，換到的是位元級無破壞性仲裁與強健的錯誤偵測。（d）為什麼 SPI 的線數會隨從機數增加：每個從機要一條獨立的晶片選擇線，`線數 = 3 + 從機數`；I²C 則用位址取代選擇線，永遠只要 2 條。

| --- | --- | --- | --- | --- | --- | --- | --- |
| PCIe 4.0 ×4 | 64 Gbit/s（16 GT/s × 4 lane） | 128/130 ＝ 98.461538 % | **7876.923077 MB/s** | 18 | 點對點（多裝置要 switch） | 0.3 m | 1 |

邊界對照：切到 **PCIe**、裝置數 4、長度 1 m → 兩個判定都不通過：「PCIe 是點對點，掛 4 個裝置要 switch」與「1 m 超過典型的 0.3 m」。切到 **CAN**、長度 40 m、裝置 32 → 全部通過，**這是六種裡唯一能拉 40 m 又掛幾十個節點的**，代價是 0.036036 MB/s。切到 **SPI**、裝置數 8 → 線數 **11 條**，**每多一個從機就多一條線，這是 SPI 擴充性的天花板**。

### 13 `13-處理器家族選型.html`

**目標**：把全課的取捨收攏成一個可操作的決策：給定工作負載類型、運算需求、功耗預算、產量與延遲要求，六個處理器家族各要幾顆、耗多少瓦、總共多少錢、誰勝出。重點不是記住某顆晶片的規格，而是**學會這張表怎麼填**。

**要點**：通用 CPU（分支密集、單執行緒效能高、軟體生態最好）；微控制器（microcontroller, MCU，CPU ＋ 記憶體 ＋ I/O 在同一顆，低功耗、延遲確定）；DSP（digital signal processor，為乘加累積 MAC 最佳化）；GPU（大量執行緒的資料級平行，功耗高）；NPU（neural processing unit，為神經網路推論的矩陣運算最佳化，能效最好）；FPGA（可重組邏輯，適合固定管線串流，開發成本高但可以做到硬即時）；**能效（Gops/W）**與**總成本（單價 × 顆數 × 產量 ＋ NRE）**是兩個常常打架的指標；**確定性延遲**只有 MCU、DSP、FPGA 給得起。來源：11-計算機組織與微處理機 §8。

**推導必寫**：（a）為什麼要用「效率係數」而不是直接比峰值：峰值是廠商在最理想的核心迴圈上量的，換一種工作負載能取到的比例天差地遠——分支密集的程式在 GPU 上只能發揮個位數百分比。（b）顆數為什麼要向上取整：半顆晶片不存在，`顆數 = ⌈需求 / (峰值 × 效率係數)⌉`。（c）NRE 為什麼會翻轉結論：FPGA 的一次性工程費用攤到產量上，產量小的時候它是主要成本，產量大的時候可以忽略——**這條交叉線就是選型決策的核心**。（d）為什麼能效最好的不一定被選上：只要兩者都滿足需求，比的就是總成本；NPU 能效贏 190 倍，但單價貴、產量一大就輸給便宜的 DSP。

| 控制 2 | `<select id="cp-work">`，`option` 依序：`matrix`「矩陣乘法／推論」、`control`「控制流密集（分支多）」、`mac`「MAC 密集（FIR 濾波）」、`stream`「固定管線串流」。標籤：`工作負載類型`。**預設 `matrix`** |

| 邊界情形 | 全部家族都不可行 → 顯示「目前的功耗預算或延遲要求下沒有可行方案，最接近的是 X，還差 Y」，**不得留白或輸出 NaN**；`cp-ops = 1000` 且 `cp-work = control` → NPU 的實際可達 ＝ 4000 × 0.02 ＝ 80 Gops/s，需要 **13 顆**（⌈1000 / 80⌉），必須指出「這個數字本身就是答案：這個家族不適合這種工作負載」（**指揮官 2026-08-28 修正：原稿寫 50000 顆是漏乘峰值、誤用 `1000 / 0.02` 所致；顯示條件改為顆數 ≥ 10 即觸發**）；`cp-volume = 100` → FPGA 的 NRE 攤到每顆 500.000000 美元，必須指出 NRE 在小量時的主導性；`實際可達 > 0` 恆成立（效率係數皆大於 0），**不得除以 0** |

**不要混淆（至少四條）**：Gops/s 的「ops」在不同家族指的不是同一種運算（NPU 的是低精度整數乘加，CPU 的是通用指令），**跨家族比峰值本來就不公平**，這也是要乘效率係數的原因；能效好不等於總成本低；FPGA 不是「比較慢的 ASIC」，它是用查找表模擬邏輯的另一種架構（見姊妹課第 13 章）；「確定性延遲」不是「延遲很低」，是**最壞情況有上界**——CPU 的平均延遲可能更低，但它沒有上界。

**可觀察證據**：把同一個演算法分別在 CPU 與加速器上跑，用牆鐘時間與功率計（或平台的能耗計數器）量出實際的 Gops/W；資料手冊給的是峰值，實測值除以峰值就是你這個工作負載的效率係數。**能證明**：這個演算法在這個平台上的實際吞吐與能效。**不能證明**：換一種實作會不會更好（效率係數對程式寫法極度敏感）；也證明不了廠商的峰值是假的——那個數字通常是真的，只是量的是別的東西。

**連到哪門課**：可重組邏輯與查找表見 `../邏輯設計-互動課程/13-可程式邏輯與HDL.html`；MAC 密集負載的來源（FIR 濾波器）見 `../信號與系統-互動課程/15-數位濾波器與多速率.html`；資料級平行的加速上限見本課第 07 章；這些晶片怎麼接進系統見本課第 12 章。

### 5.3 撰寫要求

- 「不要混淆」欄位必須指出**邊界**，不是同義詞。範例（章節作者照這個密度寫）：
  - 執行時間三因子：「CPI 不是『一條指令要幾拍走完』（那是延遲），是**平均每條指令佔用機器幾拍**；超純量下它可以小於 1。」
  - 微運算：「指令數與 micro-op 數是兩個不同的計數器。CISC 的一條指令可能是 1 個也可能是 4 個 micro-op，只看指令數會得到相反的結論。」
  - 端序：「端序是**記憶體裡的位元組順序**，不是位元順序。暫存器裡的值沒有端序問題。」
  - 載入使用冒險：「這是**即使有完整旁路也躲不掉**的那一種，它是管線階段排列的必然結果，不是設計偷懶。」
  - 假相依：「WAR 與 WAW 只是兩條指令剛好用了同一個名字，換個實體暫存器就沒了；RAW 換不掉，因為值真的要流過去。」
  - 推測執行：「推測在**功能上**永遠正確，錯的結果會被丟掉。問題出在它留下的微架構痕跡，那是另一個層次的事。」
  - 失誤三分類：「這是**分析工具**不是物理量。循環走訪超過容量時，衝突失誤會算出負值——那是三分類法本身的破口。」
  - 偽共享：「程式的結果完全正確，只是慢。它不是邏輯錯誤，是資料佈局問題；加鎖與它無關。」TLB：「TLB 失誤與頁缺失是兩件事：前者是翻譯不在 TLB（頁還在記憶體），後者是頁根本不在記憶體。」中斷：「中斷降低的是**延遲**不是 CPU 佔用。高事件率下輪詢反而可能比中斷省。」匯流排仲裁：「CAN 的位元級仲裁是**無破壞性**的——輸的那一方退出而贏的那一方不必重傳。」
- 每張卡的「位置／角色」要寫**它在本課哪一章、在哪門後續課或哪個真實裝置用到**。
- 符號（× ÷ ≤ ≥ ⌈ ⌉ Σ µ 10<sup>6</sup>）出現時要在卡內寫出讀法。
- 首次出現的英文縮寫要展開全名。
- **禁用詞配額卡（這五張是硬性規定，違反即失敗）**：
  - **「快取」卡的「不要混淆」必須寫**：本課一律用台灣標準用語「快取」；中國教材寫「緩存」，是同一個 cache。**「緩存」兩個字在全課只能出現這一次，且必須是明碼 UTF-8，不得用 HTML 數字實體。**
  - **「管線」卡的「不要混淆」必須寫**：本課一律寫「管線」；中國教材寫「流水線」，是同一個 pipeline。**「流水線」三個字在全課只能出現這一次，明碼。**
  - **「匯流排與點對點連結」卡的「不要混淆」必須寫**：本課一律寫「匯流排」；中國教材寫「總線」，是同一個 bus。**「總線」兩個字在全課只能出現這一次，明碼。**
  - **「超純量」卡的「不要混淆」必須寫**：本課一律寫「超純量」；中國教材寫「超標量」，是同一個 superscalar。**「超標量」三個字在全課只能出現這一次，明碼。**
  - **「旁路」卡的「不要混淆」必須寫**：本課一律寫「旁路」；部分教材把 forwarding 譯成「轉發」。**「轉發」兩個字在全課只能出現這一次，明碼。**
- 其餘禁用詞（「寄存器」「內存」「字節」「無序執行」「缺頁中斷」）**全課 0 次，字典也不得引述**。
- **「推測留下的痕跡」這張卡是本課倫理邊界的所在**：只寫「推測執行會把資料帶進快取，之後可以用計時差看出它來過，這是 Spectre 與 Meltdown 這一類問題的直覺」，**不得寫任何步驟、程式碼或量測配方**；並附一句「修補是系統廠商與作業系統的事，讀者該做的是保持更新」。

### 7.3 `cacheSim()` 的模擬演算法（唯一實作規範，不得偏離）

```text
輸入：seq（[{op:'R'|'W', addr:整數}] 之一，取自 CACHE_SEQ）、size、line、ways、repl、write
1. nsets = size / (line × ways)；若 nsets < 1 回傳 {invalid:true}
2. sets = 長度 nsets 的陣列，每格是一個空清單；clock = 0
3. 逐筆處理每一個 {op, addr}：
   clock += 1
   blk = floor(addr / line)；st = blk mod nsets；s = sets[st]
   e = s 中 tag === blk 的那一筆（可能不存在）
   若 e 存在（命中）：hits += 1；e.use = clock
       若 op === 'W'：write === 'wb' 則 e.dirty = true；否則 wtBytes += 4
   否則（失誤）：miss += 1
       allocate = true
       若 op === 'W' 且 write === 'wt'：allocate = false；wtBytes += 4
       若 allocate：
           memReadBytes += line
           若 s 的長度 >= ways：
               vic = repl === 'lru' ? use 最小者 : repl === 'fifo' ? ins 最小者 : use 最大者
               若 vic.dirty：wbBytes += line
               從 s 移除 vic
           把 {tag:blk, dirty:(op==='W' && write==='wb'), ins:clock, use:clock} 加入 s
4. 序列跑完後，所有 s 中 dirty 為真的項各 wbBytes += line
5. 回傳 {hits, miss, n, memReadBytes, wbBytes, wtBytes}
```

**三分類**：`強制 = seq 中不同 blk 的個數`；用同一支函式以 `ways = size / line` 再跑一次得到 `fullMiss`；`容量 = fullMiss − 強制`；`衝突 = miss − fullMiss`，**小於 0 時輸出 0 並附說明**。

**`cacheSim` 必須從 `module.exports` 匯出**，因為它是本課最需要獨立驗算的函式。

### 7.4 `branchSim()` 的走訪演算法（唯一實作規範）

```text
輸入：pattern（'loop'|'alt'|'ttnn'|'taken'|'nottaken'）、rep、kind、init
seq = PATTERN[pattern] 重複 rep 次（PATTERN.loop = "TTTTTTTN" 等，見第 4 節第 05 章）
kind === 'static_t'：誤判數 = seq 中 'N' 的個數
kind === 'static_n'：誤判數 = seq 中 'T' 的個數
kind === 'bit1'：s = (init === '10' || init === '11') ? 1 : 0
                 逐筆：a = (c === 'T') ? 1 : 0；若 s !== a 誤判 += 1；s = a
kind === 'bit2'：s = parseInt(init, 2)
                 逐筆：a = (c === 'T') ? 1 : 0；p = (s >= 2) ? 1 : 0
                      若 p !== a 誤判 += 1
                      s = a ? Math.min(3, s + 1) : Math.max(0, s − 1)
```

**`branchSim` 必須從 `module.exports` 匯出。**
