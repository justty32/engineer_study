08・同一段程式，換一個快取設計，命中率可以從 0 % 跳到 87.5 %

快取設計四維度：對映方式、替換策略、寫策略、區塊大小，四個旋鈕一起決定命中率

全課的互動核心。一組存取跑過四個設計維度：更相聯、更大的區塊都不一定更好；命中率不是快取的性質，是它與存取樣式的合成。

這章假設已懂：00 微處理機世界觀與效能公式的拍數。前置：快取與分頁機制見計算機組織的記憶體階層與虛擬記憶體；本章只做量化取捨。

痛點：兩支功能一模一樣的程式，快了 7 倍

兩支程式做同一件事、輸出相同，一支慢七倍；時間都耗在同一行陣列存取，兩邊寫法一樣，換大一倍的快取仍慢。

問題不在程式碼，而在位址落在哪裡：快取切開位址決定資料放哪格，相距剛好的兩陣列會撞進同格——同一組存取可以全失誤，也可以 87.500000 % 命中。

來源：11-計算機組織與微處理機 §5.1、§5.2。

白話直覺：位址被切成三段，中間那段決定你住哪一間

暫時把快取想成有編號的旅館房間；比喻到此，收回精確定義：快取以區塊（cache line／block）為搬運單位整塊搬；同容量下分成若干組（set）、每組若干路（way），組數 = 容量 / (區塊大小 × 路數)。直接對映（direct-mapped）每組 1 路，n 路組相聯（n-way set-associative）每組 n 路，全相聯（fully-associative）只有 1 組、路數 = 區塊數。

依因果鏈走一次。工作量從哪來：程式產生一串位址，規律有兩種：時間區域性（temporal locality）是同一筆很快再用，空間區域性（spatial locality）是附近的很快會用。這一招做了什麼決定：用中間幾位挑組，組內比標籤判命中。省下多少、多花多少：命中 1 拍、失誤多付 50 拍；改成二路，平均存取時間 51.000000 降到 7.250000 拍，代價是每組多一套比較器與替換狀態。邊界在哪：相聯度只換被踢的是誰，循環走訪反而全敗。儀器量到什麼：計數器數得出失誤次數，分不出類。

推導：位址切分、失誤三分類、寫策略的流量

（a）位址怎麼切，索引為什麼取中間。位元組位址由高到低切成三段：標籤（tag）／索引（index）／區塊內偏移（offset）。偏移位元數 = log2(區塊大小)，指出在區塊裡第幾格；索引位元數 = log2(組數)，指出哪一組；高位是標籤，確認那一路是不是要的區塊。等價算法：區塊編號 = ⌊位址 / 區塊大小⌋、組索引 = 區塊編號 mod 組數。

索引取中間，因為低位已被偏移吃掉；若改取最高幾位，相鄰區塊會全落進同一組，順序掃描每步都撞在一起，空間區域性從優勢變災難。

（b）失誤三分類（3C）怎麼算。強制失誤（compulsory） = 區塊第一次被碰到，等於不同區塊數，再大的快取也躲不掉。容量失誤（capacity） = 同容量全相聯失誤數 − 強制失誤數，即工作集塞不下。衝突失誤（conflict） = 實際失誤數 − 全相聯失誤數，是位址撞同一組的浪費，唯一能靠相聯度消掉。

（c）為什麼衝突失誤可能算出負值。三分類以全相聯配 LRU 為理想基準，但它在循環走訪超過容量時恰是最壞情形：每次都剛好踢掉下一個要用的，全不命中；直接對映映射固定反保住一部分，實際失誤比全相聯少，相減成負值。這是三分類法的已知破口，不是計算錯誤，本課顯示 0 並附說明。

（d）寫策略的流量取捨。寫回（write-back）＋寫配置（write-allocate）：寫失誤先搬整塊再改，髒塊逐出時整塊寫回。寫穿（write-through）＋不配置（no-write-allocate）：每次寫直接送出，寫失誤不搬塊。前者把多次寫併成一次回寫，後者每次只送 4 個位元組、省下逐出的整塊搬移；哪個省看寫得密不密集。

替換策略在直接對映下不存在（每組一路）。本課提供 LRU（最近最少使用）、FIFO（先進先出）、MRU（最近使用）；Random 因本站禁用亂數，只用文字說明。以上全是一階教學模型：真實快取有多層階層、預取器與近似 LRU，命中時間也與相聯度有關。

數值實例：兩個陣列相距 256 位元組，直接對映全部失誤

設定與互動元件預設值一致：序列 conflict（16 筆全是讀：0、256、4、260、8、264、12、268、16、272、20、276、24、280、28、284）、直接對映、LRU、寫回＋寫配置、區塊 32 位元組、容量 256 位元組、命中 1 拍、失誤懲罰 50 拍。容量用 2 的次方位元組（256 位元組 = 0.25 KiB；第 12 章匯流排速率才用 10 的次方 MB/s）。

位址切開：組數 = 256 / (32 × 1) = 8，偏移 5 位元（32 = 25）、索引 3 位元（8 = 23）、其餘標籤。

AMAT = thit + 失誤率 × tpenalty。thit 是命中一次的拍數（本課 1 拍），tpenalty 是失誤多花的拍數（本課 50 拍，真實系統會因排隊而變動）。直接對映：1 + 1.000000 × 50 = 51.000000 拍；二路：1 + 0.125000 × 50 = 7.250000 拍。量級對照：51 拍在 2.0 GHz、Tc = 0.500000 ns 下是 25.500000 ns，白丟 127 條 CPI 0.4 指令的時間。

三個結論。（1）有空間區域性時加大區塊免費賺命中率：stride 是步長 4 的順序掃描，行從 16 換到 64 位元組，命中率從 75.000000 % 升到 93.750000 %，容量沒加；但區塊越大、區塊數越少，沒區域性時更糟。

（2）同容量全相聯配 LRU 可能被直接對映打敗：loop 走訪 6 個區塊 3 遍，128 位元組只裝 4 塊；直接對映 22.222222 %，全相聯配 LRU 卻是 0.000000 %——每輪都剛好踢掉下一個要用的。衝突失誤算出 14 − 18 = −4，規格規定顯示 0，不是缺陷。

（3）MRU 在循環走訪上贏過 LRU：同一個 loop、128 位元組全相聯，MRU 拿 44.444444 %，因為它固定犧牲剛用過的。寫策略不影響命中率，mixed 兩列都是 60.000000 %，差別在流量：寫回＋寫配置讀 256 ＋ 寫回 256 = 512 位元組；寫穿＋不配置讀 192 ＋ 寫穿 40 = 232 位元組，不到一半。

自由實驗：同一組存取序列，四個設計維度一起轉

場景是一顆單層快取接在主記憶體前面，四組固定的存取序列代表四種常見的程式行為：兩陣列交錯、順序掃描、循環走訪、讀寫混合。機器這一側可以改對映方式、替換策略、寫策略、區塊大小與容量，時間這一側可以改命中時間與失誤懲罰。要看的是命中率、失誤三分類、主記憶體流量與 AMAT 各差多少，以及換一組序列之後同一個設計會從最好變成最壞。

這個序列全部是讀取，寫策略那一格不影響結果；直接對映每組只有一路，替換策略那一格也不影響結果。組數 8、每組 1 路。命中 0 次、失誤 16 次，命中率 0.000000 %。失誤三分類：強制 2、容量 0、衝突 14。主記憶體讀取 512 位元組、寫回 0 位元組。AMAT = 1 + 1.000000 × 50 = 51.000000 拍。這 14 次失誤在同容量全相聯下不會發生，換成二路組相聯就能消掉。兩個區塊的組索引都是 0，交錯存取讓它們互相踢掉。命中率是設計與存取樣式的乘積，換一個序列同一個設計就可能從最好變最壞。

不要混淆

  • 命中率不是快取的性質。邊界在「換了序列會不會變」：換一組樣式，命中率可從 0 % 變成 93.75 %，它是快取與存取樣式一起的性質；規格書的命中率都附帶沒寫出的基準測試。
  • 「更相聯一定更好」是錯的。邊界在 loop 那組反例：全相聯配 LRU 拿 0.000000 %，直接對映拿 22.222222 %。相聯度只消衝突失誤，不保證挑對犧牲者。
  • 區塊變大不是免費的。邊界在有沒有空間區域性：有就賺命中率，沒有就區塊變少、搬運量變大，兩頭都輸。
  • 寫穿不等於「比較慢」。邊界在寫得密不密集：mixed 上寫穿 232 位元組不到寫回 512 的一半，因為寫回要為每個髒塊付整塊回寫。
  • 失誤三分類是分析工具不是物理量。邊界在極端情形：基準全相聯 LRU 在循環走訪上最壞，衝突失誤才算出負值。

可觀察證據：拿什麼量、量到什麼

perf stat 的 cache-references、cache-misses 與 L1-dcache-load-misses 這類細項可量出實際失誤率。把矩陣乘法的迴圈順序從 i j k 換成 i k j，失誤數明顯下降，這是最容易重現的對照。

能證明：這段程式在這台機器的失誤次數、改寫後有沒有降。不能證明：失誤屬於哪一類——計數器不分類，要靠模擬器；也證明不了「容量不夠」，因為對映衝突症狀相同，把陣列起始位址墊開（padding）再量，失誤數大降就是衝突。
