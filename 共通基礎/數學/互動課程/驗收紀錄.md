## 7.5 複驗期間的新觀察（皆非缺陷，供 Lead 知悉）

### N-1　`styles.css` 未轉 CRLF —— 這是**正確**的，自報說法應更正

修正清單第 7 項寫「全課程目錄 **19 檔**行尾統一 CRLF」，但實測只有 **18 檔**是 CRLF，`styles.css` 仍是 LF。

**不應該去修它。** BUILD-SPEC 鐵律第 2 條要求 `styles.css` 與 `專題/機器人數學基礎/互動課程/styles.css` **一個位元組都不能差**，而對照組是 LF。若把本課的 `styles.css` 轉成 CRLF，位元組數會由 4,141 變成 4,155，**當場違反鐵律 #2**。

實測確認兩檔目前仍位元組相同（sha256 前 16 碼皆 `894f24a10105d006`）。**建議只更正自報措辭為「18 檔 ＋ styles.css 依鐵律 #2 維持與來源相同的 LF」，不要動檔案。**

### N-2　`polezero` 的 `<` 未跳脫（風格不一致，非功能缺陷）

`app.js` 的 `polezero` 在 `zline` 中寫出未跳脫的半形 `<`，例如 `0 < ζ = 0.447214 < 1：` 與 `ζ = −0.554700 < 0：`；但**同一個函式**的另一分支用了跳脫的 `&gt;`（`σ &gt; 0`），`dist` 函式也用 `&lt;`。三種寫法並存。

**已在真實瀏覽器確認不是缺陷**：HTML 剖析器只有在 `<` 後緊接字母時才視為標籤起點，這裡 `<` 後是空白，因此被當成文字節點。實測渲染結果：

```
…包絡 eσt = 0.367879
0 < ζ = 0.447214 < 1：欠阻尼，會邊振盪邊衰減。
```

`polezero-output` 的子元素為 `P,P,P,P,P,P,P,P` 共 8 個，**內容無遺失、無 pageerror**。純屬寫法不一致，可日後順手統一為 `&lt;`，**不影響本次交付**。

> 驗收員自記：首輪與本輪的純文字剝離器（`replace(/<[^>]+>/g,'')`）會把 `< 0：…</p>` 整段誤吃成標籤，一度看似「文字遺失」。已改用瀏覽器 `textContent` 實測澄清，**未據此開立假缺陷**。
