## 錯誤
- `Neovim/04-除錯與語言環境.md:72-75`｜高｜DAP 鍵位寫錯：`<leader>do` 標成 Step over、`<leader>dO` 標成 Step out，實際 LazyVim（dap/core.lua 46–47 行）是 `do`＝Step Out、`dO`＝Step Over；`<leader>dq`「停止除錯」不存在，停止是 `<leader>dt`（Terminate）｜改為 `do` Step out、`dO` Step over、`dt` 終止；可補 `<leader>dl` 重跑上次、`<leader>dr` 開關 REPL。
- `Neovim/03-Lisp家族REPL.md:38-40`｜高｜說「這份設定把 HUD 關掉了，要看結果用 `,ls`」，但 `lua/plugins/conjure.lua` 設 `conjure#log#hud#enabled = true`、`open_when = "log-win-not-visible"`（log 視窗沒開時才跳 HUD），並把寬高設成 0.55／0.4｜改寫此節：HUD 開著、log 視窗可見時不重複跳；`,lh` 可切換 HUD 大小。
- `Neovim/03-Lisp家族REPL.md:16-35`｜中｜按鍵表缺設定自訂的 `,le`（在目前視窗開 log，`q` 還原來源）、`,ll`（開 log 並跳到最新結果；Conjure 原生的 `log_jump_to_latest`、`log_buf` 已被停用）、`,lh`（切換 HUD 大小），以及 log buffer 內的 `q` 關閉行為｜在表中補這 4 項並註明「自訂」。
- `Neovim/03-Lisp家族REPL.md:31-32`｜中｜表頭說「接在 `,` 後」，但 Conjure 的 `gd`（跳定義）與 `K`（查文件）預設是不加 localleader 的裸鍵（`conjure#mapping#def_word = "gd"`、`doc_word = "K"`）｜這兩列移出表格，另註「直接按 `gd`／`K`，不用前綴」。
- `Neovim/01-安裝與基本概念.md:64`、`Neovim/04-除錯與語言環境.md:141`｜中｜`super-tab` 的 `Tab` 是 `select_and_accept`（選取並接受，snippet 中則跳下一個欄位），`S-Tab` 是 `snippet_backward`；換項目要用 `Up/Down` 或 `C-n/C-p`。筆記寫「Tab 選下一個、S-Tab 選上一個」是錯的（設定檔 settings.lua 只設 preset，沒有覆寫 Tab）｜改為「Tab 接受目前項目（或跳到 snippet 下一欄），C-n/C-p 上下選，S-Tab 回 snippet 上一欄」。
- `Neovim/04-除錯與語言環境.md:113`｜中｜「功能：…VS Code（讀 launch.json 等整合）」與 `lazyvim.json` 不符：實際啟用的 extras 沒有 `vscode`；而且 LazyVim 的 vscode extra 是讓 LazyVim 跑在 VS Code（vscode-neovim）裡，與讀 launch.json 無關（讀 launch.json 是 nvim-dap 內建的 `dap.launch.json` provider）｜刪掉 VS Code 這項；可補一句「launch.json 由 nvim-dap 自己讀，不需要 extra」。
- `Neovim/06-自己寫插件-實戰-cmera.md:143,145`｜中｜說 `vim.system` 的 callback「在背景執行緒呼叫」、「在 luv 的執行緒裡跑」不正確：callback 在 Neovim 主執行緒的 libuv 事件迴圈中以「fast event」狀態執行，不是另一條執行緒；限制來自 fast 狀態下不能呼叫多數 API（E5560）｜改為「callback 在事件迴圈的 fast 狀態下執行，多數 API 不能直接呼叫，所以用 `vim.schedule` 延到安全時機」。
- `Neovim/06-自己寫插件-實戰-cmera.md:217`｜低｜`Snacks.win` 給 `position = "right"` 時開的是右側分割視窗（只有 `position = "float"` 才是浮動視窗），`backdrop = false` 對分割視窗也無作用｜改成「在右側開一個佔 45% 寬的分割視窗」。
- `Neovim/06-自己寫插件-實戰-cmera.md:128,147`｜低｜`text = true` 時 `obj.stderr` 是空字串 `""` 而非 nil，Lua 中 `""` 為真，`obj.stderr or obj.stdout` 永遠不會退回 stdout；說明「把 stderr（或 stdout）丟給使用者」與實際行為不符（設定檔 cmera.lua／codegen.lua 68 行同樣有此問題）｜教學上改寫為 `(obj.stderr ~= "" and obj.stderr) or obj.stdout or ""`，並在文中點出「空字串在 Lua 是真值」這個坑。
- `Neovim/05-自己寫插件-基礎.md:146`｜低｜「不 return M，require 拿到的會是 nil」不正確：模組沒有回傳值時 `require` 回傳 `true`（`package.loaded[name] = true`）｜改為「拿到的會是 `true` 而不是你的 table，接著 `.setup` 就會報錯」。
- `Neovim/05-自己寫插件-基礎.md:19`｜低｜說「`~/.config/nvim/lua/` 會自動加進 runtimepath」不精確：加進 runtimepath 的是 `~/.config/nvim`，`require` 再到每個 runtimepath 目錄底下的 `lua/` 找模組｜改寫為「`~/.config/nvim` 在 runtimepath 上，`require` 會到其下 `lua/` 找」。
- `Neovim/04-除錯與語言環境.md:20,44`｜低｜`cppdbg` 在所有平台上都是 cpptools（不只 Windows）；另外 codelldb 使用自己內附的 LLDB，不會去 PATH 找 gdb／lldb｜改為「VSCode 的 cppdbg（各平台都是 cpptools，走 GDB/LLDB 的 MI）」與「codelldb 用自帶的 LLDB」。
- `Neovim/02-自訂快捷鍵與命令.md:22`｜低｜`<C-s>`「任何 mode 都能用」：LazyVim 只在 normal／insert／visual／select（`{ "i","x","n","s" }`）映射，命令列與終端模式不行｜改為「normal、insert、visual 都能用」。
- `Neovim/03-Lisp家族REPL.md:52`｜低｜「沒有 slurp、barf、括號跳轉等操作」：Vim 內建 `%` 的括號跳轉仍可用｜改為「沒有 slurp／barf 等結構編輯操作（`%` 跳對應括號仍可用）」。
- `Neovim/03-Lisp家族REPL.md:206`｜低｜macOS 用 Homebrew 裝 GNU coreutils 後指令名是 `gstdbuf`，設定檢查的是 `stdbuf`，不會自動套用｜補一句「macOS 需把 gnubin 放進 PATH 或建 `stdbuf` 別名」。
- `Neovim/06-自己寫插件-實戰-cmera.md:302`｜低｜寫 `.venv/python`，實際與 02 章 93 行皆為 `.venv/bin/python`｜統一為 `.venv/bin/python`。

## 難懂
- `Neovim/03-Lisp家族REPL.md:7,18-19`｜「form」「root form」對非 Lisp 讀者沒定義；建議在表前加一句：form＝一個完整的括號式子，root form＝最外層那個。
- `Neovim/03-Lisp家族REPL.md:162`｜「適合嵌入式腳本開發」有歧義（嵌入式系統 vs. 可嵌入的擴充語言）；s7 的定位是「嵌進 C 程式當擴充語言」，建議改用「可嵌入」。
- `Neovim/03-Lisp家族REPL.md:66` vs `Neovim/06-自己寫插件-實戰-cmera.md:277`｜03 章說 `formatting.lua` 已把整個 `lisp` 的 formatter 設成空清單，06 章又說「LazyVim 看到 lisp 就會想自動格式化，所以對 `.cmera` 另設 `vim.b.autoformat = false`、不影響真正的 Lisp 檔案」，讀者會困惑真正的 Lisp 檔到底有沒有格式化；建議 06 章明講這是「雙重保險」，並說明兩層各擋什麼。
- `Neovim/06-自己寫插件-實戰-cmera.md:189`｜「scratchpad」未解釋；建議寫明 `scratch=true` 會設 `buftype=nofile`、`bufhidden=hide`、不建 swapfile。
- `Neovim/01-安裝與基本概念.md:41-48`｜leader 鍵出現了卻沒提 which-key 彈窗（按下 Space 停一下會列出可用鍵），要到 05 章 68 行才順帶提到；建議在 01 章就介紹，這是查鍵最快的方法。
- `網路安全/README.md:3`｜「foundations-first 工作流」是內部工作流術語，讀者不懂；建議改成「先打基礎、再進攻擊手法」。

## 範例
- `Neovim/05-自己寫插件-基礎.md:215`｜`ft = { ..., ... }` 在表格建構子中寫 `...`，照抄貼上會變成 vararg 而非省略號（主 chunk 中語法合法但語意不同，函式內則是語法錯誤）；改用註解 `-- ...`，與 rainbow 範例一致。
- `Neovim/05-自己寫插件-基礎.md:82-87`｜用 `BufReadPost` ＋ `*.txt` 設 textwidth 會漏掉新開的檔案（`BufNewFile`）；教學範例建議改用 `FileType`＋`pattern = "text"`，順便示範 filetype 為基礎的寫法。
- `Neovim/05-自己寫插件-基礎.md:249`｜`dir = "/Users/你的名字/..."` 是 macOS 路徑，但 README 19 行說這套設定只在 Linux 跑；改為 `~/projects/my-awesome-plugin`（`vim.fn.expand` 或直接寫 `/home/...`）。
- `Neovim/06-自己寫插件-實戰-cmera.md:166-185`｜片段用到未定義的 `lines`、`meta`；加一行註解說明 `lines = vim.split(content, "\n")`、`meta = generators[generator]`，讀者才接得上。
- `Neovim/06-自己寫插件-實戰-cmera.md:320`｜「在 `BufWritePost` 觸發 `M.preview()`」：`M.preview` 內的 `current_file()` 會再 `silent! write`，每次存檔變成寫兩次（autocmd 預設非 nested 所以不會無限遞迴，但值得點出）；建議示範直接呼叫不含存檔步驟的內部函式。
- `Neovim/01-安裝與基本概念.md:12-13`｜只備份 `~/.config/nvim`；LazyVim 官方建議同時備份 `~/.local/share/nvim`、`~/.local/state/nvim`、`~/.cache/nvim`，否則舊插件與新設定會混用；建議補上。
