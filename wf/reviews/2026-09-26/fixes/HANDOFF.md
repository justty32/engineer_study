# 任務：依 2026-09-26 全站審稿報告修整筆記與互動課程

調度者：主 session（Claude Opus）。各隊領導是 opus，讀完本檔再讀自己的報告。報告目錄：`wf/reviews/2026-09-26/`。

## 背景與唯一目標

審稿已完成，報告格式是「`檔名:行號`｜嚴重度｜問題｜建議」。目標：**把報告裡的建議落實到原始檔**，每份報告留一份處置紀錄。

## 改什麼、不改什麼（範圍 gate）

- **必改**：內容錯誤（數值、公式、單位、事實、方向、符號）、題目答案鍵與容差錯誤、程式／互動 bug、壞連結、錯字、缺括號、用語不一致、浮點雜訊外露。
- **應改**：「難懂」「範例」「教學設計」「網頁品質」中**局部**的建議（一段內重寫、補一句說明、補一個數值例、補錨點／連結、補字典卡、調整滑桿範圍、改回饋文字）。
- **延後給使用者決定（不改，記入處置紀錄的「延後」段）**：單條建議需要改動 > 5 個檔、新增頁面／章節、整課改版（例如「全課加圖」「每章改結構」）、與 PROJECT-BRIEF 或 decisions 的既定取捨相衝突、或你判斷會改變原意。
- **審稿可能錯**：動手前先驗證（重算、看原文上下文）。審稿誤判就不改，處置紀錄寫「駁回＋理由」。
- 鐵律：繁體中文、UTF-8、不加圖片、不新增依賴、不改原意。審稿標註「刻意保留」或對照表 wait-user 清單（`wf/wait-user/對照表缺詞.md`）說勿誤刪的，照留。
- 行號會因前面的修改而位移：以文字內容定位，不要盲信行號。

## 分工與領地（同一時間一個目錄只有一隊可寫）

- 筆記隊（T1–T3）：只寫報告點名的 `.md` 筆記與對照表，**不得碰任何 `*互動課程*` 目錄**。
- 互動課程隊（T4–T6）：只寫自己報告對應的互動課程目錄（HTML／CSS／JS／該目錄內 md）。
- 所有隊：**不得寫** `wf/`（自己的處置紀錄除外）、`.github/`、`互動學習網站/`、別隊的報告範圍。需要動到領地外 → 記在處置紀錄「越界待辦」段，交調度者。
- 處置紀錄：`wf/reviews/2026-09-26/fixes/<報告編號>-處置.md`，格式：統計一行（已修 N／駁回 N／延後 N）→「延後」條列（檔:位置｜原建議｜為何延後）→「駁回」條列（理由）→「越界待辦」。已修的不必逐條列。

## 執行方式（含 context 管理）

- 一份報告一條線：把一份報告（或大報告的一段）交給一個工人做；工人優先用 gpt-sol：`codex exec -m gpt-5.6-sol --sandbox workspace-write --skip-git-repo-check -C /home/lorkhan/repo/engineer_study '<提示>' < /dev/null > <log> 2>&1`（`< /dev/null` 必留；可並行多個，但**同一目錄同時只給一個工人**）。你的 sonnet 做機械驗收（語法、id 對照、連結、lint）。工人產出落檔，不要把整份 log cat 進 context。
- 你在 `wf/reviews/2026-09-26/fixes/<隊名>-STATE.md` 記續行點（哪幾份已完成、哪份進行中）。
- 互動課程每門改完必驗：`node --check app.js`（或各 js）、HTML 引用的 id 與 js 一致、相對連結存在；能用 node 載入 CALC 的，重算被改過的數值。
- 收尾跑 `bash wf/tools/wf-lint.sh wf`，不得新增錯誤。

## git

- **只 commit 自己領地與自己的處置紀錄**：`git add -- <路徑…> && git commit -m '<訊息>' -- <路徑…>`；遇 `index.lock` 等幾秒重試。**禁止** `git add -A`／`git add .`／`git stash`／`git reset`／`git checkout -- `別人的檔。
- 每完成 2–4 份報告 commit 一次，訊息格式 `fix(<範圍>): 依 9/26 審稿 NN–NN 修整 …`，結尾加：
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`
- **不 push**（調度者統一 push）。

## 驗收（就這 4 條）

1. 每份負責的報告都有 `fixes/<編號>-處置.md`，統計行存在。
2. 互動課程隊：每門課 js 通過 `node --check`，id 對照 0 缺漏。
3. `wf-lint` 沒有比開工前多出的錯誤。
4. 全部改動已 commit 到 main（`git status --short -- <你的領地>` 為空），未 push。

## 回報

結束時用最多 15 行回報：每份報告的「已修／駁回／延後」三個數、commit hash 清單、越界待辦（一行一條）、遇到的阻礙。不要貼 diff。
