# 一、Linux（專題/Linux/互動課程/）

## 總評
- 正文的指令範例大多正確：chmod 755／644、640 加 bob 的判定、realpath、`ps -o pid,ppid,stat,cmd`、`grep '^ERROR'`、`stat -c '%A %a %U %G'`、apt／dnf 對照、grep 結束狀態 0／1／2 都核對無誤。
- 問題集中在 app.js 的模擬器。模擬器說是在模仿 shell 或 grep，實際語意卻不一樣：grep 用 JS RegExp 而不是 BRE，還會吞掉空行；變數展開用的是字串取代，不認變數名稱邊界與單引號；glob 的 `*` 會比對到隱藏檔。這些對「以後拿真 shell 驗證」的讀者會直接造成錯誤預期。
- 有一處正文與字典互相矛盾：Ctrl-Z 送出的訊號，app.js 寫 SIGSTOP，字典寫 SIGTSTP（字典的寫法才對）。
- 教學設計：13 個互動裡有 5 個只是「選單 → 固定說明」，偏被動；全課沒有自我檢核題；07 章名為「文字處理」，實際只教 grep。

## 內容錯誤
- `app.js:58`（`psstate` T）｜中｜「被 SIGSTOP 或 Ctrl-Z 暫停」：Ctrl-Z 由終端送出的是 SIGTSTP（可攔截），不是 SIGSTOP（不可攔截）。同課字典「前景／背景與作業控制」卡寫的是正確的 SIGTSTP，兩處矛盾。這也直接牽涉同頁「哪些訊號可攔截」這個教學重點｜改成「被 SIGSTOP（不可攔截）或 Ctrl-Z 送出的 SIGTSTP（可攔截）暫停」。
- `app.js:90`（`envexpand` 說明）×`08-環境變數與shell.html:14`｜中｜輸出說明寫「單引號 '...' 內不展開」，但工具本身照樣展開：`'$HOME'` 實測輸出 `'/home/alice'`。HTML 又說「本工具不模擬引號」，三方說法不一致，讀者會以為單引號也會展開｜工具遇到單引號區段時原樣保留，或刪掉輸出中的引號說明，改成「本工具忽略引號，真實 shell 單引號內不展開」。
- `06-管道與重導向.html:7-8`｜低｜`ls /home/alice /missing > files.txt` 之後，`cat files.txt` 顯示成 `notes.txt  projects`（並排兩欄）。但 stdout 不是終端時，ls 會改為一行一個（本機實測輸出 `notes.txt⏎projects⏎`）｜改成兩行。也可以順勢補一句「ls 會偵測輸出是不是終端」，正好呼應本章 fd 的概念。
- `app.js:57`（Z）｜低｜殭屍「佔一個項目不佔資源」：殭屍仍占用 PID 與行程表項目；大量殭屍可能耗盡 pid_max，這正是要處理它的原因｜改成「不再耗 CPU 與記憶體，但仍占 PID 與行程表項目」。
- `app.js:67-68`｜低｜SIGSTOP=19、SIGCONT=18 只是 x86／ARM 上的編號（MIPS 為 23／25，SPARC／Alpha 也不同），輸出卻教 `kill -19`｜加註「編號依架構而異，建議用名稱 `kill -STOP`」，並把名稱寫法排在前面。
- `app.js:49`（`access`）×`04-使用者群組與存取.html:9`｜低｜使用者填 root 時，模擬器把 root 判為「其他人」，讀寫都不可。真實核心中 root 有 CAP_DAC_OVERRIDE，讀寫會略過 rwx 檢查；但 04 章的「sudo 不是打開全部權限」很容易讓人以為 root 也受 rwx 限制｜使用者為 root 時另外輸出「root 會略過一般讀寫權限檢查（執行仍需至少一個 x）」。
- `app.js:96`｜低｜`dnf check-update` 被描述成只「更新可用套件清單」：它會刷新中繼資料，但主要用途是列出可升級項目（有更新時結束碼 100）。與 `apt update` 語意最接近的是 `dnf makecache`｜改成 `sudo dnf makecache`，或在說明中註明 check-update 會同時列出可升級項目。
- `09-套件管理.html:8`｜低｜`The following NEW packages will be installed:` 是 apt 2.9 以前的輸出；Ubuntu 24.10 以後的新版 apt 改成 `Installing:` 等新格式｜加註「訊息依 apt 版本略有不同」。

## 程式／互動 bug
- `app.js:84`（`grepw`）｜中｜`lines.filter(l=>l!==''&&…)` 先把空行濾掉，導致 `^$`（找空行的標準寫法）永遠命中 0 行（實測 `a\n\nb` → 0 行）｜只排除 textarea 結尾那一個空字串（`split` 後 pop 掉最後的 ''），其餘空行保留。
- `app.js:83`（`grepw`）｜中｜工具用 JS `RegExp` 實作，等同 grep -E／-P 的語意；正文 07 章卻說基本語法與 -E 不同。實測 `ERROR|WARN` 命中 3 行，真實 `grep 'ERROR|WARN'`（BRE 中 `|` 是普通字元）只命中字面含 `ERROR|WARN` 的 1 行；`+ ? ( ) {}` 與 `\d` 也一樣有差｜加一個「-E」勾選框：未勾選時先把 BRE 轉成 JS 語法（把 `| + ? ( ) {` 跳脫，`\| \+ \?` 還原成元字元），並禁用 `\d`；至少要在輸出加註「本工具相當於 grep -E」。
- `app.js:89`（`envexpand`）｜中｜`/\$\{?HOME\}?/` 不認變數名稱邊界：`$HOMEDIR` → `/home/aliceDIR`、`$USERNAME` → `aliceNAME`、沒閉合的 `${HOME` 也照樣展開（實測）。真實 bash 會把它們當成 HOMEDIR、USERNAME 這兩個變數（未設定 → 空字串），`${HOME` 則是語法錯誤。這正好是新手最常踩的坑，工具卻教了相反的答案｜改用 `/\$\{(\w+)\}|\$(\w+)/g` 依完整名稱查表，查不到就展開成空字串並提示「未設定的變數展開為空」。
- `app.js:25-29`（`globToRe`）｜中｜`*` 會比對開頭是 `.` 的檔名（實測 `*` 命中 `.bashrc`），bash 預設（未開 dotglob）不會。02 章正在講「rm * 會碰到哪些檔」，這個差異跟安全直接相關。另外 `[]a]`（`]` 放在第一個表示字面字元）與沒閉合的 `[abc` 都處理錯｜樣式不以 `.` 開頭時，在開頭加上 `(?!\.)`；`[` 之後第一個 `]` 視為字面字元；沒閉合的 `[` 當成普通字元。
- `app.js:17`（`resolvePath`）｜低｜`~bob/x` 被解析成 `/home/userbob/x`。真實 shell 的 `~bob` 是 bob 的家目錄｜`~name` 形式要特別處理，或在輸出說明「本工具只支援單獨的 `~`」。
- `app.js:21`｜低｜判斷「絕對／相對」時用的是還沒 trim 的 `p`，`resolvePath` 卻先 trim 過：輸入「 /etc」時結果是 `/etc`，說明卻寫「這是相對路徑」（實測）｜判斷前先 `p=p.trim()`。
- `app.js:39,45`｜低｜八進位正規式沒有加 `^`：`1755` 會悄悄丟掉 setuid／sticky 那一位，顯示成 755；`x9644` 也被當成 644 接受（實測）｜改成 `/^0?([0-7])([0-7])([0-7])$/`；四位數時提示「第一位是特殊位元，本工具未模擬」。
- `app.js:85`｜低｜checkbox `grep-ic` 同時掛了 `input` 與 `change`，切換一次會重畫兩次（`change` 那支多餘）｜刪掉 `change` 那支。

# 三、網路協定（專題/網路協定/互動課程/）

## 總評
- 概念層次清楚，「每層回答什麼問題、證據在哪、不能證明什麼」貫穿全課；手算例全部正確（58/158、2^8、0.95^20、確認號 1500、TTL 剩餘時間、330 ms）。縮寫展開也確實遵守 BRIEF。
- 但課名是「細講」，全課卻沒有任何一個標頭欄位排列或位元組範例：沒有乙太網路、IPv4、TCP 標頭欄位，沒有十六進位封包，也沒有 tcpdump／dig／curl／ss／ip 指令。所以「封包欄位」實際上無可驗證，這是最大的缺口。
- 模擬器有兩個語意錯誤：00 章讓負載拉到 1500，超過乙太網路 MTU 卻沒提示；02 章 TTL 歸零後仍說封包「經過 70 個路由器」。05 章 HEAD 的示意回應帶了本文，301 沒有 Location。
- BRIEF 寫「每個互動可重設」，實作只有 00 章做到；字典搜尋同樣只比對關鍵字，NAT、SYN、三次握手、狀態碼、擁塞都搜不到。

## 內容錯誤
- `00-封包與分層.html:7,9`×`app.js:15`｜中｜實驗要求把負載「提高到 1500」，滑桿上限也是 1500，得到 1558 位元組。但乙太網路 MTU 1500 是限制 IP 封包的大小，在 20＋20 標頭下 TCP 負載最多 1460（MSS）；1500 位元組負載必須切成兩個區段，模型卻顯示成一個封包，沒有任何提示｜滑桿上限改為 1460，或超過 1460 時輸出「超過 MTU：需切成 ⌈P/1460⌉ 個區段，總負擔 ×N」；正文補一句 MTU／MSS（字典也一併補）。
- `app.js:58-59`（`setupRoute`）×`02-網際網路協定與路由.html:6`｜中｜跳數滑桿上限 70，`ttl=max(0,64−hops)`，輸出「經過 70 個路由器後，存活時間欄位由 64 變為 0」（實測）。真實情況是第 64 個路由器把 TTL 減到 0 就丟棄封包，並回 ICMP Time Exceeded，封包不可能「經過」第 65 個以後的路由器｜hops ≥ 64 時輸出「在第 64 跳被丟棄，該路由器回傳 ICMP 超時訊息（traceroute 就是利用這點）」，滑桿上限改為 64。
- `05-超文字傳輸協定.html:7`｜低｜分別介紹了 https、example.test、8443、/articles/42、view=full 五個欄位，卻從未寫出組合後的 URL 字串｜補上 `https://example.test:8443/articles/42?view=full`，並標出 `:`、`/`、`?` 這些分隔符。
- `03-傳輸控制與使用者資料包.html:3`｜低｜「UDP 只加入埠與檢查資訊」漏了長度欄位（UDP 標頭 8 位元組＝來源埠、目的埠、長度、檢查和）｜改成「只加入埠、長度與檢查和，共 8 位元組」。
- `名詞與概念字典.html`（QUIC 卡）｜低｜「使用者空間傳輸協定」：QUIC 常在使用者空間實作，但這是實作選擇，不是協定定義（已有核心內實作在開發中）｜改成「通常在使用者空間實作的傳輸協定」。
