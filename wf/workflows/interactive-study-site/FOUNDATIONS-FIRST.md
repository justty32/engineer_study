# foundations-first — 零基礎互動課程剖面

[interactive-study-site](README.md)｜硬體原理子工作流 [PRINCIPLES-FIRST](PRINCIPLES-FIRST.md)｜品質關卡 [QUALITY-GATES](QUALITY-GATES.md)｜白話講解方法 [plain-explain](../plain-explain.md)

[interactive-study-site](README.md) 的剖面之一：讀者對這個領域**完全陌生**時，課程要先建立世界觀、翻譯名詞、講清概念，才准操作與診斷。本檔只加這一層要求，建置與發布流程仍走 [interactive-study-site](README.md)。硬體與物理主題再套 [PRINCIPLES-FIRST](PRINCIPLES-FIRST.md)。

**何時套用**（任一成立）：使用者說「基礎薄弱」「從零開始」「名詞看不懂」「不要先考我」「不要有奇怪名詞」；使用者要求繁體中文為主並保留英文對照；主題橫跨多個概念群，需要課程首頁、字典與分章頁；既有頁面要讀者作答或診斷，但此前沒教會所需模型；使用者要**清除對話後還能從 repo 接著做**。
**何時不套用**：讀者已有模型，只是要練熟判斷與取捨 → 直接走 [interactive-study-site](README.md) 主線。

## Done when

- `PROJECT-BRIEF.md` 有「讀者基線」「語言與名詞契約」「prerequisite gap」三段，且都非空。
- 課程有明確零基礎入口頁（`00-*`），每章開頭有「這章假設已懂」並連得回前置頁或字典。
- 下方「可延續性五問」表每列的「答案在哪個檔」欄非空。

## 必要輸入

1. **讀者基線**：已會、不會、相鄰強項、造成理解債的名詞（本專案預設基線在 [plain-explain](../plain-explain.md)）。
2. **目標能力**：學完能解釋、操作、判斷、診斷或設計什麼。
3. **概念依賴圖**：每章真正需要的最少前置概念。
4. **名詞清單**與 **5. 概念清單**：照 [plain-explain](../plain-explain.md) 的兩種條目分開填。
6. **來源包**：本地來源優先；限制、版本、公式與典型值可追溯。
7. **教學邊界**：不教什麼、是否離線、是否純文字、時間是否只作導航。

上述內容寫入 `PROJECT-BRIEF.md`（骨架 [TEMPLATE.project-brief.md](TEMPLATE.project-brief.md)），不可只存在聊天紀錄。

## 語言、名詞與概念

沿用 [plain-explain](../plain-explain.md) 的**語言與名詞契約**（術語首次出現 `繁中（English, ACR）`、台灣慣用語、類比必須收回真實機制）、**名詞條目 vs 概念條目**兩種模板與**通用因果骨架**——那裡是這套規則的唯一出處，本檔不重述。網站要多做的只有兩件：

- 正文、按鈕、回饋與導覽都算「正文」，一起守語言契約；程式識別字與標準名稱保留原文。
- 名詞跨頁反覆出現、或約 15 個以上時，建**獨立可搜尋字典頁**（`名詞與概念字典.html`）。字典是回查用的，不要求背完才准進主線。

## 先教後操作

每節固定順序照 [plain-explain](../plain-explain.md) 的八步（why 問題 → 一句話答案 → 最少前置 → 因果鏈 → 例子 → 易混 → 應用 → 證據），網站再加一條：**互動放在完整教學與數值例之後**。公式或規則只能在量與角色已說清楚後出現。

開工前先做一次「凍結先考後教」：列出每個互動暗中要求的 prerequisite，逐一確認前文教過；移除強制答對、分數、紅色羞辱、倒數壓力與「答對才解鎖」。速查頁與進階頁可以保留，但必須有明確的零基礎入口。從讀者真正缺的底層開始，不從課名或考綱開始；`00-零基礎起點.html` 教該領域最小世界觀、角色、資料／狀態與必要動作。

## 自由實驗契約

自由實驗**不是考題**：操作即更新，不設「提交答案」。每個實驗開工前把這張表填滿，填不滿就是還沒設計完：

| 欄位 | 必填內容 |
|------|---------|
| 教學問題 | 這個操作要讓讀者看懂**哪一條因果**？ |
| 控制量 | 名稱、單位、範圍、預設值、預設值的來源 |
| 狀態方程 | 輸入如何變成結果；簡化假設是什麼 |
| 可觀察輸出 | 數值、狀態、文字替代（不倚賴顏色或動畫）|
| 即時 why | 每次改動同步更新的「為什麼變成這樣」一句 |
| 邊界狀態 | 至少正常、過大、過小、缺失／失敗四種 |
| 重設 | 回到具代表性的教學狀態，不抹除必要說明 |

自由探索完成後，才可以加**無壓力**的小型預測、診斷或取捨——它們用來檢查模型能不能轉移，不用來阻擋瀏覽。

## 有量的主題

主題若有**可量測的量**（電壓、時間、頻率、比例、效能數字、實驗量測值），每個概念要多答三件事：**量與單位**、**簡化假設**（用了哪個理想模型、在什麼範圍內成立）、**用什麼工具或證據能驗證**。公式只能在量與角色都講清楚之後才出現，且附至少兩個極端案例。

## 多頁結構與拆頁條件

大型主題的預設結構（責任不變）：

```text
index.html                  課程地圖、讀者基線、起點與概念依賴
00-零基礎起點.html          不假設任何領域先備知識
名詞與概念字典.html         可搜尋的名詞／概念條目
01-… 02-…                   一頁一個概念群
自我檢核.html               無壓力、可重做的小型檢核（可選）
app.js                      對應各頁 DOM；共用程式必須先檢查元素存在
styles.css                  從正本 cp（見 build-with-agents/codex-notes.md）
PROJECT-BRIEF.md / BUILD-SPEC.md / 驗收紀錄.md
```

任一條成立就拆成多個頁面：一頁裝了兩個以上**可獨立學習、前置不同**的概念群；超過約 6 個主要章節，或無法在一次短學習時段內建立單一模型；互動之間的 DOM／狀態彼此無關；同一檔同時承擔「第一次教學」與「日後速查」（拆成課程頁與字典／速查頁）；手機導覽、焦點、捲動位置或認知負擔已經難以控制。

拆完必須有首頁、章節導覽、上一頁／下一頁與相對連結，**不得產生孤兒頁**。

## 可延續性五問

交付前假設下一個執行者**完全看不到目前的對話**。repo 必須自己答得出這五題，答案落在檔案裡而不是記憶裡：

| 問題 | 答案在哪個檔 |
|------|-------------|
| 讀者會什麼、不會什麼？語言與名詞規則是什麼？ | `PROJECT-BRIEF.md` 讀者基線、用語裁決 |
| 為什麼從這一章開始？概念依賴是什麼？ | `PROJECT-BRIEF.md` 概念依賴圖 |
| 哪些頁是零基礎／字典／主線／進階／速查？ | `PROJECT-BRIEF.md` 交付物段＋課程 `index.html` |
| 關鍵來源、互動公式、典型值與邊界在哪？ | `BUILD-SPEC.md` 逐章契約 |
| 哪些驗收已通過、哪些還要真人或瀏覽器確認？ | `驗收紀錄.md`＋ [WAIT_USER](../../WAIT_USER.md) |

## 派發句模板

新對話不必重述整套方法，直接說：

```text
請用 interactive-study-site 的 foundations-first 剖面，把「<主題>」做成零基礎互動課程。
我在這個主題基礎薄弱，但軟體背景強；正文用繁體中文，術語要附英文與白話解釋，
名詞和概念分開，不要先考後教，內容過大就拆頁。
```

硬體／物理主題再加：`並套用 principles-first 硬體原理子工作流，每個概念都要給出量與單位、簡化假設與驗證工具。`

## 反模式

- 因為讀者會寫程式，就假設他已懂 OS、網路、資安、計算機組織或硬體。
- 靠倒數、完成百分比與答對解鎖，假裝讀者已經學會。
- 把整門課塞進一個超長頁面，零基礎、主線、進階、字典與速查混在一起。
- 清除對話後，新執行者無法從 repo 重建讀者基線與各頁責任。
