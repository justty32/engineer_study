# foundations-first — 零基礎互動課程

← [互動網站工作流](README.md)｜[硬體原理子工作流](PRINCIPLES-FIRST.md)｜[品質關卡](QUALITY-GATES.md)｜[共用寫作規範](../common/writing.md)

把陌生技術主題做成「先建立世界觀、翻譯名詞、解釋概念，再操作與診斷」的多頁互動課程。適用於網路安全、作業系統、網路、資料庫、硬體、科學等領域；硬體與物理主題再套用 [principles-first](PRINCIPLES-FIRST.md) 子工作流。

```text
Done when: 不假設未聲明的先備知識；正文與 UI 以繁體中文為主，
           英文術語首次出現有對應、縮寫與白話功能；名詞和概念分開教；
           大型課程已按概念依賴拆頁；清除對話後仍能只靠 repo 繼續。
```

## 觸發條件

任一條成立就使用：

- 使用者說「基礎薄弱」「從零開始」「名詞看不懂」「不要先考」「不要有奇怪名詞」。
- 使用者要求繁體中文為主並保留英文對照。
- 新主題跨多個概念群，需要課程首頁、字典與分章頁。
- 現有頁面要求作答、診斷或做取捨，但此前未教會 prerequisite。
- 使用者要清除對話後從新主題繼續，方法與讀者基線必須持久化。

## 必要輸入

1. **讀者基線**：已會、不會、相鄰強項、造成理解債的名詞。
2. **目標能力**：學完能解釋、操作、判斷、診斷或設計什麼。
3. **概念依賴圖**：每章真正需要的最少前置概念。
4. **名詞清單**：繁中、英文全名、縮寫、白話功能、所在層級、易混概念。
5. **概念清單**：角色、輸入、機制、狀態改變、結果與證據。
6. **來源包**：本地來源優先；限制、版本、公式與典型值可追溯。
7. **教學邊界**：不教什麼、是否離線、是否純文字、時間是否只作導航。

上述內容寫入 `PROJECT-BRIEF.md` 或內容地圖，不可只存在聊天紀錄。

## 語言與名詞契約

- 正文、按鈕、回饋與導覽以**繁體中文**為主；標準名稱、程式識別字與必要原文保留英文。
- 術語首次出現使用 `繁中（English，縮寫）`，例如：`傳輸層安全性協定（Transport Layer Security, TLS）`。
- 縮寫首次出現必須展開繁中意思與英文全名；後文才可只寫縮寫。
- 沒有穩定繁中譯名時，先講白話動作，再保留業界英文；不能用英文 noun phrase 取代解釋。
- 類比只搭橋，後面必須回到真實協定、程序、權限、狀態、資料或物理機制。

## 名詞解釋與概念解釋

兩者不可混為一張定義卡：

### 名詞條目

```text
名稱：繁中（English, Acronym）
白話：它實際做什麼。
位置／層級：它存在於哪裡、誰使用它。
機制：靠什麼生效。
不要混淆：與相鄰名詞的邊界。
```

### 概念條目

```text
問題：讀者真正想知道的 why。
角色與前置：誰參與、先要有什麼。
因果：輸入／事件 → 機制 → 狀態或資料流改變。
結果：系統、使用者或攻擊者看到什麼。
證據：可由哪種 log、封包、儀器、程序或檔案驗證。
反例：最容易誤套的相似情況。
```

跨兩頁以上反覆使用、易混淆或總量約 15 個以上時，建立獨立可搜尋字典。字典用來回查，不要求背完才能進主線。

## 通用因果骨架

技術概念固定沿這條鏈：

```text
目標／資產與系統邊界
  → 哪個角色、輸入、事件或前置條件出現
  → 真實機制如何處理
  → 資料流、控制流或系統狀態如何改變
  → 對使用者、系統或安全性質造成什麼結果
  → 能從 log、封包、程序、檔案、記憶體或量測看到什麼證據
```

網路安全主題再明確標出：資產、身分、actor、攻擊者能力、信任邊界、控制措施，以及機密性／完整性／可用性／身分保證受到的影響。

## 建置流程

### 0. 凍結先考後教

- 列出每個互動暗中要求的 prerequisite。
- 移除強制答對、分數、紅色羞辱、倒數壓力與答對才能解鎖。
- 速查或進階頁可保留，但必須有明確零基礎入口。

### 1. 建概念依賴與 `00` 起點

- 從讀者真正缺的底層開始，不從課名或大學考綱開始。
- 若讀者連第一層也不熟，建立 `00-零基礎起點.html`，教該領域最小世界觀、角色、資料／狀態、數值表示與必要動作。
- 每章開頭列「這章假設已懂」並能連回前置頁或字典。

### 2. 先教後操作

每節順序：why 問題 → 一句話答案 → 最少前置 → 因果鏈 → 自由實驗／trace → 易混概念 → 實際應用 → 可觀察證據。公式或規則只能在量與角色已說清楚後出現。

### 3. 自由實驗

- 操作即更新，不設「提交答案」。
- 每次改動同步更新數值／狀態、結果與 why。
- 至少提供正常、過大、過小、缺失或失敗等適用邊界。
- 完成模型探索後，才可加入無壓力的診斷或取捨。

### 4. 多頁課程與拆檔

大型主題預設結構：

```text
index.html                  課程地圖、讀者基線、起點與依賴
00-零基礎起點.html          不假設領域先備知識
名詞與概念字典.html         可搜尋的繁中／英文與易混概念
01-主題.html …              一頁一個概念群
<page>.js                   對應該頁 DOM；共用程式安全偵測元素
styles.css                  共用視覺語言
PROJECT-BRIEF.md            讀者、範圍、方法與不做事項
BUILD-SPEC.md／驗收紀錄.md  互動、公式、連結與證據
```

任一條成立就拆成多個 HTML：

- 一頁含兩個以上可獨立學習、具有不同 prerequisite 的概念群。
- 超過約 6 個主要章節，或無法在一次短學習時段建立單一模型。
- 互動具有彼此無關的 DOM／JavaScript 狀態。
- 同一檔同時承擔第一次教學與日後速查；改拆課程頁與字典／速查頁。
- 手機導覽、焦點、捲動位置或認知負擔難以控制。

拆頁後必須有首頁、章節導覽、上一頁／下一頁與相對連結；不得產生孤兒頁。

### 5. 清除對話後的可延續性

交付前假設下一個 agent 完全看不到目前對話，repo 必須能回答：

1. 讀者會什麼、不會什麼，語言與名詞規則是什麼？
2. 為什麼從這一章開始，概念依賴是什麼？
3. 哪些頁是零基礎、字典、主線、進階與速查？
4. 關鍵來源、互動公式、典型值與邊界在哪裡？
5. 哪些驗收已通過、哪些仍需真人或瀏覽器確認？

答案落在 `PROJECT-BRIEF.md`、`README.md`、`BUILD-SPEC.md`／內容地圖與 `驗收紀錄.md`。

## 清除對話後的派發句

新對話不需要重述整套方法，可直接說：

```text
請用 foundations-first 工作流，把「<主題>」做成零基礎互動課程。
我在這個主題基礎薄弱，但軟體背景強；正文用繁體中文，
術語要附英文與白話解釋，名詞和概念分開，內容過大就拆 HTML。
```

若是硬體／物理主題，再加：`並套用 principles-first 硬體原理子工作流。`

網路安全可直接派發：

```text
請用 foundations-first 工作流建立「網路安全」零基礎互動課程；
先教網路、OS、身分、權限、密碼學與威脅模型的最小 prerequisite，
再進攻擊、防禦、封包與 log 證據，不要先考，也不要留下未解釋縮寫。
```

## 反模式

- 因為讀者會寫程式，就假設他已懂 OS、網路、資安、計算機組織或硬體。
- 用大量英文或縮寫製造專業感，卻沒有繁中、全名、白話動作與層級位置。
- 把名詞解釋當概念解釋，只列定義卻沒有角色、狀態、因果與證據。
- 先考後教，或靠倒數、完成百分比與答對解鎖假裝已學會。
- 把整門課塞進超長 HTML，將零基礎、主線、進階、字典與速查混在一起。
- 清除對話後，新 agent 無法從 repo 重建讀者基線與頁面責任。
