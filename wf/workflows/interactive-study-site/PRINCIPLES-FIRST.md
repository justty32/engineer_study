# principles-first — 硬體原理優先子工作流

← [零基礎課程母工作流](FOUNDATIONS-FIRST.md)｜[互動網站工作流](README.md)｜[品質關卡](QUALITY-GATES.md)｜[共用寫作規範](../common/writing.md)

本檔是 [foundations-first](FOUNDATIONS-FIRST.md) 的硬體／物理子工作流。母工作流負責零基礎入口、繁中／英文術語、名詞與概念、拆頁及清除對話後可延續；本檔只增加電源、參考點、回路、電流／電荷／能量、物理公式、極端案例與儀器量測。先完整套用母工作流，再使用本檔，不另複製建置與發布流程。

```text
Done when: 每個必要概念已從物理因果講清楚，首次術語可原地讀懂，
           自由實驗能讓讀者觀察參數→現象→原因，並能指出實機量測證據；
           最後的診斷不依賴此前未教過的知識。
```

## 何時必須走這個剖面

任一條成立就使用：

- 使用者說「題目很多但知識點不會」「這為什麼會 work」「名詞看不懂」「基礎忘了」。
- 互動要求讀者作答，但此前頁面沒有教會完成它所需的模型。
- 讀者只熟悉相鄰領域，例如軟體很強、硬體很弱；類比只能搭橋，不能替代真實機制。
- 主題含電路、力學、熱流、控制或訊號等有明確物理狀態與因果的內容。

已具備模型、目標是熟練判斷或比較取捨時，才直接走一般 `interactive-study-site`。

## 必要輸入

1. **讀者矩陣**：會什麼、不會什麼、哪些術語已造成理解債。
2. **why 問題**：用讀者原話列出「為什麼」，不可先改寫成考綱標題。
3. **應用邊界**：概念最後要接回哪個裝置、工程決策或故障。
4. **概念依賴圖**：完成核心概念前，真正必須先會的最小集合。
5. **術語清單**：繁中／英文、白話動作、物理機制、可觀察現象、易混概念。
6. **來源包**：本地筆記優先；公式、典型值、限制與邊界需可追溯。
7. **教學邊界**：時間只作導航，不製造壓力；是否允許圖片、外部資產與依賴仍服從專案規則。

## 核心因果骨架

每個物理概念固定沿這條鏈說明：

```text
電源與參考點
  → 哪個開關／路徑導通，回路是否閉合
  → 電流、電荷或能量往哪裡
  → 節點電壓、力、溫度或行波如何改變
  → 接收器／系統判成什麼
  → 儀器實際量到什麼
```

通訊主題再向上接：`電氣現象 → 位元與時序 → 封包意義`。不能從 API 或協定名稱倒推物理原理。

## 工作流程

### 0. 回饋分流

- 列出所有「被考但未教」的 prerequisite。
- 凍結 quiz-first 設計：移除強制答對、分數、解鎖、紅色錯誤與倒數壓力。
- 原速查頁可保留；另建原理頁並互相連結，不強塞成一條過長頁面。

### 1. 建立概念依賴圖

- 從讀者真正缺的底層開始，不從課名開始。
- 每個節點只保留理解下游所需的內容。
- 例：`V/I/R 與參考地 → 電容/RC → GPIO 電晶體開關 → 推挽/開漏 → 上拉`；`差動 → 傳輸線/Z₀ → 反射 → 終端 → 偏壓`。

### 2. 翻譯術語

首次出現格式：

```text
上拉（pull-up）：用電阻把無人驅動的線補充電荷到高電位；
它不是主動輸出 1，也不是終端電阻。
```

每個名詞至少回答：它做什麼、靠什麼機制、實機會看到什麼、最容易和什麼混淆。用類比後必須回到真實元件與因果。

### 3. 寫每一節

固定順序：

1. 讀者的 why 問題。
2. 一句話直接回答。
3. 最少前置概念。
4. 完整因果鏈。
5. 公式：符號、單位、假設、物理意義與至少兩個極端案例。
6. 自由實驗。
7. 常見誤解與反例。
8. 接回實際介面／工程用途。
9. 用什麼儀器、預期看到什麼。

### 4. 設計自由實驗

自由實驗不是考題。操作即更新，不要「提交答案」。契約包含：

| 欄位 | 必填內容 |
| --- | --- |
| 教學問題 | 這個操作要讓讀者看懂哪一條因果？ |
| 控制量 | 物理量、單位、範圍、預設值與來源 |
| 狀態方程 | 輸入如何成為結果；簡化假設是什麼 |
| 可觀察輸出 | 數值、狀態、波形文字替代與儀器證據 |
| 即時 why | 每次改動都要同步解釋「為什麼變成這樣」 |
| 邊界狀態 | 至少正常、過大、過小、開路／短路等適用極端 |
| 重設 | 回到具代表性的教學狀態；不抹除必要說明 |

完成自由探索後，才可加入小型預測、診斷或取捨；它們用來檢查模型能否轉移，不用來羞辱或阻擋瀏覽。

### 5. 建置產物

- `PROJECT-BRIEF.md`：增加讀者理解債、教學模式與 prerequisite gap。
- `原理內容地圖.md`：概念依賴、因果鏈、術語與來源；小站可併入內容盤點。
- `PRINCIPLES-BUILD-SPEC.md`：每節與自由實驗契約；小站可併入 BUILD-SPEC。
- 原理頁使用獨立 HTML 與 JavaScript；可共享 CSS，但不可共享會假設另一頁 DOM 的初始化程式。
- `驗收紀錄.md`：記錄原理關卡、公式 fixture、極端值、桌面／手機與離線證據。

## 基準驗收 fixture

任何實作都先用與主題等價的 fixture 驗證方法；硬體介面至少包含：

### 上拉

必須說清楚：裝置放手 → 下拉電晶體關閉 → 上拉替寄生電容充電 → 線升到 VDD；充完後穩態電流近零。拉低時形成 `VDD → R → transistor → GND`，$I\approx(V_{DD}-V_{OL})/R$。R 小較快但 sink 電流與耗電增加。

### 終端

必須說清楚：行波具有 $V/I=Z_0$；負載不匹配時，為滿足線尾邊界條件而產生反射；$R_L=Z_0$ 時 $\Gamma=0$，能量進入電阻成熱。不能只說「吸收雜訊」。雙向總線在兩個物理端終端，不是每台都裝。

## 反模式

- 先考後教，或靠倒數／進度製造已學會的感覺。
- 點選後只顯示正確／錯誤；翻卡假裝互動。
- 一上來丟 $\Gamma$、RC、CPOL 等術語，公式早於物理量。
- 用「像水流」後不回到回路、元件、電荷與限制。
- 把 4.7 kΩ、120 Ω 等典型值說成萬用答案。
- 說終端「吸收雜訊」；混淆上拉、終端與偏壓，或直流電阻與特性阻抗。
- 一段混合接線、時序與封包，沒有分層。
- 只有動畫，沒有數值、單位、因果文字或儀器證據。
