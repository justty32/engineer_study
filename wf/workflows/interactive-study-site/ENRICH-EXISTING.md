# enrich-existing — 用 codex 批次擴充既有互動課程的文字講解

← [工作流入口](README.md)｜[零基礎課程](FOUNDATIONS-FIRST.md)｜[硬體原理子工作流](PRINCIPLES-FIRST.md)｜[品質關卡](QUALITY-GATES.md)

當「互動課程網站已經存在、互動也能動」，只是**文字講解太精簡、讀者讀不懂**時，用這個子工作流把每頁的解說做得更豐富、更深入淺出。指揮者（Claude）只做調度與驗證，實際改寫交給 **codex CLI** headless 批次執行。

## 適用時機

- 課程頁已是自足互動 HTML（各頁互動小工具靠該群 `app.js` 內的元素 `id` 掛勾）。
- 目標是**加厚文字**：白話直覺、實例演算、因果與可觀察證據、常見誤解、術語中英對照。
- **不**重做互動、不改版面、不改結構。要新增互動元件請走主工作流的第二輪派工，不走本子工作流。

## 硬性紅線（傳給 codex，違反即失敗）

1. **不得修改該群 `app.js`**（一個字都不動）。
2. **不得改動／改名／刪除任何既有 `id`、`class`、`data-*` 或互動小工具 DOM**；只在其周圍增補文字。
3. **不得改檔名、topbar、pager 與頁間相對連結**。
4. **不得加任何外部資源**（圖片／外部字型／CDN／遠端 API／第三方 script）；維持純離線純文字。
5. **不改原意、不杜撰**；簡化模型標明假設與適用範圍。
6. **公式一律純文字 HTML，禁止任何 LaTeX 語法**（不得出現 `\(` `\)` `\[` `\]` `$` `$$`，也不引入 MathJax／KaTeX）。本網站**沒有數學渲染器**，LaTeX 會顯示成生的反斜線。改用 Unicode 符號（θ × · √ ≈ ≤ ≥ Σ π Δ →）加 `<sub>`／`<sup>`（例：H<sub>T</sub>、2<sup>32</sup>、4×4）。這是既有頁面的慣例。

## codex 呼叫方式

- 帳號限制：以 ChatGPT 帳號登入時**不能用 `-m gpt-5-codex`**（回 400）；不指定 `-m`，用預設模型。
- headless：`codex exec --sandbox workspace-write --cd <repo根> -`，prompt 走 stdin。
- 每群一個 codex job，寫入不同資料夾者可並行（建議一次 2 群，控管速率與驗證負荷）。
- prompt = 「目標資料夾一行」＋（數學多的群加一句純文字公式提醒）＋下方《共用指令稿》。

## 流程

1. **盤點**：`find <群> -maxdepth 1 -name '*.html'`；確認該群有 `app.js`／`styles.css`。
2. **試點一群**：先跑一個代表性群，人工檢視風格與豐富度，取得使用者同意。
3. **逐群套用**：同意後依序（或每次 2 群並行）跑完其餘群。
4. **每群驗證**（見下）；有殘留問題就補一個 focused codex 修正 pass（例如「LaTeX → 純文字」）。
5. **交付**：更新 `wf/SESSION-LOG.md` open 狀態；本庫無 build/test，驗收以內容、連結、格式、UTF-8 為準。

## 每群驗收檢查（指揮者親自跑）

```sh
d="<目標群>"
# 1) app.js / styles.css 未被動（應為空）
git diff --stat -- "$d/app.js" "$d/styles.css"
# 2) app.js 依賴的所有 id 仍存在於該群頁面
ids=$(grep -oE 'byId\("[^"]+"\)|getElementById\("[^"]+"\)' "$d/app.js" | grep -oE '"[^"]+"' | tr -d '"' | sort -u)
for id in $ids; do grep -qF "id=\"$id\"" "$d"/*.html || echo "MISSING id: $id"; done
# 3) 無 LaTeX 殘留
grep -rlF -e '\(' -e '\)' -e '\[' -e '\]' "$d"/*.html
# 4) 無新增外部資產（僅允許回主站連結）
grep -oiE '(src|href)="https?://[^"]+"' "$d"/*.html | grep -viE 'justty32.github.io'
# 5) node 檢查（若動到 js；本子工作流不應動）
node --check "$d/app.js"
```

全部通過（缺 id 0、LaTeX 殘留 0、外部資產 0、app.js 差異空）才算該群完成。

## 共用指令稿（複製給 codex，開頭再接「目標資料夾」）

```text
# 任務：擴充互動課程頁的文字講解（深入淺出、繁體中文）

你是內容編輯，要把「目標資料夾」裡每一頁互動課程 HTML 的文字講解改得更豐富、更好懂。讀者是：電機／通訊本科畢業、軟體能力很強、但其他理工基礎並不扎實的自學者。目標是讓他「讀得懂、建立直覺、記得住」。

## 絕對禁止（違反即算失敗）
1. 不得修改 app.js（一個字都不要動）。
2. 不得改動、改名或刪除任何既有 HTML 元素 id、class、data-* 屬性，或互動小工具的 DOM 結構（app.js 靠它們運作）；只在其周圍增補說明文字。
3. 不得改檔名、不得改動 topbar 與 pager 與各頁之間的相對連結。
4. 不得加入任何外部資源：圖片、外部字型、CDN、遠端 API、分析碼、第三方腳本一律禁止。維持純離線、純文字。
5. 不改變原意、不得杜撰；簡化模型要標明假設與適用範圍。

## 要做的事（逐頁）
對資料夾內每一個章節 HTML 頁（00-*.html 起，含 00A 先修頁與名詞與概念字典.html；index.html 課程地圖只在必要時小幅潤飾），大幅擴充其解說性文字：
- 白話先講清楚：每個關鍵概念先用一兩句生活化或軟體工程師熟悉的說法點出「它在解決什麼問題」，再回到真實機制與名詞。比喻之後一定要收回到真實運作與其限制。
- 深入淺出的推導：需要公式時一律用純文字 HTML 寫數學，禁止任何 LaTeX 語法（不得出現 \( \) \[ \] $ $$，也不得引入 MathJax／KaTeX；本網站沒有數學渲染器，寫 LaTeX 會顯示成生的反斜線）。改用 Unicode 數學符號（θ × · √ ≈ ≤ ≥ Σ π Δ）搭配 <sub> 下標與 <sup> 上標。公式要附符號、單位、假設、量綱，並帶一組具體數字的實例演算。
- 因果鏈與可觀察證據：說明「操作 → 狀態變化 → 結果 → 可在哪裡看到證據」（封包擷取、log、系統狀態、量測工具等），並指出某工具能證明什麼、不能證明什麼。
- 常見誤解／不要混淆：用清單明確拆開容易混淆的概念。
- 首次出現的術語：同時給繁體中文、英文全名與必要縮寫，之後可只用中文或縮寫，與同課程其他頁、字典用語一致。
- 既有互動小工具：可增補「這個實驗在示範什麼、怎麼玩、看到數字變化代表什麼、為什麼」的引導文字，但不新增需要寫 JavaScript 的互動元件。
- 字典頁：補齊每個名詞的「位置／功能／機制／邊界」與每個概念的「角色／狀態或資料流／因果／結果／可觀察證據」。

## 風格與版面
- 繁體中文為主、UTF-8。可重排 HTML 為好讀多行，但保持有效 HTML。
- 盡量沿用既有 CSS class（card、grid、flow、output、eyebrow、lead、prereq 等）排新內容。盡量不動 styles.css；若確有可讀性需要只可小幅新增，且不得破壞版面、不得手機或桌面溢出／重疊。
- 內容更豐富但不灌水；每段都要有資訊量。

## 收尾自檢
- 確認沒有動到 app.js（git diff --stat，app.js 不應出現）。
- 確認每頁互動元件 id 仍與 app.js 對得上。
- 確認沒有新增任何外部 URL，也沒有殘留 LaTeX 分隔符。
- 最後用中文列出「每一頁各做了哪些擴充」的簡短清單。
```
